## 一、背景与问题

### 家族公告里缺的那一档

九天之前，2024 年 3 月 4 日，Anthropic 发布了 Claude 3 家族：Haiku、Sonnet、Opus 三个模型，按智能、速度和成本分层。那篇公告（LR-001）说，Opus 是最强的一档，Sonnet 居中，Haiku 是最快、最轻的一档。但发布当时，只有 Opus 和 Sonnet 可以使用，Haiku 是“即将推出”。

这就留下了一个缺口：家族分层里最便宜、最快的那一档，用户还用不上。本篇要补的，就是这个缺口——Haiku 正式发布了。

### 这篇公告要回答的问题

严格说，这篇短博客没有提出一个科学问题。它要回答的是一个产品问题：需要快速、便宜地处理大量文本的企业用户，能不能现在就用上 Haiku？

博客开篇就把答案摆出来：Haiku 是“同等智能级别里最快、最便宜的模型”，具备“最先进的视觉能力”，在行业基准上表现强劲，适合广泛的企业应用。

不解决这个问题会怎样？对实践来说，没有 Haiku 这一档，企业用户只能在 Sonnet 和 Opus 之间选：要么为不需要的智能付费，要么忍受更慢的速度。Haiku 的定位是补上这个空位——处理季度财报、合同、法律案件这类大批量文档，以及客服这种需要快速响应的场景。

为什么这篇公告现在能写？博客没有说。家族公告与本篇之间隔了九天，合理的推测是 Haiku 在这段时间里完成了上线准备，但博客正文没有给出任何解释——它只是宣布“今天发布”。这一点记下来：九天间隔的原因，文中未说明。

读完之后应该改变的认知，其实很有限：这篇公告没有改变任何关于模型能力的科学认知，它改变的只是一个使用上的事实——Haiku 从“即将推出”变成了“现在可用”。读完之后应该改变的做法也很具体：需要速度和成本优先的任务，可以考虑用 Haiku 而不是 Sonnet 或 Opus。

## 二、方法与设计

### 这篇东西的性质

先说清楚：它是一篇模型发布帖，不是同行评审论文，也不是实验。按论文意义上的实验设计，它没有假设检验，没有随机化，没有对照组，没有预注册，也没有统计分析。下面按它本来面目来评估它：一则由速度、价格与基准主张支撑的能力宣称。

### 博客的论证结构

整篇博客只有四段实质内容加一段发布信息，结构很简单：

第一，定性：Haiku 是同等智能级别里最快、最便宜的模型，有最先进的视觉能力，基准表现强劲。

第二，速度：企业用户需要快速分析大数据集、快速产出结果，比如客服。Haiku 在绝大多数工作负载上比同行快三倍；对 32K token 以下的提示，每秒处理 21K token（约 30 页）；输出也快，适合响应式聊天体验和并行执行许多小任务。

第三，价格：输入输出 token 的定价比是 1:5，针对长提示的企业工作负载设计；成本是同等性能级别其他模型的一半。举了两个例子：一美元可以处理分析 400 起最高法院案件，或 2,500 张图片。

第四，安全与可用性：Haiku 优先考虑企业级安全与稳健性，经过严格测试以减少有害输出和越狱的可能性，另有持续系统监控、端点加固、安全编码实践、强数据加密协议、严格访问控制、定期安全审计和渗透测试。更多措施见 Claude 3 模型卡。从今天起，客户可以通过 API 使用 Haiku，或在 claude.ai 上用 Claude Pro 订阅使用；Haiku 已上线 Amazon Bedrock，即将上线 Google Cloud Vertex AI。

## 三、主要发现

### 发现一：Haiku 正式发布了，可用渠道有三条

从今天（2024 年 3 月 13 日）起，客户可以通过 Claude API 使用 Haiku，或在 claude.ai 上用 Claude Pro 订阅使用。Haiku 已上线 Amazon Bedrock，即将上线 Google Cloud Vertex AI。

这就是本篇唯一一个完全可核实的、没有附加条件的事实：一个模型从“即将推出”变成了“可用”。它与 LR-001 的关系也在这里落定：家族公告发布时 Haiku 还不能用，本篇补上了可用性。

### 发现二：速度宣称——三倍快，每秒 21K token

博客说，Haiku 在绝大多数工作负载上比同行快三倍；对 32K token 以下的提示，每秒处理 21K token（约 30 页）。输出也快，能支撑响应式聊天体验和并行执行许多小任务。

这两个数字的条件是不对称的。“每秒 21K token”给了条件：提示在 32K token 以下。但“三倍快”没有给条件：没说同行是谁，没说拿什么工作负载比的，也没说“绝大多数”是多少。速度的测量方式——硬件、并发、批大小、输出长度、百分位——一个都没提。

### 发现三：价格宣称——输入输出比 1:5，成本是同级别的一半

博客说，Haiku 的定价模型里输入输出 token 的比例是 1:5，针对长提示的企业工作负载设计；企业可以依靠 Haiku 快速分析大批量文档，成本是同等性能级别其他模型的一半。

举的两个例子是：一美元可以处理分析 400 起最高法院案件，或 2,500 张图片。这两个例子的问题在于，博客没有说明每起案件或每张图片平均多少 token，也没有说明“处理分析”具体包括什么操作——是只读一遍，还是生成摘要、做问答？没有这些条件，两个例子无法换算成可核查的价格，也无法与其他模型比较。

### 发现四：视觉能力与基准表现——只有定性说法，没有数字

博客说 Haiku 具备“最先进的视觉能力”，在行业基准上表现“强劲”。正文里没有给出任何一个基准的名字，也没有给出任何一个分数。如果页面上有基准对比图，抓取到的文本里没有它的内容，所以这里的数字一律按未核实处理，不印数字。

这一点与 LR-001 的区别值得说清楚：家族公告的模型卡转载里有 Haiku 的基准数字（例如 MMLU 75.2%），但那些数字属于 LR-001 的材料，来自模型卡副本与二手摘要，不是本篇正文的。本篇正文自己没有给出任何基准数字。

### 发现五：安全宣称——一串措施，没有证据

博客说，Haiku 优先考虑企业级安全与稳健性，经过严格测试以减少有害输出和越狱的可能性；另有持续系统监控、端点加固、安全编码实践、强数据加密协议、严格访问控制、定期安全审计和渗透测试。更多措施见 Claude 3 模型卡。

这是一串措施清单，不是一份证据。测试了什么、结果如何、与谁比较，正文一个字没提。它的可核查性依赖于模型卡，而模型卡不是本篇的精读对象。

## 五、精读点评

### 这篇公告要回答的问题，到底答得怎么样

先说优点。这篇公告很短，但结构是诚实的：它没有假装自己是一篇论文。它要做的事只有一件——宣布 Haiku 可用了，并告诉企业用户为什么值得用：快、便宜、能上 Bedrock 和 claude.ai。可用性这个核心事实是清楚的，渠道也写明白了。作为发布帖，它完成了本职工作。

但按精读的标准，有几个地方需要较真。

第一，**最关键的速度与成本宣称都没有可核查的条件**。“三倍快”没有对手、没有工作负载、没有硬件；“一半成本”没有对手、没有任务、没有用量；“一美元 400 起案件”没有每起案件的 token 数。这三个宣称合起来，恰好是这篇公告的全部卖点，但没有一个能让读者独立验证。读者只能选择相信 Anthropic 的说法，或者自己去测。

第二，**基准表现的宣称是空的**。博客说 Haiku 在行业基准上表现“强劲”，有“最先进的视觉能力”，但正文里没有一个基准的名字、没有一个分数。如果页面上有基准对比图，抓取到的文本里没有它的内容——这意味着，即使读者想核查，也得去看图，而图里的数字没有方法说明。相比之下，家族公告（LR-001）至少还给了模型卡，里面有 Haiku 的基准数字；本篇连这个都没有。

第三，**安全那一段是措施清单，不是证据**。严格测试、持续监控、端点加固、渗透测试——这些词每一个都听起来很扎实，但没有一个附带结果。测试覆盖了什么、发现了什么、与 Sonnet 和 Opus 相比如何，正文一概没提。它的可核查性完全依赖于模型卡，而博客正文没有给出模型卡的任何数字。

第四，**九天间隔没有解释**。家族公告说 Haiku“即将推出”，九天后本篇说“今天发布”。这九天里发生了什么——是 Haiku 完成了最后的测试，还是单纯排期到了——博客没有说。这个缺口很小，但它说明这篇公告的叙事是不完整的：它只宣布结果，不交代过程。

### 科学问题还原：这篇工作真正移走了哪块石头

这篇公告的反常起点不是一个科学反常，而是一个产品缺口：家族分层里最便宜、最快的那一档，在家族发布时还不能用。反常不在于模型“有什么新能力”，而在于**产品线缺了一档**——用户只能在 Sonnet 和 Opus 之间选，没有速度与成本优先的选项。

不解决这个问题，企业用户要么为不需要的智能付费，要么忍受更慢的速度。对实践来说，缺口补上之后，大批量文档分析与客服这类场景才有了匹配的选项。对领域来说，这篇公告没有改变任何认知——它没有提出新的科学主张，也没有推翻任何已有信念。

为什么这篇公告现在能写？博客没有说。合理的推测是 Haiku 在这九天里完成了上线准备，但这只是推测，文中没有证据。blocker 不是技术难题，而是“还没上线”——而“为什么九天前没上线”这个问题，博客没有回答。

方法与问题的匹配点在这里不太适用：这篇公告没有方法，它用的手段就是“宣布 + 给数字”。但这个手段有一个内在的上限：它只能回答“能不能用、多少钱、多快”，回答不了“快多少、便宜多少、强多少”——而后者恰恰是它自己提出的主张所需要的证据。公告没有给出这些证据，方法与问题的匹配在这里断了。

答案改变了什么？认知上，什么都没改变——Haiku 的能力在家族公告里已经介绍过了，本篇没有增加任何新的能力信息。实践上，改变是具体的：Haiku 从“即将推出”变成了“现在可用”，企业用户多了一个速度与成本优先的选项。改变有限的地方在于，读者仍然不知道 Haiku 到底有多快、多便宜、多强——这篇公告给出的数字都缺条件，基准数字干脆没有。

### 为什么链：为什么“最快最便宜”这个说法站不住

最承重的主张是开篇那句：Haiku 是同等智能级别里最快、最便宜的模型。往下追一层：为什么读者应该相信它快？博客给出的最近原因是每秒 21K token（提示在 32K token 以下）。但这个数字没有硬件、没有并发、没有批大小，别人无法复现。更关键的是，“三倍快”这个更有冲击力的说法，连这个数字的条件都没有——没有对手、没有工作负载。

再往下追一层：为什么“最便宜”可信？博客给出的原因是 1:5 的输入输出定价比和“一半成本”的说法，外加一美元 400 起案件、2,500 张图片的例子。但每百万 token 的具体价格没有给出，对手没有具名，每起案件、每张图片的 token 数也没有给出。没有这些条件，“便宜”只是一个相对说法，无法换算成读者自己的账单。

还有一层值得追：为什么博客敢说视觉能力“最先进”、基准表现“强劲”，却一个数字都不给？最简单的解释是：数字在图里。但图里的数字有没有方法说明、是不是与家族公告模型卡里的数字一致，读者从正文里无法知道。这里存在一个断层：博客用定性词做了定量主张，却把定量证据放在了正文之外。

### 四维价值 verdict

认知价值：低。它没有推翻或确认任何信念，也没有回答任何科学问题。如果这篇公告不存在，读者对 Haiku 能力的了解不会少什么——家族公告（LR-001）已经介绍了 Haiku 的定位，模型卡里已经有它的基准数字。本篇唯一新增的认知是“Haiku 现在可用了”，这是一个产品事实，不是一个科学发现。

方法价值：低。它没有留下任何别人能直接拿走复用的东西——没有数据集、没有代码、没有评估方法、没有可复现的实验设计。唯一能复用的是一组价格与速度的宣称数字，而且这些数字缺条件，别人连复现都做不到。

边界价值：比较清晰——但不是作者写出来的，是读者自己划出来的。这篇公告不证明 Haiku 到底有多快、多便宜、多强，不证明它的视觉能力真的“最先进”，也不证明它的安全测试真的“严格”。最容易误读的推论是“Haiku 是同等智能级别里最好的选择”——博客的说法只覆盖速度与成本，没有覆盖质量、可靠性与适用范围，读者不应该拿它去论证“Haiku 在所有方面都够用”。

启示价值：低。它没有使任何下一步研究成为可能。最便宜的决定性下一步不是一个实验，而是一次独立测量：用固定提示集、固定输出长度、明确并发，在 Haiku 与具名的同行模型上测一次延迟与每美元任务完成量，再把结果与博客的“三倍快”“一半成本”对照。如果测出来接近，宣称成立；如果差得远，宣称就被修正。这个测量的成本不高，但它需要 Anthropic 之外的独立测量者来做——博客本身没有提供做这件事所需的任何条件。

### 效度评分

内部效度 1 分（满分 5 分）：这不是一项实验，没有对照、没有可检验的假设，证据就是作者自己的宣称。威胁点：速度与成本宣称都没有对照条件，对手未具名，测量方法未说明。

外部效度 2 分：结论只对“2024 年 3 月 13 日发布的 Claude 3 Haiku、在 Anthropic 自己的 API 与 claude.ai 上”这个范围成立。换别的部署渠道、别的工作负载、别的提示长度，速度与成本数字是否成立，博客没有给出任何可以外推的依据。

构念效度 2 分：核心构念“同等智能级别”本身没有定义——博客没有说明“智能级别”是怎么划分的、Haiku 与谁同级。“最先进的视觉能力”也没有操作化：没有基准名字、没有分数，读者不知道“先进”是指什么。

统计结论效度 1 分：全文没有任何可核查的统计量——没有样本量、没有误差棒、没有置信区间、没有运行次数。唯一能量化的表述（21K token/秒、1:5、一美元 400 起案件）都没有完整的测量条件。

可复现性 1 分：没有公开代码、没有数据、没有评估方法，别人无法重跑任何一项发现。唯一能复现的是“去用 Haiku、自己测速度与成本”——但博客没有说明用什么提示、什么并发、什么硬件，连这个也复现不了。

总体判断：这是一则完成了本职工作的发布帖，价值在于“宣布可用”而不是“证明了什么”。它值得被记住的原因只有一个：Haiku 从家族公告里的“即将推出”变成了“现在可用”，Claude 3 家族的分层从此完整。但它的速度、成本与基准宣称都没有可核查的条件，证据全靠作者的说法。置信度低：核心事实（Haiku 发布了、可用渠道是哪些）可信，因为这是可验证的产品事实；但关于“有多快、多便宜、多强”的判断，置信度应下调——这些问题这篇公告没有回答。

### 证伪器

- 主张“Haiku 在绝大多数工作负载上比同行快三倍”的证伪器：用固定提示集、固定输出长度、明确并发，在 Haiku 与具名的同行模型上测一次延迟；如果 Haiku 的延迟不是同行的大约三分之一，该主张即被修正。
- 主张“成本是同等性能级别其他模型的一半”的证伪器：用同一批任务、同一用量，在 Haiku 与具名的同行模型上算一次实际账单；如果 Haiku 的账单不是对方的大约一半，该主张即被修正。
- 主张“视觉能力最先进、基准表现强劲”的证伪器：公开正文里没有给出的基准名字与分数，再与同行模型在同一 harness 下的分数对照；如果 Haiku 的分数低于同行，该主张即被修正。

### 替代解释

替代解释一：速度优势只在短提示、小并发的条件下成立。预测差异：如果这个解释是对的，那么在长提示（超过 32K token）或高并发下，Haiku 的速度优势会缩小甚至消失。区分实验：按提示长度分段测一次延迟，看 21K token/秒这个数字在提示变长之后是否还成立。博客只给了 32K token 以下的条件，本身就暗示了这个边界。

替代解释二：成本优势来自定价结构，而不是能力相当。预测差异：如果这个解释是对的，那么在需要高质量输出的任务上，Haiku 可能需要更多的重试或更长的输出才能达到与 Sonnet 相当的质量，实际每任务成本并不比 Sonnet 低一半。区分实验：按任务完成质量（而不是按 token 数）算一次每任务成本，看“一半成本”在质量对齐之后是否还成立。博客没有做这个实验；它的“一半成本”只按 token 定价算，没有按任务质量算。

### 作者自述局限 vs 分析者发现的局限

作者自述的局限：**没有**。博客没有“局限”一节，没有承认任何不确定性。

分析者发现的、作者没有明说的局限有四条。第一，速度与成本宣称都没有完整的测量条件，对手未具名，这是最严重的缺失，博客没有把它列为局限。第二，基准表现的宣称没有数字，数字如果存在只在图里，正文无法核查。第三，安全措施只列了清单，没有给出任何测试结果。第四，九天间隔没有解释，家族公告与本篇之间的衔接是不完整的。

### 接下来看什么

排第一的是启示价值里的最便宜的决定性实验：独立测量——用固定提示集、固定输出长度、明确并发，在 Haiku 与具名的同行模型上测一次延迟与每美元任务完成量，再与博客的“三倍快”“一半成本”对照。判据是测量结果与宣称的接近程度：如果接近，宣称成立；如果差得远，宣称就被修正。这个实验比任何新的模型评估都更值得先做，因为它决定了这篇公告的核心卖点值不值得相信。

其次看两件事。一是看 Claude 3 模型卡里的 Haiku 基准数字（LR-001 的材料）与本篇若有的基准图是否一致——如果一致，至少说明基准数字有一个来源；如果不一致，说明两个地方的数字来自不同的评估运行，需要追问。二是看 Haiku 后续的实际使用反馈：企业用户是否真的在用它处理大批量文档、成本是否真的降下来了——这是检验“一半成本”最直接的证据，但它在 Anthropic 之外，需要用户侧的数据。

## 六、§I 结论、结果与价值总览

一句话结论：Claude 3 Haiku 于 2024 年 3 月 13 日正式发布，补上了 Claude 3 家族里“即将推出”的那一档——这是本篇唯一完全可核实的事实；它主打的速度与成本优势都没有给出可核查的对照条件，基准成绩只在图里、正文核对不了，所以这是一则值得记住的发布事实，不是一份可以用来论证“最快最便宜”的证据。

核心结论：

1. Haiku 于 2024 年 3 月 13 日正式发布，可通过 Claude API、claude.ai（Claude Pro 订阅）使用，已上线 Amazon Bedrock，即将上线 Google Cloud Vertex AI。置信度高，证据是正文的发布信息；它与 LR-001 的关系已核实——家族公告发布时 Haiku 是“即将推出”，本篇补上了可用性。
2. 博客宣称 Haiku 在绝大多数工作负载上比同行快三倍，对 32K token 以下的提示每秒处理 21K token（约 30 页）。置信度低，证据是正文第 2 段；“三倍快”没有对手、没有工作负载、没有硬件条件，无法独立验证。
3. 博客宣称 Haiku 的输入输出 token 定价比是 1:5，成本是同等性能级别其他模型的一半，一美元可处理分析 400 起最高法院案件或 2,500 张图片。置信度低，证据是正文第 3 段；每百万 token 的具体价格未给出，对手未具名，两个例子的换算条件缺失。
4. 博客宣称 Haiku 有最先进的视觉能力、基准表现强劲，并列出一串安全措施。置信度低，证据是正文第 1 段与第 4 段；基准名字与分数正文里一个都没有，安全测试只列了措施、没有结果。
5. 这篇博客没有作者自述的局限，也没有解释家族公告与本篇之间九天间隔的原因。置信度高，证据是正文全文——它是一则发布帖，不是论文，局限的缺席本身是体裁使然，但按精读标准必须记下来。
