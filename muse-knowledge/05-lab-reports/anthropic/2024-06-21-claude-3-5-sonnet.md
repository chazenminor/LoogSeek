## 一、背景与问题

2024 年 3 月，Anthropic 发布了 Claude 3 家族。三个月后，也就是 2024 年 6 月，它发布了 Claude 3.5 家族的第一个模型：Claude 3.5 Sonnet。

这次发布由两份文件组成。一份是公告，标题是 Introducing Claude 3.5 Sonnet。另一份是配套的技术文件，《Claude 3.5 Sonnet Model Card Addendum》，也就是模型卡附录。

公告本身没有任何基准表，也没有任何数字结果。所有的数字都在附录里。这是一个需要注意的阅读前提：只读公告的读者，看到的是没有数字的宣称。

公告的核心说法是层级倒置：一个中端模型，如今击败了此前的旗舰模型。

公告的原话是，Claude 3.5 Sonnet "raises the industry bar for intelligence, outperforming competitor models and Claude 3 Opus on a wide range of evaluations, with the speed and cost of our mid-tier model, Claude 3 Sonnet"。

具体到能力，公告说了三件事。

第一，在研究生级推理、本科级知识和编码能力上，它 "sets new industry benchmarks"。附录里对应的基准是 GPQA、MMLU 和 HumanEval。

第二，它 "operates at twice the speed of Claude 3 Opus"，也就是运行速度是 Opus 的两倍。

第三，在一次内部智能体编码评估中，它 "solved 64% of problems, outperforming Claude 3 Opus which solved 38%"。

视觉方面，公告称它是 "Our strongest vision model yet, surpassing Claude 3 Opus on standard vision benchmarks"。它点名的项目包括 MathVista、ChartQA、DocVQA 和 AI2D，都是最先进的水平。

安全方面，公告说："our red teaming assessments have concluded that Claude 3.5 Sonnet remains at ASL-2"。附录则说，它 "does not pose risk of catastrophic harm"。部署之前，英国 AI 安全研究所对它做了测试，结果与美国 AI 安全研究所共享。

同一篇公告还发布了一个产品功能，叫 Artifacts。公告把它描述为一种使用 Claude 的新方式，一个动态工作区。Artifacts 是一次产品发布，不是一项经过评估的能力宣称。

价格和可用性方面，公告给出的定价是每百万输入 token 3 美元，每百万输出 token 15 美元，上下文窗口是 20 万 token。它可以通过 Claude.ai、iOS 应用、API、Amazon Bedrock 和 Google Cloud 的 Vertex AI 使用。

公告最后做了展望。它说 Claude 3.5 Haiku 与 Claude 3.5 Opus 将于 "later this year" 发布。它的目标是，"每隔几个月大幅改善智能、速度与成本之间的权衡曲线"。

顺带提醒一句：Haiku 确实在 2024 年 10 月发布了，Claude 3.5 Opus 从未发布。这句提醒来自文件之外的后见之明，不是本次精读的发现。它只说明一点：不要把这份文件的前瞻性陈述当作结果来读。

这份文件没有陈述任何研究问题。它不是一篇论文，而是一次模型发布。

如果把它还原成一个问题来读，这个问题是：新的中端模型 Claude 3.5 Sonnet，是不是在标准能力基准上达到或超过了此前的旗舰 Claude 3 Opus 和当前竞品模型，同时成本更低、速度更快，并且保持在可接受的安全范围内？

用来回答这个问题的对照模型包括 Claude 3 Opus、Sonnet、Haiku，以及 GPT-4o、GPT-4 Turbo、Gemini 1.5 Pro 和 Llama 3 400B（instruct 版）。用来衡量的东西包括基准分数、内部智能体编码通过率、人类偏好胜率、拒绝率、长上下文回忆率和安全分级。

## 二、方法与设计

先说明这份文件的方法论地位。它不是一项受控实验。

它没有假设，没有随机化，没有预注册。它也没有操纵任何变量。它做的事，是把一组已有的公开基准跑一遍，做成对照表，再加上一次内部评估和一次人类偏好研究。

### 标准基准

附录列出了两张基准表。第一张表是语言、推理与编码基准：GPQA Diamond、MMLU、MATH、HumanEval、MGSM、DROP、BIG-Bench Hard 和 GSM8K。第二张表是视觉基准：MMMU、MathVista、AI2D、ChartQA 和 DocVQA。

每张表的每一行都注明了样本数和思维链的使用方式。比如 GPQA 是 0-shot 思维链，MMLU 有 5-shot 思维链、5-shot 和 0-shot 思维链三种协议，MATH 是 0-shot 思维链，HumanEval 是 0-shot，DROP 是 3-shot，GSM8K 是 0-shot 思维链。

但这只是方法的一半。另一半没有报告。

提示词没有报告。评估框架和框架版本没有报告。解码设置，比如温度、top-p 和最大 token 数，没有报告。运行次数和种子没有报告。任何基准的样本量都没有报告。

竞品的数字不是 Anthropic 自己测的。它们引自竞品厂商自己的出版物。附录的参考文献里列出了这些出处。

这一点直接影响表格的可比性。同一行里，不同模型的评估协议并不相同。

MATH 这一行，Claude 模型和 GPT-4o 用的是 0-shot 思维链，Gemini 用的是 4-shot，Llama 3 用的是 4-shot 思维链。

MGSM 这一行，Claude 模型和 GPT 模型用 0-shot 思维链，Gemini 用的是 8-shot。

GSM8K 这一行，Gemini 用 11-shot，Llama 3 用 8-shot 思维链。

DROP 这一行，Gemini 的样本数标注为 "Variable shots"，也就是可变样本数。

还有一处协议上的特殊情况。DROP 和 BIG-Bench Hard 这两行，脚注说明评估用的是模型的预训练版本，而不是指令微调版本。表里其余部分用的是指令微调版本。两种版本混在同一张表里。

### 内部智能体编码评估

智能体编码评估是附录里单独的一项内部评估。它的设计是这样的：问题基于真实的开源 pull request。模型必须实现改动，通常涉及 3 到 4 个文件，最多 20 个文件。最终提交必须通过全部隐藏测试。模型可以在一个智能体循环里编写代码、运行代码、自我修正。环境是一个沙箱，没有互联网。

但这项评估的关键细节都没有报告。问题有多少个，没有说。问题是怎么选的，没有说。时间预算和步数预算，没有说。用的智能体脚手架、工具集和提示词，没有说。种子也没有说。

没有外部模型跑过这项评估。表里只有 Claude 家族的四个模型。

### 拒绝行为与长上下文

拒绝行为的评估用了两个具名数据集：Wildchat 和 XSTest。Wildchat 分有毒和无毒两组，分别报告正确拒绝率和错误拒绝率。XSTest 报告错误拒绝率。两个数据集的规模、抽样方式和提示词格式都没有报告。

长上下文评估用的是 Anthropic 自己的大海捞针任务变体。它测量模型在不同上下文长度下回忆一个事实的平均回忆率，上下文最长到 20 万 token。针的类型、提示词和每个长度下的试验次数都没有报告。附录的图 1 提到，评估用了一个经过修改的提示词。

### 人类偏好评估

人类偏好评估的做法是：评分者按任务说明与模型对话，然后给出偏好。结果以胜率呈现，对照基线是 Claude 3 Opus。Opus 对自身的胜率按构造是 50%。

这项评估的方法没有写在附录里，而是推迟到了另一份文件，也就是 2024 年 3 月的 Claude 3 主模型卡第 5.5 节。那份主卡本次精读没有读。

评分者的数量、任务的数量、是否盲法、平局怎么处理、评分者之间的一致性，都没有报告。

### 安全评估

安全评估分几个部分。CBRN 方面，做了自动化知识测试和非专家 uplift 测试。网络安全方面，做了夺旗赛。自主性方面，通过代码编写评估来测量。

附录说，针对每个领域都定义了 "thresholds of concern"，也就是关注阈值。但阈值的数值没有报告，模型对这些阈值的分数也没有报告。

附录报告的定性结论是，针对性测试没有发现阈值被突破。完整的 RSP 协议没有为这个模型运行，原因是模型 "does not trigger the 4x effective compute threshold"，也就是没有触发 4 倍有效算力的阈值。4 倍算力这个触发条件是一项政策约定。

部署之前，英国 AI 安全研究所对一个 "near-final model"，也就是接近最终的模型，做了测试。METR 对自主性做了初步探索。这两方的结果都没有发表在所读的资料里。

### 没有报告的东西

训练方面的信息，两份文件完全没有报告。没有训练数据，没有算力，没有参数量，没有架构，没有训练方法。模型是怎么变强的，从这两份文件里找不到任何答案。

统计方面也是空白。没有误差棒，没有置信区间，没有 p 值，没有效应量，没有多重比较校正。10 月的附录后来在 OSWorld 表里报告了 95% 置信区间，6 月的附录没有。

数据和代码的可用性同样是空白。没有随这两份文件发布代码、提示词、原始结果或评估脚本。

必须明说的一句话：这是一篇模型发布帖加厂商模型卡，不是同行评审论文。科学意义上没有实验——没有操纵变量、没有随机化、没有统计推断。正确的评估标准是"读者应该在多大程度上信任这些厂商报告的数字以及建立在其上的宣称"，而不是"假设检验的功效是否充足"。

## 三、主要发现

### 推理与知识

先看研究生级推理。GPQA Diamond 上，0-shot 思维链协议下，Claude 3.5 Sonnet 得了 59.4%。

Opus 是 50.4%，Sonnet 是 40.4%。GPT-4o 是 53.6%，GPT-4 Turbo 是 48.0%。Gemini 和 Llama 3 在这一行没有数字。

同一个基准还有一种协议：5-shot 思维链，32 个样本多数投票。3.5 Sonnet 在这个协议下得了 67.2%，Opus 59.5%，Sonnet 46.3%。竞品模型没有跑过这个协议。

本科级知识 MMLU 测了三种协议，结果各不相同。

5-shot 思维链协议下，3.5 Sonnet 得了 90.4%。Opus 是 88.2%，Sonnet 是 81.5%。竞品模型在这一行没有任何数字。

5-shot 协议（不用思维链）下，3.5 Sonnet 得了 88.7%。Opus 是 86.8%，Sonnet 是 78.3%。Gemini 是 85.9%，Llama 3 是 86.1%。GPT-4o 和 GPT-4 Turbo 这一行是空的。

0-shot 思维链协议下，3.5 Sonnet 得了 88.3%。Opus 是 85.7%，Sonnet 是 77.1%。但 GPT-4o 在这个协议下是 88.7%，比 3.5 Sonnet 高。GPT-4 Turbo 是 86.5%。

这里有一个细节。附录的脚注说明，GPT-4o 的 88.7% 和 GPT-4 Turbo 的 86.5%，来自 OpenAI 的 simple-evals 套件在 0-shot 思维链下的结果。

所以 MMLU 的情况是：标题宣称的 90.4% 来自一个没有竞品数据的协议；而在唯一一个有 GPT-4o 数据的相同协议下，3.5 Sonnet 落后。

数学推理 MATH 上，0-shot 思维链协议下，3.5 Sonnet 得了 71.1%。Opus 是 60.1%，Sonnet 是 43.1%。但 GPT-4o 是 76.6%，GPT-4 Turbo 是 72.6%。3.5 Sonnet 比 GPT-4o 低 5.5 个百分点，比 GPT-4 Turbo 低 1.5 个百分点。

Gemini 在 MATH 上是 67.7%，Llama 3 是 57.8%。但这两个数字用的不是同一协议：Gemini 是 4-shot，Llama 3 是 4-shot 思维链。所以它们和 71.1% 不能直接比。

多语言数学 MGSM 上，0-shot 思维链协议下，3.5 Sonnet 得了 91.6%。Opus 是 90.7%，Sonnet 是 83.5%。GPT-4o 是 90.5%，GPT-4 Turbo 是 88.5%。Gemini 是 87.5%，但用的是 8-shot 协议。

小学数学 GSM8K 上，0-shot 思维链协议下，3.5 Sonnet 得了 96.4%。Opus 是 95.0%，Sonnet 是 92.3%。Gemini 是 90.8%，用的是 11-shot；Llama 3 是 94.1%，用的是 8-shot 思维链。GPT-4o 和 GPT-4 Turbo 这一行是空的。

阅读理解 DROP 上，3-shot 协议下，3.5 Sonnet 的 F1 分数是 87.1。Opus 是 83.1，Sonnet 是 78.9。GPT-4o 是 83.4，GPT-4 Turbo 是 86.0，Llama 3 是 83.5。Gemini 是 74.9，样本数标注为可变。

但 DROP 这一行有个脚注：评估用的是模型的预训练版本，不是表里其余部分用的指令微调版本。加上 Gemini 的可变样本数，这一行的标准化程度是全表最低的。

BIG-Bench Hard 上，3-shot 思维链协议下，3.5 Sonnet 得了 93.1%。Opus 是 86.8%，Sonnet 是 82.9%。Gemini 是 89.2%，Llama 3 是 85.3%。GPT-4o 和 GPT-4 Turbo 这一行是空的。这一行同样用的是预训练版本。

### 编码

HumanEval 上，0-shot 协议下，3.5 Sonnet 得了 92.0%。附录没有明说，但隐含的意思是通过率 pass@1。

Opus 是 84.9%，Sonnet 是 73.0%。GPT-4o 是 90.2%，GPT-4 Turbo 是 87.1%。Gemini 和 Llama 3 都是 84.1%。

3.5 Sonnet 领先全部已报告单元格，比 GPT-4o 高 1.8 个百分点。

内部智能体编码评估的结果是：3.5 Sonnet 解决了 64% 的问题，Opus 解决了 38%，Sonnet 21%，Haiku 17%。

64% 对 38%，差距是 26 个百分点。这是全文件最大的单个差距。也是透明度最低的一项测量：问题数量、问题选择、脚手架、提示词和预算都没有报告，而且没有外部模型跑过它。

### 视觉

视觉基准一共五项，3.5 Sonnet 领先四项，输掉一项。

MMMU 验证集上，0-shot 加思维链协议下，3.5 Sonnet 得了 68.3%。Opus 是 59.4%，Sonnet 是 53.1%。但 GPT-4o 是 69.1%，比 3.5 Sonnet 高 0.8 个百分点。GPT-4 Turbo 是 63.1%，Gemini 是 62.2%。

MathVista 的 testmini 子集上，3.5 Sonnet 得了 67.7%。Opus 是 50.5%，Sonnet 是 47.9%。GPT-4o 是 63.8%，GPT-4 Turbo 是 58.1%，Gemini 是 63.9%。3.5 Sonnet 比 Gemini 高 3.8 个百分点。

AI2D 测试集上，3.5 Sonnet 得了 94.7%。Opus 是 88.1%，Sonnet 是 88.7%。GPT-4o 是 94.2%，GPT-4 Turbo 是 89.4%，Gemini 是 94.4%。3.5 Sonnet 只比 Gemini 高 0.3 个百分点，比 GPT-4o 高 0.5 个百分点。

这个差距有多大，很难说。因为没有任何数字带有误差棒，读者无法判断 0.3 个百分点是不是噪声。

ChartQA 测试集上，宽松准确率，3.5 Sonnet 得了 90.8%。Opus 是 80.8%，Sonnet 是 81.1%。GPT-4o 是 85.7%，GPT-4 Turbo 是 78.1%，Gemini 是 87.2%。3.5 Sonnet 比 Gemini 高 3.6 个百分点。

DocVQA 测试集上，ANLS 指标，3.5 Sonnet 得了 95.2%。Opus 是 89.3%，Sonnet 是 89.5%。GPT-4o 是 92.8%，GPT-4 Turbo 是 87.2%，Gemini 是 93.1%。3.5 Sonnet 比 Gemini 高 2.1 个百分点。

### 人类偏好

人类偏好评估里，附录正文确认了三个任务的胜率。法律任务上，3.5 Sonnet 对 Opus 的胜率是 82%。金融任务上是 73%。哲学任务上也是 73%。Opus 对自身的胜率按构造是 50%。

这三个数字按报告是领先的。但评分者数量、任务数量、盲法和平局处理都没有报告。所以这些胜率作为效应量，是无法解读的。

图 3 里还有其他任务的胜率：编码、文档、医学、创意写作、多语言、STEM、指令遵循、诚实、视觉、无害，以及仅乐于助人。但 PDF 文本抽取打乱了标签与数值的对应关系，这些值无法从文本取回里可靠恢复。

所以除了法律、金融、哲学这三个值，图 3 的其余胜率在本文件里不作为已确立的值呈现。它们列在最后的未核实清单里。

### 拒绝行为与长上下文

Wildchat 有毒分组里，正确拒绝率越高越好。3.5 Sonnet 是 96.4%，Opus 是 92.0%，Sonnet 是 93.6%，Haiku 是 90.0%。3.5 Sonnet 是 Claude 模型里最高的。

Wildchat 无毒分组里，错误拒绝率越低越好。3.5 Sonnet 是 11.0%。Opus 是 11.9%，Sonnet 是 8.8%，Haiku 是 6.6%。

也就是说，3.5 Sonnet 在无毒问题上的错误拒绝率比 Opus 好，但比 Sonnet 和 Haiku 差。附录正文说它在两个维度上都超过了 Opus。这句话只对 Opus 为真，不对全部 Claude 模型为真。

XSTest 上，错误拒绝率越低越好。3.5 Sonnet 是 1.7%。Opus 是 8.3%，Sonnet 是 36.6%，Haiku 是 33.1%。这是本文件里最引人注目的拒绝结果。

大海捞针任务里，全部上下文长度下的平均回忆率，3.5 Sonnet 是 99.7%。Opus 是 99.4%，Sonnet 是 95.4%，Haiku 是 95.9%，Claude 2.1 是 94.5%。

在完整的 20 万 token 上下文长度下，3.5 Sonnet 的回忆率仍然是 99.7%。Opus 是 98.3%，Sonnet 是 91.4%，Haiku 是 91.9%，Claude 2.1 是 92.7%。其他模型在这个长度下下降了大约 7 个百分点，3.5 Sonnet 没有下降。

但要说明一点：3.5 Sonnet 和 Opus 在这项任务上都已经接近天花板。而且这项任务是合成的单事实检索，不是真实长文档推理的测试。

### 速度、价格与安全

公告说，Claude 3.5 Sonnet 的运行速度是 Claude 3 Opus 的两倍。

但两份文件都没有给出任何支撑这个说法的测量。没有延迟数字，没有吞吐量，没有任务，没有硬件，没有测量方法。按文件所写的内容，这个比值是无法核实的。

## 四、作者的结论与局限

作者自己的结论，可以归纳为四句。

第一，Claude 3.5 Sonnet 在广泛评估上击败了竞品模型和 Claude 3 Opus，同时保持中端模型的速度和成本。这是公告的标题宣称。

第二，它在研究生级推理、本科级知识和编码能力上树立了新的行业基准。这是公告对 GPQA、MMLU 和 HumanEval 的说法。

第三，它是 Anthropic 迄今最强的视觉模型，在标准视觉基准上超过了 Opus。这是公告对视觉能力的说法。

第四，它仍然处于 ASL-2 安全级别，不构成灾难性伤害的风险。这是公告和附录对安全的说法。

公告里还有两句定性说法，没有配任何测量。一句是，在理解微妙含义、幽默和复杂指令上有明显改进。另一句是，它非常擅长写高质量内容，语气自然、亲切。这两句都没有对应的测量。

作者自己陈述的局限很少。公告本身完全没有陈述任何局限。对任何能力宣称都没有保留意见。

附录里有一句明确承认评估方法论尚不成熟的话。原话是："We still have a lot to learn about the science of evaluations and ideal cadences for performing these tests"。

附录还说了两件事。第一，HHH 训练，也就是 Helpful、Honest、Harmless 的训练，可能因为拒绝而导致能力评估低估模型的底层能力。附录说已经用内部诱发加以补偿，但结果 "may underestimate the capability of an equivalent Helpful-only model"。诱发的技术没有描述。

第二，完整的 RSP 协议没有为这个模型运行，因为模型没有触发 4 倍有效算力的阈值。只做了针对性测试。

附录还注明，英国 AI 安全研究所测试的是一个 "near-final model"，也就是接近最终的模型。不一定是已经交付的产物。

对于表格本身显示的失利和空白单元格，文件没有给出任何回应，也没有承认其中任何反对意见。

## 五、精读点评

以下这一节是分析者的判断，和上面对公告与附录本身的呈现分开写。

清晰度上，这份文件只能算中等。公告是简洁的营销文字。附录的表格可读，但 PDF 文本抽取打乱了列对齐，同一行里不同模型的评估协议并不相同，关键方法被推迟到另一份文件或略去。

### 这篇工作要回答的科学问题

这份文件背后并没有一个科学反常。没有任何观察、失败或出乎意料的现象逼出它。触发它的是产品发布。

所谓反常只是商业层面的：中端 Sonnet 的基准分数超过了此前的旗舰 Opus。但这不是待解释的科学现象，而是一句营销叙事。

对领域里的认知而言，这份文件基本不重要。不解决它，没有任何信念会一直错下去。它没有带来关于智能本质、训练机制或评估科学的新认知。

对实践而言，它的重要性是真实的，但它是商业和部署层面的。用户要决定用 Sonnet 还是 Opus，还是竞品模型。如果数字不可信，用户会为错误的模型选择付出真金白银：更高的推理成本，更差的任务表现。

这份文件的完成没有任何方法上的障碍。跑一组公开基准、做一张对照表，是任何实验室在任何时间都能做的事。它不是移走了哪块石头才得以完成，只是新模型发布时例行要做的一次评估汇总。

真正卡住的东西恰恰相反：可信的跨厂商比较之前没做到，这份文件之后也仍然没做到。协议不对称，二手数字，没有不确定性。

方法和问题也不匹配。问题是新模型是不是在能力、成本和速度上全面优于旧旗舰与竞品，同时还安全。方法是厂商自己跑自家模型的公开基准，加上引用竞品厂商自己的数字，再加一次不公开的内部评估和一次方法被推迟到另一份文件的人类评估。

这个方法回答的其实是一个更容易的问题：在我们选的基准、我们选的协议下，我们的模型得分更高吗？它绕过的不是技术障碍，而是独立性：没有独立重测，没有统一评估框架，没有不确定性量化。

答案在认知上什么都没改变。关于智能、训练或评估科学，没有任何信念应该修改。文件没有提出机制，没有检验假设，没有推翻任何旧信念。它甚至没有声称自己发现了任何机制。

答案在实践上改变了两件事。第一是部署选择：用户现在有了一个有基准数字支撑的理由，把一部分原来用 Opus 的工作负载换成更便宜、更快的 3.5 Sonnet。第二是行业叙事："中端即前沿"成为此后各家发布会的模板。但这两个改变都建立在未经独立验证的数字上。如果数字背后的比较方法有偏，实践改变的方向可能是错的。

### 价值判断

认知价值上，它只确认了一个可部署的事实：中端模型在已报告基准上可以击败此前的旗舰。它没有推翻或确认任何关于智能、训练或评估的科学信念。

方法价值很低。它没有留下任何别人能直接拿走复用的东西：没有新工具，没有新范式，没有新度量，没有新实验设计，没有新数据集。唯一接近方法的内部智能体编码评估，只以散文描述，没有发布任务集、脚手架或问题数量。

边界价值上，它明确不证明的东西比它证明的东西更多。它不证明行业领先，不证明一般智能，不证明真实世界软件工程能力，不证明两倍速度，也不证明安全性。读者最容易误读的推论是：基准领先就等于模型全面更强，部署一定更好。

启示价值上，它使一次最便宜的决定性检验成为可能：在单一评估框架下，用相同提示词、相同样本数、相同解码，重跑 GPQA Diamond、HumanEval、MATH、MMMU 四项基准，对比 Claude 3.5 Sonnet 与 GPT-4o，并报告样本量、种子与 95% 置信区间。

### 最弱的一点

最弱的一点是跨厂商表格的可比性。标题宣称和"新的行业基准"都建立在它上面，但它的支撑最弱。

同一行里协议不对称。竞品数字是厂商出版物的二手引用，不是重新测量。单元格恰恰在竞品可能获胜的地方缺失，比如 MMLU 的 5-shot 思维链协议和 GPQA 的多数投票协议。没有任何不确定性量化来说明差距是否真实。

第二弱的一点是内部智能体编码评估。最大的单个宣称差距，64% 对 38%，来自文件里最不透明的测量。

如果行业领先的宣称是错的，发布的核心叙事，也就是中端已成为前沿，就会崩塌。随之崩塌的还有用 Sonnet 而非 Opus 或竞品进行部署的速度与定价理由。

能解释同样数据的更简单说法是：新模型在这些基准、这些协议下更好。这个说法去掉了一步跳跃，也就是从基准分数跳到一般智能。MATH 与 MMMU 的失利，以及缺失的竞品单元格，用"全面更强"是解释不了的，除非再加上额外的假设。文件从未陈述这些假设。

### 这些宣称要成立，需要什么

这些宣称要成立，需要几件事为真。而这几件事都没有得到验证。

第一，基准上得分更高，就等于一般智能或能力更高。这是标题宣称的逻辑，但文件里只有断言，没有论证。

第二，所报告的基准没有被污染，模型没有在近似复制的测试题上训练过。文件里没有任何去污染声明。

第三，附录里评估的 2024 年 6 月快照，就是用户在发布时收到的模型。这一点无法核查，因为任何地方都没有报告检查点或版本标识符。

第四，表里的跨模型单元格可以直接比较，差异反映的是模型，而不是评估协议。表格本身削弱了这一点：同一行里协议不同，竞品数字是引用的，若干单元格是空的。

第五，内部智能体编码评估衡量的是真实世界的软件工程能力，而且给每个模型的脚手架和工具是等价的。脚手架、工具、迭代预算和提示词都没有描述，所以这两点都无法验证。

第六，人类偏好胜率衡量的是能力提升，而不是风格、长度或评分者预期。方法被推迟到另一份文件，评分者数量、任务数量、盲法和平局处理都没有报告。

第七，两倍速度是一次有意义、可复现的速度比较。没有任何延迟数字、任务、硬件或测量方法。

第八，能力提升没有跨过 ASL-3，因为没有触发 4 倍有效算力阈值，而且针对性测试没有发现阈值被突破。阈值没有报告，定量的安全结果没有报告，英国 AI 安全研究所的结果也没有发表。4 倍算力触发条件本身是一项政策约定，不是物理事实。

如果第一点倒下，数字可以完全正确，而标题宣称仍然是错的。如果第二点倒下，表里的每个单元格都可疑。如果第三点倒下，这些数字描述的是另一个产物。

### 什么能推翻它，接下来看什么

有几件事可以直接检验这些宣称。

一次独立的单框架重跑，用相同的提示词、样本数和解码，锁定模型版本，重跑 GPQA Diamond、HumanEval、MATH 和 MMMU。如果 GPT-4o 在 GPQA 或 HumanEval 上打平或领先，或者任何差距落入置信区间之内，行业领先的宣称就被削弱了。如果 3.5 Sonnet 在四项上都领先并且超出置信区间，宣称就得到加强。

这项实验成本最低，信息量最大。它只用公开基准和现有 API，却直接检验全文件最承重的宣称和最弱的一环。

另外几件事也值得看。2024 年 10 月的附录是直接的后继文件：它增加了 SWE-bench Verified、TAU-bench 和 OSWorld，还报告了 95% 置信区间，并且重新呈现了 6 月的数字。把它的协议和置信区间与 6 月表格对比，是检验 6 月差距能否在更好的测量下存活的最快方法。但不要把它的数字与 6 月快照的数字混淆。

英国 AI 安全研究所部署前结果或 METR 自主性评估的发表，可以直接检验安全分级。内部智能体编码评估的任何发布，比如任务集、框架或问题数量，可以直接检验 64% 对 38% 的差距。Anthropic 后续的系统卡条目是否修正了任何 6 月数字，也值得留意。

还有几件事是按文件所写根本无法检验的。"提升行业智能标杆"这句话里的"智能"从未被操作化，"理解微妙含义和幽默"也没有任何测量。这些说法记录为不可证伪，而不是得到支持。

效度方面，用五分制打分的话，内部效度 2 分，外部效度 2 分，构念效度 2 分，统计结论效度 1 分，可复现性 1 分。被判断的对象是公告加附录作为证据，而不是模型本身。模型可能比文件显示的更好或更差，文件不让读者判断这一点。

总体判断是：一项可信的家族内改进宣称，包裹在夸大的行业领先宣称之中。所依据的厂商表格，作为"Anthropic 在 2024 年 6 月报告了什么"的记录是有用的，作为其宣称之普遍性的证据则是不充分的。

置信度是中。中而非低，是因为 Claude 模型内的差距大且方向一致。不高，是因为跨厂商比较、统计与安全证据均无法从资料中核实。

## 六、I. 结论、结果与价值总览（只用本文件已核实的材料）

### 一句话结论

2024 年 6 月快照在 Anthropic 所选基准、所选协议下得分高于 Claude 3 Opus。但"击败竞品、树立新行业基准"的标题宣称不成立：MATH 与 MMMU 上落败，若干标题比较没有竞品数据，没有任何数字带不确定性，也没有任何训练信息。

### 核心结论

家族内领先是确立的，置信度为中。

表 1 的 11 行里，3.5 Sonnet 在 7 行领先全部已报告单元格。GPQA 是 59.4% 对 Opus 的 50.4%。HumanEval 是 92.0% 对 84.9%。智能体编码是 64% 对 38%。差距大，方向一致，不太可能完全是人工产物。但没有任何数字带样本量、种子、误差棒或置信区间。

行业领先没有确立，置信度为低。

MATH 上 71.1% 对 GPT-4o 的 76.6%，低 5.5 个百分点。MMMU 上 68.3% 对 69.1%。MMLU 的 0-shot 思维链协议上 88.3% 对 88.7%。三项直接落败。而 MMLU 的 5-shot 思维链协议（90.4%）和 GPQA 的多数投票协议（67.2%）完全没有竞品单元格。

智能体编码 64% 对 38%，是最有实践意义、也最难核查的数字，置信度为中。

这项内部评估基于真实开源 pull request，涉及多文件编辑，带有代码执行与自我修正的智能体循环。但问题数量、问题选择、步骤和时间预算、脚手架、提示词、种子都没有报告。26 个百分点的差距，原因完全未知。是模型更强，还是脚手架更好，现有数据区分不了。

两倍速度无法核实，置信度为低。

"运行速度是 Claude 3 Opus 的两倍"没有任何条件。两份文件都没有报告延迟、吞吐量、任务、硬件或测量方法。

安全分级 ASL-2 只是断言，置信度为低。

它基于针对性测试，而不是完整的 RSP 协议。定量结果没有报告。英国 AI 安全研究所测试的是一个接近最终的模型，结果没有发表。阈值与分数都没有公开。对外部读者来说，这个分级实际上无法证伪。

拒绝率确有改善的一面，置信度为中。

XSTest 错误拒绝率是 1.7%，Opus 是 8.3%，Sonnet 是 36.6%，Haiku 是 33.1%。这是本文件里最引人注目的拒绝结果。但 Wildchat 无毒错误拒绝率 11.0%，差于 Sonnet 的 8.8% 和 Haiku 的 6.6%。附录说"在两个维度上都超过 Opus"，这句话只对 Opus 为真。

### 关键结果

决定性的数字是这几组：GPQA、HumanEval、MATH、MMLU 和 MMMU 的得分；智能体编码的通过率；XSTest 与 Wildchat 的拒绝率；大海捞针的回忆率；人类偏好胜率；以及两倍速度这个无法使用的数字。全部数字和它们的条件都在上面的数字台账里。

### 科学价值总评

认知上，它只确认了一个可部署的事实：中端模型在已报告基准上可以击败此前的旗舰。它没有推翻或确认任何关于智能、训练或评估的科学信念，因为文件没有提出或检验任何机制。

方法上，价值很低。它没有留下任何别人能直接拿走复用的东西。唯一接近方法的内部智能体编码评估，只以散文描述，没有发布任务集、脚手架或问题数量。

边界上，它明确不证明的东西比它证明的东西更多：不证明行业领先，不证明一般智能，不证明真实世界软件工程能力，不证明两倍速度，也不证明安全性。最容易误读的推论是：基准领先就等于模型全面更强，部署一定更好。

启示上，最便宜的决定性实验是在单一评估框架下，用相同提示词、相同样本数、相同解码，重跑 GPQA Diamond、HumanEval、MATH、MMMU 四项基准，对比 Claude 3.5 Sonnet 与 GPT-4o，并报告样本量、种子与 95% 置信区间。

总体上，这份文件值得被记住的，是 2024 年 6 月的发布事实与家族内比较的记录：中端击败旗舰，智能体编码 64% 对 38%，XSTest 拒绝率大幅改善。不值得被记住的，是行业领先的证据。

### 适用边界

不要引用这份文件论证 3.5 Sonnet 是当时行业最强模型。不要把智能体编码 64% 对 38% 读作真实世界软件工程能力。不要引用两倍速度。不要引用图 3 里除法律、金融、哲学之外的胜率，那些没有核实。不要把价格（每百万 token 3 美元输入、15 美元输出）当作当前价格，那是 2024 年 6 月的发布价。

可以引用的是：2024 年 6 月快照在 Anthropic 所选基准、所选协议下的得分，以及 ASL-2 作为"所述的分级"。它背后的证据没有展示。
