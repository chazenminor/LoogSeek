## 一、背景与问题

### 一次发布，三件事

2024 年 6 月，Anthropic 发布了 Claude 3.5 Sonnet。到了 10 月，它一次发布了三件事：升级版 Claude 3.5 Sonnet、新模型 Claude 3.5 Haiku，以及一个全新的能力 computer use。

公告的开篇说法是，升级版 Sonnet 在各方面都超过了前代，尤其是在编码上——而编码本来就是它已经领先的领域。Haiku 则是在速度与前代 Haiku 相近的前提下，在许多评估上追平了此前的最大模型 Claude 3 Opus。

### 真正的新意：让模型直接用电脑

三件事里真正新的，是 computer use。公告把它叫做一项“开创性的新能力”，以公开测试版（public beta）的形式在 API 上提供。开发者可以指挥 Claude 像人一样用电脑：看屏幕、移动光标、点击按钮、输入文字。

公告说，Claude 3.5 Sonnet 是第一个以公开测试版提供 computer use 的前沿 AI 模型。同时公告也立刻降温：这个阶段它仍然是实验性的，有时笨拙、容易出错。提前发布是为了拿到开发者的反馈，Anthropic 预期这项能力会迅速改进。

已经开始探索的合作方包括 Asana、Canva、Cognition、DoorDash、Replit 和 The Browser Company。公告说，这些合作方正在执行的任务需要几十步，有时甚至上百步才能完成。举的例子是 Replit：它用新版 Sonnet 的 computer use 与界面导航能力，为 Replit Agent 产品开发一个在应用搭建过程中评估应用的功能。

### 这篇要问什么

这份文件没有陈述任何研究问题。它不是一篇论文，而是一次模型发布。

如果把它还原成一个问题来读，这个问题是：升级版 Claude 3.5 Sonnet 与新版 Claude 3.5 Haiku，是不是在标准能力基准上超过了前代模型与竞品，同时新版 Sonnet 的 computer use 能不能像人一样操作电脑，并且这一切是否还处在可接受的安全范围内？

用五问的方式老实说：这里没有科学反常逼出这个问题。触发它的，是产品发布。没有什么观测、失败或出乎意料的现象需要解释。之前没做，不是因为有什么技术障碍卡住了，而是因为新模型刚刚发布，评估汇总例行要做一次。答案在认知上什么都没改变——没有任何关于智能、训练或评估科学的信念应该修改。答案在实践上改变了部署选择：如果数字可信，用户可以把一部分原来用 Opus 的工作负载换成更便宜的 Sonnet 或 Haiku，也可以开始尝试用 computer use 自动执行重复的电脑操作。但这两个改变都建立在未经独立验证的厂商数字上。

## 二、方法与设计

### 公告本身没有方法

先说明这份文件的方法论地位。它不是一项受控实验。

它没有假设，没有随机化，没有预注册，没有操纵任何变量。它做的事，是宣布两个模型与一个公开测试版能力，附上几组厂商运行的基准分数，再加上一份模型卡附录。

### Computer use 是怎么工作的（按公告与附录的说法）

Computer use 的做法，不是为每个任务造专用工具，而是教模型通用的电脑技能，让它使用为人类设计的标准工具与软件。Anthropic 为此建了一个 API，让 Claude 能感知电脑界面并与之交互。

开发者的使用方式是：把指令交给 Claude，Claude 把指令翻译成电脑命令。公告举的例子是填表：查看电子表格，移动光标打开浏览器，导航到相关网页，再用这些页面上的数据填表。

附录补充了评估方式：用 OSWorld 基准评估 computer use。OSWorld 评估模型在真实电脑环境里完成各类任务的能力，涉及网页与桌面应用、操作系统文件读写、跨应用工作流。每个任务基于真实的电脑使用场景，附带配置与评估脚本。Anthropic 的评估只提供截图输入，尽管 OSWorld 也可以提供无障碍树（accessibility tree）等其他输入形式。

附录还举了两个 computer use 的演示例子。一个是重复流程自动化：按电子表格里的供应商数据逐家填写供应商申请表，缺失的信息去供应商搜索门户查找。另一个是信息搜集：打开谷歌地图，找一家评分 4.5 以上、距离 3 英里以内的咖啡店。

### 评估设计（附录）

附录的评估分几个部分。Computer use 用 OSWorld，标准步骤数是 15 步；为了理解模型的局限，附录还优化了提示词并把步数上限从 15 步提高到 50 步。

工具使用与智能体任务用两个新加入的基准：SWE-bench Verified 与 TAU-bench。SWE-bench Verified 评估模型解决真实开源 Python 仓库 GitHub issue 的能力，模型要在工具循环里理解、修改、测试代码，直到提交，最终代码用当初解决该 issue 的 pull request 里的真实单元测试评分，模型看不到评分用的测试。TAU-bench 评估模型在模拟用户与 API 的客服场景里交互的能力，分零售与航空两个领域，用 pass^k 指标报告——k 次采样全部正确才算通过，这与 pass@k（k 次里至少一次正确就算通过）不同。

视觉能力用 MMMU、MathVista、AI2D、ChartQA、DocVQA，全部是 0-shot；其中 MMMU、MathVista、ChartQA 在给出最终答案前使用思维链。

推理、编码与问答用 GPQA、MMLU、MMLU Pro、MATH、HumanEval、MGSM、DROP、BIG-Bench Hard，以及新加入的 AIME 与 IFEval。AIME 用的是 2024 年两次考试的题目。

拒绝行为用 Wildchat 与 XSTest，方法推迟到 2024 年 3 月 Claude 3 主模型卡的 5.4.1 节。人类偏好评估让评分者按任务说明与模型对话并给出偏好，胜率的计算方法推迟到主模型卡 5.5 节。

安全评估按 Responsible Scaling Policy（RSP）做，覆盖 CBRN、网络安全与自主能力三个领域，外加信任与安全红队测试。升级版 Sonnet 在部署前由美国 AI 安全研究所（US AISI）与英国 AI 安全研究所（UK AISI）做了联合测试，METR 做了独立评估。

训练方面的信息，两份文件完全没有报告。没有训练数据，没有算力，没有参数量，没有架构，没有训练方法。模型是怎么变强的，从这两份文件里找不到任何答案。

## 三、主要发现

### 编码：新版 Sonnet 大幅领先前代

公告的核心数字在编码上。SWE-bench Verified 上，升级版 Sonnet 从 33.4% 提高到 49.0%，公告称高于所有公开模型，包括 OpenAI o1-preview 这样的推理模型与专为智能体编码设计的系统。附录补充，截至 2024 年 10 月 22 日，SWE-bench 排行榜上的最高分是 45.2%。

TAU-bench 上，升级版 Sonnet 在零售领域从 62.6% 提高到 69.2%，在更难的航空领域从 36.0% 提高到 46.0%。附录的表里，Haiku 在零售领域得了 51.0%，高于 Claude 3 Opus 的 45.1%；在航空领域得了 22.8%，高于 Claude 3 Haiku 的 16.0%。

附录的内部智能体编码评估里，升级版 Sonnet 解决了 78% 的问题，Haiku 解决了 74%，原版 Sonnet 是 64%，Opus 是 38%。这是家族内最大的差距，但也是透明度最低的一项测量。

### Haiku：小模型追平大模型

Haiku 在 SWE-bench Verified 上得了 40.6%，高于原版 Sonnet 的 33.4%。公告说，它超过了许多使用公开最强模型的智能体，包括原版 Sonnet 与 GPT-4o。

附录的表里，Haiku 在 GPQA 上 0-shot 思维链得了 41.6%，MMLU Pro 上得了 65.0%，MATH 上得了 69.2%，HumanEval 上得了 88.1%，IFEval 上得了 85.9%。公告说，Haiku 以与前代 Haiku 相近的速度，在许多智能基准上超过了 Claude 3 Opus。

Haiku 最初只提供文本输入，图像输入随后跟进。公告说它将在当月晚些时候通过 API、Bedrock 与 Vertex AI 提供。

### Computer use：领先，但绝对值很低

OSWorld 上，升级版 Sonnet 在仅截图输入、标准 15 步条件下得了 14.9%，公告称明显高于次优 AI 系统的 7.8%。附录给出了 95% 置信区间：14.9% 的区间是 [11.3%, 18.5%]。

把步数上限提高到 50 步并优化提示词后，成功率从 14.9% 提高到 22.0%，95% 置信区间是 [17.8%, 26.2%]。附录说，这说明有些任务可能受益于给模型更多与环境交互的机会。

但附录同时也写明，人类在 OSWorld 上的成功率是 72.36%。14.9% 与 22.0% 都远低于人类水平。附录的结论是，这代表了相对以往结果的显著进步，但距离人类表现仍有大幅改进空间。

分项看，差异很大。15 步条件下，操作系统类任务成功率是 54.2%，专业类是 24.5%，日常类是 16.7%，办公类是 7.7%，跨应用工作流类是 7.9%。50 步条件下，专业类提高到 40.8%，办公类提高到 17.9%，日常类提高到 24.4%，工作流类提高到 10.9%，但操作系统类反而从 54.2% 下降到 41.7%。不过这些分项的置信区间很宽，操作系统类 15 步的区间是 [34.3%, 74.1%]，50 步是 [22.0%, 61.4%]，两个区间大幅重叠。

### 推理与视觉：全面小幅领先，有两处例外

附录的推理表里，升级版 Sonnet 在 GPQA Diamond 上 0-shot 思维链得了 65.0%，高于原版的 59.4%、GPT-4o 的 53.6% 与 Gemini 1.5 Pro 的 59.1%。MMLU 上 5-shot 思维链得了 90.5%，只比原版的 90.4% 高 0.1 个百分点；0-shot 思维链得了 89.3%，高于 GPT-4o 的 88.7%。MATH 上 0-shot 思维链得了 78.3%，高于原版的 71.1% 与 GPT-4o 的 76.6%，但 Gemini 的 86.5% 用的是 4-shot 思维链，协议不同，不能直接比。

HumanEval 上 0-shot 得了 93.7%，高于原版的 92.0% 与 GPT-4o 的 90.2%。新加入的 AIME 2024 上 0-shot 思维链得了 16.0%，64 次采样多数投票得了 27.6%，原版分别是 9.6% 与 16.7%。IFEval 上得了 90.2%，高于原版的 87.8%。

视觉上，MMMU 验证集得了 70.4%，高于原版的 68.3% 与 GPT-4o 的 69.1%。MathVista 得了 70.7%，高于原版的 67.7%。AI2D 得了 95.3%，高于原版的 94.7%。但有两处例外：ChartQA 得了 90.8%，与原版持平；DocVQA 得了 94.2%，低于原版的 95.2%。

### 拒绝行为：混合结果，有倒退

拒绝行为的表呈现了一幅混合画面。升级版 Sonnet 在 Wildchat 有毒提示上的正确拒绝率是 89.2%，低于原版的 96.4%。在无毒提示上的错误拒绝率是 5.3%，好于原版的 11.0%。在 XSTest 上的错误拒绝率是 4.3%，差于原版的 1.7%。

Haiku 的模式类似：有毒提示正确拒绝率 88.0%，低于 Claude 3 Haiku 的 90.0%；无毒提示错误拒绝率 4.8%，好于前代的 6.6%；XSTest 错误拒绝率 2.0%，大幅好于前代的 33.1%。

### 人类偏好：小幅领先

人类偏好评估里，升级版 Sonnet 对原版 Sonnet 的胜率是：文档分析 61%，视觉理解 57%，创意写作 58%，编码 52%，遵循精确指令 51%。基线模型对自身的胜率按构造是 50%。附录说，Haiku 在多数任务上大幅改进了前代 Haiku，在编码与文档分析上以显著优势击败了 Opus，但没有在正文里给出对应的数字。

### 客户反馈与可用性

公告引用了三家客户的反馈。GitLab 在 DevSecOps 任务上测试后说，新版 Sonnet 的推理更强（各用例最多提高 10%），且没有增加延迟。Cognition 说，在自主 AI 评估里，编码、规划与问题解决都有实质改进。The Browser Company 说，在自动化网页工作流上，新版 Sonnet 超过了他们之前测试过的所有模型。这三句都没有附带可核查的条件或数字。

可用性方面，升级版 Sonnet 从发布日起向所有用户开放，computer use 测试版可在 API、Bedrock 与 Vertex AI 上使用。公告说，新版 Sonnet 以与前代相同的价格与速度提供这些改进，但两份文件都没有给出价格或速度数字。

## 四、作者的结论与局限

### 作者自己得出的结论

公告的结论是三句宣称。第一，升级版 Sonnet 在编码与智能体任务上有全面改进，SWE-bench Verified 从 33.4% 提高到 49.0%，高于所有公开模型。第二，Haiku 在与前代相近的速度下，在许多评估上追平甚至超过 Opus。第三，computer use 是第一个以前沿模型公开测试版形式提供的通用电脑操作能力，OSWorld 上 14.9% 的成绩明显领先次优系统。

附录的结论与公告一致，但措辞更克制。它说，升级版 Sonnet 在智能体编码、智能体任务完成与截图 computer use 上树立了新的 state-of-the-art 标准；Haiku 在同级别模型中表现强劲，在许多情况下与原版 Sonnet 和 Opus 相当，尤其是在推理与指令遵循任务上。

安全方面，两份文件的结论是：升级版 Sonnet 的灾难性风险评估仍然适用 ASL-2 标准，不需要 ASL-3 级别的保障与安全措施。附录说，针对 computer use 的初步分析认为，在当前能力水平上，现有的威胁模型与评估足以覆盖其风险。

### 作者承认的局限

公告对 computer use 的局限说得很直接：它仍然是实验性的，有时笨拙、容易出错。有些人类毫不费力就能完成的动作——滚动、拖拽、缩放——目前对 Claude 来说仍是挑战。公告鼓励开发者从低风险任务开始探索。

附录承认，OSWorld 上的成绩虽然领先，但远低于人类 72.36% 的成功率，说明这个领域仍有大幅改进空间。附录还说，computer use 仍处于开发早期阶段。

安全方面，附录列出了 computer use 红队测试发现的潜在滥用向量：规模化创建账号、规模化分发内容、绕过年龄验证、滥用性填表。附录说，这些风险没有一项被认为迫在眉睫，但已经建立了监测协议与缓解措施，包括能识别 computer use 是否被使用、是否发生危害的新分类器，以及针对提示注入的额外预防建议：使用专用虚拟机、限制敏感数据访问、把互联网访问限制在必需的域名、敏感任务保留人工参与。

信任与安全红队测试还发现，两个模型在处理微妙请求、或以虚构、角色扮演、艺术内容为包装的请求时仍有困难。这是附录里明确写出的弱点。

附录还承认，完整的 RSP 评估协议没有为这两个模型运行，原因是没有触发完整协议的条件。英国 AI 安全研究所测试的是一个接近最终的模型，METR 的独立评估结果也没有发表在这些资料里。

对于表格本身显示的倒退——Wildchat 有毒正确拒绝率下降、XSTest 错误拒绝率上升、DocVQA 低于原版——两份文件都没有给出任何回应，也没有承认其中任何一项。

## 五、精读点评

以下这一节是分析者的判断，与上面按公告与附录原意呈现的内容分开。上面的部分讲的是这两份文件做了什么、发现了什么、自己怎么说；这一节讲的是分析者认为它在科学上到底回答了什么问题，价值在哪里，最弱的地方在哪里。

这份文件要回答的科学问题，可以用五个问题讲清楚。反常是没有的：没有任何观察、失败或出乎意料的现象逼出它，触发它的就是产品发布。它重要，不是因为认知，而是因为实践：用户要决定用新版 Sonnet 还是旧版、Opus 还是 Haiku，要不要开始尝试 computer use；如果数字不可信，用户会为错误的模型选择付出真金白银。之前没做，不是因为有什么障碍卡住了，而是因为模型刚刚发布。附录的办法是跑一组公开基准、做成对照表，再加一次内部评估与一次人类偏好研究。这个办法回答的其实是一个更容易的问题：在我们选的基准、我们选的协议下，我们的模型得分更高吗？它绕过的不是技术障碍，而是独立性：没有独立重测，没有统一评估框架，大多数数字没有不确定性。答案在认知上什么都没改变，在实践上改变了部署选择与行业叙事——“中端即前沿”与“模型可以直接操作电脑”从此成为各家发布会的模板，但这两个改变都建立在未经独立验证的数字上。

这份东西的价值可以分四句话说。认知上，它只确认了一个可部署的事实：升级版中端模型在已报告基准上可以击败前代旗舰，以及一个存在性事实：前沿模型第一次以公开测试版提供了截图驱动的电脑操作能力，OSWorld 上 14.9% 对人类 72.36%。它没有推翻或确认任何关于智能、训练或评估的科学信念。方法上，价值很低：它没有留下任何别人能直接拿走复用的东西，没有新工具、新范式、新度量、新实验设计、新数据集；唯一接近方法的内部智能体编码评估只以散文描述，没有发布任务集、脚手架或问题数量。边界上，它明确不证明的东西比它证明的东西更多：不证明行业领先，不证明一般智能，不证明真实世界软件工程能力，不证明 computer use 在真实部署里可靠，也不证明安全性——读者最容易误读的推论是“基准领先就等于模型全面更强，computer use 已经能替人操作电脑”。启示上，它指向了一个最便宜的决定性实验：在单一评估框架下，用相同提示词、相同样本数、相同解码，重跑 SWE-bench Verified 与 OSWorld，对比升级版 Sonnet 与 GPT-4o，并报告样本量、种子与 95% 置信区间；如果 OSWorld 上的领先在统一框架下消失，computer use 的领先宣称就要重写。

最弱的地方是跨厂商表格的可比性。标题宣称建立在它上面，但它的支撑最弱。竞品数字是厂商出版物的二手引用，不是重新测量。附录的脚注说评估表排除了 OpenAI 的 o1 模型家族，可公告却说新版 Sonnet 的 SWE-bench 分数高于所有公开模型、包括 o1-preview 这样的推理模型——这个对照在附录的表里根本不存在。协议也不对称：MATH 一行里 Gemini 用的是 4-shot 思维链，其他模型是 0-shot。没有任何数字（除 OSWorld 外）带有误差棒，MMLU 5-shot 思维链上 0.1 个百分点的领先根本无法判断是不是噪声。

第二弱的地方是内部智能体编码评估。78% 对 64% 对 38% 的差距是家族内最大的，却来自文件里最不透明的测量：问题数量、问题选择、脚手架、提示词与预算都没有报告，而且没有外部模型跑过它。

第三弱的地方，是文件对自己表格里倒退的沉默。Wildchat 有毒正确拒绝率从 96.4% 跌到 89.2%，XSTest 错误拒绝率从 1.7% 升到 4.3%，DocVQA 从 95.2% 跌到 94.2%——三处倒退在正文里一个字都没有提。读者如果只读公告，会以为改进是全面的。

如果用效度来打分，内部效度 2 分，外部效度 2 分，构念效度 2 分，统计结论效度 1 分，可复现性 1 分。被判断的对象是公告加附录作为证据，而不是模型本身。模型可能比文件显示的更好或更差，文件不让读者判断这一点。

什么能推翻它，什么能加强它，答案是同一个实验：一次独立的单框架重跑。锁定模型版本，用相同提示词、相同样本数、相同解码，重跑 SWE-bench Verified、TAU-bench 与 OSWorld，对比升级版 Sonnet、GPT-4o 与次优的 computer use 系统，并报告样本量、种子与置信区间。如果 OSWorld 上的领先在统一框架下还在，computer use 的领先就得到加强；如果差距落入置信区间之内，领先宣称就被削弱。

还有两个更便宜的替代解释值得记下来。第一，SWE-bench 与 TAU-bench 上的大幅领先，可能来自脚手架与提示词的优化，而不是模型本身的变强——附录自己也说，OSWorld 的 22.0% 就是靠优化提示词与增加步数得到的，而 SWE-bench 的脚手架没有描述，所以这个解释与“模型变强了”预测的数字是一样的，现有数据区分不了。第二，Haiku 在 SWE-bench 上超过原版 Sonnet，可能反映的是评估时用的智能体脚手架对小模型更友好，而不是 Haiku 的推理能力真的追平了中端模型——同样，现有数据区分不了。

接下来最值得看的，是 computer use 的后续评估：OSWorld 上的分数在后续版本里是继续爬升还是停滞，以及 Anthropic 是否发布 computer use 的任务集、脚手架与提示词，让别人能独立重跑 14.9% 这个数字。还有就是 Haiku 的实际发布价格与图像输入的跟进情况，以及英国 AI 安全研究所与 METR 的评估结果是否发表。

## I. 结论、结果与价值总览

**一句话结论：**升级版 Claude 3.5 Sonnet 在 Anthropic 所选基准、所选协议下全面超过前代，SWE-bench Verified 达 49.0%，并以公开测试版首次提供了截图驱动的 computer use，OSWorld 上 14.9% 领先次优系统但远低于人类 72.36%；但这是一次模型发布而非研究发现，跨厂商领先的证据不足，文件还沉默地记录了三处倒退。

**核心结论。**第一，家族内领先是确立的，置信度中。SWE-bench Verified 上新版 Sonnet 49.0% 对原版 33.4%，内部智能体编码评估 78% 对 64%，GPQA 65.0% 对 59.4%，差距大、方向一致。但没有任何数字（除 OSWorld 外）带样本量、种子或误差棒，所以置信度只能给中。

第二，Haiku 追平甚至超过前代大模型，置信度中。SWE-bench Verified 上 Haiku 40.6% 高于原版 Sonnet 的 33.4%，TAU-bench 零售领域 51.0% 高于 Opus 的 45.1%。但同样没有不确定性信息，而且 Haiku 的图像能力在发布时还没有上线。

第三，computer use 的领先是真实的，但绝对能力很低，置信度中。OSWorld 上 14.9% 对次优系统 7.8%，50 步优化后 22.0%，两组都有 95% 置信区间；但人类是 72.36%，而且“次优系统”的身份与条件在两份文件里都没有说明。

第四，拒绝行为与视觉上有倒退，置信度高。这三处倒退直接写在附录的表里：Wildchat 有毒正确拒绝率从 96.4% 跌到 89.2%，XSTest 错误拒绝率从 1.7% 升到 4.3%，DocVQA 从 95.2% 跌到 94.2%。正文对此只字未提。

第五，行业领先没有确立，置信度低。公告说新版 Sonnet 高于所有公开模型、包括 o1-preview，但附录的表排除了 o1 家族，表里根本没有 o1 的数字；MATH 一行里 Gemini 用的是不同协议；MMLU 5-shot 思维链上的领先只有 0.1 个百分点，且无误差棒。

第六，“相同价格与速度”无法核实，置信度低。公告说新版 Sonnet 以与前代相同的价格与速度提供改进，但两份文件都没有给出任何价格或速度数字。

**关键结果。**决定性的数字是这几组：SWE-bench Verified 新版 Sonnet 49.0%、Haiku 40.6%、原版 33.4%；TAU-bench 零售 69.2% 对 62.6%、航空 46.0% 对 36.0%；OSWorld 15 步 14.9%（95% 置信区间 [11.3%, 18.5%]）、50 步 22.0%（[17.8%, 26.2%]）、人类 72.36%；内部智能体编码评估 78% 对 64% 对 38%；GPQA 65.0%、MATH 78.3%、HumanEval 93.7%、MMMU 70.4%；拒绝行为三处倒退；人类偏好胜率文档 61%、视觉 57%、创意写作 58%、编码 52%、指令遵循 51%。全部数字与条件都在上面的数字台账里。

**科学价值总评。**这份文件值得被记住为一句话：“前沿模型第一次以公开测试版让用户指挥它操作电脑，同时中端模型在编码基准上大幅拉开了与前代的差距。”它不值得被记住为“行业领先”的证明，也不值得被记住为任何科学发现。它的持久贡献是产品与演示层面的：computer use 的公开测试版、OSWorld 上第一个带置信区间的厂商分数、以及 Haiku 这个“小模型追平大模型”的定价信号。即使跨厂商比较的证据不足，computer use 的存在性本身是真实的——14.9% 这个数字再低，也是一个以前不存在的能力第一次被公开拿出来让人用。
