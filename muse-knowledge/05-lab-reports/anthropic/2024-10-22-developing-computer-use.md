## 一、背景与问题

### 大量现代工作发生在电脑上

文章开篇点出一个简单的事实：大量现代工作是通过电脑完成的。让 AI 像人一样直接操作电脑软件，就能解锁一大批现在的 AI 助手做不到的应用。

### 下一个前沿：不用专用工具，直接用软件

过去几年，AI 在复杂逻辑推理、看懂图像这些能力上已经有了重要进展。作者认为，下一个前沿是 computer use：模型不再通过为它量身定制的专用工具来交互，而是被授权像人一样使用几乎任何一款软件。

这句话里藏着文章后面要展开的一个对比。此前的思路是“让工具去适应模型”——给 AI 造专门设计的环境和工具。现在的思路反过来了，是“让模型去适应工具”——Claude 直接进入人们每天用的电脑环境。

### 这篇要问什么

这篇札记要回答的问题可以说成一句话：怎么把一个语言模型训练成能看屏幕、动鼠标、敲键盘的 computer use 模型，并且在发布它的同时把安全风险控制住？

它不是一篇要证明某个科学假设的论文。它要讲的是一个工程过程：从已有的工具使用与多模态能力出发，训练出这项技能；然后评估它有多强；再说明为它做了哪些安全措施。

## 二、方法与设计

### 从工具使用与多模态能力出发

作者说，此前的工具使用（tool use）与多模态工作为 computer use 打下了基础。操作电脑需要两项能力：看懂图像——在这里是电脑屏幕的图像；以及根据屏幕上的内容，推理什么时候、怎么执行具体的操作。把这两项能力结合起来，Anthropic 训练 Claude 去解读屏幕上发生了什么，再用手头的软件工具去完成任务。

### 关键技能：数像素

具体的工作方式是这样的：当开发者给 Claude 一个使用某款软件的任务并给它必要的权限后，Claude 先看屏幕截图，然后数出为了点到正确位置，需要在垂直或水平方向上移动光标多少像素。

作者强调，训练 Claude 准确数像素是关键。没有这项技能，模型很难发出鼠标指令。作者打了一个比方：这和模型常常在“banana 这个词里有几个 A”这种看似简单的问题上出错，是同一类困难。

### 训练：只在几款简单软件上训，没有联网

训练用的软件出人意料地少：只有几款简单的软件，比如计算器和文本编辑器。出于安全原因，训练期间不允许模型访问互联网。

作者说，他们对 Claude 泛化得如此之快感到惊讶。只在这么几款简单软件上训练，再结合 Claude 已有的其他技能，模型就能把用户的书面提示变成一串合乎逻辑的步骤，然后在电脑上执行操作。他们还观察到，模型在遇到障碍时甚至会自我纠正、重试任务。

### 试错的过程

作者没有把这个过程写成一帆风顺。他们说，虽然最初的突破之后进展很快，但走到突破之前经历了大量的试错。一些研究人员说，开发 computer use 接近他们刚入行时想象的“理想化”的 AI 研究过程：不断迭代、反复回到绘图板，直到取得进展。

## 三、主要发现

### OSWorld 上 14.9%，是同类最佳，但离人还很远

文章给出的唯一一个基准数字来自 OSWorld——一个用来测试开发者让模型使用电脑的尝试的评估。Claude 目前在 OSWorld 上拿到 14.9%。

作者的说法是，这个数字离人类水平还很远。人类水平一般是 70–75%。但它远高于同一类别里次优 AI 模型的 7.7%。作者据此称 Claude 是目前同类模型中的最先进者，这里的“同类”指的是“像人一样使用电脑的模型，也就是看屏幕、再根据屏幕内容采取行动的模型”。

OSWorld 的具体版本、任务数量、评估日期，原文都没有说明。

### 安全评估：仍在 AI 安全等级 2

安全一节的出发点是作者的一个判断：computer use 主要是降低了 AI 系统应用已有认知技能的门槛，而不是从根本上提升了这些技能。所以他们最关心的是当下的危害，而不是未来的危害。

他们按《负责任扩展政策》（Responsible Scaling Policy）里的前沿威胁评估了 computer use 是否增加了风险。结论是：更新后的 Claude 3.5 Sonnet，包括新的 computer use 技能，仍然处在 AI 安全等级 2（AI Safety Level 2）。也就是说，它不需要比现有措施更高标准的安全与安保措施。

作者还写了对未来的判断：如果未来的模型因为存在灾难性风险而需要 AI 安全等级 3 或 4 的保障，computer use 可能会加剧这些风险。他们认为，现在引入 computer use 更好——趁模型还只需要等级 2 的保障，先开始处理安全问题，而不是等到模型风险大得多的时候才第一次加入 computer use 能力。

### 一个具体风险：提示注入

信任与安全团队对新的 computer use 模型做了广泛分析，找出了潜在的脆弱性。其中一个被点名的是“提示注入”（prompt injection）：一种网络攻击，恶意指令被喂给 AI 模型，导致它推翻此前的指令，或执行偏离用户原意的行动。

由于 Claude 能够解读联网电脑上的截图，它有可能接触到包含提示注入攻击的内容。文章提醒公开测试版的用户采取相关预防措施，并给开发者提供了一份进一步的指南，放在参考实现里。

### 滥用与选举：分类器、监控与引导

除了外部攻击，还有用户故意滥用的可能。作者说，团队已经开发了分类器和其他方法来标记和缓解这类滥用。

因为美国大选临近，他们对可能被视为破坏公众对选举过程信任的滥用尝试保持高度警惕。作者同时说，computer use 目前还不够先进、也没有达到能构成比现有能力更高风险的规模。尽管如此，他们已经采取措施，监控 Claude 被要求从事与选举相关的活动，并建立了系统，把 Claude 从生成和发布社交媒体内容、注册网络域名、与政府网站互动这类活动上引导开。

这些安全措施会在公开测试期间持续评估和迭代，以平衡能力与负责任的使用。

### 仍然慢、经常出错、很多动作做不了

作者对现状的评价很坦率：即使已经是当前最先进的水平，Claude 的 computer use 仍然慢，而且经常出错。

人日常在电脑上做的许多动作，比如拖动、缩放等等，Claude 还不能尝试。还有一个结构性的限制：Claude 看屏幕的方式像“翻页书”（flipbook）——拍一张张截图再拼起来，而不是观察更细粒度的视频流。这意味着它可能错过短暂出现的动作或通知。

作者还举了两个录制发布演示时遇到的“有趣的错误”。一次，Claude 不小心点到了停止按钮，结束了一段长时间的屏幕录制，导致所有素材丢失。另一次，Claude 在代码演示中途突然停下来，开始浏览黄石国家公园的照片。

### 展望：更快、更可靠、更容易实现

作者预计，computer use 会迅速改进，变得更快、更可靠，对用户想完成的任务更有用；对软件开发经验较少的人来说，实现起来也会容易得多。在每一个阶段，研究人员都会与安全团队密切合作，确保新能力配有相应的安全措施。

他们最后邀请公开测试版的开发者通过一份表格反馈，好让研究人员继续改进这项能力的实用性与安全性。

## 四、作者的结论与局限

### 作者自己得出的结论

作者的中心结论有三层。第一，computer use 是一个重要突破：模型不再需要专用工具，可以直接像人一样使用现有的软件。第二，这项能力已经是同类最佳，OSWorld 上 14.9%，远高于次优模型的 7.7%。第三，它是安全的，可以现在就发布：按《负责任扩展政策》评估后仍处在 AI 安全等级 2，引入的时机恰好在风险还可控的时候。

### 作者承认的局限

作者没有单独写一节“局限”，但全文的自我限定非常明确。

首先是能力本身：仍然慢、经常出错；拖动、缩放这类人日常做的动作还不能尝试；“翻页书”式的截图观察方式会错过短暂的动作或通知。

其次是性能差距：14.9% 离人类水平的 70–75% 还很远，作者自己用了“nowhere near”（远不及）这个词。

第三是安全风险没有被消除，只是被管理：提示注入是已识别的脆弱性，用户需要自己采取预防措施；滥用缓解靠的是分类器与监控，作者说这些措施会在测试期间持续评估和迭代——也就是说，它们在发布时还没有定型。

最后是范围：全文没有声称这些结论能推广到其他模型、其他评估或未来的版本。OSWorld 这一个数字是全文唯一的性能证据。

## 五、精读点评

以下这一节是分析者的判断，与上面按原文原意呈现的内容分开。上面的部分讲的是这篇东西做了什么、发现了什么、自己怎么说；这一节讲的是分析者认为它在科学上到底回答了什么问题，价值在哪里，最弱的地方在哪里。

这篇东西要回答的科学问题，可以用五个问题讲清楚。反常是：大模型已经会推理、会看图，但它们只能通过为它们量身定制的专用工具与世界交互——真实世界里的工作却发生在为人类设计的软件界面上。它重要，是因为如果模型能直接操作现有的软件，一大批助手做不到的应用就打开了；不解决它，AI 的能力就始终被困在 API 与专用工具的围墙里。之前做不了，是因为这件事同时要求两项能力——看懂屏幕图像、以及把意图翻译成精确的鼠标键盘动作——而后者里最不起眼的一环（数像素）恰恰是模型最容易失败的地方。这篇札记的办法是把工具使用与多模态能力结合起来，在计算器和文本编辑器这样简单的软件上训练，然后观察它能不能泛化。这个设计能回答问题，是因为它选了一个最小的训练集：如果只在这么简单的软件上训都能泛化，那说明泛化来自模型已有的能力与训练方法的结合，而不是来自大量针对性的训练数据。答案改变的是：computer use 这条路是走得通的，至少在概念验证的层面上——14.9% 对 7.7% 的数字说明它已经超过了此前的尝试，但 14.9% 对 70–75% 的数字也说明它离能用还很远。

这篇东西的价值可以分四句话说。认知上，它确认了一个具体事实：只在几款简单软件上训练的模型，能够把屏幕操作泛化到更广的任务上，并且在 OSWorld 上超过此前最好的同类模型；但这个事实只建立在一个基准、一个数字上。方法上，它留下了一个可以拿走的做法：把“数像素”当作一个显式的、必须训到位的子技能，而不是指望模型自己从通用训练里学会它——这是全文最实在的、可复用的产出。边界上，它明确不证明 computer use 已经可靠可用，作者自己说它慢、经常出错、很多动作做不了；读者最容易误读的推论——“14.9% 意味着电脑操作问题已经解决了”——文章没有证明，恰恰相反，它用 70–75% 的人类水平划清了界线。启示上，它指向了一个最便宜的决定性实验：在 OSWorld 之外再跑一个独立的电脑操作基准（或者同一基准的另一个版本），看 14.9% 对 7.7% 的领先还在不在；如果领先消失，这个“同类最佳”的主张就只是一个基准、一个版本的产物。

最弱的地方是，全文只有一个基准数字，而且连这个数字的条件都没有给全。OSWorld 的版本、任务数、评估日期、次优模型具体是哪个模型，原文一概没有说明。读者无法核实 14.9% 对 7.7% 的差距是不是在误差范围内，也无法知道这个差距在别的基准上还存不存在。更关键的是，训练过程本身几乎没有细节：训练数据长什么样、训了多久、像素计数是怎么训的、自我纠正是怎么观察到的，全都没有报告。没有这些，这篇札记讲的是一个故事，而不是一个可以复现、可以检验的主张。

如果用效度来打分，内部效度在这里几乎无从谈起：没有对照实验、没有消融、没有统计检验，只有一个基准数字与一个定性观察（“泛化得很快”“会自我纠正”），这些观察都没有给出发生率或测量方式。外部效度很低：一个基准、一个模型、训练只用了几款简单软件，作者自己也没有声称能推广到别的软件或任务。

构念效度处在中间：低层面的操作化是清楚的，OSWorld 分数与人类水平 70–75% 的定义都写在正文里；但高层面的“泛化”这个构念没有被独立测量——“从计算器和文本编辑器泛化到更广的任务”是一个定性说法，没有给出在哪些新软件、新任务上测过、成功率是多少。

可复现性很低：方法描述只有几段话，没有训练数据、没有超参、没有代码、没有模型权重。一个能干的读者可以照着这个思路去训一个自己的 computer use 模型，但复现不出 14.9% 这个数字，也验证不了“只在几款简单软件上训就能泛化”这个说法。

什么能加强这篇东西，什么能打破它，答案是同一个实验：换一个基准重跑。在 OSWorld 之外找一个独立的电脑操作评估，用同一版 Claude 3.5 Sonnet 测一次，看领先还在不在；同时把 OSWorld 的版本、任务数与次优模型的名字补出来。如果领先还在，这个主张就大幅加强；如果领先消失、甚至在别的基准上输给别的模型，那就说明这篇的结论只是一个基准、一个版本的产物。另外一个更便宜的中间步骤是：把训练细节补出来——训练软件到底是哪几款、像素计数是怎么训的、自我纠正的观察是在多少次任务里出现的——这些不需要新实验，只需要把已经做过的工作写清楚。

## I. 结论、结果与价值总览

**一句话结论：**Anthropic 用一篇工程札记说明了 computer use 是怎么训出来的——在工具使用与多模态能力的基础上，教会模型看截图、数像素，只在计算器和文本编辑器等几款简单软件上训练，模型就泛化到了更广的电脑操作，并在 OSWorld 上以 14.9% 成为同类最佳，但离人类水平的 70–75% 还很远，且仍在 AI 安全等级 2。

**核心结论。**第一，computer use 的训练路径是可行的，置信度中。证据是作者的叙述：只在几款简单软件上训练，模型就能把书面提示变成一串合乎逻辑的步骤并执行，遇到障碍还会自我纠正。但这些都是定性观察，没有发生率或测量方式，所以置信度只能给中。

第二，Claude 在 OSWorld 上是同类最佳，置信度中。证据是 14.9% 对次优模型 7.7% 这一组数字。但 OSWorld 的版本、任务数、评估日期与次优模型的名字都没有报告，数字无法独立核实，所以置信度只能给中。

第三，computer use 离人类水平还很远，置信度高。证据是 14.9% 对人类水平 70–75% 的对比，作者自己用了“远不及”这个词。

第四，computer use 没有提升安全等级，置信度中。证据是按《负责任扩展政策》评估后仍处在 AI 安全等级 2。但评估细节没有报告，读者只能相信作者的结论。

第五，这项能力目前慢、经常出错、很多动作做不了，置信度高。证据是作者自己的明确陈述，加上演示中录到的两个具体错误（误删录制、浏览黄石照片）。

第六，提示注入与滥用是已识别但未消除的风险，置信度高。证据是作者点名了提示注入这个脆弱性，并说明缓解靠的是分类器、监控与引导系统，且这些措施会在测试期间持续迭代。

**关键结果。**全文唯一一组性能数字是：OSWorld 上，更新后的 Claude 3.5 Sonnet 得 14.9%，同一类别次优 AI 模型得 7.7%，人类水平一般是 70–75%。安全评估结果是 AI 安全等级 2。训练只用了几款简单软件（计算器、文本编辑器），训练期间不允许访问互联网。其余一切——训练数据规模、像素计数准确率、自我纠正的发生率、提示注入的发生率——原文都没有数字。

**科学价值总评。**这篇东西值得被记住为一句话：“computer use 这条路走得通——只在几款简单软件上训就能泛化，而且 OSWorld 上已经是同类最佳；但它离能用还很远，14.9% 对 70–75% 就是差距。”它不值得被记住为“电脑操作问题已经解决”的证明，也不值得被当作一项可复现的研究成果引用。它的持久贡献是工程性的：一个清晰的训练思路（看截图、数像素、在简单软件上训出泛化），以及一个诚实的安全姿态（在风险还可控的等级 2 时就引入能力，先处理安全问题）。即使只有一个基准数字，训练思路与安全判断这两条线在它自己的陈述内是真实的。

**适用边界。**不要引用这篇论证“computer use 已经可靠可用”或“Claude 的电脑操作能力接近人类”。不要把 14.9% 对 7.7% 当作已确立的、可复现的领先幅度——OSWorld 的版本、任务数与次优模型的名字都没有报告。不要把“只在几款简单软件上训就能泛化”当作已测量的泛化结论，原文没有给出在哪些新软件、新任务上测过、成功率是多少。不要把 AI 安全等级 2 的结论当作独立验证过的安全评估，评估细节没有报告。任何部署主张都缺关键一环：全文没有错误率分析、没有真实部署数据上的评估、没有提示注入缓解措施的效果数字。
