## 一、背景与问题

### 推理模型当时是分开的两个物种

公告开篇先定了一个背景：市面上的推理模型（reasoning models）与普通大语言模型是分开的。前者先想后答，后者直接作答。用户要在“快答”和“深想”之间换模型。

Anthropic 的立场是，这应当是一个模型内部的两种模式，而不是两个模型。公告用人脑打比方：人用同一个大脑做快速反应和深度思考，模型也该如此。

### 这篇公告要回答的问题

严格说，这篇公告没有提出一个科学问题。它要做的是发布两件事，并说服读者接受两点：第一，把推理做进同一个模型里、让用户自己控制想多久，是比“另做一个推理模型”更好的做法；第二，Claude 3.7 Sonnet 是当时最强的编程模型，而 Claude Code 能把这种能力变成可以直接在终端里 delegating 工程任务的工具。

这两点都是产品主张，不是研究主张。公告的证据是自报的基准分数、合作伙伴的评价和内部早期测试的说法，没有一项是按研究标准报告的。

### 为什么值得追问

这篇公告值得精读，不是因为它证明了什么，而是因为它标志着一个转向：推理从“一个独立的产品线”变成“所有前沿模型都内置的能力”，而且思考时长第一次变成用户可以直接控制的预算（budget）。这个设计选择——用可控的 token 预算换取回答质量——后来成了各家推理模型的标准做法。

同时也要看清它的另一面：公告里最亮眼的数字（基准对比表）恰恰是读者在页面上最难核对的部分，而最容易被引用的说法（“最智能的模型”“编程最强”）都没有给出可复现的依据。

## 二、方法与设计

### 混合推理：一个模型，两种模式

Claude 3.7 Sonnet 的核心设计是“混合推理”（hybrid reasoning）。标准模式（standard mode）下，它就是一个普通的语言模型，公告说它是 Claude 3.5 Sonnet 的升级版，回答近乎即时。扩展思考模式（extended thinking mode）下，它在回答前先自我反思（self-reflect），思考过程对用户可见。

两种模式的切换由用户决定。公告说，在两种模式下，提示模型的方法大致相同。

### 思考预算：用 token 数控制想多久

通过 API 使用时，用户可以给思考设定预算：告诉模型思考不超过 N 个 token，N 最大可以到输出上限 128K 个 token。这样可以在速度（和成本）与回答质量之间做权衡。

公告没有说明思考预算的具体实现方式：预算是硬截断还是软引导、超出预算时模型如何收尾、思考 token 如何计入上下文，都没有讲。

### 设计重心的转移：少做竞赛题，多做真实任务

公告明确说，在开发推理模型时，Anthropic 有意减少了对数学和计算机科学竞赛题的优化，把重心转向更贴近企业实际使用方式的真实任务（real-world tasks）。

这句话值得注意：它既是对自家评估取向的说明，也是在为基准表上某些竞赛类分数可能不如对手预先做铺垫。但公告没有给出这个取向转变的具体证据，比如训练数据或评估权重的变化。

### Claude Code：终端里的编程协作者

随模型一同发布的 Claude Code 是一个命令行工具，定位是“主动的协作者”（active collaborator）：它可以搜索和阅读代码、编辑文件、编写并运行测试、向 GitHub 提交并推送代码、使用命令行工具，并且在每一步都让用户留在回路里（keeping you in the loop）。

公告没有给出 Claude Code 的技术细节：它用的模型版本、工具调用的实现方式、权限与安全边界、失败时的处理，都没有讲。它只说这是一个早期产品，目前是有限研究预览。

### 评估方法：公告末尾的方法说明

公告末尾有一节评估数据源说明（Eval data sources），是全篇唯一接近方法论的部分，讲了两项基准的脚手架（scaffolding）细节。

TAU-bench 一节说，评估时给航空公司智能体政策（Airline Agent Policy）加了一段提示附录（prompt addendum），指示 Claude 更好地使用一个“规划”（planning）工具，鼓励模型在多轮轨迹中把想法写下来，与平常的思考模式分开。为了容纳规划带来的额外步骤，最大步数（按模型补全次数计）从 30 步提高到 100 步，大多数轨迹在 30 步以内完成，只有一条轨迹超过 50 步。

同一节还说明，Claude 3.5 Sonnet（新版，new）的 TAU-bench 分数与最初发布时报告的不同，原因是数据集做了小幅改进，Anthropic 在更新后的数据集上重新跑了分数，以便与 Claude 3.7 Sonnet 做更准确的比较。

SWE-bench Verified 一节说，解决这类开放式智能体任务有多种做法，有些做法把“查哪些文件、改哪些地方、跑哪些测试”的决策大量交给传统软件，只让语言模型在预定位置生成代码或从有限动作里选择。Agentless 等框架会给智能体加上基于提示和嵌入的文件检索、补丁定位，以及对回归测试做 best-of-40 的拒绝采样（rejection sampling）。其他脚手架还会用重试、best-of-N 或蒙特卡洛树搜索（MCTS）等形式补充测试时算力。

Anthropic 自己的做法要简单得多：只用最小脚手架，让模型在一次会话里自己决定运行哪些命令、编辑哪些文件。主要的“无扩展思考”pass@1 结果只给模型两个工具——一个 bash 工具和一个通过字符串替换编辑文件的工具——再加上 TAU-bench 一节提到的规划工具。

同一节还交代了一个重要的基础设施限制：由于内部基础设施的限制，500 道题里只有 489 道在 Anthropic 的内部环境中是可解的（即黄金补丁能通过测试）。为了与官方排行榜保持一致，Anthropic 在计算 pass@1 分数时把 11 道不可解的题也算作失败，并单独列出了这 11 道题的编号（见数字台账）。“高算力”（high compute）分数则采用了额外的复杂度和并行测试时算力：对同一脚手架做多次并行采样，丢弃那些破坏仓库可见回归测试的补丁（类似 Agentless 的拒绝采样做法，但不使用隐藏测试信息），再用一个打分模型（scoring model）对剩下的尝试排序，选出最优者提交。

### 假设与未验证的前提

这篇公告建立在几个没有论证的前提上。第一，基准分数高就等于编程与推理能力强——公告没有讨论基准分数与真实任务表现之间的关系。第二，合作伙伴的评价可以当作能力的证据——Cursor、Cognition、Vercel、Replit、Canva 的评价都是引述，没有给出它们的评估方法。第三，思考预算的 token 数与回答质量之间存在可预期的权衡关系——公告没有给出任何一条预算与质量的曲线。第四，Claude Code 在内部早期测试中的表现可以推广到外部开发者的真实工作——公告没有给出测试的任务样本、人数或成功标准。

这些前提里最承重的是第一条：整篇公告的“最强”宣称都建立在自报的基准分数上，而这些分数的复现细节恰恰没有完整给出。

## 三、主要发现

### 模型发布与可用性

Claude 3.7 Sonnet 于发布当日上线全部 Claude 套餐（Free、Pro、Team、Enterprise），以及 Claude 开发者平台（Claude Developer Platform）、Amazon Bedrock 和 Google Cloud 的 Vertex AI。扩展思考模式在除免费套餐外的所有渠道可用。

### 定价：与前代相同，思考 token 也计费

标准模式与扩展思考模式的定价相同，都是每百万输入 token 3 美元、每百万输出 token 15 美元，与前代模型一致。思考 token 也按输出 token 计费。

### 编程能力：合作伙伴的评价

公告引用了五家合作伙伴的早期测试评价。Cursor 说 Claude 在真实世界的编程任务上再次成为同类最佳（best-in-class），在处理复杂代码库到高级工具使用等多个方面都有显著改进。Cognition 说它在规划代码变更和处理全栈更新方面远胜其他任何模型。Vercel 强调它在复杂智能体工作流上的精确度。Replit 说已成功用它从零构建复杂的网页应用和仪表盘，而其他模型在这些任务上会停滞。Canva 的评估说它持续产出可直接用于生产的代码，设计品味更好，错误大幅减少。

这些都是引述的定性评价，没有数字、没有评估方法、没有样本量，不能当作可核查的证据。

### Claude Code 的早期测试说法

公告说，Claude Code 在早期测试中一次通过就完成了那些通常需要 45 分钟以上人工时间的任务，减少了开发时间和开销。

这个说法没有给出任务数量、任务类型、对照条件或成功率，只有一个“45 分钟以上”的时间锚点。它是一个产品宣传口径，不是测量结果。

### 安全：不必要的拒绝减少 45%

公告的安全一节说，Anthropic 对 Claude 3.7 Sonnet 做了广泛的测试与评估，并与外部专家合作，以确保它符合安全、安保与可靠性的标准。模型在区分有害请求与无害请求上更加细致，与前代相比，不必要的拒绝（unnecessary refusals）减少了 45%。

这个 45% 没有给出分母、评估集、评估方法或对照模型的具体版本，只说了“与前代相比”。它是一个自报的相对改进数字，条件不明。

### 系统卡：另有文件，不属于本篇

公告说，本次发布的系统卡（system card）涵盖了多个类别的新安全结果，包括 Responsible Scaling Policy（负责任扩展政策）评估的详细分解，以及与计算机使用（computer use）相关的新兴风险，特别是提示注入（prompt injection）攻击，系统卡还讨论了推理模型带来的潜在安全收益——比如理解模型如何做决策，以及模型的推理是否真正可信可靠。

系统卡是独立文件。本精读只按公告本身写，不把系统卡的内容当成本文的发现。

## 四、作者的结论与局限

### 作者的结论

公告的结论是展望式的，不是论证式的。它说，Claude 3.7 Sonnet 与 Claude Code 是朝着“真正增强人类能力的人工智能系统”迈出的重要一步。凭借深度推理、自主工作与有效协作的能力，它们让人类更接近一个人工智能丰富并扩展人类成就的未来。

除此之外，公告没有给出任何研究结论。它没有声称发现了什么新机制，也没有声称证明了什么科学主张。

### 作者自述的局限

公告几乎没有自述局限。最接近局限陈述的有三处：第一，Claude Code 被明确说成是一个早期产品，目前只是有限研究预览；第二，SWE-bench Verified 的 11 道题因基础设施原因不可解，公告主动说明了这一点并把它们算作失败；第三，Claude 3.5 Sonnet（新版）的 TAU-bench 分数与最初发布时不同，公告说明了这是因为数据集做了小幅改进并重新跑了分数。

除此之外，公告没有提及任何评估局限、样本局限或推广边界。

### 分析者发现的局限（作者没说的）

第一，基准对比表的全部数值只以图呈现，正文与图注都没有给出数字，读者无法从页面文本中核对任何一个分数。第二，所有分数都是 Anthropic 自报的，没有第三方复现、没有误差棒、没有运行次数，连评估时用的模型版本与提示细节都只在 SWE-bench Verified 和 TAU-bench 两节做了部分说明。第三，合作伙伴的评价全部是引述的定性说法，没有评估方法。第四，Claude Code 的“45 分钟以上”说法没有任何测量细节。第五，“不必要的拒绝减少 45%”没有分母和评估集。第六，页面最后更新于 2026-10-15，首发版与当前版之间的改动无从得知，读者读到的未必是 2025-02-24 当天发布的内容。

## 五、精读点评

### 这篇公告的分量

这是一篇产品发布公告，按研究标准衡量，它几乎没有可评估的方法论内容。它真正有信息量的部分只有两处：一是“混合推理 + 思考预算”这个产品设计选择，二是评估方法说明一节里关于 SWE-bench Verified 和 TAU-bench 脚手架的坦白——特别是 11 道题不可解、以及高算力分数与无脚手架分数之间 6.6 个百分点的差距。前者说明了产品方向，后者说明了分数对脚手架有多敏感。

其余部分——“最智能的模型”“编程最强”“一次通过完成 45 分钟以上的任务”——都是没有可核查依据的宣传口径。读者应当把它们当作 Anthropic 的自我定位，而不是测量结果。

### 效度判断

内部效度：低。公告没有报告任何对照实验，基准分数的评估条件只在两节做了部分说明，无法判断分数差异来自模型本身还是脚手架。

外部效度：低。合作伙伴评价与内部早期测试都没有给出任务样本，无法判断结论能推广到哪些真实开发场景。

构念效度：低。基准分数被当作“编程能力”“推理能力”的度量，但公告没有讨论这些分数到底量的是什么，也没有讨论脚手架在分数里的贡献。

统计结论效度：低。没有任何误差棒、运行次数或显著性信息，分数之间的差距无法判断是否超出噪声。

可复现性：低。基准对比图的数字无法从页面文本核对，SWE-bench Verified 的脚手架细节只讲了一部分，TAU-bench 的提示附录没有公开，一个能干的读者无法按公告重跑标题结果。

### 科学价值

认知价值：这篇公告没有推翻或确认任何科学信念。它确立的是一个产品事实——Anthropic 把推理做进了同一个模型，并让用户用 token 预算控制思考时长。如果这篇公告不存在，关于“混合推理”的产品方向仍可从后续产品中看出，但“第一个这么做的厂商”这个时间点会丢失。

方法价值：很低。公告没有留下可复用的方法、工具或度量。唯一可复用的东西是评估方法说明里关于脚手架敏感性的提醒：同一模型、同一基准，换一套脚手架就能差出 6.6 个百分点。

边界价值：公告没有明确划出边界。它没有说基准分数在什么条件下不成立，也没有说 Claude Code 在哪些任务上会失败。读者最容易误读的推论是把“基准分数领先”等同于“真实编程任务上领先”——公告的证据撑不起这个推论。

启示价值：最值得跟进的不是公告里的分数，而是它留下的一个可检验的问题：思考预算的 token 数与回答质量之间到底是什么关系？最便宜的决定性检验是公开一条预算–质量曲线：在同一基准上，把思考预算从小到大扫一遍，看分数如何变化、拐点在哪里。如果分数随预算单调上升且很快饱和，那么“用预算换质量”就是一个可控的工程旋钮；如果分数在某个预算后不再上升甚至下降，那就要重新理解“想得更久”的价值。

### 最弱的一环

最弱的一环是整篇公告的证据基础：所有关于“最强”的宣称都建立在自报的基准分数上，而这些分数既没有误差棒，也没有完整的复现细节，基准对比表甚至只以图呈现、无法从文本核对。分数本身可能没错，但读者没有办法独立验证。

### 证伪器与替代解释

针对“Claude 3.7 Sonnet 是当时最强的编程模型”这一主张，一个直接的证伪器是：在同一脚手架、同一提示、同一解码设置下，让 Claude 3.7 Sonnet 与同期竞品在 SWE-bench Verified 的完整 500 题上各跑一次，如果 Claude 3.7 Sonnet 的分数低于竞品，主张即被反驳。

替代解释至少有两个。第一，分数差距来自脚手架而非模型：Anthropic 自己的数字已经显示，同一模型换一套脚手架就能差出 6.6 个百分点，因此基准表上的领先可能主要是脚手架的领先。区分的办法是固定脚手架、只换模型，看差距是否还在。第二，分数差距来自评估提示的定制：TAU-bench 的分数用了专门为 Claude 写的提示附录与规划工具，如果竞品没有得到同等的提示优化，比较就不公平。区分的办法是给所有模型用同一套提示与工具重新评估。

### 接下来看什么

最值得先看的是两件事。第一，系统卡里关于安全评估的详细结果——公告本身只给了“不必要的拒绝减少 45%”这一个数字，系统卡才是评估细节所在。第二，第三方在同一脚手架下的独立复现分数，特别是 SWE-bench Verified 官方排行榜上其他提交的分数，以及 Claude Code 在真实开发者任务上的独立评测。

## §I 收尾综合

**一句话结论：**这是一篇产品发布公告，不是研究论文——它发布了混合推理模型 Claude 3.7 Sonnet 与命令行编程助手 Claude Code，但关于“最强”的宣称建立在自报且无法从文本核对的基准分数上。

**核心结论：**

1. Claude 3.7 Sonnet 是 Anthropic 宣称的“市场上第一个混合推理模型”，标准模式与扩展思考模式合一，用户可通过 API 用 token 预算（上限 128K）控制思考时长。置信度：高——这是公告明确陈述的产品事实。
2. 定价与前代相同，每百万输入 token 3 美元、每百万输出 token 15 美元，思考 token 按输出计费。置信度：高——正文明确给出。
3. SWE-bench Verified 高算力分数 70.3%、无脚手架分数 63.7%（均为 n=489 子集），两者相差 6.6 个百分点，说明分数对脚手架高度敏感。置信度：中——数字来自评估方法说明一节的正文，但评估细节仍不完整。
4. 公告中关于编程能力领先、Claude Code 节省时间、安全改进的说法均无可核查的测量细节。置信度：高——正文确实没有给出这些细节。
5. 基准对比图的全部数值无法从页面文本中核对，列为未核实。置信度：高——本次通读的文本抓取中确实没有这些数字。

**关键结果表：**

**科学价值总评：**认知价值低——没有新的科学主张；方法价值低——没有留下可复用的方法，只留下一个关于脚手架敏感性的提醒；边界价值低——公告没有划出任何边界；启示价值中等——它提出了一个值得检验的产品方向（用 token 预算控制思考时长），以及一个最便宜的决定性检验（公开预算–质量曲线）。总体而言，这篇公告值得被记住的不是它的分数，而是它标志着推理从独立产品线变成所有前沿模型内置能力的转向。

**适用边界：**这篇公告不证明 Claude 3.7 Sonnet 在真实编程任务上领先于竞品，不证明 Claude Code 能可靠地完成 45 分钟以上的工程任务，也不证明思考时间越长回答就越好。任何人都不该拿公告里的基准分数或合作伙伴引述为这些主张背书。能从中引用的只有产品事实（发布了什么、定价多少、思考预算如何工作）和评估方法说明里明确写出的脚手架细节。
