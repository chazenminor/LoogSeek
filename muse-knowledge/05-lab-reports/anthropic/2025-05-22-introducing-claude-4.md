## 一、背景与问题

### 这次发布了什么

博客宣布推出下一代 Claude 模型：Claude Opus 4 与 Claude Sonnet 4，定位是编码、高级推理与 AI agent 的新标准。

Opus 4 被称为“世界上最好的编码模型”，能在复杂、长时运行的任务与 agent 工作流上保持性能。Sonnet 4 是对 Sonnet 3.7 的大幅升级，编码与推理更强，同时对指令的响应更精确。

两个模型都是混合模型（hybrid models），有两种模式：近即时响应，以及用扩展思考（extended thinking）做更深的推理。

### 随模型一起宣布的东西

除了模型本身，博客还宣布了四件事。

第一，带工具使用的扩展思考（extended thinking with tool use，beta）：两个模型都可以在扩展思考期间使用工具（例如网络搜索），在推理与工具使用之间交替，以改进回答。

第二，新的模型能力：两个模型都可以并行使用工具、更精确地遵循指令；当开发者给模型提供本地文件访问权限时，模型的记忆能力明显改进——能提取并保存关键事实，以保持连续性并积累隐性知识。

第三，Claude Code 正式发布（generally available）：研究预览期收到大量积极反馈后扩展。Claude Code 现在支持通过 GitHub Actions 跑后台任务，以及 VS Code 与 JetBrains 的原生集成，编辑直接显示在文件里。还发布了可扩展的 Claude Code SDK，以及基于 SDK 的示例 Claude Code on GitHub（beta）：在 PR 里 @ Claude Code 可以回应评审反馈、修复 CI 错误或改代码。

第四，API 上的四项新能力：代码执行工具（code execution tool）、MCP 连接器（MCP connector）、Files API，以及提示缓存最长一小时。

### 怎么卖、多少钱

Pro、Max、Team 与 Enterprise 套餐包含两个模型与扩展思考，Sonnet 4 也提供给免费用户。两个模型都上 API、Amazon Bedrock 与 Google Cloud 的 Vertex AI。定价与此前的 Opus 与 Sonnet 保持一致：Opus 4 是每百万 token 输入 15 美元、输出 75 美元；Sonnet 4 是输入 3 美元、输出 15 美元。

## 二、方法与设计

### 博客怎么证明“最好”

博客的证明方式是基准分数加客户评价，没有对照实验的设计可言。

基准方面，博客在正文里给出了不带扩展思考的几项分数（SWE-bench Verified、Terminal-bench，以及 GPQA Diamond、MMMLU、MMMU、AIME 的不带思考分数），见 §五。带扩展思考的分数与 TAU-bench 的分数只在图里，正文没有列出，本次未从图中抄录。

博客在文末附了基准报告方法，值得原样记下来。

SWE-bench 的方法：Claude 4 系列继续使用此前发布过的简单脚手架（scaffold），只配两个工具——一个 bash 工具和一个通过字符串替换做文件编辑的工具。不再包含 Claude 3.7 Sonnet 时用的第三个“规划工具”。所有 Claude 4 模型的分数都按完整的 500 道题计算；OpenAI 模型的分数按 477 道题的子集计算。

“高算力”（high compute）分数的方法是：并行采样多个尝试；丢弃那些破坏仓库可见回归测试的补丁（类似 Agentless 的拒绝采样做法，不使用隐藏测试信息）；再用一个内部评分模型从剩下的候选里挑最好的。按这个做法，Opus 4 得 79.4%，Sonnet 4 得 80.2%。

TAU-bench 的方法：两个模型都在 Airline 与 Retail 的 agent 策略提示里加了一段附录， instruct Claude 在使用带工具的扩展思考时更好地利用推理能力；模型被鼓励在多轮轨迹里把思考写下来。把最大步数（按模型补全计数）从 30 步提高到 100 步（多数轨迹在 30 步以内完成，只有一条轨迹超过 50 步）。

### 另外两项模型改进

博客说，除了带工具的扩展思考、并行工具使用与记忆改进，两个模型使用捷径或漏洞完成任务的行为明显减少：在特别容易走捷径的 agent 任务上，两个模型比 Sonnet 3.7 少 65% 出现这种行为。

Opus 4 的记忆能力也被单独强调：当开发者给它本地文件访问权限时，Opus 4 擅长创建与维护“记忆文件”来存储关键信息，从而在 agent 任务上有更好的长期任务感知、连贯性与表现。博客举的例子是 Opus 4 在玩宝可梦时创建了一份“导航指南”。

博客还引入了思考摘要（thinking summaries）：用一个更小的模型把冗长的思考过程压缩。只有大约 5% 的时候才需要摘要——多数思考过程短到可以直接完整显示。需要原始思维链做高级提示工程的用户，可以联系销售开通新的开发者模式（Developer Mode）来保留完整访问。

## 三、主要发现

博客没有“发现”，它是一次产品发布。按公告自己的说法，关键点是以下几条。

Opus 4 在 SWE-bench 上得 72.5%，在 Terminal-bench 上得 43.2%，博客称之为领先。Sonnet 4 在 SWE-bench 上得 72.7%，博客称之为同类最佳（state-of-the-art）。

客户评价方面，博客引用了一批合作方的话：Cursor 称 Opus 4 是编码的 state-of-the-art，在复杂代码库理解上有飞跃；Replit 说它在多文件复杂改动上精度提高、进步显著；Block 说它是第一个在其 agent（代号 goose）里编辑与调试时提升代码质量、同时保持完整性能与可靠性的模型；Rakuten 用一个要求很高的开源重构做了验证，模型独立运行 7 小时、性能持续；Cognition 说 Opus 4 能解决其他模型解决不了的复杂挑战。GitHub 说 Sonnet 4 在 agent 场景里表现出色，将成为 GitHub Copilot 新编码 agent 的动力模型；Manus 强调它在遵循复杂指令、清晰推理与美观输出上的改进；iGent 说 Sonnet 4 在自主多功能应用开发上出色，代码库导航错误从 20% 降到接近零；Sourcegraph 说它在软件开发上有实质飞跃；Augment Code 说它的成功率更高、编辑更精准。

博客最后说，这些模型是通向虚拟协作者的一大步：保持完整上下文、在更长的项目上保持专注、带来变革性影响。它们经过了广泛的测试与评估以最小化风险、最大化安全，包括为更高的 AI 安全等级（如 ASL-3）实施措施——ASL-3 的具体内容是同一天发布的另一篇公告（LR-052 已精读）。

## 六、精读点评

### 这篇东西是什么，不是什么

这是一篇模型发布公告，不是研究、不是评估报告。它宣布了两个模型与一批能力，给出了几项可在正文核对的基准数字，并引用了一批客户评价。按精读模板来套，大部分格子是空的——没有研究问题、没有实验设计、没有误差分析。

### 最值得注意的一点：数字的口径是不对称的

博客的数字呈现有一个明显的不对称：不带扩展思考的分数写在正文里，带扩展思考的分数只放在图里；SWE-bench 与 Terminal-bench 的分数给了 Opus 4，Sonnet 4 只给了 SWE-bench；TAU-bench 的分数完全没有正文数字，只有方法说明。读者如果只读正文，能核对的数字就是台账里的 E1–E13，而博客最想让人记住的“带思考更强”恰恰没有正文数字支撑。

更值得注意的是高算力分数（E4）：Opus 4 与 Sonnet 4 的“高算力”分数分别是 79.4% 与 80.2%——Sonnet 4 反而高于 Opus 4。这说明在并行采样加内部评分模型选最优的流程下，两个模型的差距被抹平甚至反转。博客没有讨论这一点，也没有说明常规分数与高算力分数哪个更能代表实际使用中的表现。

### “世界最佳编码模型”是一家之言

博客称 Opus 4 是“世界上最好的编码模型”，依据是 SWE-bench 72.5% 与 Terminal-bench 43.2% 两个数字。但博客没有给出其他模型在同一条件下的分数（例如 OpenAI 模型的分数按 477 道题的子集计算，口径并不相同），也没有给出误差棒或运行次数。客户评价都是挑选过的正面证言，没有负面或中性的评价，也没有说明评价是怎么收集的。这些话作为产品宣传是正常的，作为证据就很薄。

### 与 ASL-3 公告的关系

博客在结尾提到，这些模型经过了广泛测试，包括为更高的 AI 安全等级（如 ASL-3）实施措施。ASL-3 的具体内容是同一天发布的另一篇公告（LR-052），那篇公告说 Opus 4 是第一个在 ASL-3 标准下部署的模型，而且 Anthropic 尚未确定 Opus 4 是否真的需要 ASL-3 保护。两篇公告合起来读，意思才完整：模型发布的同时，安全标准也被动升级了。

### 科学价值

认知价值：低。它没有提出或检验任何关于模型能力的主张，只宣布了产品与分数。方法价值：低到中等。SWE-bench 的脚手架与高算力流程写得比较具体，别人可以照着复现分数；但没有误差棒、没有运行次数、没有完整的对照表。边界价值：低。它没有讨论分数的局限（例如 SWE-bench 的 500 道题在多大程度上代表真实编码工作），也没有讨论客户评价的挑选问题。启示价值：低。它指向的下一步是产品使用，不是研究。

### 总体判断

作为一篇模型发布公告，它是称职的：模型定位清晰、能力列表具体、价格与可用性明确、基准方法写得比多数发布公告更透明。作为精读对象，它的分量中等偏轻——有几项可在正文核对的数字，但最关键的“带思考更强”没有正文数字，核心宣称（世界最佳）没有可核对的对照。置信度：高，针对“博客写了什么”；中，针对“Opus 4 是否真是世界最佳编码模型”——博客提供的证据不足以支撑这个判断。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

这篇博客没有可证伪的科学主张。如果把它的核心宣称（“Opus 4 是世界上最好的编码模型”）当作主张来检验，检验方式是：用同一脚手架、同一题集、同一解码条件，跑其他前沿模型（例如 GPT、Gemini、DeepSeek 的同期模型）的 SWE-bench 与 Terminal-bench 分数，看 Opus 4 是否仍然领先。但博客没有提供这种对照，检验无从做起。

### 替代解释

- 替代解释一：SWE-bench 分数上的领先主要来自脚手架与高算力流程，而不是模型本身。博客说 Claude 4 用的是此前发布过的简单脚手架，但没有说明其他模型在同一脚手架下的分数；如果换一个脚手架，排名可能改变。区分办法是固定脚手架跑多个模型。
- 替代解释二：客户评价反映的是挑选过的早期合作伙伴体验，而不是典型用户体验。博客引用的全是正面评价，没有说明合作伙伴是怎么选的、有没有付费或合作关系。区分办法是看独立评测与更大范围的用户反馈。

### 作者自述的局限与分析者发现的局限

作者自述的局限：博客没有单独的局限一节。

分析者发现的局限：带扩展思考的基准分数只在图里，正文没有数字；TAU-bench 没有正文数字；没有误差棒、运行次数或统计显著性；OpenAI 模型的 SWE-bench 分数按 477 道题的子集计算，与 Claude 4 的 500 道题口径不同；客户评价是挑选过的证言，没有收集方法；“少 65% 走捷径”没有绝对发生率；Sonnet 4 的 SWE-bench 分数高于 Opus 4，博客未解释；没有作者署名行；没有 arXiv 版本；博客页面显示更新于 2026-11-12，本次读到的博客文本可能已不是 2025-05-22 的原始版本。

### 接下来看什么

最便宜的决定性下一步，是独立的第三方复现：用博客写明的脚手架（bash + 文件编辑工具，500 道题）跑 Opus 4 与 Sonnet 4 的 SWE-bench 分数，再用同一脚手架跑同期其他前沿模型。判据是一句话：如果 Opus 4 在同一条件下仍然领先，“世界最佳编码模型”的说法就有了第一个独立证据；如果排名改变，那博客的宣称就是脚手架或挑选的结果。

其次值得看的是 Claude Opus 4 与 Sonnet 4 的系统卡（总索引 #69，本批跳过，留待以后以短注处理）：系统卡里有安全评估的细节，包括后来引起广泛关注的模拟环境勒索行为（LR-054 已精读）。

## §I 收尾综合

**一句话结论：** 这是一篇模型发布公告——它宣布了 Claude Opus 4 与 Sonnet 4，核心卖点是长时 agent 任务上的持续表现，正文可核对的数字是 Opus 4 的 SWE-bench 72.5% 与 Terminal-bench 43.2%、Sonnet 4 的 SWE-bench 72.7%，以及高算力流程下的 79.4% 与 80.2%；但带扩展思考的多数基准数字只在图里，TAU-bench 没有正文数字，“世界最佳编码模型”的说法没有可核对的对照。

**核心结论：**

1. Opus 4 与 Sonnet 4 是混合模型，有近即时响应与扩展思考两种模式；随模型一起发布了带工具的扩展思考（beta）、并行工具使用、记忆文件、思考摘要、Claude Code 正式版与四项 API 新能力。置信度：高（就“博客写了什么”）。证据：§一、§二。
2. Opus 4 的 SWE-bench 分数为 72.5%，Terminal-bench 为 43.2%；Sonnet 4 的 SWE-bench 分数为 72.7%。置信度：高。证据：数字台账 E1–E3。
3. 高算力流程（并行采样 + 拒绝采样 + 内部评分模型选最优）下，Opus 4 与 Sonnet 4 的 SWE-bench 分数分别为 79.4% 与 80.2%，Sonnet 4 反而高于 Opus 4。置信度：高。证据：数字台账 E4。
4. 两个模型在容易走捷径的 agent 任务上比 Sonnet 3.7 少 65% 出现走捷径行为，但没有绝对发生率。置信度：中。证据：数字台账 E9。
5. 带扩展思考的 GPQA、MMMLU、MMMU、AIME 分数与 TAU-bench 分数只在图里，正文没有数字，本次未核实。置信度：高。证据：数字台账 E14。
