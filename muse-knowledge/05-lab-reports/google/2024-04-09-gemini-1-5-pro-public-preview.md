## 三、主要发现

### 公开预览：范围扩大

Gemini 1.5 Pro 这次通过 Gemini API 向 180 多个国家的开发者开放公开预览。公告同时提醒，开发者可以在 Google AI Studio 创建或使用 API 密钥开始搭建。

100 万 token 的上下文窗口不是这次的新东西。公告把它作为二月试用版已有的能力复述了一遍。

### 音频与视频模态：这次新增的核心

Gemini 1.5 Pro 的输入模态扩展到了音频（语音）理解，原生支持，不经过先转文字再理解的两步。公告称这是首个原生音频理解能力，同时在 Gemini API 与 Google AI Studio 里提供。

视频方面，模型现在可以在 Google AI Studio 里对上传的视频同时推理图像帧与语音。公告说，API 对这项能力的支持即将推出，也就是说发布时视频的跨模态推理还只在 AI Studio 里可用，API 还没有。

演示示例是上传一段 Jeff Dean 的讲座录音，模型把它变成一份带答案的测验。公告给出的录音长度是 117,000+ token。这只是一个演示示例，不能读成音频理解能力的测量结果。

### 文件接口：新推出的 File API

公告同时推出了一个新的 File API，目的是让处理文件变得容易。除此之外，公告没有展开讲这个接口支持哪些文件类型、有什么大小限制、怎么计费。

### Gemini API 的三项改进

公告说，这次回应了开发者的几项主要诉求，一共三项。

第一项是系统指令。现在可以在 Google AI Studio 与 Gemini API 里用系统指令引导模型的回答，定义角色、格式、目标与规则，让模型的行为贴合具体的使用场景。

第二项是 JSON 模式。可以指示模型只输出 JSON 对象（JSON objects），用来从文本或图像中抽取结构化数据。发布时可以用 cURL 开始使用，Python SDK（Python SDK）的支持即将推出。

第三项是函数调用的改进。现在可以选择模式来限制模型的输出，提高可靠性。可选的输出包括文本、函数调用，或者只输出函数本身，一共三种。

### 新的文本嵌入模型

从当天起，开发者可以通过 Gemini API 使用下一代文本嵌入模型 text-embedding-004（text-embedding-004）。在 Vertex AI（Vertex AI）里，它的名字是 text-embedding-preview-0409。

公告对这个模型的说法只有一句话：它在 MTEB 基准上检索性能更强，优于同等维度的现有模型。没有分数，没有对比模型名单，没有维度数字。

公告配了一张表格图，图的说明文字另有一句关于维度的说法。这句说法只在图内，正文里没有对应的数字，所以按未核实处理，不在这里印数字。

公告结尾说，这只是未来几周里许多改进的第一批，团队在继续让 AI Studio 与 Gemini API 成为用 Gemini 搭建最容易的途径。

## 五、精读点评

这一节是分析者的判断，和上面对公告的呈现分开写。

### 这篇公告真正要回答的问题

这篇公告真正要回答的问题是：在二月试用之后，开发者用 1.5 Pro 时还缺什么，以及它什么时候能真正拿来用？它给出的答案分两层。一层是可用性：180 多个国家、通过 Gemini API 的公开预览。另一层是功能：音频理解、文件处理、系统指令、JSON 模式、函数调用改进、新嵌入模型。第一层是事实，第二层里“新功能存在”是事实，“新功能有多好”则是没有配证据的断言。

### 科学问题还原：五问

**现象是什么？** 二月试用版的 1.5 Pro 只有文本、图像、视频输入，没有原生的语音输入；开发者对输出的控制手段也有限，想要结构化输出、想要固定模型角色，都没有现成的机制。反常不在某一次实验失败，而在使用缺口上：一个以长上下文和多模态为卖点的模型，偏偏缺语音输入，又缺输出控制。公告要回答的正是“这些缺口补上了没有”。

**为什么重要，不解决会怎样？** 对实践来说，如果音频理解、JSON 模式、系统指令一直缺着，开发者就得自己搭转录、自己写解析、自己在提示词里反复约束格式，1.5 Pro 的长上下文优势在很多真实任务里用不起来。对领域来说，缺的不是科学认知，而是一款模型能不能成为开发者的默认选择。不解决，什么都不会“错下去”，但公开预览的吸引力会打折扣。

**为什么之前做不了？** 卡住的点是产品节奏，不是科学瓶颈。试用版先验证 100 万 token 上下文与多模态推理，音频理解、文件接口与输出控制是下一批要补的功能。没有一块“石头”可移走，只有按顺序把功能做出来、开放出来。因此公告真正的贡献不在方法，而在产品本身（公开预览的范围与新功能）。

**方法与问题是否匹配？** 公告的“方法”是发布公开预览并列出新功能。这确实回答了“开发者现在能用什么”：音频理解、系统指令、JSON 模式、函数调用模式、新嵌入模型，都有明确的可用状态。但它没有回答“这些新功能有多可靠”：没有准确率、没有合规率、没有基准分数。公告回答的是一个更容易的问题（“功能存在”），而不是开发者真正关心的问题（“功能好不好用”）。方法与问题只匹配了一半。

**答案改变了什么？** 认知上几乎什么都没改变。公告没有提供任何可检验的机制解释（没有架构、数据或训练变化），也没有可复核的证据。因此关于“什么让模型变强”的信念不应改变。

实践上改变的是开发者的选择面：180 多个国家可以通过 API 用上 1.5 Pro，音频输入、系统指令、JSON 模式、File API、新嵌入模型都已可用或即将可用。这些是真实、可查的产品事实，开发者可以据此开始搭建。

### 价值判断

认知价值是低的。公告没有推翻或确认任何科学信念。它宣布了新功能，却没有提供可检验的机制或可复核的证据。读完之后，关于“什么让模型变强”的信念不应改变。

方法价值也是低的。公告没有留下别人能直接拿走复用的工具、范式、度量、实验设计或数据集。没有代码、数据、提示、评估框架或权重随公告发布。唯一接近可复用的只是新功能本身的使用方式（系统指令、JSON 模式、函数调用模式），而且细节只讲到能用的程度。

边界价值是高的，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：音频理解的准确率、JSON 模式的输出合规率、系统指令的实际控制效果、嵌入模型在 MTEB 上的具体分数、以及 1.5 Pro 相对二月试用版的能力变化幅度。

读者最容易误读的推论，是把“功能存在”读成“功能可靠”，把“优于同等维度模型”读成“嵌入模型全面领先”。边界写得越清，结论越可信。这篇公告可信的是发布事实与功能清单，不是能力宣称。

启示价值在于，最便宜的决定性实验是公开实测：用公开的音频任务测原生音频理解，用结构化抽取任务测 JSON 模式的输出合规率，用 MTEB 的公开评测复现嵌入模型的宣称。具体设计在下面“接下来看什么”里写。

### 最弱的一环

最弱的一环在嵌入模型的性能宣称上。整句宣称的说服力，依赖于三件公告从来没有拿出来的东西。

第一，MTEB 上的具体分数。第二，对比的是哪些“同等维度的现有模型”。第三，输出维度是多少。

这三件东西都没有。宣称的唯一佐证是一张配图表格，而表格的说明文字只在图内，正文无法核实。

同一处薄弱也适用于“首个原生音频理解能力”里的“首个”二字。公告没有给出任何对照：没有说比谁先、没有引用二月版本或技术报告里音频能力的状态。首个与否，从这篇公告里是核实不了的。

### 效度判断

下面是针对公告作为证据的评分，满分 5 分，评的是证据，不是模型本身。

内部效度 1 分。没有实验，经典内部效度威胁大多是“说不清”而非受控。适用的具体威胁是演示挑选（唯一的证据是一个挑好的讲座录音示例）、嵌入模型宣称的对比模型未具名，以及功能清单本身由发布方单方面陈述、没有任何独立核查。

### 其他可能的解释

同一份功能清单，至少有两种别的解释也能说得通。

第一种是发布节奏的解释。公告的重点不是能力跃升，而是把试用版推进到公开预览：范围扩大到 180 多个国家，补上开发者催得最紧的几项功能。功能清单的真正含义是“产品就绪”，而不是“模型变强”。

第二种是演示挑选的解释。讲座录音转测验的演示挑了一个条件极好的例子：一位知名研究者的讲座、清晰的录音、结构分明的内容。演示成功，可能反映的是这个例子的容易，而不是音频理解能力的普遍水平。

这种解释预测，换一段带口音、带噪声、带多人对话的录音，效果会明显下降。区分证据是在多种真实录音上的实测，而不是单个演示。

### 什么观察能反驳这些宣称

原生音频理解的宣称可以这样检验：用公开的语音问答或语音摘要任务，在多种录音条件下实测。如果模型在清晰讲座之外明显失灵，或者需要先转文字才能回答，“原生音频理解”作为能力的宣称就被削弱了。

公开预览覆盖 180 多个国家的宣称可以这样检验：在多个国家的开发者账号上实际调用 API。如果大量国家无法访问，覆盖宣称就被反驳了。

## I. 结论、结果与价值总览

### 一句话结论

作为产品发布，它可信地宣布了 Gemini 1.5 Pro 在 180 多个国家的公开预览与一批真实的新功能；作为“新功能有多强”的证据，它不成立。能力宣称没有配任何可核查的数字。

### 核心结论

1. **公开预览与功能清单确立（置信度：高）。** 180 多个国家通过 Gemini API 开放公开预览、原生音频理解、File API、系统指令、JSON 模式、函数调用模式选择、新嵌入模型 text-embedding-004，都是公告正文直接陈述、可核查的事实。

2. **演示示例确立，但只证明一次演示成功，不证明音频理解能力（置信度：中）。** 演示用的是一段 117,000+ token 的 Jeff Dean 讲座录音，视频为加速播放。没有其他录音、没有对照、没有评分标准。

3. **嵌入模型“优于同等维度模型”未确立（置信度：低）。** 只有一句话宣称，没有分数，没有对比模型名单，没有维度数字。配图表格的说法只在图内，未核实。

4. **“首个原生音频理解”未确立（置信度：低）。** 公告没有给出任何对照，没有说明二月版或技术报告里音频能力的状态。“首个”二字从这篇公告里核实不了。

5. **视频跨模态推理与 JSON 模式的 Python SDK 支持在发布时尚未就绪（置信度：高）。** 公告自己说了这两项“即将推出”。这是公告里最诚实的两处限定。

### 关键结果

公开预览覆盖 180 多个国家，是确立的。发布时通过 Gemini API 提供，但没有国家名单。

上下文窗口 100 万 token，是确立的，但它是二月试用版已有的能力，不是本次新增。

配图表格里关于维度的说法是仅图内、未核实的，不作为已确立的结论引用。
