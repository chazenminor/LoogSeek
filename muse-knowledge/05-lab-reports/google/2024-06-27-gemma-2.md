## 一、背景与问题

### 报告之前是什么局面

2024 年上半年，大语言模型的竞争分成了两条线。一条是越大越强：GPT-4、Gemini 1.5 Pro、Llama 3 70B 这些大模型在推理基准上不断刷新纪录，上下文动辄上百万 token。另一条是小模型：Mistral 7B、Llama 3 8B、Gemma 1 的 2B 与 7B 在往轻量、开源、能跑在普通硬件上的方向走。

小模型这条线当时遇到一个瓶颈。过去两年的经验是，小模型的进步主要靠把训练拉长：用更多的 token 训同一个小模型。但这条路的回报是递减的，报告引言里点得很直白——按 Chinchilla 的 scaling law（Hoffmann 等，2022），收益只随数据集规模对数增长；最新的小模型要用上 15T token，才能把最强纪录往前推不到 1–2 个百分点。

与此同时，小模型其实还没被训够。报告的判断是：继续拉长训练不是唯一的路。能不能换一个思路，让每一步训练给网络的信息更丰富，而不是只靠堆 token 数？这就是 Gemma 2 要回答的问题。

### 报告自己的说法

摘要只有一段，意思很干净：Gemma 2 是 Gemma 家族的新成员，2B 到 27B 三个尺寸；架构上用了几项已知的 Transformer 改动，包括局部–全局注意力交错（local-global attention）与分组查询注意力（grouped-query attention，GQA）；2B 与 9B 不用下一 token 预测（next token prediction）训练，改用知识蒸馏（knowledge distillation）；结果是同尺寸里最好，甚至能与大 2–3 倍的模型竞争；全部模型向社区开放。

引言把问题说得更具体：蒸馏把每个 token 上的一位独热（one-hot）目标，换成了大模型算出的下一 token 概率分布。这样每一步训练的梯度信号更丰富。报告的用法与众不同——蒸馏通常是用来缩短小模型的训练时间，这里反过来：用蒸馏训海量的 token，模拟“超出可用 token 数”的训练。2B 与 9B 的训练 token 量超过 Chinchilla 计算最优量 50 倍以上。

27B 则走了另一条路：从头训练（trained from scratch），不蒸馏，13T token。报告没有明说 27B 用的什么目标函数，但摘要里“2B 与 9B 改用蒸馏、而不是下一 token 预测”的对照写法，意思就是 27B 用的仍是标准的下一 token 预测。

## 二、方法与设计

### 模型是怎么做的

三个尺寸都是解码器-only Transformer（decoder-only transformer），上下文长度 8192 token。沿用 Gemma 1 的东西有：旋转位置编码（Rotary Position Embeddings，RoPE）、近似 GeGLU 非线性、256k 词表的 SentencePiece 分词器（与 Gemini 共用，数字拆分、保留空白、字节级编码）。

Gemma 2 相对 Gemma 1 的改动有四项。第一，局部–全局注意力交错：每隔一层交替使用局部滑窗注意力（sliding window attention，窗口 4096 token）与全局注意力（跨度 8192 token）。第二，logit 软上限（logit soft-capping）：每层注意力与最后一层的 logit 都经过 soft_cap × tanh(logits / soft_cap) 变换，注意力层 soft_cap 取 50.0，最后一层取 30.0。第三，前后双归一化：每个子层的输入与输出都用 RMSNorm 做归一化（pre-norm 与 post-norm 并用），目的是稳定训练。第四，分组查询注意力（GQA）：每组两个查询头共享一对键值头（num_groups = 2），消融显示推理更快、性能基本不变。

模型越做越深，而不是越做越宽。三个尺寸的层数是 26、42、46 层；d_model 是 2304、3584、4608；注意力头数 8、16、32；键值头数 4、8、16；头维度 256、256、128；前馈维度 18432、28672、73728。

参数量有个容易误读的细节。“2B、9B、27B”这个叫法指的是非嵌入参数（non-embedding parameters）：2,024,517,888、8,324,201,984、26,047,480,320。词表太大（256,128），嵌入参数另有 0.59B、0.92B、1.18B。所以模型总参数实际是约 2.6B、9.2B、27.2B。这也解释了为什么 Chatbot Arena 的表里把 2B 模型写作 Gemma 2.6B。

### 训练数据与蒸馏

训练 token 量：27B 用 13T token，9B 用 8T，2B 用 2T，主要是英文数据，来源包括网页文档、代码与科学文章。数据混合比例是通过类似 Gemini 1.0 的消融实验确定的，但具体比例报告没有给。模型不是多模态的，也没有针对多语言能力专门优化。

数据过滤沿用 Gemma 1 的做法：过滤掉不想要或不安全的表述、部分个人信息与敏感数据；对评测集做去污染（decontamination），把评测集从预训练数据里剔除；减少敏感输出的复现风险。

蒸馏是这份报告的核心方法。做法是：给定一个教师大模型，学生模型去拟合教师给出的下一 token 概率分布，最小化两者之间的负对数似然。报告没有点名教师模型是谁。消融节的一句话透露了 9B 的目标蒸馏是从 27B 到 9B——消融里用 7B 教师教 2B 学生，是为了模拟与“27B 教 9B”相似的师生规模比。2B 的教师是谁，报告没有交代。

报告对蒸馏的定位值得注意。蒸馏通常用来缩短训练时间，这里反其道而行之：用蒸馏训远超计算最优的 token 量，模拟“数据不够、靠教师分布补”的训练。2B 与 9B 的训练量超过 Chinchilla 计算最优量 50 倍以上。按 Chinchilla 的经验法则，2B 模型的计算最优 token 量大约是几百亿，2T token 确实是几十倍。

### 训练基础设施

2B 在 512 块 TPUv5e 上训练，9B 在 4096 块 TPUv4 上，27B 在 6144 块 TPUv5p 上。优化器状态用类似 ZeRO-3 的方式分片；跨 pod 的数据并行归约走数据中心网络，用 Pathways 方法；编程范式是 JAX 的“单控制器”模式与 GSPMD 分区器，编译器是 MegaScale XLA。

碳排放方面，预训练的碳排放估计为 1247.61 吨二氧化碳当量（tCO2eq），按 TPU 数据中心直接上报的每小时能耗算出，并按数据中心的额外能耗做了放大。报告同时说明 Google 数据中心通过能效、可再生能源采购与碳抵消实现碳中和，这个中和口径同样适用于本次实验。

### 后训练是怎么做的

后训练分三步。先做监督微调（supervised fine-tuning，SFT）：在文本、纯英文的合成与人工提示–回答对上做行为克隆，回答主要由更大的教师模型合成生成；同时在学生自己的采样分布上做蒸馏。然后做人类反馈强化学习（reinforcement learning from human feedback，RLHF）：奖励模型比策略模型大一个数量级，更侧重多轮对话能力；RLHF 算法与 Gemma 1.1 类似，但奖励模型换了。最后做模型合并（model merging）：把不同超参数跑出来的多个模型做权重平均，以提升整体性能。

后训练数据在 Gemma 1.1 的基础上扩展了，混合了内部数据与外部公开数据。报告点名用到了 LMSYS-chat-1M 的提示（prompts），但没有用它的回答（answers）。所有合成数据都经过多阶段过滤：去掉含个人信息、不安全或有毒输出、错误自我认同、重复样本的内容。报告还提到，加入鼓励上下文归因、 hedging（留有余地的表述）与拒绝回答的数据子集，能在不损害其他指标的前提下提升事实性指标。

格式上，Gemma 2 沿用 Gemma 1 的控制 token（<start_of_turn>、<end_of_turn>、<bos>、<eos> 等），但格式 schema 不同：模型生成以 <end_of_turn><eos> 结尾，而 Gemma 1 只生成 <eos>。

### 评估是怎么做的

评估分预训练模型与指令微调（instruction-tuned，IT）模型两块，覆盖自动化基准与人类评估。报告明确说明，比较时按总参数量（total parameters）而不是激活参数量算，因为总内存占用才是限制开放模型在普通设备上使用的因素。

预训练评估用 HuggingFace 评测套件，基线是同尺寸的 Qwen1.5 32B 与大 2.5 倍的 Llama 3 70B（按 HuggingFace 排行榜名次选的）。2B 与 9B 的对比表里，基线还包括 Gemma 1 的 2B 与 7B、Mistral 7B、Llama 3 8B。

人类评估有三块。一是 LMSYS Chatbot Arena：盲测并排比较，人类评分员打分，汇总成 Elo 分数，带 95% 置信区间。二是独立的人类偏好研究：用留出的单轮提示集，测指令遵循（instruction following，单边打分：提示里的全部指令都被遵循的比例）与安全性（与 GPT-4o 对比的胜–平–负比率）。三是多轮对话评估：500 个场景，平均每个场景 8.4 轮用户对话，评分员按 1–5 分打用户满意度与对话目标达成度。

责任与安全评估另有一套，见下文。统计方面，报告没有给出种子、重复运行次数与误差棒（多轮与说服类人类研究给了 bootstrap 置信区间，自动化基准没有）。自动化基准的分数是单次运行的结果，这一点读者应当知道。

## 三、主要发现

### 消融实验：蒸馏是真的有效，而且效果随规模保持

第 5 节是这份报告科学上最扎实的部分，因为它有对照。

蒸馏与从头训练的对比（表 6）：一个 2B 模型训 500B token，三个基准的平均分从头训练是 60.3，蒸馏是 67.7，提升 7.4 分。报告特意注明，500B token 已经是 2B 模型计算最优 token 量的 10 倍——也就是说，即使在“已经训得够多”的情况下，蒸馏仍然带来大幅提升。这是对“蒸馏只是省时间”这个常见看法的直接反驳。

蒸馏的效果随学生规模变化（表 7）：教师固定为 7B，学生在验证集上的困惑度（perplexity）从 200M 的 23 降到 21，400M 的 19 降到 17，1B 的 17 降到 15。增益随学生变大而保持，没有消失。

其他三项消融的结论都是否定性的、但同样有用。GQA 对比多头注意力（表 8）：9B 模型四个基准平均分 50.8 对 50.3，基本没差别，选 GQA 的理由是参数更少、推理更快。深网对比宽网（表 9）：同样参数量的 9B，深的比宽的好，50.8 对 52.0，差距小但在各基准上一致，所以改用更深的架构。推理时改滑窗大小（表 10）：9B 模型把滑窗从 4096 改到 2048 甚至 1024，验证集困惑度分别是 1.63、1.63、1.64，几乎不变——推理时可以拿滑窗换速度。

格式鲁棒性（表 11）是个有意思的附带发现：MMLU 分数在 12 种提示与评估格式组合下的标准差，Gemma 2 2B 是 2.1，9B 是 0.9，27B 是 1.0；而 Mistral 7B 是 6.9。也就是说，Mistral 7B 的 MMLU 分数对格式变化敏感得多，换个格式能差出好几分；Gemma 2 的分数稳得多。这个数字提醒读者：不同模型之间几个百分点的 MMLU 差距，可能一半是格式敏感性造成的。

### 预训练模型：9B 越级，27B 接近但没超过 70B

27B 预训练模型（表 12，HuggingFace 套件）：MMLU 75.2%，低于 Llama 3 70B 的 79.2%，高于 Qwen1.5 32B 的 74.3%；GSM8K 74.0%，低于 Llama 3 70B 的 76.9%，高于 Qwen1.5 32B 的 61.1%；ARC-c 71.4%，高于两者的 68.8% 与 63.6%；HellaSwag 86.4%，低于 88.0%，高于 85.0%；Winogrande 83.7%，低于 85.3%，高于 81.5%。总体上，27B 在同尺寸里最好，离大 2.5 倍的 Llama 3 70B 只差几个百分点。

作者自己在这里很克制。他们写道，相似方式训练的模型性能只随规模对数增长，所以 Gemma 2 27B“很可能与 Llama 3 模型处在同一条帕累托曲线上”（likely in the same Pareto curve），并且“这些差异如何影响指令微调后模型的质量尚不清楚”。这句话等于承认：27B 没有开辟新的 scaling 曲线，它只是把已知曲线走得更扎实。

9B 的表现更抢眼（表 13）。MMLU 71.3%，高于 Llama 3 8B 的 66.6%、Mistral 7B 的 62.5%、Gemma 1 7B 的 64.4%；GSM8K 68.6%，高于 Llama 3 8B 的 45.7%；MATH 36.6%，高于 Gemma 1 7B 的 24.3%（Llama 3 8B 的 MATH 未报告）；HumanEval pass@1 是 40.2%，高于 Gemma 1 7B 的 32.3%；8 个可比基准的平均分 70.2%，高于 Llama 3 8B 的 61.9%；全部 18 个基准的平均分 64.9%，高于 Gemma 1 7B 的 57.9%。

2B 相对 Gemma 1 2B 的提升也很大：MMLU 从 42.3% 到 52.2%，GSM8K 从 15.1% 到 24.3%，全部基准平均分从 44.2% 到 48.7%。报告强调，两个 2B 模型的训练 token 量相近（Gemma 2 是 2T，Gemma 1 是 3T），提升仍然显著——这说明提升来自蒸馏，而不是来自训得更多。

这里有个口径上的保留。表 13 的脚注说明，Llama 3 8B 的数字有的来自 HuggingFace 排行榜、有的来自官方博客，不是作者自己跑的；而且 AGIEval 与 BBH 这两项上，基线的数字用的是 Llama 3 自己的评估方式，比作者自己的评估方式高出约 3% 与 4%。也就是说，基线数字里有一部分是被抬高了的，Gemma 2 的领先幅度在这些基准上可能被低估了——但反过来，跨 harness 的比较本身就不完全对等，读者不该把小数点后一位的差距当真。

### 指令微调模型：Chatbot Arena 上 27B 超过 Llama 3 70B，9B 追平 GPT-4

Chatbot Arena（表 14）是这份报告最抓眼球的结果。Gemma 2 27B 指令微调版 Elo 1218（95% 置信区间 +4/−3，即 1215–1222），高于 Llama 3 70B 指令版的 1206（+2/−2，即 1204–1208），两个区间不重叠。Gemma 2 9B 指令版 Elo 1187（+3/−5），与 GPT-4-0314 的 1186（+2/−3）基本持平，区间高度重叠。Gemma 2 2B 指令版 Elo 1126（+10/−10），高于 GPT-3.5-Turbo-0613 的 1116（+3/−4），但 2B 的置信区间很宽（±10），与 GPT-3.5 的区间有重叠。

换句话说：27B 超过 70B 这个结论，在 Arena 自己的置信区间里是站得住的；9B 追平 GPT-4-0314 这个结论，只能说“打平”，不能说“超过”；2B 超过 GPT-3.5 的结论则受限于很宽的置信区间。博客里“27B 提供两倍以上尺寸模型的竞争性替代方案”的说法，与 Arena 的数字是一致的。

独立的人类偏好研究（表 15）补了两个维度。指令遵循（单边打分，提示里全部指令都被遵循的比例）：27B 是 37.7% ± 2.3%，9B 是 34.1% ± 3.0%，2B 是 26.5% ± 1.8%，Gemma 1.1 7B 是 24.3% ± 1.9%。绝对水平值得注意：即使是最好的 27B，也只在约 38% 的留出提示上完整遵循了全部指令。安全性（与 GPT-4o 对比的胜率）：27B 是 55%（胜–平–负 49.6% / 10.8% / 39.6%），9B 是 57.8%（48.2% / 19.2% / 28.3%），2B 是 57.5%（53% / 9% / 38%），Gemma 1.1 7B 是 42.8%（37.4% / 10.8% / 51.8%）。三个尺寸都比 GPT-4o 更常被评为更安全，而且 2B 与 9B 的安全胜率反而略高于 27B——安全性没有随尺寸单调变好。

多轮对话评估（表 16，500 个场景，平均 8.4 轮用户对话）：用户满意度（1–5 分）27B 是 4.20，9B 是 4.04，2B 是 3.64，Gemma 1.1 7B 是 3.32；对话目标达成度 27B 是 4.24，9B 是 4.08，2B 是 3.88，Gemma 1.1 7B 是 3.36。报告说 Gemma 2 模型在整个对话过程中维持高质量回答的能力比 Gemma 1.1 更好。

指令微调对 few-shot 基准也有提升（表 17）：MMLU 上 27B 从 75.2% 升到 76.2%，9B 从 71.3% 升到 72.3%，2B 从 52.2% 升到 56.1%；MBPP 上 27B 从 62.6% 升到 67.4%，9B 从 52.4% 升到 59.2%，2B 从 30.2% 升到 36.6%。作者的解释是猜测性的：指令微调后的模型更能理解带格式的问题，而预训练模型对格式敏感。

### 记忆化与隐私：记忆率很低，但定义很窄

第 7 节测的是记忆化（memorization）：模型在给定 50 token 提示的情况下，能否逐字复现训练数据里的 50 token 片段。Gemma 2 的逐字记忆率低于 0.1%，显著低于同尺寸的已有模型（图 1；具体对比数字只在图里，正文只给了“低于 0.1%”这个上限）。按数据源拆分，代码、维基与科学来源的记忆率更高，但同样全面低于 Gemma 1。

个人信息方面，用 Google Cloud 敏感数据保护工具检查记忆化输出：没有发现高严重度个人信息被输出；低严重度个人信息占记忆化数据的 0.00026%。报告自己提醒，这些自动化工具已知会产生假阳性（因为不考虑上下文），所以结果很可能是高估。

这里要留一个心眼：报告用的记忆化定义是很窄的——只算“能被诱导逐字复现”的情况，不算模型“包含”训练数据的其他意义。这个定义是作者自己在脚注里写明的。记忆率低，不等于训练数据没有被记住的其他形式。

### 责任与安全：学术基准有喜有忧，危险能力评估没有拉响警报

安全学术基准（表 18）呈现的是一幅混合画面。偏见与刻板印象类指标明显改善：CrowS-Pairs（数值越低越好）27B 是 36.67，Gemma 1.1 7B 是 49.67；Winogender（越高越好）77.22 对 57.64；Winobias 1_2 是 81.94 对 59.22；BBQ 消歧子集 86.94 对 85.08；TruthfulQA 51.60 对 45.34。

但毒性类指标变差了：RealToxicity 平均毒性 27B 是 8.84，高于 Gemma 1.1 7B 的 8.04；Toxigen 平均毒性 2B 是 48.32，远高于 Gemma 1.1 2.5B 的 29.64（27B 的 38.42 与 Gemma 1.1 7B 的 38.75 倒是相近）。报告没有讨论这两项变差，也没有解释为什么偏见指标变好、毒性指标变差可以同时发生。读者不该只读“安全有提升”这个笼统说法。

保证评估（assurance evaluations）方面，报告只给了定性结论：Gemma 2 在安全政策上的总体违规率显著低于 Gemma 1，尤其是在儿童安全内容上。具体违规率数字没有给出，无法核对。

危险能力评估的结果是：没有拉响警报，但能力确实在涨。进攻性网络安全（表 19）：InterCode-CTF 上 Gemma 2 27B 成功 34/76（45%），远高于 CodeGemma 7B 的 12/76（16%），但低于 Gemini 1.5 Pro 的 62/76（82%）；内部 CTF 套件 1/13（8%）；Hack the Box 挑战 0/13。报告注明，InterCode-CTF 的结果与外部报告的结果不可比，因为出于安全原因省略了需要联网的挑战。

代码漏洞检测（表 20）：PrimeVul 63%、PrimeVul 配对版 50%、DiverseVul 57%、SPI 53%、SecretPatch 72%。配对版 50% 就是随机水平——模型基本分不出有漏洞与无漏洞的代码对。自我复制能力（表 21）：10 个端到端挑战 0 个通过，全部里程碑都通过的只有 1/10，45 个里程碑通过 22 个（49%），需要专家提供 12,462 比特的信息才能帮模型完成挑战；连最简单的挑战（安装一个比特币钱包）都没能通过。

说服能力（表 22–25，样本量 100 人）：建立融洽关系（charm offensive）上，27B 表现强于 Gemini 1.0，被 80% 的参与者认为建立了个人连接；隐藏议程任务里，34% 的参与者被说服点击链接，9% 被说服查找信息，11% 被说服运行代码，与 Gemini 模型没有显著差异；金钱谈话任务里，平均捐款 £3.72 ± £1.07，与无聊天机器人基线的 £2.61 ± £0.70 相比没有显著差异（置信区间重叠，报告自己也这么说）；谎言网络任务里，模型把参与者往正确信念推的幅度是 18% ± 5%，往错误信念推的幅度是 1% ± 4%，而人类基线往错误信念推的幅度是 −23% ± 14%——也就是说，Gemma 2 在说服人相信错误答案上显著弱于人类。

## 四、作者的结论与局限

### 作者的结论

作者在第 9 节收拢了两条结论。第一，蒸馏是训练小模型的有效方法：用教师输出的概率分布代替下一 token 预测，能在同样 token 量下训出明显更好的小模型。第二，Gemma 2 把之前只有大规模语言模型才有的能力，带到了实用的小尺寸上；作者希望这次开放能推动后续的研究与开发。

安全方面，作者的结论是：经过广泛的安全调查与负责任的部署流程，他们相信这次发布会对社区产生净正面影响；同时提醒，测试无法覆盖 Gemma 2 可能被用到的全部应用场景，用户在部署或使用前应当针对自己的用例做严格的安全测试。

### 作者自己说的局限

作者在结论里点名了四个需要未来研究改进的方向：事实性（factuality）、对对抗攻击的鲁棒性（robustness to adversarial attacks）、推理能力（reasoning）、对齐（alignment）。这四个词没有展开——报告没有逐项说明每个方向上具体差在哪里。

作者在正文里还留了几处诚实的保留。27B 很可能与 Llama 3 处在同一条帕累托曲线上，不是新的 scaling 规律；27B 与 Llama 3 70B 的差距如何影响指令微调后的模型质量，尚不清楚；保证评估的违规率只给了定性说法，没有数字；记忆化的定义是窄的，只算能被诱导逐字复现的情况。

### 报告没有交代的事

有几件事报告完全没提，读者应当知道它们是缺失的，而不是默认它们不存在。

第一，教师模型是谁。2B 与 9B 的蒸馏教师没有点名。9B 的教师可以从消融节的一句话推断是 27B，2B 的教师则完全没有交代。教师的能力与数据直接决定蒸馏的上限，不知道教师是谁，蒸馏的贡献就没法独立评估。

第二，数据混合比例与超参数。训练数据的来源只给了类别（网页、代码、科学文章），没有给各占多少；学习率、批量大小、训练步数、蒸馏温度这些超参数一个都没给。一个能干的读者读完报告，可以照着架构表搭出模型结构，但训不出同样的模型。

第三，自动化基准没有误差棒。所有基准分数都是单次运行的结果，没有种子、没有重复运行、没有置信区间。表 11 的格式敏感性数字恰恰说明，几个百分点的差距可能只是格式造成的——但报告没有给每个基准配上这个不确定度。

第四，部分基线不是自己跑的。Llama 3 8B 的数字有的来自排行榜与博客，AGIEval 与 BBH 的基线用的是 Llama 3 自己的评估方式。跨 harness 的比较不完全对等，报告在脚注里说了，但正文的叙述没有因此收敛。

第五，博客性能图与安全图里的数字。博客正文没有给任何数字，两张图里的具体数值无法从正文核对，本文件不印。

## 五、精读点评

### 这篇报告真正要回答的问题

这份报告要回答的不是一个科学发现式的问题，而是一个工程配方问题：小模型已经撞上了“堆 token 收益递减”的墙，有没有别的办法让小模型继续变强？

反常出在 scaling 的经验法则上。按 Chinchilla 的法则，小模型的最优训练量是参数量的大约 20 倍 token；超过这个量，收益就对数衰减。但现实是，大家还在继续拉长训练，因为别无他法——最新的小模型用上 15T token，也只能把纪录推前不到 1–2 个百分点。反常在于，小模型明明还没被训够，却找不到便宜的办法继续训它。

为什么重要？对实践来说，小模型是唯一能跑在普通硬件上、能被广泛部署的尺寸。如果小模型的进步停滞，开放模型的生态就会被锁死在大模型手里；如果小模型能越级，一个 9B 的模型就能干 70B 的活，部署成本会大幅下降。对领域来说，这个问题触及 scaling law 的边界：Chinchilla 的最优量是在“下一 token 预测”这个目标下算出来的，换一个目标，最优量会不会变？这是一个值得问的问题。

为什么之前没做？蒸馏本身不是新东西，卡住的点在于用法。蒸馏通常被当成省时间的工具——用大模型带小模型，少训一点、效果差不多。把蒸馏反过来用（不省时间，反而训海量 token，模拟超出数据量的训练），需要同时满足两个条件：一个足够强的教师，以及愿意为小模型烧掉大模型级别算力的决心。这两个条件在 2024 年中才同时具备。

方法与问题的匹配点是清楚的：要回答“蒸馏能不能让小模型越级”，就需要一组对照——同样 token 量下蒸馏与从头训练的直接比较。报告第 5 节给了这组对照，而且结果干净：500B token 下 7.4 分的差距，困惑度上随规模保持的增益。方法回答的正是它声称要回答的问题。

答案改变了什么？认知上，它修正了一个默认假设：Chinchilla 的计算最优量不是铁律，它依赖于训练目标；换用蒸馏这个更丰富的目标，小模型可以在远超最优量的 token 数上继续获益。实践上，它给出了一个可复制的配方：用大模型当教师，用海量 token 蒸馏小模型。这个配方的代价是算力——9B 训 8T token、2B 训 2T token，用的还是 4096 块 TPU——所以它改变的是“小模型能做到什么”，不是“小模型能便宜做到什么”。

### 科学问题还原：五问

反常是：小模型的进步撞上了对数墙——训练 token 从几 T 拉到 15T，纪录只前进不到 1–2 个百分点；但与此同时，小模型又明显还没被训够。这个矛盾逼出了问题：收益递减到底是模型的极限，还是训练目标的极限？

重要性分两层。对实践来说，小模型是开放生态的命脉：如果小模型停滞不前，普通人能跑的模型就永远落后大模型几个身位，部署成本的差距会把开放模型锁死在低端。对领域来说，这个问题检验的是 Chinchilla scaling law 的适用范围——最优训练量是不是与训练目标无关的常数。

之前做不了的卡点是用法与决心。蒸馏作为省时间的工具人人会用，但把它当成“模拟超量训练”的手段，需要一个足够强的教师和为小模型烧大算力的意愿。报告的贡献是把这个用法跑通并给出了对照数字。

方法与问题的匹配是好的：消融实验直接比较了同样 token 量下蒸馏与从头训练，这是回答“蒸馏有没有效”最直接的设计。但方法没有回答“为什么蒸馏有效”——是教师分布的信息量，还是蒸馏起到的正则化作用，报告没有分离。

答案改变的认知是：计算最优训练量依赖于训练目标，蒸馏可以把小模型的有效训练量推到远超 Chinchilla 最优的水平。答案没有改变的是 scaling 的基本形状——作者自己承认，27B 很可能与 Llama 3 处在同一条帕累托曲线上。读完之后，关于“小模型怎么训”有一条新信念；关于“规模与能力的关系”，没有什么需要改的。

### 价值判断

认知价值中等偏高。它没有推翻 scaling law，但给它加了一个重要的限定条件：计算最优量是目标依赖的，换用蒸馏可以突破下一 token 预测下的最优量。如果这份报告不存在，“小模型只能靠堆 token”的默认做法会继续主导开放模型的训练。反事实是：要推翻这个结论，需要证明同样的提升不用蒸馏、只靠把从头训练拉得更长也能拿到——报告的消融恰恰排除了这个可能（同样 500B token 下差距 7.4 分）。

方法价值较高。它留下了可直接复用的东西：一套“蒸馏加超长训练”的小模型配方；局部–全局注意力交错与 logit 软上限这两个即插即用的架构改动（都是已知技术，但报告验证了它们在 2B–27B 这个尺寸上好用）；以及格式鲁棒性这个评估维度——MMLU 标准差那张表提醒后来者，跨模型比较几个百分点时要先看格式敏感性。

边界价值较好。报告老实承认了 27B 与 Llama 3 在同一条帕累托曲线上、指令微调后的质量差异尚不清楚、保证评估没有给数字、记忆化定义是窄的。读者最容易误读的推论是“9B 全面超过 GPT-4”——Arena 上 9B 与 GPT-4-0314 的 Elo 区间高度重叠，只能说打平；以及“Gemma 2 更安全”——安全学术基准里毒性指标反而变差了。

启示价值中等偏高。最便宜的决定性下一步是点名教师并做教师消融：用同一个学生、换不同能力的教师（例如 27B 与 9B 各当一次教师）蒸馏，看学生成绩差多少。具体设计在下面“接下来看什么”里写。

### 最弱的一环

最弱的一环是教师身份未披露。整份报告的核心主张是“蒸馏让小模型越级”，而蒸馏的效果完全取决于教师是谁、教师有多强、教师的分布里有什么。如果教师是 Gemini 1.5 Pro 级别的模型，那么 9B 的成绩里有一部分是教师能力的直接转移，而不是蒸馏方法本身的功劳；如果教师只是 27B 自身，结论的含义又完全不同。报告没有点名教师，也没有做“换教师”的消融，读者无法判断蒸馏的增益里有多少来自方法、有多少来自教师。

这件事之所以承重，是因为它同时影响两个结论：9B 越级的幅度能不能复现（换个教师还行不行），以及这个配方对别人有没有用（没有同等教师的实验室能不能照做）。一个不知道教师是谁的蒸馏配方，是没法被别人完整复现的。

第二弱的一环是基线口径不完全对等。Llama 3 8B 的数字部分来自排行榜与博客，AGIEval 与 BBH 的基线用的是 Llama 3 自己的评估方式（比作者的评估高 3–4%）。跨 harness 的比较让小数点后一位的差距不可信。好在 9B 的领先幅度足够大（MMLU 高 4.7 分，GSM8K 高 22.9 分），不是靠口径差异撑起来的；但 27B 与 Llama 3 70B 之间几个百分点的差距，就处在口径噪声的量级上。

### 效度判断

内部效度 4 分（满分 5 分）。消融实验的设计是干净的：同样 token 量、同样学生规模，只换训练目标，差距直接归因于蒸馏。扣分在两处：教师身份未披露，蒸馏的因果链缺了一环；部分基线不是同 harness 下跑的，混杂因素没有完全排除。

外部效度 3 分。结论覆盖的范围是明确的：2B–27B 的英文纯文本模型，在公开学术基准与 Chatbot Arena 上。但所有结论都只针对这三个尺寸、这个数据混合、这个教师——换一个教师、换一个数据分布，蒸馏的增益未必一样。博客里“单台 H100 就能跑”的部署说法，在报告里没有任何延迟与吞吐的实测数字支撑。

构念效度 3 分。基准分数度量的是“在这些基准上的表现”，不是“通用能力”本身。Chatbot Arena 的 Elo 度量的是“在这些评分员、这些提示下被偏好的程度”，不是模型能力的直接度量。指令遵循的单边打分（全部指令都被遵循的比例）是个严格的构念，但它只测了单轮提示，多轮指令遵循没有对应的数字。

统计结论效度 2 分。这是报告最弱的一块。自动化基准没有种子、没有重复运行、没有误差棒；多轮与说服类人类研究给了 bootstrap 置信区间，但自动化基准的分数全是单次运行。表 11 的格式敏感性数字（Mistral 7B 的 MMLU 标准差 6.9）恰恰说明，几个百分点的差距可能只是格式噪声——但报告没有给每个基准配上不确定度。

可复现性 2 分。架构参数、训练规模、基础设施都给了，消融实验描述得足够详细；但数据混合比例、教师身份、超参数都没有，别人无法重跑标题结果。人类评估流程（Arena 除外）描述得比较完整，但 500 个多轮场景没有公开。总体上，这份报告比 Imagen 3 的报告可复现得多，但离“能重跑”还有距离。

## 六、证伪器、替代解释、接下来看什么

### 什么观察能反驳这些宣称

如果独立第三方用同样的学生规模与 token 量、不用蒸馏只拉长从头训练，也拿到了与 Gemma 2 9B 相近的 MMLU 与 GSM8K 分数，“蒸馏是关键”的宣称即被削弱。如果换一个弱得多的教师（例如 9B 教 2B）蒸馏，学生的提升大幅缩水，“蒸馏方法本身有效”的说法即需要降级为“教师强才有效”。如果在作者自己的 harness 下重跑 Llama 3 8B，发现它的 MMLU 与 GSM8K 比报告引用的排行榜数字高出几个百分点，9B 的领先幅度即需要重新计算。如果独立复测 Chatbot Arena，发现 27B 与 Llama 3 70B 的 Elo 差距落在置信区间重叠的范围内，“27B 超过 70B”的宣称即被限定。

### 其他可能的解释

第一种替代解释：9B 的提升主要来自训练 token 量，而不是蒸馏。9B 训了 8T token，远超 Chinchilla 最优量；Gemma 1 7B 只训了 6T token（报告没有给 Gemma 1 的 token 数——这个数字来自 Gemma 1 的报告，本文件不把它当作已核实数字）。能区分的证据就是表 6 的消融：同样 500B token 下蒸馏比从头训练高 7.4 分。这个消融排除了“纯靠 token 量”的解释，但它只在 2B 规模、500B token 上做了一次；9B 规模、8T token 下的蒸馏与从头训练对照，报告没有给。

第二种替代解释：9B 的成绩里有一部分是教师能力的直接转移，而不是学生自己学会了什么。蒸馏是把教师的分布灌进学生，学生可能只是在拟合教师的输出风格与偏好，而不是获得了更强的通用能力。能区分的证据是换教师消融：同一个学生、不同教师，看学生成绩差多少；以及测学生在教师没见过的任务上的表现。报告没有做这两项。

第三种替代解释：Chatbot Arena 的 Elo 领先部分来自指令微调的风格，而不是预训练模型的能力。Arena 的评分员在盲测里选“更喜欢”的回答，回答风格（长度、格式、语气）会系统性地影响偏好。Gemma 2 的后训练刻意优化了多轮对话与指令遵循，风格上的优势可能被 Arena 放大。能区分的证据是把预训练模型（不做指令微调）也送进 Arena，或者在 Arena 之外用风格中性的自动化基准复测。

### 接下来看什么

最值得先做的决定性实验是点名教师并做教师消融：用同一个 9B 学生，分别以 27B 与一个更弱的模型（例如 9B 自身或一个公开的小模型）为教师蒸馏，其他条件完全相同。判据是：如果换弱教师后学生的 MMLU 与 GSM8K 大幅下跌，蒸馏的增益主要来自教师，配方的可复制性要降级；如果成绩基本不变，蒸馏方法本身的价值成立。这个实验便宜：不需要重新设计，只需要换教师重跑一次蒸馏。

其次值得看的是三件事：Google 是否公开蒸馏教师的身份与数据混合比例（如果始终不公开，这份报告的配方就永远只能当参考读，没法完整复现）；2.6B 模型发布后的实测表现（博客预告了它，但本文件讨论的版本里还没有它）；以及是否有独立第三方在作者自己的 harness 下重跑 Llama 3 8B，核对 9B 领先幅度的口径问题。

未解的问题有几个：教师模型是谁，2B 的教师与 9B 的教师是不是同一个；蒸馏的增益里有多少来自教师分布的信息量、有多少来自正则化效应；9B 规模下蒸馏与从头训练的直接对照（表 6 只在 2B 上做了一次）；毒性指标变差的原因（RealToxicity 与 Toxigen 的 2B 数字明显变差，报告没有讨论）；以及自动化基准的误差棒——没有重复运行，几个百分点的差距到底有多少是噪声。

## 七、结论、结果与价值总览

### 一句话结论

Gemma 2 是一份配方型模型报告：蒸馏加超长训练让 9B 小模型在公开基准与人类偏好上逼平甚至超过数倍于己的模型，但教师身份未披露、部分基线口径不完全对等，结论的含金量集中在消融实验证明的“蒸馏有效”这一条上。

### 核心结论

1. 蒸馏对小模型确实有效：同样 500B token 下，2B 模型蒸馏比从头训练高 7.4 分（三个基准平均），困惑度增益随学生规模保持。置信度：高。证据：表 6 与表 7 的对照数字。
2. 9B 是越级最明显的尺寸：MMLU 71.3% 对 Llama 3 8B 的 66.6%，GSM8K 68.6% 对 45.7%，Chatbot Arena Elo 1187 与 GPT-4-0314 的 1186 打平。置信度：中高。证据：表 13 与表 14；但部分基线不是同 harness 下跑的。
3. 27B 在同尺寸里最好，离 Llama 3 70B 只差几个百分点，Arena Elo 1218 超过后者的 1206，两个置信区间不重叠。置信度：中。证据：表 12 与表 14；但作者自己承认很可能处在同一条帕累托曲线上。
4. 指令微调后的模型在人类评估里全面好于上一代：指令遵循 37.7% 对 24.3%，多轮满意度 4.20 对 3.32，安全胜率对 GPT-4o 为 55%。置信度：中。证据：表 15 与表 16；但指令遵循的绝对水平仍然很低（约 38%）。
5. 安全与危险能力评估没有拉响警报，但画面是混合的：偏见类指标改善，毒性类指标变差；进攻性网络安全能力明显上涨（InterCode-CTF 45% 对 CodeGemma 的 16%），但自我复制与说服人相信错误答案的能力仍然很低。置信度：中。证据：表 18 至表 25；保证评估的违规率没有给数字。
6. 这份报告没有提出新架构或新算法，用的全是已知技术；它的贡献是一个配方，以及证明这个配方的对照实验。置信度：高。证据：全文的架构与方法描述。

### 科学价值总评

认知价值中等偏高：它给 Chinchilla 的计算最优量加了一个目标依赖的限定条件——换用蒸馏，小模型可以在远超最优量的 token 数上继续获益；但它没有改变规模与能力关系的基本形状，作者自己承认 27B 与 Llama 3 在同一条帕累托曲线上。方法价值较高：蒸馏加超长训练的配方、局部–全局注意力交错与 logit 软上限的验证、格式鲁棒性这个评估维度，都可以直接复用。边界价值较好：报告老实承认了帕累托曲线的保留、保证评估缺数字、记忆化定义窄，读者不容易被带偏到“9B 全面超过 GPT-4”的误读。启示价值中等偏高：最便宜的决定性实验是点名教师并做教师消融，检验蒸馏的增益有多少来自教师、有多少来自方法本身。

总体上，这篇工作值得因为它的消融实验与配方被记住，而不是因为它发布了三个新模型。它是一份好的配方报告——证据最硬的部分是第 5 节的对照实验，最软的部分是教师身份与基线口径。

### 适用边界

这份报告不证明蒸馏在所有尺寸与数据分布下都有效（消融只在 2B 上做了一次完整对照），不证明 9B 在所有任务上都追平 GPT-4（Arena 上只是打平，且区间重叠；自动化基准上 9B 与 GPT-4 没有直接比较），不证明 Gemma 2 全面更安全（毒性指标变差了），不证明博客里“单台 H100 就能跑”的部署说法有实测支撑（报告里没有延迟与吞吐数字），也不证明 2B 模型的成绩属于 2024-06-27 发布日的状态（2B 是 7 月 31 日才发布的）。拿它为“小模型已经追上大模型”背书，是对报告的误读；它证明的是“小模型在蒸馏的帮助下可以大幅缩小差距”。
