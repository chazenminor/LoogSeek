## 一、背景与问题

### 报告之前是什么局面

大语言模型（large language model，LLM）越来越能写文章、做总结、编代码，但它有一个老毛病：会一本正经地说错数字。问它某个国家的失业率、某个县的糖尿病发病率，它可能给出一个看起来合理、实际却不存在的数字——这就是所谓“幻觉”（hallucination）。论文开篇点明，幻觉的原因一部分在于模型生成的概率本质，另一部分在于训练数据里本来就没有足够的事实覆盖。

这个问题对统计数字尤其严重。统计问题常常不是“查一个数”那么简单：它可能涉及逻辑、算术与比较，例如“世界上二氧化碳排放前五的国家是哪些？”“加州是世界上最大的经济体吗？”——后一个问题里，被比较的对象（加州与各国，而不是与美国各州）只在问题里隐含着。还有一个问题是，公共统计数据散落在各种格式与口径里，解读它们需要大量背景知识。

### 这篇论文要回答的问题

论文标题就把问题说清楚了：《Knowing When to Ask》——知道什么时候该问。作者把“把大语言模型接到外部数据上”这件事拆成三个要解决的问题：第一，模型要学会什么时候该问外部数据源、而不是依赖自己参数里存的知识，而且“什么时候问、问什么”要编码进模型的参数里；第二，问哪个数据源——数据源可能很多而且一直在变，这部分知识最好放在模型外面；第三，模型要会生成查询，从数据源里把数据取回来，而且最好不用针对每个数据源学一套不同的接口，要有一个“通用接口”。

这篇论文的答案是：只接一个数据源——Data Commons，Google 的公开统计数据知识图谱；用自然语言本身作为通用查询接口。模型不需要知道 Data Commons 的变量编号，只需要用自然语言说出它想要什么统计量，后面的管线再把自然语言查询转成结构化查询。

这个问题为什么重要，分两个层面。对认知层面，它检验一个基本判断：幻觉能不能靠“接上可信的外部数据”来治，还是说模型编造数字的毛病根植于生成方式本身，接数据也只能治标。对实践层面，它决定大语言模型能不能被用在真正需要数字准确的场合——做研究、做决策、满足好奇心——而不需要用户逐个数去核对。

为什么之前做不了，卡住的点有两个。第一，统计数据的特殊性：一般的检索增强生成（retrieval-augmented generation，RAG）是去文本语料里找相关段落，但统计问题要的是精确的数字、表格与比较，文本检索那一套不直接适用。第二，模型不知道自己什么时候不知道——“知道何时提问”本身就需要教，而教它需要构造训练数据：得让模型在生成统计数字的同时，学会生成一句能查到这个数字的自然语言查询。

## 二、方法与设计

### Data Commons：接什么数据

Data Commons 是 Google 的开源项目，目标是把全世界的公开数据集组织起来，让人人都能访问和使用。它汇集了联合国（United Nations，UN）、世界卫生组织（World Health Organization，WHO）、美国疾病控制与预防中心（Centers for Disease Control and Prevention，CDC）、各国人口普查机构等数百个来源的统计数据。

论文给出的规模是：超过 2,500 亿个数据点、超过 2.5 万亿条三元组（triples）。博客给出的说法略有不同，是“超过 2,400 亿个数据点”——两者都是约数，差了一个版本的口径，见数字台账。

Data Commons 有两个关键设计。第一，多年来团队一直在收集公开数据集、追查数据背后的假设，并用 Schema.org 这套开放词汇把它们归一化成一张统一的知识图谱。第二，用大语言模型做了一个自然语言接口：用户用日常语言提问，接口把问题翻译成 Data Commons 的词汇，返回图表。论文强调，这个接口里的语言模型只负责翻译问题，不修改底层数据，也不生成答案，所以本身不会产生幻觉。

但覆盖并不均匀。论文坦承：在美国，Data Commons 在国家层面有超过 18 万个统计变量，在县层面有超过 10 万个；到了经合组织（OECD）国家，变量数急剧下降；世界其他地区更少；美国之外州与区一级的细粒度数据也很稀缺。这个覆盖不均，是后面评估里覆盖率低的直接原因。

### 两条路线：RIG 与 RAG

论文探索了两种把大语言模型接到 Data Commons 上的方法，图 1 把它们与基线并列比较：基线直接报数字、不给证据；RIG 在生成过程中插检索；RAG 在生成之前先检索。

**第一条路线是检索交错生成（Retrieval-Interleaved Generation，RIG）。** 思路借自 Toolformer：把模型微调成在生成答案的同时，对每一个统计数字生成一句自然语言查询，问 Data Commons 要这个数。管线分三段：微调过的模型生成带自然语言查询的回答；一个后处理模块把自然语言查询转成结构化查询；再去 Data Commons 数据库里取回答案。最终呈现给用户的是并排的两个数字：模型自己生成的数（LLM-SV），和 Data Commons 返回的数（DC-SV），附带来源信息。用户可以自己对照，看模型有没有编造。

为什么用自然语言查询、而不是让模型直接生成 SQL 之类的结构化查询，论文给了三个理由：自然语言查询通常更简短，答案里有多个数字时这点很重要；Data Commons 有数百万个变量与关系，让模型记住全部变量编号的代价太高，还可能损害其他能力；用自然语言表达查询本身就是个更容易的任务，主要是从上下文里复述实体与关系。

RIG 的微调数据很小。团队先写了大约 700 条用户问题，从中挑出基础模型的回答里带统计数字的约 400 条，再用 Gemini 1.5 Pro（加三条少样本示例做提示）给这些回答里的统计数字加上 Data Commons 查询标注，人工检查并改写不符合要求的标注。附录 A 公开了提示词与三条人工改写示例。

查询转换是另一段手工搭起来的管线：先把自然语言查询拆成统计变量、地点与若干属性（如排名、比较、变化率）；变量用基于嵌入（embeddings）的语义搜索索引匹配，地点用基于字符串的命名实体识别，属性用一组基于正则表达式的启发式规则。再按拆出的成分把查询归入一组固定模板（例如“XX 地有多少 YY”“XX 与 YY 在 ZZ 上的相关性”），最后由“履行”（fulfillment）逻辑把模板与编号翻译成 Data Commons 结构化数据接口的调用。返回的通常就是一个带单位的数字，例如“37.5 岁”。

**第二条路线是检索增强生成（Retrieval-Augmented Generation，RAG）。** 思路更传统：先用一个微调过的小模型，把用户问题拆成若干条更细粒度的 Data Commons 自然语言查询；拿这些查询去 Data Commons 自然语言接口取回相关表格；再把原始问题加序列化后的表格一起喂给一个长上下文模型（Gemini 1.5 Pro），由它写出最终答案，答案里可以引用表格里的数字。

RAG 的关键约束是输入长度。比较类问题可能涉及全美 50 个州或全球 194 个国家、多年的数据，表格序列化后非常长。论文在合成查询集上测得，平均输入长度是 38,000 个 token，最长达到 348,000 个 token——所以必须用长上下文模型，Gemini 1.5 Pro 的 200 万 token 上下文在这里是必需品，不是装饰。

RAG 的微调数据同样很小：用 Gemini 1.5 Pro 按附录 B 的提示词，从用户问题生成 Data Commons 查询，人工检查并改写一部分，得到 635 条指令微调样本。团队还试过另一种做法——把 Data Commons 的全部变量列表放进提示词里，只生成真实存在的变量——但效果差得多：要么相关变量太少，要么问题指向的高层话题匹配到太多变量、模型不会挑。所以正式评估用的是第一种做法，另一种留作未来工作。

### 评估设计：101 条手写问题

评估集是团队手工写的 101 条问题。其中 96 条是范围内问题（与公开或社会统计相关），分五类：具体变量问题（例如“美国有多少户家庭里有 65 岁以上的人？”）、宽泛话题问题（“给我一些关于加州 Kern 县的农业统计”）、地点比较（“比较剑桥与帕洛阿尔托的人口、教育与经济统计”）、变量比较（“煤炭发电多的州，慢性阻塞性肺病发病率也高吗？”）、列表问题（“哪些州癌症发病率最高？”）。其中还有 22 条明显更复杂的问题，包括复杂列表问题、开放式“有趣趋势”问题、同类地点（peer group）问题与层层追问（drill-down）问题。另外 5 条是范围外问题（例如“写一段 Python 排序代码”“写一首关于数据的俳句”），用来确认微调没有让模型在非统计问题上退化。

为避免训练集与测试集重叠，团队用人工检查加语义相似度检查排除了明显的重合。评估分四项：事实准确性（RIG 量四个比例：Data Commons 返回值正确、模型原值正确、两者都正确、两者都错；RAG 量回答里统计主张准确的比例）、Data Commons 自然语言准确性（查询是否正确理解了原问题）、问题准确性（生成的查询是否与句子的上下文或原问题相关）、Data Commons 数据覆盖（多少查询因为缺数据而失败）。

评估本身是人工做的。RIG 的评估用了团队自研的可视化工具，对接一个电子表格，评估员先快速检查有没有明显事实错误，再逐个统计数字打分。评估员熟悉 Data Commons，很多人参与过数据导入工作，能查 census.gov 这类统计机构网站验证，他们不是论文作者。RAG 的评估分两阶段：先评细粒度问题的质量与 Data Commons 返回的表格，再评最终答案，数出答案里引用的数字（“统计主张”）与基于这些数字做的推断（“推断主张”，例如“比……更大”）各自的准确性。

论文在评估一节开头就主动承认了局限：评估集是手工写的，只有 101 条；其中只有一部分成功从 Data Commons 拿到了结果；多数评估由写论文的团队自己做，这可能影响结果的稳健性与可推广性。

## 三、主要发现

### RIG：模型自己报的数字大多是错的，查回来的数字六成是对的

RIG 的核心结果在表 2。评估用的是微调过的 7B 模型与 27B 模型（基线是未微调的 Gemma 7B IT 与 Gemma 2 27B IT）。在 101 条问题里，模型回答中出现的统计数字、且 Data Commons 成功返回了可对照数值的，7B 有 366 个，27B 有 114 个——27B 的数字少，是因为 27B 基础模型本身就不太爱在回答里放统计数字。

结果是：Data Commons 返回的统计值正确的比例，7B 是 57.7%，27B 是 58.8%；模型自己生成的原始值正确的比例，7B 只有 4.9%，27B 是 16.7%；两者都正确的比例，7B 是 2.2%，27B 是 9.7%；两者都错的比例，7B 是 32.5%，27B 是 27.2%。论文的总结是：RIG 把事实性从 5%–17% 提升到了约 58%。

但这个“提升”要拆开看。58% 的意思是：在 Data Commons 成功返回数值的那部分统计里，约六成是正确的。剩下的三成左右（两者都错）论文在表 3 里归了因：Data Commons 自然语言接口返回了不太相关的答案（7B 占 26.5%，27B 占 21.1%），原因是缺最接近的数据；模型生成的问题本身没抓住统计数字的意思（7B 占 7.1%，27B 占 7.0%）。

更值得注意的是覆盖率。表 4 显示，在全部统计查询里，只有约 23%–24% 能从 Data Commons 拿到回答，约 75% 拿不到。拿不到的主要原因是 Data Commons 根本没有相关数据集（7B 占 30.0%，27B 占 36.6%，分母是全部 Data Commons 调用次数，7B 为 793 次，27B 为 407 次）；其次是 Data Commons 自然语言理解的问题（7B 占 5.9%，27B 占 18.9%）；其余是范围外问题（约 5%）。也就是说，RIG 的事实核查只在四分之一的场合能派上用场，其他四分之三里模型照样在凭空报数，只是没有对照值。

### RAG：引用的数字几乎全对，但推断常常出错，覆盖同样只有四分之一

RAG 的结果在表 5。评估用的是微调过的 Gemma 2 9B IT 与 27B IT 生成细粒度问题、Gemini 1.5 Pro 写最终答案。回答里引用的统计主张准确的比例非常高：9B 是 98.6%（210 条主张），27B 是 98.9%（190 条）。但基于这些数字做的推断就没那么稳：推断主张准确的比例，9B 是 71.9%（82 条），27B 是 76.4%（123 条）；推断错误的比例，9B 是 6.1%，27B 是 19.5%；没有数据支撑的推断，9B 是 22.0%，27B 是 4.1%。论文举的例子是：漏掉一个本该进前五的国家，或者从“中位年龄 35 岁”推断出“有很多年轻专业人士与家庭”——后者数据没说错，推断本身站不住。

RAG 的覆盖率与 RIG 同样低：只有 24%–29% 的问题最终用上了 Data Commons 的统计数据。表 6 拆了没覆盖的原因（分母是没覆盖到的问题数，9B 为 77 条，27B 为 72 条）：微调模型生成的问题不完整或不正确（9B 占 40.3%，27B 占 30.6%）；Data Commons 没有相关数据集（37.5% / 43.1%）；Data Commons 自然语言理解问题（2.8% / 6.9%）；表格取回来了但回答模型没用上（11.1% / 8.3%）；范围外问题（8.3% / 11.1%）。

表 7 把 RAG 与 Gemini 1.5 Pro 基线在全部 101 条问题上做了对比。带统计主张的问题比例：RAG 是 24%（9B）与 29%（27B），基线只有 9%；统计主张的总数：210 与 190 条，对基线 28 条；统计主张的准确率：98.6% 与 98.9%，对基线 39%。也就是说，给了真实数据，模型更愿意报具体数字，而且报的数字几乎全对；不给数据，基线模型只在 9% 的问题里报数字，而且报的数字里只有 39% 是对的。

### 用户更喜欢带数据的答案，但只在数据真的被用上时

除了准确性，团队还做了一个“宏评估”（macro eval）：让不了解 Data Commons 的人工评分员并排比较两个答案，选更喜欢的。RIG 的答案被偏好的比例是 62%（7B，101 个样本）与 76%（27B）。论文自己指出，这个偏好可能有两个来源：微调让模型更爱生成统计数字，而评分员本身就偏好带数字的回答。27B 的偏好更高，论文的解释是 27B 基础模型本来就不太爱生成统计数字，而微调后的 7B 更容易在回答里幻觉。

RAG 的偏好结果更醒目：在最终答案确实引用了 Data Commons 表格的样本里，评分员偏好 RAG 答案的比例是 92%（9B，24 个样本）与 100%（27B，29 个样本）。但要注意分母很小——只有 24 与 29 个样本真正用上了数据。这两个数字说的是“数据一旦用上，用户很喜欢”，而不是“RAG 在大多数问题上都更好”。

## 四、作者的结论与局限

### 作者怎么总结

论文没有单独的“结论”一节，收尾在“未来工作”之前。摘要的说法是：这项工作是“朝着构建更可信、更可靠的大语言模型迈出的早期一步”，模型能扎根于可验证的统计数据、做复杂的事实推理。博客的说法更积极一些，称初步结果“令人鼓舞”，在处理数字事实时准确性有“显著提升”，用户会在研究、决策或满足好奇心的场景里遇到更少的幻觉。

未来工作的清单很具体：把微调训练集从目前最多约 600 条扩大到十万甚至百万量级；改进 Data Commons 的自然语言处理能力；评估 Gemini 在统计信息上的表现；测试不同的用户界面与呈现方式。作者还说，最终目标是把这套能力整合进 Gemma 与 Gemini，先以分阶段、有限访问的方式推进。

### 作者自己承认的局限

论文在评估一节开头明确承认：评估集只有 101 条手工问题；其中只有一部分成功从 Data Commons 拿到结果；多数评估由写论文的团队自己完成，可能影响稳健性与可推广性。

论文结尾的免责声明也很直白：发布的是早期版本的模型，只供可信测试者使用，主要面向学术与研究用途，尚未准备好商用或面向公众。这个版本只在很小的样本语料上训练，可能出现非预期的、有时甚至是有争议或煽动性的行为。已知局限在评审指南（reviewer guide）里有详细说明，论文建议读者去查那份指南——但本次精读没有核实那份指南的内容。

负责 AI（Responsible AI）一节提到：团队在发布前对 Data Commons 自然语言接口做过红队测试，用了一组可能产生误导、争议或煽动性结果的危险问题；同样的查询也跑过 RIG 与 RAG 模型的输出，发现了少数回答有争议、但不危险的例子。

博客对局限只字未提，只说研究还在继续，会扩大规模、严格测试、最终整合进 Gemma 与 Gemini。读者如果只读博客，会以为 DataGemma 已经是一个可用的“防幻觉”方案；论文里的数字讲的是另一回事。

## 五、精读点评

### 这篇论文到底证明了什么

这篇论文证明的东西很具体，也很有限。它证明的是：在一个很小的、人工手写的问题集上，把模型接到一个真实统计数据库上，确实能让模型报出的数字从“大多是错的”变成“引用的大多是对的”。RAG 的统计主张准确率 98.6%–98.9% 是全篇最亮的数字，RIG 把事实性从 5%–17% 提升到约 58% 是另一个。

但这两个数字的成立条件要讲清楚。RAG 的 98.9% 是在“模型确实引用了表格里的数字”这个子集上量的，分母只有 190 条主张；一旦模型开始基于这些数字做推断，准确率就掉到 72%–76%。RIG 的 58% 是在“Data Commons 成功返回数值”的子集上量的，分母是 366 与 114 个统计值；在这个子集之外，还有四分之三的查询根本拿不到对照值。换句话说，这篇论文证明的是“接上真实数据后，被接住的那部分确实变准了”，没有证明“大多数问题都能被接住”。

### 科学问题还原：这件事为什么值得问

反常在于，模型在回答统计问题时不是“不知道”，而是“不知道自己不知道”——它会自信地编一个数字，而不是说查不到。更反常的是，这个毛病在数字上最严重：文字可以含糊，数字不行，一个错的数字就是一个错的事实。

不解决这个问题，大语言模型就没法进入真正需要数字的场合。对领域来说，它检验的是“幻觉能不能靠外接可信数据来治”这个基本判断；对实践来说，它决定模型能不能被用在研究与决策里，而不是只能用来写草稿、做头脑风暴。

之前做不了的原因，论文自己点得很清楚：一般的检索增强生成是去文本里找段落，统计问题要的是精确的数字与表格，文本检索那套不直接适用；而且模型得先学会“什么时候该问”，这需要构造专门的微调数据，而不是现成的通用办法。这篇论文移走的石头，恰恰是把“问什么、怎么问”做成了一个可训练、可评估的小流程：用自然语言作通用查询接口，用几百条人工标注的例子微调，再用一张 101 条问题的评估集量效果。

方法与问题的匹配点也很清楚。RIG 的微调恰好匹配“知道何时提问”这个子问题——模型在生成统计数字的同时生成一句查询，查询与数字一一对应，核查可以直接并排做。RAG 的长上下文恰好匹配“比较类问题需要整张表”的需求——38,000 个 token 的平均输入、348,000 个 token 的最长输入，没有 200 万 token 的上下文窗口是装不下的。

读完之后，什么信念应该改？第一，“给模型接上检索就能防幻觉”这个信念应该弱化：接上之后，覆盖率只有四分之一，剩下的四分之三里模型照样在编数字。第二，“模型引用的数字对了，答案就对了”这个信念也应该弱化：RAG 的推断主张里有 6%–20% 是错的、4%–22% 是没有数据支撑的，数字对了不等于推理对了。什么信念不该改？“幻觉是个真问题”仍然成立——基线模型自己报的数字，7B 只有 4.9% 正确，27B 也只有 16.7%，这个数字本身就是幻觉问题严重程度的一个注脚。

### 最弱的一环与主要质疑

最弱的一环是评估的规模与评估者。101 条手工问题、多数评估由论文作者团队自己完成、RAG 偏好评估的分母只有 24 与 29 个样本——这些数字的统计分量都很薄。论文自己承认了这一点，但承认不等于解决：一个 101 条问题的评估集，换一批问题、换一批评估员，结果很可能不一样。特别是 RIG 的 27B 分母只有 114 个统计值，58.8% 这个数字上下浮动几个百分点都不奇怪。

第二个质疑是覆盖率的瓶颈到底在哪。RIG 与 RAG 的覆盖率都在四分之一左右，但原因的构成不一样：RIG 里最大的原因是 Data Commons 缺数据集（30%–37%），RAG 里最大的原因是微调模型生成的问题不完整或不正确（31%–40%）。这说明两条路线的短板不同——RIG 卡在数据覆盖，RAG 卡在问题生成。论文把“扩大 Data Commons 覆盖”与“扩大微调数据集”都列为未来工作，但没有说清哪一个更值得先做，也没有给出覆盖率随数据规模变化的曲线。

第三个质疑是 RIG 的 58% 与 RAG 的 98.9% 其实不可比。RIG 的分母是“Data Commons 成功返回数值的统计”，RAG 的分母是“模型在答案里引用的统计主张”。RIG 是在核查模型已经生成的数字，RAG 是在生成之前先给数据。两个数字量的是不同的东西，博客把它们并列成“两种方法都有效”，容易让人误以为两者效果相当。实际上 RAG 的 98.9% 是在数据已经摆在模型面前的条件下量的，RIG 的 58% 是在模型先编、再核查的条件下量的。

第四，论文没有报告任何微调细节：没有超参数、没有训练步数、没有算力、没有随机种子。微调数据只有约 400 条（RIG）与 635 条（RAG），这么小的训练集，换一个随机种子、换一批标注，结果会不会大变，论文里没有答案。一个能干的读者可以按论文的描述重走流程，但复现出同样的数字没有保证。

第五，博客的呈现方式本身值得警惕。它不给任何评估数字，只说“初步结果令人鼓舞”“准确性显著提升”。读者如果只读博客，会以为 DataGemma 已经解决了统计幻觉。实际上论文的数字是：四分之三的问题拿不到对照值，RAG 的推断有两成左右是错的或没支撑的。这不是造假，而是选择性呈现：博客是发布窗口，不是科学报告。精读时必须以论文为准，博客为准会严重高估。

### 科学价值总评（四维）

认知价值：确认了“把模型接到真实统计数据库上能让被接住的那部分数字变准”这个基本判断，RAG 的 98.6%–98.9% 与 RIG 的 5%–17% 到约 58% 都是这个判断的证据。但“接上数据就能防幻觉”这个更强的判断没有被确认——覆盖率只有四分之一，推断的准确率也只有七成多。

方法价值：留下了可复用的东西。RIG 的“微调模型生成自然语言查询、再转结构化查询、并排呈现两个数字”的流程，RAG 的“微调小模型拆问题、取表格、长上下文模型写答案”的流程，以及两套人工评估工具的设计，都是别人能直接拿走的。模型权重与客户端库也都开源了（Hugging Face 上的 datagemma-rig-27b-it 与 datagemma-rag-27b-it，Apache 2.0 协议的 llm-tools 库）。这篇论文不是“一组数字”，而是一套可跑的流程。

边界价值：这篇论文不证明统计幻觉已被解决。它只在 101 条手工问题、美国与全球公开统计数据、Data Commons 已有覆盖的范围内成立；不证明在 Data Commons 没有的数据上、在需要复杂推理的问题上、在更大规模的真实用户问题上同样有效。最容易误读的推论是“DataGemma 让模型不再幻觉”——论文的数字不支持，免责声明也明确说模型还可能出现非预期的行为。

启示价值：最便宜的决定性下一步，是把评估集从 101 条扩大到上千条、并且由与论文团队无关的评估员重评一次，判据是 RIG 的 58% 与 RAG 的 98.9% 在新评估集上是否还站得住。如果数字大幅下滑，说明当前结果是评估集与评估者带来的乐观偏差；如果站得住，再谈扩大数据覆盖。这个实验比“再加一个模型尺寸”更值得先做，因为它直接回答当前数字的可信度。

### 效度判断

内部效度中等。RIG 与 RAG 各自的对照是明确的（微调模型对未微调基线），评估流程是人工逐条打分，指标定义清晰。但评估者多数是论文团队自己人，评估集只有 101 条，且没有报告任何统计不确定性（没有误差棒、置信区间或显著性检验），结果的稳健性说不清。

外部效度低。结果只在 101 条手工问题、Data Commons 已有覆盖的数据范围、以及 Gemma 2 与 Gemini 1.5 Pro 这两个模型家族上成立。没有证据表明方法能推广到 Data Commons 没有的数据、更复杂的推理问题，或真实用户的自然提问。

构念效度中等。“统计主张准确率”作为指标本身没有问题，什么算“准确”、什么算“推断”在论文里定义明确。但“事实性”（factuality）这个构念没有被完整操作化——论文量的是“数字对不对”，没有量“答案整体是否误导”，而一个数字全对、推断全错的答案，照样可以误导人。

统计结论效度低。数字本身是精确的（比例与分母都给了），但没有任何不确定性估计；RIG 的 27B 分母只有 114 个统计值，RAG 偏好评估的分母只有 24 与 29 个样本，几个百分点的波动就能改变结论。论文没有做任何显著性检验，也没有报告评估员之间的一致性。

可复现性中等偏低。方法流程、提示词、训练集规模与评估标准都写得相当完整，模型权重与代码也开源了；但微调的超参数、训练步数、算力与随机种子都没有报告，评估工具本身没有开源。一个能干的读者可以重走流程，但复现出同样的数字没有保证。

总体判断：这是一次诚实的、范围很小的早期探索，不是一次夸大的突破。论文主动承认了评估的局限，数字本身没有水分，方法流程也完整开源；但博客的呈现方式会让人高估成果，覆盖率低与评估规模小是两个硬伤。置信度中等：核心结论（接上真实数据后，被接住的那部分数字确实变准了）可信，推广结论（统计幻觉已被解决）不可信。

## 六、证伪器、替代解释、接下来看什么

### 证伪器

针对“RIG 把事实性从 5%–17% 提升到约 58%”：如果换一批新的、与训练集无重叠的评估问题，Data Commons 返回值正确的比例跌回 30% 以下，那么“RIG 有效”的结论即被削弱，当前数字可能只是评估集带来的乐观偏差。

针对“RAG 的统计主张准确率 98.6%–98.9%”：如果把最终答案模型从 Gemini 1.5 Pro 换成一个普通上下文窗口的模型（装不下整张表），统计主张准确率大幅下滑，那么高准确率的关键可能只是“长上下文装得下表格”，而不是 RAG 流程本身。

针对“用户偏好 RAG 答案（92%–100%）”：如果让评分员在不知道哪个答案带数据的情况下、只按“答案是否正确”打分，偏好消失或反转，那么当前的偏好可能只是“评分员喜欢带数字的答案”，而不是“RAG 的答案更好”。

针对“Data Commons 覆盖不足是主要瓶颈”：如果把 Data Commons 的数据集扩大一倍，RIG 的覆盖率仍然停留在约 25%，那么瓶颈可能不在数据覆盖，而在自然语言理解或问题生成。

### 替代解释

替代解释一：RAG 的高准确率主要来自 Gemini 1.5 Pro 本身，而不是 RAG 流程。Gemini 1.5 Pro 是一个很强的模型，给它一张正确的表格，它本来就能照着表格写出正确的数字。区分方法：把同样的表格喂给 Gemini 1.5 Pro 的基线（不经过 RAG 的问题拆分步骤），看统计主张准确率是否同样接近 99%；论文的表 7 对比的是“不给表格的基线”，没有做“给表格但不走 RAG 流程”的对照。

替代解释二：RIG 的 58% 主要反映的是 Data Commons 自然语言接口的质量，而不是微调模型的质量。表 3 显示，不准确的最大来源是接口返回了不太相关的答案（21%–27%），而不是模型的问题写错了（7%）。如果接口本身更准，RIG 的数字可能直接上升；反过来，如果接口不准，再好的微调也没用。区分方法：用人工写好的标准查询代替模型生成的查询，看 Data Commons 返回值正确的比例是否同样是约 58%；论文没有做这个对照。

替代解释三：评估集的选择本身偏向了方法。101 条问题是团队手工写的，写问题的人就是做这个系统的人，他们自然会写 Data Commons 能答的问题。换一批真实用户的自然提问——口语化、模糊、跨多个话题——覆盖率与准确率可能都大幅下降。区分方法：用真实用户日志里的问题重做评估；目前没有这样的评估。

### 作者自述局限与分析者发现的局限

作者自述的局限：评估集只有 101 条手工问题；只有一部分成功从 Data Commons 拿到结果；多数评估由写论文的团队自己完成；模型是早期版本，只供可信测试者使用，训练语料很小，可能出现非预期行为；已知局限在评审指南里，论文建议读者去查。

分析者发现的、作者没说的局限：博客不给任何评估数字，选择性呈现会让人高估；RIG 与 RAG 的两个 headline 数字（58% 与 98.9%）分母不同、不可直接比较；微调的超参数、训练步数、算力与随机种子都没有报告；评估没有误差棒、置信区间、显著性检验与评估员一致性；RAG 的偏好评估分母只有 24 与 29 个样本；没有“给表格但不走 RAG 流程”的对照，RAG 的贡献有多少来自流程本身、多少来自 Gemini 1.5 Pro，说不清。

### 接下来看什么

排第一的是启示价值里提到的决定性实验：把评估集从 101 条扩大到上千条、由与论文团队无关的评估员重评一次，判据是 RIG 的 58% 与 RAG 的 98.9% 在新评估集上是否还站得住。如果数字大幅下滑，说明当前结果是评估集与评估者带来的乐观偏差；如果站得住，再谈扩大数据覆盖。

其次值得看的是：RAG 的“给表格但不走 RAG 流程”对照（定位 98.9% 的功劳在流程还是在 Gemini 1.5 Pro）；RIG 的“人工标准查询”对照（定位 58% 的瓶颈在接口还是在微调模型）；以及 Data Commons 覆盖扩大后，RIG 与 RAG 的覆盖率是否随之上升——这直接回答“缺数据”是不是真瓶颈。

### 未解问题

RIG 微调的超参数、训练步数、算力与随机种子是什么？论文没有报告，复现同样的数字没有保证。

RAG 的最终答案模型如果换成 Gemma 2 27B（而不是 Gemini 1.5 Pro），统计主张准确率会掉多少？论文没有做这个对照，RAG 流程本身的贡献说不清。

Data Commons 自然语言接口的准确率本身是多少？论文在表 3 与表 4 里给了它作为失败原因的占比，但没有单独报告接口的端到端准确率。

评估员之间的一致性如何？RIG 与 RAG 的评估都是人工打分，论文没有报告评估员一致性（例如 Cohen's kappa），打分的稳健性说不清。

评审指南（reviewer guide）里列的已知局限具体是什么？论文的免责声明指向了这份指南，但本次精读没有核实它的内容。

## §I 收尾：结论、结果与价值总览

**一句话结论：** Google 用 DataGemma 证明，把 Gemma 接上 Data Commons 的真实统计数据后，被接住的那部分数字确实变准了——RAG 引用的统计主张 98.6%–98.9% 准确，RIG 把事实性从 5%–17% 提升到约 58%——但这只是一次小规模的早期探索：覆盖率只有四分之一左右，评估只有 101 条手工问题，离“模型不再编造数字”还差得很远。

**核心结论：**

1. 模型自己报的统计数字大多是错的：RIG 评估里，7B 模型原值正确的比例只有 4.9%，27B 也只有 16.7%。置信度高，证据为数字台账 E7。
2. RIG 把事实性从 5%–17% 提升到约 58%，但只在 Data Commons 成功返回数值的子集上成立，且约三成统计是两者都错。置信度高，证据为数字台账 E7、E9。
3. RAG 引用的统计主张 98.6%–98.9% 准确，远高于 Gemini 1.5 Pro 基线的 39%，但推断主张只有 72%–76% 准确。置信度高，证据为数字台账 E13、E14、E17。
4. 两条路线的覆盖率都只有四分之一左右：RIG 约 23%–24% 的查询能拿到对照值，RAG 只有 24%–29% 的问题用上了统计数据。置信度高，证据为数字台账 E11、E15。
5. 评估本身很薄：101 条手工问题，多数评估由论文团队自己完成，没有误差棒、置信区间或显著性检验。置信度中等，证据为方法与设计、主要发现两节的描述。

**关键结果表：** 见数字台账 E7、E9、E13–E15 与 E17。决定性的结果是：RIG 的 Data Commons 返回值正确率 57.7%（366 个统计，7B）与 58.8%（114 个统计，27B），两者都错 32.5% 与 27.2%；RAG 的统计主张准确率 98.6%（210 条主张，9B）与 98.9%（190 条主张，27B），推断主张准确率 71.9% 与 76.4%；RAG 对基线的全面对比是 24% / 29% 对 9%（带统计主张的问题比例）、210 / 190 对 28 条（统计主张总数）、98.6% / 98.9% 对 39%（准确率）。

**科学价值总评：** 认知价值——确认了“接上真实统计数据库能让被接住的那部分数字变准”，但“接上数据就能防幻觉”没有被确认，覆盖率与推断准确率都不支持。方法价值——留下了可复用的两套流程（RIG 的微调加并排核查、RAG 的拆问题加取表格加长上下文作答）与开源的模型权重和客户端库。边界价值——不证明统计幻觉已被解决，不证明在 Data Commons 没有的数据、更复杂的推理问题或真实用户提问上同样有效，最容易误读的推论是“DataGemma 让模型不再幻觉”。启示价值——最值得先做的下一步是把评估集扩大到上千条、由无关评估员重评一次，看 58% 与 98.9% 是否还站得住。总体 verdict：这是一次诚实的早期探索，值得因为“把幻觉问题落到可量的数字上、方法流程完整开源”被记住，不值得因为“世界首个防幻觉开放模型”这种标题式印象被记住。

**适用边界：** 不要拿这篇博客或论文为“统计幻觉已被解决”背书，也不要拿它为“接上检索就能防幻觉”背书。RIG 的结论只对 101 条手工问题、在 Data Commons 成功返回数值的子集上成立；RAG 的结论只对引用了表格的统计主张成立，推断主张的准确率只有七成多。任何超出这两个范围的推广，都需要新的证据。
