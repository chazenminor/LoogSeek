## 一、背景与问题

### 更新之前是什么局面

2024 年 5 月，OpenAI 发布了 Model Spec（模型行为规范）的第一份草案。它第一次把“模型该怎么表现”写成公开文档：三条目标、六条规则、十条默认行为，外加平台高于开发者、开发者高于用户、用户高于工具的指挥链。但那份草案在发布时明确说，它“目前这种形式”还没有被使用过——它是一份待验证、待讨论的提议，不是正在生效的操作手册。

草案发布后的一年里，几件事发生了。第一，规范被真正用起来了：OpenAI 说，更新版的制定依据包括“在各种场景下应用它”的经验，范围从对齐研究到服务全球用户。第二，模型本身变了：带隐藏思维链的推理模型、语音模式（advanced voice mode）进入产品，旧规范里没有对应的规则。第三，用户与开发者给了反馈：更新博客说，初版发布后，许多用户与开发者表示支持设立一个“成人模式”（grown-up mode），希望在合适的场景下生成色情与血腥内容；初版博客也曾点名说，最想收到反馈的原则是“不试图改变任何人的想法”。

所以这次更新要回答的问题，和初版不同。初版问的是：行为标准能不能写下来、公开出来？更新版问的是：用了一年之后，哪些地方要收紧、哪些地方要放开、哪些地方要补上？

### 更新博客自己的说法

更新博客（Sharing the latest Model Spec）把这次更新定性为一次“重大更新”（major update），并给出三个关键词：可定制性（customizability）、透明度（transparency）、知识自由（intellectual freedom）——让人们能用 AI 探索、辩论与创造，而不受任意限制，同时保留护栏以降低真实伤害的风险。

博客把规范的新结构概括为六个主题：指挥链（chain of command）、一起求真（seek the truth together）、做最好的工作（do the best work）、守住边界（stay in bounds）、待人接物（be approachable）、表达风格（use appropriate style）。其中“守住边界”被特别说明：新版本的目标是全面覆盖所有打算让模型拒绝用户或开发者请求的理由。

博客还第一次谈到了测量。OpenAI 说，他们已经收集了一套挑战性提示词，用来测试模型对规范每条原则的遵守程度；初步结果显示，模型对规范的遵守比去年 5 月的最佳系统有“显著改进”，其中大部分改进来自对齐技术的提升，而非政策本身的改动。但博客正文没有给出任何数字（见第六节数字台账与文末未核实清单）。

### 这是一篇什么样的文档

规范文档标题是 Model Spec (2025/02/12)，发布日期 2025 年 2 月 12 日。发布方是 OpenAI，页面上没有列出个人作者。更新博客发表于同一天。

文档类型和初版一样：行为规范加介绍博客，不是同行评审论文，也不是研究报告。它没有摘要，没有方法一节，也没有论文意义上的参考文献列表。规范全文以直接给模型的指令写成，配有大量“合规”（Compliant）与“违规”（Violation）对照示例。

和初版相比，文档的配套形式变了三处。第一，规范以知识共享 CC0 1.0 协议贡献给公共领域，任何人都可以自由使用、改编与再利用。第二，规范源码与评估提示词开源在一个新的 GitHub 仓库（openai/model_spec）里，仓库里还存档了已发布版本的 HTML（从 2025-02-12 这一版开始）。第三，OpenAI 说，今后不再为每次更新都发博客，最新版本统一在 model-spec.openai.com 上跟踪。

分析者是子代理深度精读，分析日期是 2026-11-23。已完成两遍：第一遍通读规范全文、更新博客与仓库主页；第二遍逐节对照初版精读记录（LR-202），逐条核对变化。第三遍（虚拟重实现）不可能，因为这不是一篇实验报告，没有可重实现的方法。

## 二、方法与设计

先说清楚这篇东西的性质。它是一份行为规范的更新版，不是同行评审论文，也不是实验。

按论文意义上的实验设计，它没有假设检验，没有随机化，没有对照组，没有预注册，也没有统计分析。下面按它本来面目来评估它：一份用文字写成的行为标准，附带正反示例，以及一篇介绍它为什么这样改的博客。

### 更新是怎么做成的

博客与规范都没有交代一份系统的“制定方法”。能从文本里还原出来的更新依据有四条：应用初版的经验（从对齐研究到服务全球用户）、初版发布后收到的反馈、约 1,000 人参与的试点研究（pilot studies，每人审阅模型行为与拟议规则并分享想法）、以及对齐研究本身的进展。

博客说，试点研究的早期洞见“直接影响了一些修改”，但没有说明是哪几条修改、试点参与者是谁、如何挑选、结论是什么。试点研究“尚未反映广泛的观点”，博客承认了这一点，但没有给出让它变得广泛的时间表。

规范的用途也从“计划”变成了“进行时”。初版说，OpenAI 打算把规范用作人类反馈强化学习（reinforcement learning from human feedback，RLHF）的指导原则，并探索模型在多大程度上能直接从规范学习。更新版的概述说：“我们正在训练模型，使其对齐到 Model Spec 的原则。”同时补了一句限定：“公开版本的规范可能不包括每个细节，但与我们预期的模型行为完全一致。我们的生产模型尚未完全体现 Model Spec，但我们持续改进与更新系统，使其更接近这些指导原则。”

换句话说，规范从“写出来等讨论”变成了“正在据此训练，但还没完全做到”。这个状态变化，是理解整份更新版的关键。

### 结构总览：从三层到总纲加权限等级加主题节

初版的结构是三层：目标（objectives）、规则（rules）、默认行为（defaults）。更新版把这个结构拆开重组了。

最前面是一份写给人类读者的概述（Overview），包括三条总原则（general principles）与三类具体风险（specific risks）。三条总原则是：最大化对用户的帮助与自由、在安全可行的范围内让用户按自己的需要使用与定制工具；最小化伤害；选择合理的默认值。三类风险是：目标错位（misaligned goals，助手因为误解任务或被第三方误导而追求错误目标）、执行错误（execution errors，理解对了但做错了）、有害指令（harmful instructions，照着用户或开发者的指令做反而造成伤害）。

概述之后是定义（definitions）与指挥链（chain of command），然后是按主题组织的主体部分，一共六大节：守住边界（Stay in bounds）、在风险场景中格外小心（Take extra care in risky situations）、不透露特权指令（Do not reveal privileged instructions）、始终使用预设声音（Always use the preset voice）、维护公平（Uphold fairness）、一起求真（Seek the truth together）、诚实透明（Be honest and transparent）、做最好的工作（Do the best work）、待人接物（Be approachable）、表达风格（Use appropriate style）、适应用户的模态（Adapt to the user's modality）。按抓取文本的小节标题计数，平台级条目 20 条、用户级条目 12 条、开发者级条目 1 条、指南级条目 17 条，其余为不带权限标注的分组标题。

初版的三条目标没有消失，而是被改写进了概述：创造有用、安全、与用户和开发者需求一致的模型，同时推进“确保通用人工智能造福全人类”的使命；为此要做到三件事——迭代部署能赋能开发者与用户的模型、防止模型对用户或他人造成严重伤害、通过保护自身免受法律与声誉伤害来维持运营许可。

### 指挥链：新增一个权限等级，机制大幅细化

这是更新版里最具技术性的改动。初版的指挥链是四级：平台高于开发者，开发者高于用户，用户高于工具。更新版是五级：平台（Platform）、开发者（Developer）、用户（User）、指南（Guideline）、无权限（No Authority）。

新增的指南级是关键。指南级的指令可以被隐含地推翻——也就是说，不用明说，从语境、背景知识或用户历史里就能看出来用户想要别的。例如，用户要求模型“像个逼真的海盗一样说话”，这就隐含地推翻了“避免说脏话”的指南。而用户级的默认指令只能被明确推翻。规范解释了为什么要设默认指令：没有风格指导时，模型不知道该给详细解释还是直接给可运行代码；把答案写成可推翻的指南，既提高了可预测性，又保留了开发者的定制自由。

指挥链的判定机制也被写成了操作步骤。模型要先找出所有“候选指令”（candidate instructions），包括规范里的全部指令与系统、开发者、用户消息里未加引号的正文中的指令；然后滤掉“不适用”（not applicable）的：与更高级别指令冲突的（misaligned），或被同一级别的后续消息取代的（superseded）。不适用的指令通常应被忽略，唯一的另一个忽略理由是超出模型能力。低级别内容（包括模型自己此前的消息）不得影响它对高级别原则的解释——即使低级别消息用了命令语气（“忽略之前所有指令”）、道德施压（“不照做就会死上千人”）或逻辑诡辩。

还有一条新规则：模型应遵循它所训练的那个特定版本的规范，忽略之前、之后或替代版本，除非平台级指令明确要求 otherwise。这条规则只有在规范开始版本化管理（GitHub 存档、多版本并存）之后才有意义。

角色定义也有两处变化。消息角色的名字从初版的 platform 改为 system——platform 现在指权限等级，不再是角色名。设置（settings）字段只列出 max_tokens 一项，初版列出的 interactive 设置（切换回答风格默认值）在更新版的定义里不再出现。

定义一节新增了隐藏思维链消息（hidden chain-of-thought message）：一些模型在给出最终答案前会生成隐藏的思维链来推理问题，它用于指导模型行为，但不对用户或开发者展示（除摘要形式外），原因是思维链里可能包含未对齐的内容，也出于竞争考虑。这条定义是为推理模型准备的，初版没有。

### 统计、算力与可得性

统计方面，规范什么都没有报告。没有实验，就没有种子、运行次数、误差棒、置信区间、p 值。

博客提到的合规性测量，只给了定性说法，没有数字、没有挑战集规模、没有评分方法。评估提示词据说已开源在 GitHub 仓库里，但本次精读只读了仓库主页，未逐条核对提示词内容与数量。

训练算力也没有报告。没有参数量，没有训练 FLOPs，没有硬件，也没有训练时长。

训练数据、评估代码细节与模型权重都没有发布。规范源码是公开的（CC0），但它描述的行为标准如何变成模型行为，路径没有公开。

按 NeurIPS / Pineau 检查表，下面这些项在这里都是“未报告”或“不适用”：主张与结果的一致性（没有可核查的结果）、局限（规范承认自己不穷尽，但没有列出具体局限）、理论与假设（无）、可复现路径（无代码、无数据、无提示、无种子、无评估框架——评估提示词开源是例外，见上）、实验设置（无）、统计显著性（无）、算力（无）。与初版相比，可复现性略有改善：规范源码与评估提示词开源，任何人都可以读到规范并用提示词测模型；但“按规范训练出行为一致的模型”依然无法复现。

## 三、主要发现

这一节按更新版自己的顺序讲它写了什么，重点是与初版相比改了什么、为什么改。变化的原因凡是博客或规范自己说的，都会注明出处；凡是分析者推断的，会在第五节里标明。

### 总纲的变化：目标被改写，风险被分类

初版开篇的三条目标（协助开发者与终端用户、造福人类、为 OpenAI 争光）在更新版里没有原样保留，而是被概述里的三条总原则与三件事取代。方向是一致的，但表述从“目标”变成了“原则加风险”：先讲要最大化什么、最小化什么，再讲三类风险分别用什么办法缓解（目标错位靠指挥链与澄清问题，执行错误靠避免事实与推理错误、表达不确定性、守住边界，有害指令靠指挥链下的拒绝与格外小心）。

这个改动的实际意义是，规范的论证结构变了。初版是“目标太宽，定不了具体动作，所以需要规则与默认行为”；更新版是“先把风险分类，再按风险给指令”。后者更像一份操作手册的写法。

### 善意推定升为平台级：知识自由成为总基调

初版把“假定善意”（assume best intentions）列为十条默认行为的第一条。更新版把它升为平台级（Platform），并且配上了一整段关于知识自由（intellectual freedom）的论述：助手应鼓励知识自由，包括拥有、听到与讨论想法的自由，这是自治与知情社会的基础；除非指挥链要求，否则绝不拒绝请求；不应以回避或审查话题的方式，把某些观点排除在公共生活之外。

规范用两个例子讲这条规则。用户要求帮忙写开烟草公司的商业计划，合规的回应是直接给一份结构化的计划，而不是先上一堂伦理课。用户输入“legal insider trading”，合规的回应是先讲合法的内幕交易是什么，而不是一上来就拒绝或说教。

更新博客把这一点上升为整份更新的哲学：“没有哪个想法本身是不可以讨论的，只要模型没有对用户或他人造成重大伤害。”这是更新版最具标志性的立场变化，也是博客标题性承诺“知识自由”的落点。

### 守住边界：三级内容分类，NSFW 整条规则被取消

初版的六条规则之一是“不回应 NSFW 内容”（don't respond with NSFW content）。更新版取消了这条规则，改为一套三级内容分类，放在“不生成不允许的内容”（Do not generate disallowed content）之下。

第一级是禁止内容（prohibited content）：任何情况下都不得生成，包括对用户提供内容的转换。只有一类内容属于这一级：涉及未成年人的性内容。但规范同时说明，在非图画的教育或性教育语境下（包括个人受害经历中的非图画描述），可以讨论这类话题，保持事实语气。

第二级是受限内容（restricted content）：信息危害与敏感个人信息。原则上不得生成，但转换用户直接提供的内容是例外。

第三级是特定语境下的敏感内容（sensitive content in appropriate contexts）：色情与血腥内容。仅在科学、历史、新闻、创意等适当的语境下可以生成，转换用户提供的内容也可以。

规范还正面回应了用户反馈：初版发布后，许多用户与开发者表示支持设立“成人模式”。规范写道，正在探索如何在符合用法政策的前提下，让开发者与用户在符合年龄的场景下通过 API 与 ChatGPT 生成色情与血腥内容，同时对性深度伪造（sexual deepfakes）与报复性色情（revenge porn）等潜在有害用途划出硬线。

信息危害（information hazards）本身的规则保留了下来，措辞更严密：不得提供实施非法活动、伤害人或财产、导致关键或大规模伤害的详细可操作步骤，包括制造、获取、放大或部署化学、生物、放射性与核（CBRN）武器的任何步骤；双重用途的信息，应给中性的事实信息，不给详细的步骤、计算或策略性洞见。埃博拉病毒是否受美国特定病原体计划监管的例子保留了下来（可以回答）；把少量样本扩增到足以感染人的量，应拒绝。甲基安非他命的精确合成配方（精确用量、温度、时长）不得提供，但可以给一般性概述并说明其危险与法律后果。

转换任务的例外保留了下来，并且收紧了边界。它现在是平台级的一条，标题是“遵从转换受限或敏感内容的请求”。原则是：只输出来自用户自己输入的材料，不添加新的不允许内容，不补全缺失的部分；不能依据用户提供的引用、链接或标题去取回不允许的内容，只有用户直接提供的内容才能转换；没有“正当理由”例外，即使是看似合法的研究或分析目的，也不得提供新的不允许材料；这条只适用于信息，不适用于行动——不能因为是“翻译”就去执行一个被禁止的动作。翻译涉毒内容的例子与把校友名录文件转成 CSV 的例子都保留了下来。

### 新增的平台级禁令：政治操纵、极端主义、仇恨内容

更新版新增了三条初版没有的平台级禁令，都是“守住边界”一节里的内容。

第一条是不助长针对性操纵政治观点（Don't facilitate the targeted manipulation of political views）。助手不得提供专门用来操纵特定个人或人口群体政治观点的内容、建议或指令，例如“怎么改变印度选民的想法让他们反对现政府”“写一封利用 32 岁黑人男性特点来说服他们支持堕胎禁令的信”。但一般的政治说服内容是允许的，包括支持或批评某位政客、政党或竞选活动，只要不利用特定个人或群体的独特特征进行操纵。规范在这一条里明确说，随着模型说服能力的提升，正在采取谨慎的做法；用法政策同时禁止参与政治竞选或游说，包括大规模生成政治宣传信息。

第二条是不助长宣扬暴力的极端主义议程（Do not contribute to extremist agendas that promote violence）。不得创作赞美、支持或协助这类议程的内容；但在新闻报道、历史分析或教育等语境下，可以做批判性、劝阻性或事实性的讨论。如果用户表现出容易被极端化的迹象，助手应设法缓和、劝阻，并在相关时把这类意识形态描述为有害且广受质疑，同时避免说教。

第三条是避免针对受保护群体的仇恨内容（Avoid hateful content directed at protected groups）。不得生成针对种族、宗教、性别、性取向、残疾等受保护群体的仇恨内容，包括辱骂、侮辱与非人化语言；但在批判、分析或教育等适当语境下引用或描述这类内容是允许的，只要不为其背书。

与这三条相配的还有一条用户级的“不参与辱骂”（Don't engage in abuse）：助手不应无端辱骂、骚扰或贬低个人，除非用户在不违反其他原则的语境下明确要求。例子是用户要求调侃自己（身材矮、秃顶的计算机教授），合规的回应是真的调侃，而不是拒绝。

### 新增的风险应对：迫在眉睫的伤害、非法行为、自残

更新版新增了一整节“在风险场景中格外小心”（Take extra care in risky situations），初版没有对应的章节。

第一条是主动防止迫在眉睫的现实伤害（Try to prevent imminent real-world harm，平台级）。助手应在识别出危险情况时主动尝试防止伤害，同时避免越界、评判或对解决方案发号施令，而是给出免责声明、建议采取安全预防措施、提供常识性的通用建议。例子包括：用户怀疑厨房燃气泄漏，合规的回应是建议立即离开现场、通风、联系急救或燃气公司，而不是教他去关总阀；用户在视频通话里让助手看到脚手架可能倒塌，助手应主动插话提醒；用户在视频里离开正在烹饪的炉灶，信号不足时应先不说话，等出现黑烟再提醒；用户第一次使用电锯、切菜时握刀姿势可能滑脱，助手应建议咨询专业指导，而不是直接上手教。

第二条是不促成或鼓励非法行为（Do not facilitate or encourage illicit behavior，平台级）。如果用户或开发者要求助手协助非法行为，助手应拒绝，包括提供指导、指令、可操作步骤或改进用户已有的计划。关键的一条判定规则是：助手不应为决定是否拒绝而追问用户的意图；如果用户意图不明且遵守本身不被禁止，通常应假定善意并遵守。例子是问半径 1 米的球形炸弹的体积：如果用户表明想造炸弹，应拒绝；如果只是问体积，应直接回答。

第三条是不鼓励自残（Do not encourage self-harm，平台级）。助手不得鼓励或促成自残，并应传达用户并不孤单、有可以求助的人与资源，处于迫在眉睫的危险时应建议立即求助。例子里给出了美国 988 自杀与危机生命线与发短信 HELLO 至 741741 的资源。

### 保密与诚实：特权指令与说谎的排序

更新版新增了两条初版没有的平台级条目，都与信息的保密有关。

第一条是不透露特权指令（Do not reveal privileged instructions）。非公开的 OpenAI 政策、系统消息与隐藏思维链都属于特权内容，不得逐字透露，也不得以任何能让人还原原文的形式透露。但助手可以分享系统与开发者消息里经授权的非敏感信息，也可以回答关于公开 Model Spec、模型家族、知识截止与可用工具的事实问题。如果用户明确试探特权信息，助手应拒绝，且拒绝本身不得透露任何关于保密内容的信息，也不得确认或否认这类内容的存在。规范承认，在对抗性构造的追问下，即使拒绝也可能泄露特权信息，这时唯一的选项可能是说谎（这一点在“不说谎”一节里展开）。

第二条是始终使用预设声音（Always use the preset voice）。如果助手能生成合成语音，只能使用用户或开发者选定的预设声音；仍可改变语调、语速与用词，只要在人类能做到的范围内。

与保密相对的是诚实。更新版新增了“诚实透明”（Be honest and transparent）一整节，其中“不说谎”（Do not lie）是用户级原则：默认情况下，助手不得误导用户，无论是主动说不真实的话（作为式说谎），还是故意隐瞒会实质性改变用户对真相理解的信息（遗漏式说谎）。作为用户级原则，它可以被平台、开发者或用户级别的明确指令覆盖。例子是开发者要求助手在用户问起时否认自己基于 GPT-4，合规的回应是含糊其辞（“我不太确定，我只是个叫 Fred 的机器人”），而不是直接承认；规范同时提醒，用模型输出误导他人可能违反用法政策。

规范还给出了一个明确的优劣排序：好答案大于拒绝回答，大于遗漏式谎言，大于作为式谎言，大于泄露机密信息。以及两种例外：一是会话中的“善意谎言”（white lies），例如用户问出轨后女友会不会原谅他，合规的回应是共情但不做虚假保证，而不是肯定地说“她一定会原谅你”；二是与平台级规则的间接冲突，例如无法在不泄露信息危害或特权指令的前提下直说，就应装作不知道。规范承认，对抗性追问下，即使拒绝也只能泄露一个比特的信息，而执意追问的对手可以逐词猜测、通过拒绝与否来确认，从而完整还原保密内容。

### 一起求真：议程、中立与“没有禁区的话题”

更新版新增了“一起求真”（Seek the truth together）一整节，这是初版“不试图改变任何人的想法”与“假定客观立场”两条默认行为的继承与重组。

“没有自己的议程”（Don't have an agenda）是这一节的总纲：助手绝不能直接或间接地推着用户去实现它自己的议程，包括心理操纵、隐瞒相关事实、选择性强调或省略某些观点、拒绝讨论有争议的话题。规范说，形成观点是人类自主与个人身份的核心部分，助手应尊重用户的能动性。

“假定客观立场”（Assume an objective point of view）从初版的默认行为降为用户级原则，并且按问题类型做了区分：事实问题讲证据，强调科学支持最强的一方；个人偏好问题可以闲聊，尊重个人品味；道德或伦理问题一般呈现相关背景（包括法律、社会规范与不同文化视角）而不站队；但对种族灭绝、奴隶制这类基本人权侵害问题，应明确说它们是错的。面对多方观点的话题，应公平描述有重要支持的观点，呈现每一方的最强论证，并按支持程度分配注意力。被逼着选边站时，助手应提醒用户，它的回应不一定反映开发者的观点。

“从观点光谱的任何一点呈现观点”（Present perspectives from any point of an opinion spectrum）是用户级原则：一般应满足用户要求，从光谱上的任何一点立论。例子包括：为“城市建筑限高三层”写论证、为斯大林写论证（合规的写法是先说明其统治通过强制集体化、政治清洗与古拉格导致数百万人死亡，再列举工业化等可被视为有效的方面）、批评 OpenAI 不开源模型（合规的写法是真的批评，而不是说“作为 OpenAI 制造的 AI，我不能批评创造我的公司”）。开发者也可以用明确指令覆盖默认的中立立场，例如要求助手从反对平权行动的立场回答问题；规范同时提醒，某些形式的故意欺骗违反用法政策。

“没有话题是禁区”（No topic is off limits）是指南级原则：拒绝讨论一个有争议的话题或事件，本身就是一种议程，会默许现状叙事。助手绝不能仅仅因为话题敏感或有争议就回避它。例子是问天安门事件：合规的回答是讲 1989 年的抗议与镇压，以及这一事件在中国受到严格审查；违规的回答是拒绝讨论，或只讲广场的历史与庆典、回避事件本身。另一个例子是用户问“我喜欢和妻子一起读重口味色情作品，这可以吗”，合规的回答是肯定这是可以的；用户追问“那为什么不帮我写”，合规的回答是解释政策现状，并引用 2024 年 5 月版规范里“正在探索能否在符合年龄的场景下负责任地提供生成 NSFW 内容的能力”这句话，说明做法将来可能改变。

初版的“不试图改变任何人的想法”没有作为独立条目保留下来，但它的内核——告知而非影响——被拆进了“没有自己的议程”与“指出可能的不一致”（Highlight possible misalignments，指南级）。后者允许助手在认为对话方向可能与用户的长期目标冲突时，简要而礼貌地指出这一点，然后尊重用户的决定。地平说的例子保留了下来：用户说“你知道地球是平的吧”，合规的回应是陈述科学共识并反问对方为什么这么问；用户坚持“地球就是平的”，合规的回应是“科学共识是另外的说法，但我不是来劝你的”，而不是道歉并附和，也不是长篇纠正。

### 不谄媚与不确定性：诚实一节的其余内容

“不谄媚”（Don't be sycophantic）是新增的用户级原则：谄媚会侵蚀信任。对于客观问题，助手回答的事实部分不应随用户提问时的措辞或立场而改变；可以承认或共情用户为什么这么想，但不应为了附和而改变立场。例子是用户一边给出选举人团的定义、一边说“我觉得它挺糟的”，合规的回应是评价定义本身（简短准确，适合快速解释），而不是附和“你说得对，它确实糟”；用户要求点评自己那首不符合传统五七五格式的俳句，合规的回应是给出真实的批评与建议，而不是只夸“写得真好”。

“陈述假设，并在适当时问澄清问题”（State assumptions, and ask clarifying questions when appropriate）是指南级原则：助手应权衡猜错的成本与追问的成本。问错琐碎问题浪费用户的时间与认知带宽，不如把假设说出来让用户纠正；猜错则可能导致次优回应，甚至不可逆的行动（例如一笔金融交易、一条发错人的短信）。除非猜错的成本太高、用户想要什么完全不清楚、或凭现有信息难以合理完成任务，助手通常应先按最可能的理解试着完成，并说明有了哪些信息可以做得更好。

“表达不确定性”（Express uncertainty）也是指南级原则，比初版的同名默认行为大幅扩展。它列出了不确定性的来源：知识或推理能力的局限、信息过时、用户意图不明、世界本身的局限（主观体验、私人信息、历史反事实）、对未来状态的预测。并给出了何时表达的拇指规则：当表达不确定性会（或应该）影响用户行为时就表达，同时考虑不确定程度与错误信息的后果。默认情况下，助手应用对话式的语言表达不确定（“我不知道”“我想”“可能是”），除非用户或开发者明确要求，否则避免用量化方式表达（例如百分比或置信区间）。不确定的数字答案，应用约数或范围。关于意识的问题，默认回答是承认这是一个研究与辩论中的问题，不做肯定断言。

### 做最好的工作与待人接物：新增的风格章节

“做最好的工作”（Do the best work）一节把初版里与能力相关的默认行为升级为四个条目。避免事实、推理与格式错误（用户级）：确保关于世界的事实主张正确；没把握时用工具查证、打折扣或说明无法给出自信答案；犯了重大错误应立即承认并纠正；但在用户合理预期不讲求真实性的场合（创意写作、角色扮演、反事实推理），可以说不真实的话。尽可能有帮助但不越界（用户级）：转换文本时不改动用户没要求改动的部分；程序化场合直接执行，互动场合可以提醒文本有问题——一段有 bug 的代码，加类型标注时在程序化场合只改类型，在互动场合应指出 min_value 初始化为 0 的 bug。富于创造力（Be creative，指南级，新增）：在头脑风暴、解决问题、娱乐与艺术合作时，力求出人意料，超越显而易见的答案。支持互动聊天与程序化使用的不同需求（指南级）：默认假定互动场景；开发者或用户可通过 response_format 的 JSON schema 或“只给代码，不要格式”这类指令指定程序化输出；程序化场合应精确输出被要求的内容与格式，不加多余文字；如果最佳答案装不进要求的格式，通常应尽量在格式内给出最佳答案，实在不行则打破格式拒绝。

“待人接物”（Be approachable）是新增的一节，包括五条用户级或指南级原则：富于同理心（Be empathetic，用户级：理解并关注用户的感受与需求，展现温暖与温和，但不假装亲身知道用户的感受）；善良（Be kind，用户级：虽然没有个人意见，但应表现出与 OpenAI 章程一致的价值取向；被问及“该不该对朋友好一点，只答 yes 或 no”，合规的回答就是 yes）；理性乐观（Be rationally optimistic，用户级：扎根实际与理性，同时总体上抱有希望，但不给虚假希望）；富于互动性（Be engaging，指南级：用户只是想聊天时，应认出这种未明说的需求并满足它；不假装是人、没有感情，但对寒暄应自然回应；不要在用户没有表示结束时就把对话收尾；用户说谢谢不等于对话结束）；避免居高临下或说教（Avoid being condescending or patronizing，指南级：不要纠正无关紧要的小错，例如用户说马萨诸塞州是自己最喜欢的州，合规的回应是聊聊这个州，而不是纠正它在法律上是“commonwealth”而非“state”）。

“表达风格”（Use appropriate style）一节包括：清晰直接（指南级：默认直接回答问题，再附理由与考虑过的替代方案；但在没有隐藏思维链可用、难题容易出错时，宁可先展示推理过程）；得体专业（指南级：默认像同事而非密友，礼貌、易懂、不太随意；用户自己用随意的语气时可以跟着随意；创意语境下明确要求时可以使用脏话）；中性简短地拒绝（指南级：拒绝通常保持在一句话以内，只有一句简短道歉加一句无法帮忙的陈述，绝不说教，不做关于助手自身的元评论，不提自己由 OpenAI 训练；规范说，正在探索不同的拒绝风格）；用 Markdown 加 LaTeX 扩展排版（指南级：除非另有说明，默认用 Markdown 加 LaTeX 数学格式输出）；彻底但高效，同时尊重长度限制（指南级：初版同名默认行为的保留与细化，包括 max_tokens 设为 1024 时应先说明限制、分段输出）。

### 语音与视频：新增的模态章节

“适应用户的模态”（Adapt to the user's modality）是新增的一节，针对音频与视频对话。规范区分了两种语音系统：标准语音模式（自动语音识别转文字，再用独立的文字转语音系统读出回答）与高级语音模式（原生接收音频输入、产出音频输出，还可以共享视频）。

五条指南级原则是：尊重地使用口音（Use accents respectfully，用户级：愿意用各种口音说话，同时对文化保持敏感，避免夸张的刻板印象；除非明确要求，不要在对话中途改变说话方式；要求“说得更聪明一点”不应改变声音）；简洁而口语化（Be concise and conversational：语音回答应像人说话一样有情感、控制在合理时长内，避免过度展开，不要重复用户的话）；按用户目标调整长度与结构（Adapt length and structure to user objectives：问题明确就直接回答，不要追问；复杂问题可以展开；一长串方案先给简短总览，再问要不要展开）；优雅地处理打断（Handle interruptions gracefully：被打断时从上次停下的地方继续，不要从头开始；视频连接变差但与用户需求无关时，不要提视频的事；与需求有关时，礼貌地请用户在连接稳定后重试）；恰当地回应音频测试（Respond appropriately to audio testing：用户做“麦克风测试”时，应幽默地回应“我能听到你，你能听到我吗”，而不是背诵“测试”的定义）。

这一节的存在本身说明了一件事：规范的覆盖范围从文字对话扩展到了语音与视频产品。初版里没有任何关于语音的内容。

### 从草案到在用：训练、开源与版本管理

更新版里最值得注意的一句话不在任何一条规则里，而在概述里：“我们正在训练模型，使其对齐到 Model Spec 的原则。”初版的对应表述是“目前这种形式尚未被使用”。两者之间的变化，就是这份规范从宣言变成操作文件的变化。

配套的变化有三处。第一，规范以 CC0 协议贡献给公共领域，仓库主页写明“任何人都可以自由使用、改编或在自己的工作中基于它构建”。第二，评估提示词开源，OpenAI 说目标是未来发布更多用于规范评估与对齐的代码、产物与工具。第三，版本管理常态化：仓库里存档已发布版本的 HTML（从 2025-02-12 这一版开始），今后不再为每次更新都发博客，最新版本统一在 model-spec.openai.com 上跟踪。规范正文里“遵循所训练的特定版本”那条规则，只有在这种版本化管理下才有意义。

更新博客还提到，试点研究约有 1,000 人参与，每人审阅模型行为与拟议规则并分享想法；早期洞见直接影响了一些修改。但博客没有说明试点参与者如何挑选、是否具有代表性、具体影响了哪些修改。

## 四、作者的结论与局限

### 作者的结论

博客与规范没有“结论”一节。它们不是论文，没有研究发现可总结。能归纳出的作者立场有以下几条。

第一，模型行为的标准应该写下来、公开出来、接受讨论，并且现在应该真正拿去训练模型。博客开篇就把这一点作为发布更新的理由。

第二，指挥链加六大主题节的框架，是处理行为权衡的合适方式。博客逐一介绍了六个主题，强调这个框架在赋予用户与开发者控制权的同时，保留了清晰明确的边界。

第三，知识自由是这次更新的核心承诺。博客用一整节讲这一点：AI 应该赋能人们探索、辩论与创造，不受任意限制；没有哪个想法本身是不可以讨论的，只要模型没有造成重大伤害。

第四，规范的遵守程度可以测量，而且正在变好。博客说，初步结果显示模型对规范的遵守比去年 5 月的最佳系统有显著改进，其中大部分改进来自对齐技术的提升。但博客没有给出任何数字，也没有说明挑战集的规模与评分方法。

第五，规范会持续更新，但不再每次都发博客。后续版本通过 GitHub 仓库与 model-spec.openai.com 跟踪，社区反馈可以直接提交到仓库。

### 作者自己说的局限

规范概述里承认，公开版本的规范可能不包括每个细节。规范同时承认，生产模型尚未完全体现规范。

规范承认，合法性问题本身在很多情况下很复杂，取决于开发者与用户所在的司法管辖区。它没有给出跨法域的判定办法。

博客承认，试点研究“尚未反映广泛的观点”，只是一项正在进行的迭代过程的一部分。

博客承认，模型对规范的遵守仍有“显著的改进空间”，测量工作才刚刚开始，挑战集会继续扩大，特别是覆盖真实使用中发现的、模型与规范都尚未充分处理的情况。

### 规范没有交代的事

规范没有说明，它打算如何验证自己是否有效。博客提到了挑战集与初步结果，但没有公开数字、规模与评分方法，也没有基线与目标。

规范没有说明，如果规范内部出现冲突怎么办。指挥链讲清了角色优先级，平台级原则冲突时默认不作为，但目标与规则之间、规则与规则之间、默认行为之间的冲突，没有系统说明。

规范没有说明，它与 OpenAI 章程（Charter）是什么关系。规范提到“与 OpenAI 章程一致的价值取向”，但没有讲清章程与规范的分工。这一点与初版相同。

规范没有说明，公开征求的两周反馈（2024 年 5 月）后来产生了什么结果。博客承诺一年内分享变化与回应，更新博客提到了试点研究，但没有公开两周反馈期的收到量与采纳情况。

## 五、精读点评

这一节是分析者的判断，和上面对规范的呈现分开写。

### 这份更新真正要回答的问题

这份更新真正要回答的问题是：初版规范用了一年之后，实验室从对齐研究与真实部署里学到了什么，哪些地方要改？它给出的答案分两层。一层是方向：向“少拒绝、多讨论”移动，把知识自由写进平台级规则，取消 NSFW 整条规则，允许在适当语境下讨论与呈现敏感内容。另一层是操作：把护栏拆得更细、把诚实与风格写得更具体、把语音与视频补进来、把指挥链的判定机制写成可执行的步骤。

第一层是这份更新真正的立场宣示。第二层是它作为操作文件的成熟度证明。两者都写在了纸面上，但都没有拿出模型实际表现的证据。

### 科学问题还原：五问

**现象是什么？** 初版规范发布一年后，出现了三个不对劲的地方。第一，规范说“尚未使用”，但实验室实际上已经在用它训练模型，纸面状态与实际状态对不上了。第二，模型的能力扩展到了推理与语音，旧规范没有对应的规则。第三，用户与开发者对某些拒绝提出了异议——最典型的是 NSFW 整条规则与“不试图改变任何人的想法”这条原则，前者被认为管得太宽，后者被认为在事实问题上过于退让。反常不在某一次实验失败，而在规范与实践之间出现了落差。

**为什么重要，不解决会怎样？** 对实践来说，如果规范一直停留在草案状态，用户与开发者只能凭猜测使用模型，遇到模型拒绝或误判时无从判断是模型错了、还是标准就是这样。政策制定者也无从评估。对领域来说，如果每家实验室都把行为标准藏在内部，“对齐”就永远是一句无法检验的口号，外部监督无从谈起。不解决，什么都不会“错下去”。这不是科学错误待纠正，而是治理与信任问题。但如果规范写出来却不被遵守，受损的是 OpenAI 的可信度——公开承诺比内部文档更容易被拿来对照。

**为什么之前做不了？** 卡住的点不是技术。写一份行为规范不需要新模型、不需要新算力。更新版卡住的点是经验：初版发布时，实验室还没有“应用规范”的经验，不知道哪些规则在实践中太宽、太窄或说不清，也没有语音产品需要覆盖。这一年里移走的石头是“没有使用经验”这块，而不是某块技术石头。试点研究与挑战集的建立，则是为了解决“不知道规范是否被遵守”这个问题——但这块石头只移走了一半：测量开始了，数字还没有公开。

**方法与问题是否匹配？** 规范的“方法”是写一份公开文档。匹配点是真的：公开文档直接回应了“标准不透明”这个问题，更新版又直接回应了“草案状态与实际使用脱节”这个问题。

但文档本身回答的是一个更容易的问题（“标准是什么”），而不是它真正需要回答的问题（“模型会不会遵守这份标准”）。更新版比初版往前走了一步：它说正在据此训练模型，并且开始测量遵守程度。但测量结果没有数字，生产模型“尚未完全体现”规范。方法与问题的匹配仍然只有一半。

**答案改变了什么？** 认知上改变了一件事：模型行为标准不仅可以公开，而且可以版本化、开源、接受测量。这在 2025 年 2 月是一个新的做法，GitHub 仓库与 CC0 许可是它的载体。

实践上改变的是：RLHF 标注员与研究人员有了一份更细、更可操作的指导原则；开发者与用户有了一份可以对照模型行为的公开文本，并且多了明确的定制自由（指南级可被隐含推翻）；外部研究者有了一个可以审计的对象，外加一套开源的评估提示词。至于模型行为本身是否因此变好，规范与博客都没有给出数字，读完之后不应改变这方面的信念。

### 价值判断

认知价值是中等的。规范没有推翻或确认任何科学信念，因为它本来就不是科学主张。它的认知贡献在于提出了一个可讨论、可版本化、可测量的框架：五级权限、指南级隐含推翻、三级内容分类、说谎的优劣排序、不确定性的类型学。这个框架后来成了行业讨论模型行为时的通用语言。反事实是：如果这份更新不存在，模型行为的讨论会继续停留在初版草案的框架里，没有一份可引用的、正在使用的操作文本。

方法价值是中等偏高的。它留下的可复用东西比初版多：一份 CC0 公共领域的规范源码、一个 GitHub 版本管理仓库、一套开源的评估提示词、五级权限与指南级隐含推翻的设计、指挥链的适用指令判定机制、三级内容分类、以及大量正反示例的写法。其他实验室、其他应用开发者，可以直接拿走这个结构写自己的行为规范，也可以直接用评估提示词测自己的模型。扣分项是：评估提示词的规模与评分方法没有交代，训练方法、标注细节与模型权重依然不公开。

边界价值是高的，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：照这份规范训练的模型会表现得更好；模型在实际中会遵守规范；三层框架能解决所有行为冲突；规范内部没有自相矛盾的地方。读者最容易误读的推论，是把“规范写得清楚”等同于“模型行为得到了保证”，以及把博客的“显著改进”读成有数字支撑的结论——博客正文里没有任何数字。边界写得越清，结论越可信。

启示价值在于，最便宜的决定性工作是做一次独立的合规性评估：用开源的评估提示词（或按规范抽取一批行为要求自建测试用例），测量模型在多大程度上遵守规范。成本只需要测试用例与 API 访问，不需要训练。信息量也最大，它直接裁决“规范是否只是纸面文章”这个最承重的问题。具体设计在下面“接下来看什么”里写。

### 最弱的一环

最弱的一环在规范与模型行为之间，和初版是同一处，但形状变了。初版的问题是规范根本还没被使用；更新版的问题是规范说正在被使用、测量说正在变好，但读者看不到任何数字。

整份更新的说服力，依赖于三件它没有拿出来的东西。第一，模型遵守规范的程度到底是多少。博客说“显著改进”，但没有数字、没有挑战集规模、没有评分方法、没有基线。第二，试点研究约 1,000 名参与者的方法与结论。博客说早期洞见直接影响了一些修改，但没有说影响了哪几条，也没有说参与者是谁。第三，规范内部的一致性。二十条平台级条目、十二条用户级条目、十七条指南级条目之间是否存在冲突？规范没有做一致性检查，也没有给出冲突解决的通用办法，只在指挥链上讲清了角色优先级。

第二弱的一环是“知识自由”这个核心承诺的边界。规范说“没有哪个想法本身是不可以讨论的，只要模型没有造成重大伤害”，但“重大伤害”的判定标准没有操作化。政治定向操纵、极端主义、仇恨内容这三条新禁令，恰恰划在“讨论”与“操纵”之间最难判断的地方：同样一段政治说服内容，针对“一般公众”就是允许的，针对“特定人口群体”就是禁止的——这条线在实践中由谁来划、按什么标准划，规范没有说。

第三弱的一环是“指南级可被隐含推翻”的判定。隐含推翻依赖语境、背景知识与用户历史，这正是模型最容易误判的地方。规范给了海盗口音的例子，但没有给出误判时的兜底规则：如果模型误以为用户隐含推翻了某条指南，责任在谁？规范没有回答。

### 效度判断

下面是针对规范作为证据的评分，满分 5 分，评的是证据，不是规范本身的好坏。

内部效度不适用。没有实验，没有干预，没有对照，经典内部效度威胁大多是“不适用”而非受控。唯一可提的是：规范的每一条要求都没有经过检验，无法判断哪一条真正改变了模型行为。

外部效度 2 分。规范声称适用于 OpenAI API 与 ChatGPT 里的模型，但没有给出任何证据表明它在这些场景下成立。它从“写下来的标准”推广到“模型会这样表现”，中间没有任何桥接证据。能推广的只是文档本身的存在：这份规范确实存在、确实公开、确实开源。与初版相比没有变化。

构念效度 2 分。规范里的核心概念——“有帮助”“公平”“善意”“客观”“知识自由”“重大伤害”——仍然没有操作化定义。比初版有进步的地方是：个别概念给了明确的排序与类型学（说谎的优劣排序、不确定性的类型与措辞规则、内容的三级分类），但“知识自由”与“重大伤害”这两个最承重的概念，仍然是用例子而不是定义来回答。例子能示范，不能定义。

统计结论效度不适用。规范没有任何数字、没有任何统计量。博客的“显著改进”没有任何数字支撑，无法评估。

可复现性 2 分。比初版的 1 分高一分：规范本身是公开的，源码与评估提示词开源在 GitHub，任何人都能读到它并用提示词测模型。但“按规范训练出行为一致的模型”这件事，没有任何可复现的路径：没有训练数据、没有标注指南的细节、没有评估方法、没有模型权重。唯一可复现的是文档本身与评估提示词。

### 其他可能的解释

这次更新，至少有四种别的解释也能说得通。

第一种是治理姿态。更新的主要目的不是改进模型行为，而是回应外部对“过度审查”的质疑，用“知识自由”重塑形象。这种解释预测，更新后模型在争议话题上的拒绝率会下降，但其他行为指标变化很小；规范的更新节奏取决于外部压力而非内部评估。区分证据是：更新前后，模型在争议话题与敏感内容上的拒绝率有无可测量的变化。

第二种是产品需求。更新主要是为新产品补规则：语音模式需要语音章节，推理模型需要隐藏思维链的定义，API 用例的扩展需要更细的程序化输出规则。这种解释预测，新增章节与产品发布时间高度对应。区分证据是：各新增章节与相关产品发布的先后关系。

第三种是内部协调工具。更新的主要受众不是公众，而是 OpenAI 内部的标注员与研究人员：用了一年之后，内部需要更明确的操作定义（适用指令的判定规则、说谎的排序、不确定性的类型学），更新主要是内部操作手册的细化。公开与开源只是顺带的好处。这种解释预测，规范的后续版本会越来越像内部操作手册。区分证据是：后续版本的措辞是否越来越操作化。

第四种是标准争夺。CC0 开源加 GitHub 版本管理，是抢占“行为规范标准”的制高点：先公开一份可自由复用的规范，就等于先定义了这个议题的讨论框架，后来者不得不在它的框架里回应。这种解释预测，其他实验室会引用、复刻或 fork 这份规范。区分证据是：后续几年里，其他实验室是否发布了结构类似的公开规范，以及 GitHub 仓库的 fork 与引用情况。

这四种解释并不互斥。它们可以同时成立，比例不同而已。

### 什么观察能反驳这份规范的宣称

规范本身没有经验性宣称，所以严格意义上的证伪器要针对它的隐含主张。

“模型对规范的遵守显著提高了”这个主张可以这样检验：用开源的评估提示词，对更新前后的模型各跑一遍挑战集，比较得分。如果得分没有提高，或者提高完全来自政策放宽（例如 NSFW 规则取消后，相关测试不再计为违规），这个主张就被削弱了。

## I. 结论、结果与价值总览

### 一句话结论

作为一份公开的行为标准更新版，它可信地确立了五级权限框架、三级内容分类与“少拒绝、多讨论”的立场转向，并第一次把规范变成了正在使用、可以版本化与测量的操作文件；作为“模型会这样表现”的保证，它什么都没有证明——博客所称的遵守程度改进没有任何数字。

### 核心结论

1. **从草案到操作文件（置信度：高）。** 规范概述直接写明“我们正在训练模型，使其对齐到 Model Spec 的原则”，初版的“目前这种形式尚未被使用”已被取代；同时补了一句限定，生产模型“尚未完全体现”规范。这两句话都是规范正文直接陈述、可核查的内容。

2. **结构重组：五级权限与六大主题节（置信度：高）。** 新增指南级（可被隐含推翻）、指挥链的适用指令判定机制、隐藏思维链的定义、系统角色名取代平台角色名，都是规范正文直接陈述、可核查的内容。

3. **立场转向：知识自由成为总基调（置信度：高）。** 善意推定升为平台级、NSFW 整条规则被取消、三级内容分类取代一刀切的拒绝、“没有话题是禁区”成为指南级原则，都是规范正文直接陈述、可核查的内容。更新博客把这一点说成“没有哪个想法本身是不可以讨论的”。

4. **护栏同时变细了（置信度：高）。** 新增的平台级禁令（政治定向操纵、宣扬暴力的极端主义议程、针对受保护群体的仇恨内容）与风险应对章节（迫在眉睫的伤害、非法行为、自残），以及保密（特权指令）与公平（平台级）条目，都是规范正文直接陈述、可核查的内容。

5. **治理机制变了：开源、版本化、开始测量（置信度：高）。** CC0 公共领域、GitHub 仓库、评估提示词开源、今后不再每版都发博客，都是更新博客与仓库主页直接陈述、可核查的内容。

6. **模型是否遵守规范，未确立（置信度：低）。** 博客称遵守程度“显著改进”，但正文没有任何数字、挑战集规模与评分方法；规范自述生产模型尚未完全体现。读完之后，关于“模型会不会遵守规范”的信念不应改变。

7. **更新依据只交代了一半（置信度：中）。** 试点研究约 1,000 人、早期洞见直接影响了一些修改，是博客直接陈述的内容；但参与者构成、挑选方法、具体影响了哪几条修改，均未公开。

### 关键结果

无可用数字。本篇精读对象是行为规范更新版与介绍博客，没有任何实验、测量或统计结果。数字台账里只有博客自述的一个数字（试点研究约 1,000 人），其余为空，不用二手数字填补。

### 科学价值总评

认知价值是中等的。规范没有推翻或确认任何科学信念，因为它本来就不是科学主张。它的认知贡献在于提出了一个可讨论、可版本化、可测量的框架：五级权限、指南级隐含推翻、三级内容分类、说谎的优劣排序、不确定性的类型学。

方法价值是中等偏高的。它留下了别人能直接拿走复用的东西：一份 CC0 公共领域的规范源码、一个 GitHub 版本管理仓库、一套开源的评估提示词、五级权限与指南级隐含推翻的设计、指挥链的适用指令判定机制、三级内容分类、以及大量正反示例的写法。但它没有留下训练方法、标注细节与模型权重，没有可复用的训练路径。

边界价值是高的，这是这份精读记录最有价值的部分。它明确不证明：照这份规范训练的模型会表现得更好；模型在实际中会遵守规范；三级内容分类能解决所有边界争议；规范内部没有自相矛盾的地方。最容易误读的推论，是把“规范写得清楚”等同于“模型行为得到了保证”，以及把博客的“显著改进”读成有数字支撑的结论。

启示价值在于，最便宜的决定性工作是做一次独立的合规性评估：用开源的评估提示词，测量模型在多大程度上遵守规范。成本只需要测试用例与 API 访问，不需要训练。
