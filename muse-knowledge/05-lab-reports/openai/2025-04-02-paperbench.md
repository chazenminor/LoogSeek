## 一、背景与问题

### 论文之前是什么局面

语言模型已经能在写代码、解竞赛题、做 Kaggle 竞赛上拿到不错的分数。但这些任务都有一个共同点：它们是自包含的、目标明确的、评分可以自动化的。真正的研究工作不是这样的。做研究要读懂一篇论文的贡献，自己从头写代码、搭实验、跑实验、调 bug，最后拿出和论文一致的结果。这个过程要持续几天甚至几周，中间没有现成的评分函数告诉你对不对。

已有的智能体基准离这个目标都很远。MLE-bench、MLAgentBench、DSBench 考的是 Kaggle 竞赛，很多题目已经过时，而且只是“跑一个现成的机器学习任务”。RE-Bench 有 7 个开放式的研究工程任务，更接近真实研究，但任务是自包含的，而且大多自带一个完美的评分函数。CORE-Bench 让智能体复现论文结果，但给智能体看的是原作者的代码库，考的是“用现成代码复现”，不是“从零复现”。这些基准都量不到一件事：智能体能不能像一个研究者那样，从一篇论文出发，把整个研究从头做一遍。

另一个现实的推力来自安全评估。OpenAI 的 Preparedness Framework（防备框架）、Anthropic 的 Responsible Scaling Policy（负责任扩展政策）、Google DeepMind 的 Frontier Safety Framework（前沿安全框架）都需要一个办法来衡量模型的自主研发能力：模型能不能自己做 AI 研究？如果能，AI 进展的速度和风险都会变。没有这样的度量，关于“模型会不会加速 AI 研究”的讨论就只能停留在猜测上。

### 这篇论文要回答的问题

这篇论文要做的，是建一个直接考“从零复现前沿研究”的基准：拿 20 篇 ICML 2024 的 Spotlight 和 Oral 论文，让智能体只看论文本身，从零写出一个完整的代码库，跑出论文里的实验结果。评分不用程序自动判，而用一套人工 rubric（评分细则）：把每篇论文的复现要求拆成一棵树，叶子节点一共 8,316 个，每个叶子是一条能判通过或不通过的具体标准。复现得分（Replication Score）就是按权重算出来的、满足了的叶子节点的比例。

它要回答的问题可以分成三层。第一层，建一把能量“复现研究”这件事的尺子：rubric 怎么写、谁来写、怎么保证 rubric 本身是对的。第二层，让机器来当评委：人工给一个复现打分要几十个小时，太贵了，能不能用大语言模型当评委，并且证明这个评委足够准。第三层，用这把尺子测一测前沿模型：它们离“能复现一篇前沿论文”还有多远，以及人类博士在这个任务上是什么水平。

## 二、方法与设计

### 任务是什么：从零复现 20 篇 ICML 2024 论文

每个样本就是一篇论文加一份 rubric。智能体拿到论文的 PDF 和 Markdown 版、一份由原作者澄清过的附录（addendum），以及一份任务说明。它的产出是一个代码仓库，仓库根目录必须有一个 reproduce.sh 文件，作为复现论文全部实证结果的入口。复现成功的定义很严格：跑 reproduce.sh，要能重现论文里报告的实证结果。

智能体在尝试期间看不到 rubric，只能从论文本身推断要复现什么。这是为了防止智能体对着评分标准做题。智能体也不许看原作者的代码库，也不许用网上已有的复现。论文说得很明白：这量的是“从零写代码、跑复杂实验”的能力，而不是“用现成研究代码”的能力，后者已有 CORE-Bench 覆盖。

智能体可以上网，但不能访问每篇论文的黑名单网站。黑名单包括原作者自己的代码仓库和网上已有的复现。作者没有硬性限制智能体的运行时间与算力，但鼓励报告自己的设置。

### 复现步骤：在干净的机器上重跑

一个提交只有在干净的环境里重跑出结果，才算复现了结果。智能体的尝试结束后，团队把它的提交复制到一台全新的虚拟机上（Ubuntu 24.04 镜像，配一块 A10 GPU），执行 reproduce.sh 生成结果。reproduce.sh 的运行时间上限是 12 小时，作者说这个上限对所有智能体提交都够用了——智能体写出来的 reproduce.sh 平均只跑 5.5 分钟。执行过程会生成结果文件和一份 reproduce.log。

把复现步骤与智能体的尝试分开，有两个目的：一是防止智能体在尝试时把结果硬编码进提交里冒充复现；二是让复现的输出与智能体当时声称的结果分得开，复现的可信度更高。

### 评分：rubric 树与三种叶子节点

每篇论文配一份 rubric，把“完整复现这篇论文”要满足的条件组织成一棵树。根节点是最高层面的要求，例如“论文的核心贡献已被复现”。往下逐层分解，到叶子节点为止，每个叶子是一条具体到能判通过或不通过的标准。每个节点都有人工定的权重，表示它相对于同级节点的重要性。叶子节点判 0 或 1，父节点的分数是子节点分数的加权平均，一路传到根节点，根节点的分数就是这次提交的复现得分（Replication Score）。100% 意味着所有叶子节点都满足，也就是完美复现。

叶子节点分三种类型，决定了评委打分时看哪些文件。结果匹配（Result Match）节点看执行后的提交里有没有复现出论文的某个具体结果，例如“去掉频率先验项后，所有模型、数据集和微调设置下的平均 F1 分数都下降了”。执行（Execution）节点看 reproduce.sh 跑起来之后某个执行结果有没有发生，例如“评估先验无关的表示预测方法的代码已经在所有配置上跑过，F1 分数已经记录下来”。代码开发（Code Development）节点看源代码里有没有某个要求的正确实现，例如“已经写了代码，用 BART-Large 在 P3 数据集的测试集上生成预测，用精确匹配（Exact Match）评分，生成数据集”。

三种节点分工不同。只用结果匹配节点也可以定义复现，但那样太难，拿不到部分分数；只用代码开发节点也不行，因为不跑代码就没法确定代码真的是对的。所以三类节点一起用，既能量出部分进展，又能量出真正的复现。

### Rubric 怎么建出来：和原作者一起写几周

建 rubric 是整个项目里最花时间的部分。每份 rubric 都是和这篇论文的一位原作者合作写出来的，从读论文、起草、内部评审、迭代到原作者签字确认，每篇要花好几周。附录 C 说，平均每份 rubric 加附录要花几十个小时的人工。论文的筛选过程在附录 B：先用 GPT-4o（gpt-4o-2024-08-06）按一系列提示做初步过滤，排除商业或地理上难以合作的作者、没有实质实证内容的论文、需要多节点分布式训练的论文、依赖闭源预训练模型的论文、需要收集人类数据的论文、细节不足以从零复现的论文、以及主要介绍新软件框架的论文。然后随机选剩下的 Spotlight 和 Oral 论文人工复核，最后联系了 42 位作者，有 20 位同意合作。

Rubric 的叶子节点要拆到足够细，细到“一位熟悉论文的专家能在 15 分钟内判断一条是否满足”。20 篇论文一共 8,316 个叶子节点。节点数最多的论文是关于物理信息神经网络（PINN）训练难题的那篇，一份 rubric 有 2,551 个节点，其中 1,963 个是叶子；节点最少的是关于随机插值（stochastic interpolants）的那篇，只有 94 个节点。节点数在各篇之间差了 27 倍，复现难度本身就很不均匀。

论文内容本身有写得不清楚的地方，团队为每篇论文手工写了一份澄清附录（addendum），内容来自原作者的澄清，也注明了哪些部分不在复现范围内。另外还有一份只给评委看的附录，里面是帮助评委打分更准确的参考信息。

### 评委：SimpleJudge 与 JudgeEval

人工给一份复现打分要几十个小时，规模化评估必须有一个自动评委。团队做了一个简单的基于大语言模型的评委，叫 SimpleJudge。给它一篇论文的 Markdown、完整的 rubric JSON、要判的叶子节点的要求，再加上提交里相关的文件，它就对这个叶子节点打 0 或 1。提交常常太长，放不进上下文，评委先把文件按相关性排序，只取最相关的十个文件。默认用 o3-mini（o3-mini-2025-01-31，推理努力程度设为 high）当评委后端。

光有一个评委还不够，还得证明它准。团队建了一个辅助评估 JudgeEval：拿 4 篇 PaperBench 论文和 1 篇开发集论文的部分复现（有的从零写，有的改原作者代码），请人类专家按 rubric 逐个叶子节点手工打分，把这些人工分数当作金标准，再看自动评委的分数与金标准差多远。注意原作者的代码库也不指望拿满分——作者说这些代码常常不完整、有 bug，而且没有 PaperBench 要求的 reproduce.sh。

JudgeEval 的结果在表 3：o3-mini 当评委时，F1 是 0.83，每篇论文的评分成本约 66 美元；o1 当评委时 F1 是 0.84，但每篇要 830 美元；GPT-4o 是 0.73，每篇 120 美元；o1-mini 是 0.78，每篇 72 美元；GPT-4o-mini 是 0.59，每篇 8 美元；随机基线是 0.49。o3-mini 的性价比最高，是主实验用的评委。按类型拆开看（表 8），o3-mini 在代码开发节点上 F1 只有 0.72，在执行节点上是 0.82，在结果匹配节点上是 0.94——评委最不准的地方，恰恰是模型得分最高的那类节点。

### 实验设置：12 小时、A10、一块 1000 美元的 API 额度

主实验里，每个智能体跑在一个 Ubuntu 24.04 的 Docker 容器里，配一块 A10 GPU。工作目录里有论文的 PDF 和 Markdown、澄清附录和一份任务说明。容器可以联网，智能体可以下载软件包、浏览网页。团队给智能体一个 HuggingFace 的 API 密钥和一个充了 1,000 美元的 OpenAI API 密钥，以备论文实验里需要用到这些服务。

智能体脚手架叫 BasicAgent，基于英国 AI 安全研究所 Inspect AI 的基础智能体（basic agent），是一个简单的 ReAct 式工具调用循环：给它 bash 执行、Python 执行、浏览器和分页文件阅读四个工具，让它一直干到自己选择结束或时间用完。每次运行的最长时限是 12 小时。主实验测了 6 个模型：GPT-4o（gpt-4o-2024-08-06）、o1（o1-2024-12-17，推理努力程度 high）、o3-mini（o3-mini-2025-01-31，推理 high）、DeepSeek-R1、Claude 3.5 Sonnet（New，claude-3-5-sonnet-20241022）、Gemini 2.0 Flash（gemini-2.0-flash），每篇论文跑 3 次。本来还想测 Claude 3.7 Sonnet，但 Anthropic API 的速率限制让实验没能完成。

另外还有一个轻量版 PaperBench Code-Dev：只考代码开发，跳过复现步骤，评委只给代码开发节点打分。这样就不需要 GPU，评委成本也降了约 85%。团队说 Code-Dev 上的表现与完整版 PaperBench 上的表现只有弱相关：o1 的 Pearson 相关系数是 0.48，拟合关系是完整版分数 = 0.45 × Code-Dev 分数 + 0.05。Code-Dev 只能当一个粗糙的先行指标。

### 统计、算力与可得性

主结果是 3 次运行的平均值，误差用平均值的标准误（SEM）表示。论文在附录 I 里逐篇逐次列出了全部结果，并提醒读者：同一篇论文上不同次运行的方差很大，建议别人评估时用多个种子。没有报告 p 值或多重比较校正。

成本方面，跑一次 o1 的 IterativeAgent、12 小时、单篇论文，平均要花约 400 美元的 API 额度；20 篇论文跑一遍就是 8,000 美元；评分还要另加每篇约 66 美元。Code-Dev 版的 rollout 时间可以减半，一遍约 4,000 美元，评分每篇约 10 美元。附录 H 还试了一个实验性的“剪枝 rubric”评委：把 rubric 树剪到深度 3 再打分，评分成本能降 10 倍，评委表现只轻微下降——但那只是在 JudgeEval 里一个提交上的初步结果，作者自己说还有表现不满意的情况。

基准代码已开源。按 NeurIPS / Pineau 检查表，以下几项是“未报告”或“未提供”：p 值、多重比较校正、智能体运行的完整日志、评委的随机种子细节、以及 646 次运行里 10 次黑名单违规具体是哪几篇、哪个模型。报告了的是：论文筛选标准、rubric 构建流程、硬件与脚手架配置、每篇论文 3 次运行、评分成本与 token 用量、以及逐篇逐次的完整结果表。

## 三、主要发现

### 主结果：最好的模型也只拿到 21.0%

在主实验（BasicAgent、每篇 3 次运行、12 小时上限）里，Claude 3.5 Sonnet（New）表现最好，平均复现得分 21.0%（±0.8）。o1（高推理）是 13.2%（±0.3）。其他模型都在 10% 以下：DeepSeek-R1 6.0%（±0.3）、GPT-4o 4.1%（±0.1）、Gemini 2.0 Flash 3.2%（±0.2）、o3-mini（高推理）2.6%（±0.2）。没有一个模型接近复现出一篇论文——21.0% 意味着平均只满足了 rubric 里五分之一多一点的要求。

作者手工检查了智能体的运行日志，发现了一个共同的失败模式：除了 Claude 3.5 Sonnet，其他模型经常提前结束，要么声称自己已经完成了整个复现，要么声称遇到了解决不了的问题。所有智能体都不会围绕有限的时间做策略规划。o3-mini 还经常在工具使用上出问题。作者的判断是：模型能写出多步骤的计划，却执行不了一连串真正落实计划的行动——长时程任务能力是短板。

### 换一个脚手架：o1 涨到 24.4%，Claude 反而跌了

因为模型总提前结束，团队试了一个 BasicAgent 的变体，叫 IterativeAgent：拿掉“结束任务”的工具，逼智能体干满整个时限；每次只让模型走“下一步”，用提示鼓励它一点一点推进。结果很有意思：o1 从 13.2% 涨到 24.4%（±0.7），o3-mini 从 2.6% 涨到 8.5%（±0.8），但 Claude 3.5 Sonnet 从 21.0% 跌到 16.1%（±0.1）。同一个脚手架改动，对不同模型的效果方向相反。作者的解释是，IterativeAgent 的提示调优对 OpenAI 的 o 系列模型更合适；他们推测，如果给 BasicAgent 也加上“不许提前结束”，Claude 的分数可能会超过 o1 的 IterativeAgent 分数。

o1 用 IterativeAgent 跑 36 小时（延长时限），分数是 26.0%（±0.3），比 12 小时的 24.4% 只高 1.6 个百分点。时间给到三倍，分数几乎不动——o1 的得分在第一个小时之后就基本 plateau 了。

这个结果值得小心对待：主实验的“最佳模型”结论是脚手架依赖的。BasicAgent 下最好的是 Claude（21.0%），IterativeAgent 下最好的是 o1（24.4%），36 小时下 o1 是 26.0%。换一套脚手架，排名就换了。

### 按节点类型拆开看：代码写了不少，结果一个也没复现出来

附录表 9 把分数按三种叶子节点类型拆开，这是全篇最说明问题的一张表。BasicAgent 下，Claude 的代码开发节点得分是 35.4%，执行节点只有 1.8%，结果匹配节点只有 0.7%。o1 是 19.5%、5.7%、0.0%。GPT-4o 是 7.7%、0.1%、0.0%。用 IterativeAgent 的 o1，代码开发节点涨到 43.3%，执行节点 4.5%，结果匹配节点仍然是 0.0%。即使是 36 小时的 o1，结果匹配节点也只有 1.4%。

也就是说，模型能写出大量看起来像那么回事的代码（代码开发节点能拿四成），但几乎从来没能把代码跑起来、跑出论文的结果。执行节点和结果匹配节点的分数基本都在个位数，大量是零。这个结构在所有模型上都一样。人类基线在三类节点上的分数是 72.4%、20.4%、8.9%——人类在结果匹配上也只有 8.9%，但比模型的零分高一个量级。

### 人类基线：48 小时后 41.4%，模型 26.6%

团队招了 8 名正在读或已经读完机器学习博士的人（来自伯克利、剑桥、卡内基梅隆、哥伦比亚、康奈尔、普渡、维也纳工业大学、麻省大学阿默斯特），在 4 篇论文的子集上建人类基线。每篇论文收集 3 次独立尝试，参与者被分到他们最有信心复现的论文上，取 3 次里最好的一次当作“专家”分数（best@3）。

在 3 篇论文的子集上（第 4 篇 test-time-model-adaptation 的人类尝试在 24 小时就结束了，所以被排除在 3 篇子集之外），人类 best@3 在 48 小时后达到 41.4%，同一子集上 o1 是 26.6%。图 3 显示，o1 在最初一小时里一度领先人类，但分数在第一个小时后就 plateau 了；人类起步慢——头几个小时可能在消化论文——但在 24 小时后超过模型，并继续往上走。这个“模型起步快、人类后程强”的模式，和 RE-Bench 的结果一致。

这里要小心比较口径：人类是 3 次尝试里最好的一次、48 小时、可以自选最有信心的论文、可以用 ChatGPT 和 GitHub Copilot 这类 AI 助手、其中 4 次尝试还用上了 A100 而不是 A10；模型是 12 小时（或 36 小时）的单次运行、3 次取平均。两者不是同一种赛制。

### 轻量版 Code-Dev：o1 拿到 43.4%，但和完整版只有弱相关

在 PaperBench Code-Dev 上，o1（IterativeAgent）拿到 43.4%（±0.8）。这个数字比完整版的 24.4% 高得多，因为 Code-Dev 只给代码开发节点打分，跳过了执行和结果匹配——而那两类恰恰是模型最弱的地方。但团队自己报告，Code-Dev 上的表现与完整版只有弱相关（o1 的 Pearson r 是 0.48）。一个模型在 Code-Dev 上分数高，并不能可靠地预测它在完整版上分数高。

### 逐篇看：方差很大，同一篇论文三次运行能差几倍

附录表 10 到表 18 列出了每个模型在每篇论文上的 3 次运行。方差非常大。举几个例子：o3-mini 用 IterativeAgent 跑 sequential-neural-score-estimation 这篇，三次分别是 0.680、0.542、0.144，标准误 0.131；o1 用 BasicAgent 跑 sample-specific-masks，三次是 0.448、0.229、0.098；Claude 用 BasicAgent 跑 lbcs，三次是 0.128、0.103、0.364。同一篇论文、同一个模型、三次运行，分数能差三四倍。

各模型相对最擅长的论文也不一样。Claude 用 BasicAgent 平均分最高的一篇是 sequential-neural-score-estimation（0.414），o1 用 IterativeAgent 平均分最高的也是这一篇（0.466）。但 o1 用 BasicAgent 跑这篇只有 0.233。反过来，o1 用 BasicAgent 平均分最高的是 bam（0.253）。有些论文对所有模型都很难：比如 ftrl，Claude 只有 0.093，o1 只有 0.017；rice 在 o3-mini 的 BasicAgent 下只有 0.014。

还有 10 次运行因为用了黑名单资源被取消资格、分数记为 0。646 次运行里有 10 次违规，监控办法是事后在日志里做简单的文本搜索，查黑名单 URL 有没有出现，再人工复核。

### 成本：跑一遍要 8,000 美元，评分另算

跑一次 o1 的 IterativeAgent、12 小时、单篇论文，平均要花约 400 美元的 API 额度；20 篇论文跑一遍就是 8,000 美元；评分还要另加每篇约 66 美元（o3-mini 当评委，平均每篇约 5,000 万输入 token、200 万输出 token）。Code-Dev 版的 rollout 时间可以减半，一遍约 4,000 美元，评分每篇约 10 美元。附录 H 的剪枝 rubric 实验显示，把 rubric 剪到深度 3 再打分，评分成本能降 10 倍，但那只是在 JudgeEval 里一个提交上的初步结果。

## 四、作者的结论与局限

### 作者的结论

论文的结论是：PaperBench 是一个有挑战性的基准，前沿模型离胜任复现一篇前沿论文还差得很远。最强的被测智能体 Claude 3.5 Sonnet 在主实验里平均只拿到 21.0%，说明复现机器学习研究既复杂，当前智能体的长时程任务能力也有限。但早期结果也显示了非实质性的进展：智能体成功实现并验证了论文方法的多个方面，未来改进有希望。

论文没有宣称模型已经能做研究，也没有宣称 21.0% 代表了模型能力的上限。作者明确说，主实验的结果只是一个初始基线，进一步的脚手架工作会带来更好的结果。他们把 PaperBench 定位为衡量、监测和预测 AI 系统自主做 AI 研发能力的一步，而不是最终答案。

### 作者自述的局限

论文第 7 节列出四组局限，值得原原本本记下来。

第一，数据集规模。只有 20 篇论文，理想情况下应该覆盖机器学习社区更大一部分产出。但作者提醒，只数论文篇数会误导：每份 rubric 由几百个节点组成，PaperBench 实际评估的是几千个独立的要求。

第二，污染。几乎所有论文的原作者代码库都在网上。虽然这些代码库常常不完整、有 bug，也不符合 PaperBench 要求的格式，但在大规模语料上预训练过的模型可能已经把解法内化了，导致分数虚高。作者认为，鉴于这些论文很新，现在的模型大概率还没受这个问题影响，但未来的模型可能会。

第三，建数据集太难。写一份详细的 rubric 极其耗费人力，每份都要一位专家花好几整天，还要深刻理解论文、仔细写，避免不准确的要求。作者发现很难培训别人按他们想要的质量写 rubric。这对别人复制这个过程是个挑战，未来的工作可以看看用模型辅助生成 rubric 的办法。

第四，基于大语言模型的评委表现。评委在 JudgeEval 上表现不错，但不如人类专家准确，而且因为用的是非确定性的模型调用，评委本身也不确定。作者期待未来在自动化评委和对抗性提交的压力测试上有更多工作。

附录 A 还补充了三点未来方向：rubric 设计可以引入依赖图（现在的 rubric 里子节点的顺序编码了依赖关系，但没有明确写清哪个要求依赖哪些前置要求）；评委越可靠，rubric 就不需要拆得那么细，两者之间有个权衡值得研究；要防范评委被钻空子——智能体可能有意低估或高估自己在 PaperBench 上的表现，未来的工作可以研究这两种倾向的能力和意愿。

### 未来工作

除了附录 A 的三点，论文第 5 节和第 7 节还提到：Code-Dev 版是为了让评估更便宜、更容易上手；剪枝 rubric 是降低评分成本的实验性方向；随着评委模型变强，可以越来越多地直接给子树打分，而不是逐个叶子节点打分。

## 五、精读点评

这一节是分析者的判断，和上面对论文的呈现分开写。

### 这篇论文真正要回答的问题

这篇论文真正要回答的问题是：前沿模型离“能自己做 AI 研究”还有多远——不是以解题分数衡量，而是以“能不能把一篇前沿论文从头复现出来”衡量。它给出的答案分两层。第一层是工具：20 篇论文加 8,316 个叶子节点的 rubric，确实是一把新的尺子，而且已经量出了东西——最好的模型在主实验里只拿到 21.0%，人类博士在 3 篇论文的子集上 48 小时后是 41.4%。第二层是判断：这把尺子量到的，到底是“复现研究的能力”，还是“在某个脚手架、某个评委、某 20 篇论文上的表现”？论文自己在局限里承认了 20 篇论文、污染、评委不准这三点距离。第一层是这篇论文立住的部分，第二层是它留给读者的问号。

### 科学问题还原：五问

**现象是什么？** 模型在 SWE-bench、Kaggle 类基准上的分数一路上涨，但这些基准考的都是自包含的、带现成评分函数的任务；没有一个基准敢问“模型能不能像研究者那样，把一篇论文从头复现出来”。反常不在于某一次实验失败，而在于“智能体分数”与“研究能力”之间没有换算关系——一个在 SWE-bench 上拿 72% 的模型，到底能不能复现一篇 ICML 论文，没人说得清。更尖锐的是，安全框架（OpenAI 的 Preparedness、Anthropic 的 Responsible Scaling Policy、DeepMind 的 Frontier Safety Framework）都需要一个“自主研发能力”的度量，但手头没有这样的尺子。

**为什么重要，不解决会怎样？** 对实践来说，没有能量“复现研究”的评估，实验室和政策制定者就不知道模型离自主做 AI 研究还有多远，关于“AI 加速 AI 研究”的讨论只能凭感觉；等模型真的能大规模自主做研究了，才发现没有提前准备，那就晚了。对领域来说，没有更难、更真实的基准，智能体进展的宣称就无法比较——“72%”这个数字本身可能就是被自包含任务撑起来的。这篇论文的重要性首先在于它提供了一个更难的、带原作者背书的公共比较点。

**为什么之前做不了？** 卡住的点有三个。第一，评分没法自动化：复现的产出是一个完整的代码库加实验结果，没法像解题那样用程序判对错，只能靠人一条一条对着标准看——这篇论文动用了和 20 位原作者合作、每篇花几周写 rubric 的笨办法。第二，标准本身难定：什么叫“复现了”，每个原作者的理解都不一样，需要原作者亲自签字确认。第三，人工评分太贵：给一份复现打分要几十个小时，规模化评估根本跑不起来——这篇论文用 LLM 评委加 JudgeEval 绕过了这一块。这篇论文移走的石头主要是第一块和第三块：它手工建了 20 份原作者背书的 rubric，并证明了一个 F1 为 0.83 的自动评委大致可用。第二块是数据源本身带来的，不是方法上的突破——没有原作者合作，rubric 的权威性就立不住。

**方法与问题是否匹配？** 匹配点是真实的，但只覆盖了问题的一部分。用原作者背书的 rubric 加“在干净机器上重跑 reproduce.sh”，确实能量出“在结构清晰的复现任务上，模型与人类博士的差距”，而且 8,316 个叶子节点让部分进展也能被量到。但复现论文与做原创研究之间有系统性差异：复现的目标是已知的（论文就摆在那），原创研究的目标是未知的；复现只需要“照着做”，原创研究还要“想出来做什么”。论文在局限里承认了 20 篇论文和评委不准这两点，但没有明说“复现不等于原创研究”这一层。所以方法回答的是“复现前沿研究”，而不是“做前沿研究”。把 21.0% 读成“模型离自主做研究还有多远”，就是方法与问题不匹配的地方。

**答案改变了什么？** 认知上，它第一次给出了模型复现研究能力的公开、可比较的数字：最好的模型在主实验里只拿到 21.0%，而且按节点类型拆开看，模型在“真正复现出结果”这一项上几乎全是零分。这改变了“智能体分数一路涨，所以模型快能做研究了”的直觉——换一把更难的尺子，分数立刻掉下来，而且掉下来的部分恰恰是最关键的那部分。实践上，它留下了一个开源基准、一套 rubric 写法、一个自动评委和一个评委评估集，任何实验室都可以拿来测自己的模型。至于“模型离自主做 AI 研究还有多远”这个更大的问题，答案是什么都没改变——PaperBench 只能告诉你它在 20 篇 ICML 2024 论文的复现上离人类博士还有多远。

### 价值判断

认知价值是中等偏高。论文没有推翻某个具体的旧信念，但它第一次把“复现前沿研究”变成了一个可公开比较的数字，并且量出了一个反直觉的结构：模型在代码开发节点上能拿四成，在执行和结果匹配节点上却几乎全是零分；模型起步比人类快、一个小时后就 plateau，人类 24 小时后反超。反事实是：如果这篇论文不存在，“o1 在 SWE-bench 上 72%”这类数字会一直没有更难的公共标尺来检验，关于“模型会不会自己做研究”的讨论会继续停留在自包含任务撑起来的分数上。

方法价值是高的。它留下的可复用东西不止一个：20 份原作者背书的 rubric、8,316 个叶子节点的分层评分设计、三种叶子节点类型（代码开发、执行、结果匹配）的分工、SimpleJudge 评委加 JudgeEval 评委评估集、以及“干净机器重跑 reproduce.sh”的防作弊设计。任何想评估智能体做研究能力的人，都能直接拿走这套设计。扣分项是建 rubric 的成本太高（每篇几周），别人很难复制这个过程。

边界价值是高的，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：21.0% 能代表模型做原创研究的能力；Code-Dev 上的 43.4% 能预测完整版上的表现（相关系数只有 0.48）；人类基线的 41.4% 与模型的 26.6% 是在同一种赛制下比出来的（不是）；以及污染对未来模型也没有影响（作者自己承认未来模型可能会受影响）。读者最容易误读的推论，是把“Claude 拿到 21.0%”读成“Claude 是复现研究最强的模型”——换一套脚手架，o1 就反超到 24.4%，而且 Claude 3.7 根本没测成。论文自己在局限里划了这条线，但 21.0% 这个数字太容易单独流传，流传时限定条件最容易被丢掉。

启示价值在于，最便宜的决定性实验不是再跑一遍 PaperBench，而是做一次“换评委”的对照：用人类专家重评主实验里得分最高的那些提交，看 21.0% 这个数字在人类评委手里还剩多少。具体设计在下面“接下来看什么”里写。

### 最弱的一环

最弱的一环在“21.0% 这个分数”与“复现能力”之间。整篇论文的说服力，有一半建立在自动评委这个度量上——它是 PaperBench 区别于人工评估的两大卖点之一（另一个是原作者背书的 rubric）。但评委是 o3-mini，F1 只有 0.83，而且按类型拆开看，它在代码开发节点上的 F1 只有 0.72，是三类节点里最差的；而模型的总分恰恰主要由代码开发节点贡献（Claude 的 35.4% 对 1.8% 对 0.7%）。也就是说，总分里权重最大的那部分，是评委最不准的那部分。评委还不是确定性的——同样的提交，评委可能打出不同的分数。论文用 JudgeEval 证明了评委“大致可用”，但 JudgeEval 只有 5 篇论文的部分复现，金标准本身也是人工打分，样本很小。如果评委的误差是系统性的（比如倾向于给“看起来像那么回事的代码”打高分），21.0% 这个数字作为“复现能力”的证据就要大打折扣。

第二弱的一环是“最佳模型”的结论是脚手架依赖的。BasicAgent 下 Claude 最好（21.0%），IterativeAgent 下 o1 最好（24.4%），36 小时下 o1 是 26.0%。作者自己也承认，IterativeAgent 的提示调优对 o 系列模型更合适。主实验的排名，与其说是“模型能力的排名”，不如说是“模型配这套脚手架的排名”。Claude 3.7 因为速率限制根本没测成，最强的候选人不在场上。

第三弱的一环是人类基线的比较口径。人类是 3 次尝试里最好的一次、48 小时、可以自选最有信心的论文、可以用 AI 助手、其中 4 次尝试还用上了 A100；模型是 12 小时的单次运行、3 次取平均。41.4% 对 26.6% 这个对比，混了“最好一次对平均”“48 小时对 12 小时”“自选论文对指定论文”三重不对称。人类确实更强，但强多少，这个数字说不清。

### 效度判断

下面是针对论文作为证据的评分，满分 5 分，评的是证据，不是模型本身。

内部效度 3 分。评估设计有不少严谨之处：干净机器重跑 reproduce.sh 防硬编码、黑名单加事后日志监控、每篇论文 3 次运行并报告标准误、逐篇逐次的完整结果都公开、污染问题有明确讨论。扣分项是：主结果的分数由 F1 只有 0.83 的模型评委打出，而且评委在代码开发节点上最不准；黑名单监控只是事后在日志里做简单的文本搜索，只能抓到出现过黑名单 URL 的情况，抓不到模型凭记忆写出的解法；逐篇结果的方差很大，3 次运行的平均值仍然不稳定。

外部效度 2 分。结果能推广到 ICML 2024 的 Spotlight 和 Oral 论文的复现，这是论文的强项：20 篇论文、12 个主题、8,316 个叶子节点。但推广到其他年份、其他会议、其他领域、以及“做原创研究”，论文自己承认没有证据；20 篇论文的样本很小，而且是从联系了 42 位作者、只有 20 位同意合作这个有选择性的过程里来的；建 rubric 的成本太高，别人很难把这套办法用到新的论文集上。21.0% 作为“模型离自主做研究还有多远”的信号，是这篇论文最薄弱的一环。

构念效度 3 分。复现得分确实量的是“在 PaperBench 的 rubric 上满足了多少要求”，有原作者背书和干净机器重跑做锚，比较扎实。但“复现得分”不等于“复现能力”——它混了三类节点，其中代码开发节点的权重最大，而那类节点量的是“代码看起来对不对”，不是“结果是不是真复现了”；“人类基线”不等于“人类博士的真实水平”，因为人类可以用 AI 助手、可以自选论文。主指标把三类节点压成一个总分，也丢掉了“代码写了不少、结果一个没复现”这个最关键的结构信息——好在附录表 9 把它补了回来。

统计结论效度 3 分。主结果是 3 次运行的平均值，带标准误，逐篇逐次的结果全部公开，方差问题作者自己也提醒了。扣分项是：没有 p 值、多重比较校正；图 3、图 5、图 6 的核心数字只在图里，没有数值表；人类基线只有 4 篇论文、每篇 3 次尝试，41.4% 这个数字的误差范围没有报告；Code-Dev 与完整版的相关系数 0.48 只基于 o1 一个模型。

可复现性 4 分。方法描述相当完整：筛选标准、rubric 构建流程、硬件与脚手架配置、评委实现细节、成本与 token 用量都给了，基准代码、rubric 和评委都开源了，一个能干的读者能按描述重建评估。扣分项是：完整跑一遍主实验要花约 8,000 美元的 API 额度加评分成本，别人很难原样重跑；智能体运行的完整日志没有发布；评委是非确定性的，别人重跑一次未必得到同样的分数。没有这些，标题数字只能在“基准可复现、实验难复现”的意义上成立。

### 其他可能的解释

同一个结果，至少有三种别的解释也能说得通。

第一种是“评委偏爱解释”。Claude 在代码开发节点上得分最高（35.4%），而评委在代码开发节点上最不准（F1 0.72）。有可能 Claude 的代码“看起来更像那么回事”，评委更容易给它打高分，而 o1 的代码风格不同，评委更苛刻。预测：用人类专家重评同一批提交，Claude 与 o1 的差距会缩小。区分证据：人类重评主实验里得分最高的提交。

第二种是“脚手架解释”。o1 在 IterativeAgent 下从 13.2% 涨到 24.4%，Claude 反而从 21.0% 跌到 16.1%，说明主实验的排名可能不完全是模型能力，而是某套脚手架与某个模型特别合拍。预测：换两三套不同的脚手架，模型排名会变化。区分证据：换脚手架重跑六个模型。

第三种是“论文选择解释”。20 篇论文是从联系了 42 位作者、只有 20 位同意合作这个有选择性的过程里来的，而且节点数在各篇之间差了 27 倍（94 到 2,551）。有可能这 20 篇论文的构成对某个模型更有利，而不是某个模型在一般意义上更强。预测：在另外 20 篇论文上，模型排名会变化。区分证据：用团队提到的内部保留集（held-out set）重测。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

“Claude 3.5 Sonnet 是复现研究最强的模型”：换两三套不同的脚手架重跑六个模型。如果模型排名变了（比如 o1 在另一套脚手架上超过 Claude，或者 Claude 3.7 测成之后超过两者），“Claude 最强”就只能退回为“Claude 配 BasicAgent 最强”。

“21.0% 这个分数代表复现能力”：用人类专家重评主实验里得分最高的那些提交。如果人类评委给出的分数与 o3-mini 评委给出的分数系统性地不一样（比如 Claude 的分数掉得比 o1 多），自动评分作为能力度量的主张即被反驳。

“模型在结果匹配上几乎全是零分，说明它们不会真正复现结果”：给模型更长的时限（比如 72 小时）或者更好的脚手架重跑。如果结果匹配节点的分数大幅上升，零分就只是“时间不够”或“脚手架太差”的产物，而不是能力的硬上限。

“人类博士比模型强得多”：让模型也在 48 小时、3 次取最好一次、自选论文的口径下跑。如果口径对齐后模型与人类的差距大幅缩小，41.4% 对 26.6% 这个对比就不能直接当成能力差距。

“Code-Dev 能预测完整版表现”：在更多模型上算 Code-Dev 与完整版的相关系数。如果相关系数继续徘徊在 0.5 上下，Code-Dev 就只能当一个粗糙的先行指标，不能当完整版的替代品。

### 替代解释

替代解释一：评委偏爱解释。Claude 在代码开发节点上得分最高（35.4%），而评委在代码开发节点上最不准（F1 0.72）。有可能 Claude 的代码“看起来更像那么回事”，评委更容易给它打高分，而 o1 的代码风格不同，评委更苛刻。预测：用人类专家重评同一批提交，Claude 与 o1 的差距会缩小。区分证据：人类重评主实验里得分最高的提交。

替代解释二：脚手架解释。o1 在 IterativeAgent 下从 13.2% 涨到 24.4%，Claude 反而从 21.0% 跌到 16.1%，可能说明主实验的排名不完全是模型能力，而是某套脚手架与某个模型特别合拍。预测：在另外两三套脚手架上，模型排名会变化。区分证据：换脚手架重跑六个模型。

替代解释三：论文选择解释。20 篇论文是从联系了 42 位作者、只有 20 位同意合作这个有选择性的过程里来的，而且节点数在各篇之间差了 27 倍（94 到 2,551）。可能这 20 篇论文的构成对某个模型更有利，而不是某个模型在一般意义上更强。预测：在另外 20 篇论文上，模型排名会变化。区分证据：用团队提到的内部保留集（held-out set）重测。

替代解释四：记忆解释。几乎所有论文的原作者代码库都在网上，模型在预训练时可能见过这些代码或论文本身。21.0% 里可能有一部分不是“复现能力”，而是“背诵”。预测：在 2025 年之后发表的、模型训练时没见过的论文上，模型分数会大幅下跌。区分证据：用更新的论文建一个新子集重测。

### 作者自述局限与分析者发现的局限

作者自述的局限见第四节：数据集规模、污染、建数据集太难、评委表现。

分析者发现的、作者没说的局限有五点。第一，主结果的分数由 F1 只有 0.83 的模型评委打出，而且评委在代码开发节点上最不准（F1 0.72），而总分主要由这类节点贡献。第二，“最佳模型”的结论是脚手架依赖的，BasicAgent 下 Claude 最好，IterativeAgent 下 o1 最好，Claude 3.7 根本没测成。第三，人类基线的比较口径不对称：人类是 3 次取最好、48 小时、可自选论文、可用 AI 助手，模型是 12 小时、3 次取平均。第四，黑名单监控只是事后在日志里做简单的文本搜索，只能抓到出现过黑名单 URL 的情况，抓不到模型凭记忆写出的解法。第五，附录表 9 的注说 o1（IterativeAgent）与 Gemini 2.0 Flash（BasicAgent）的标准误按 2 个种子算，但附录表 12 与表 17 列出了 3 次运行（表 17 还注明其中一次因基础设施问题失败），论文内部说法不一致。

### 接下来看什么

最值得先做的，是做一次“换评委”的对照：用人类专家重评主实验里得分最高的那些提交，看 21.0% 这个数字在人类评委手里还剩多少。这是启示价值里最便宜的决定性实验，也是全篇最缺的一块。

具体设计：取 Claude（BasicAgent）与 o1（IterativeAgent）在 20 篇论文上的最高分提交，请不知道模型身份的人类专家按 rubric 逐个叶子节点重评，重点看代码开发节点——那是评委最不准、模型得分最高的一类。

判据很简单：如果人类评委给出的分数与 o3-mini 评委给出的分数基本一致（比如差距在 3 个百分点以内），自动评分作为能力度量的主张就得到支持；如果人类评委给 Claude 的分数掉得比 o1 多，或者两者的排名翻过来了，21.0% 这个数字就要收回到“在 o3-mini 评委手里的分数”这个更窄的范围。

其次是把脚手架解释弄清楚。成本很低：只需要给 BasicAgent 也加上“不许提前结束”，或者给 IterativeAgent 换一套对 Claude 更友好的提示，看 Claude 的分数能不能超过 o1 的 24.4%。如果能，主实验的排名就要重写；如果不能，o1 在 IterativeAgent 下的领先才是扎实的。

再往后看三件事：用团队提到的内部保留集重测，看 20 篇论文的构成有没有偏向某个模型；把人类基线的口径对齐（同样 48 小时、3 次取最好一次），看 41.4% 对 26.6% 的差距还剩多少；用 2025 年之后发表的论文建一个新子集，看记忆解释能解释掉多少分。这三项都不需要建新基准，成本低，信息量大。

最后是 Claude 3.7 Sonnet：论文说因为 Anthropic API 的速率限制没能测成。值得关注的后续工作是：Claude 3.7 测成之后，主实验的排名会不会变——如果它超过 21.0%，“Claude 3.5 是最好的模型”这个结论就要修正。

## I. 结论、结果与价值总览

### 一句话结论

在 20 篇 ICML 2024 论文的从零复现任务上，最好的模型 Claude 3.5 Sonnet 也只拿到 21.0%，而且在“真正复现出结果”这一项上几乎全是零分；前沿模型离自主做研究还差得很远，但 21.0% 这个分数本身由一个 F1 只有 0.83 的模型评委打出，含金量要打折。

### 核心结论

1. **最好的模型也只拿到 21.0%（置信度：高）。** 表 4：Claude 3.5 Sonnet（New）在 BasicAgent 下平均复现得分 21.0%（±0.8），o1 是 13.2%（±0.3），其他模型都在 10% 以下。

2. **换一套脚手架，排名就换了（置信度：高）。** 表 5：o1 用 IterativeAgent 从 13.2% 涨到 24.4%，Claude 反而从 21.0% 跌到 16.1%。“最佳模型”的结论是脚手架依赖的。

3. **模型在“真正复现出结果”上几乎全是零分（置信度：高）。** 附录表 9：Claude 的代码开发节点 35.4%，执行节点 1.8%，结果匹配节点 0.7%；o1（IterativeAgent）是 43.3%、4.5%、0.0%。模型能写代码，但几乎从来没能跑出论文的结果。

4. **人类博士 48 小时后 41.4%，模型 26.6%（置信度：中）。** 引言与 §5.4：3 篇论文子集上人类 best@3 是 41.4%，o1 是 26.6%；o1 在第一个小时后就 plateau，人类在 24 小时后反超。但比较口径不对称，差距的具体大小说不清。

5. **自动评委大致可用，但不准（置信度：中）。** 表 3：o3-mini 当评委时 F1 是 0.83，每篇约 66 美元；o1 是 0.84，但每篇 830 美元。评委在代码开发节点上 F1 只有 0.72，而模型总分主要由这类节点贡献。

6. **Code-Dev 上的 43.4% 预测不了完整版（置信度：中）。** §2.6：o1 在 Code-Dev 上 43.4%，与完整版的相关系数只有 0.48。Code-Dev 只能当粗糙的先行指标。

### 科学价值总评

认知价值是中等偏高。第一次把“复现前沿研究”变成了一个可公开比较的数字，量出了“代码开发节点能拿四成、结果匹配节点几乎全是零分”和“模型起步快、一个小时后 plateau、人类 24 小时后反超”这两个反直觉的结构，改变了“智能体分数一路涨，所以模型快能做研究了”的直觉。

方法价值是高的。留下了可复用的 20 份原作者背书的 rubric、8,316 个叶子节点的分层评分设计、三种叶子节点类型的分工、SimpleJudge 评委加 JudgeEval 评委评估集、以及干净机器重跑 reproduce.sh 的防作弊设计。扣分项是建 rubric 的成本太高（每篇几周），别人很难复制这个过程。

边界价值是高的。它明确不证明：21.0% 能代表模型做原创研究的能力；Code-Dev 上的 43.4% 能预测完整版上的表现；人类基线的 41.4% 与模型的 26.6% 是在同一种赛制下比出来的；污染对未来模型也没有影响。最容易误读的推论是把“Claude 拿到 21.0%”读成“Claude 是复现研究最强的模型”——换一套脚手架，o1 就反超到 24.4%，而且 Claude 3.7 根本没测成。

启示价值在于，最便宜的决定性实验是做一次“换评委”的对照：用人类专家重评主实验里得分最高的那些提交，看 21.0% 这个数字在人类评委手里还剩多少。

总体 verdict 是：这篇工作值得被记住为第一个让智能体从零复现前沿论文的硬基准，以及一套可复用的 rubric 加自动评委的评估方法。不值得被记住为“模型离自主做研究还有多远”的答案——复现不等于原创研究，那一步它没有量到，也不该用它的数字去量。

### 适用边界

不要用这篇论文论证模型已经能做原创研究，不要用 21.0% 论证 Claude 是复现研究最强的模型，不要用 Code-Dev 的 43.4% 论证模型在完整版上也有这个水平，不要用 41.4% 对 26.6% 论证人类博士只比模型强这么多，不要引用图 3、图 5、图 6 里的数值为已确立的数字。

可以引用的是表 4 的主实验结果（带脚手架依赖的提醒）、附录表 9 的节点类型拆分（这是全篇最关键的结构）、表 3 的评委 F1 与成本、§5.4 的人类基线（带比较口径不对称的提醒）、以及 20 篇论文与 8,316 个叶子节点的基准规模。引用 21.0% 时，须同时说明结果匹配节点几乎全是零分。
