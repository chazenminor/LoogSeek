## 一、背景与问题

### 发布之前是什么局面

GPT-4o 是 OpenAI 在 2024 年 5 月推出的旗舰多模态模型，也是 API 里的主力。到了 2025 年初，开发者对它的抱怨集中在三处。第一，写代码时改动不干净：改 diff 格式总出错，顺手多改与任务无关的地方，agent 式地解真实软件工程任务时成功率不高。第二，指令遵循不可靠：长对话里记不住前面的要求，格式、否定、排序这类指令时灵时不灵，应用一上规模就得靠大量重试和兜底。第三，上下文太短：128K token 的窗口装不下整个代码库或一摞长文档，信息藏在中间就容易丢，跨文档推理更是勉强。

与此同时，OpenAI 在 2025 年 2 月以研究预览（research preview）的形式推出了 GPT-4.5，一个大而贵、算力密集的模型，用来探索规模上限和收集开发者反馈。GPT-4.5 的创意、写作、幽默得到了好评，但价格和延迟让它没法成为日常 API 模型。GPT-4.1 的发布，就是要把 GPT-4o 的实用路线往前推一步，同时把 GPT-4.5 这条昂贵的探索路线收掉：帖子明确说，GPT-4.5 Preview 将在三个月后、2025 年 7 月 14 日下线，理由是 GPT-4.1 在许多关键能力上达到或超过了它，而成本和延迟要低得多。

### 这篇发布帖要回答的问题

这篇帖子要做的，是向开发者宣布三个新模型——GPT-4.1、GPT-4.1 mini、GPT-4.1 nano——并证明它们值得从 GPT-4o 迁移过来。它要回答的问题分三层。第一层，三个模型是什么：在能力—成本—延迟这条线上各占什么位置，mini 和 nano 是不是只是缩水版。第二层，它们比 GPT-4o 强在哪：编码、指令遵循、长上下文这三项主打能力，分别强多少。第三层，它们在真实开发者的生产任务上好不好用：六家 alpha 测试伙伴（Windsurf、Qodo、Hex、Blue J、Thomson Reuters、Carlyle）的内部评测结果。

它没有回答的问题同样重要：模型是怎么训出来的。帖子里没有任何关于训练数据、模型规模、架构、训练方法的信息。这是一篇产品发布帖，不是技术报告，读的时候要按这个定位来衡量它。

## 二、方法与设计

### 三个模型是什么

GPT-4.1 是旗舰，GPT-4.1 mini 是小模型，GPT-4.1 nano 是 OpenAI 有史以来第一个 nano 模型，也是当时最快、最便宜的模型。三个模型共享同一条主线：1M token 的上下文窗口（GPT-4o 是 128K），知识截止（knowledge cutoff）更新到 2024 年 6 月，输出 token 上限提高到 32,768（GPT-4o 是 16,384）。

三个模型的定位各不相同。GPT-4.1 主打“在每一点上都更强”：编码和指令遵循大幅超过 GPT-4o，长上下文理解更好。GPT-4.1 mini 主打“小模型的跃升”：在许多基准上打平甚至超过 GPT-4o，延迟几乎减半，成本降低 83%。GPT-4.1 nano 主打“极低延迟与极低成本”：1M 上下文，MMLU 80.1%、GPQA 50.3%、Aider polyglot 编码 9.8%，都高于 GPT-4o mini，适合分类、自动补全这类任务。

一个关键的可用性限定写在正文里：GPT-4.1 只通过 API 提供，不进 ChatGPT。ChatGPT 里的 GPT-4o 会逐步吸收 GPT-4.1 在指令遵循、编码和智能上的改进，但 GPT-4.1 本身不出现在 ChatGPT 中。

### 评估是怎么做的：三类证据

帖子的证据分三类，严谨程度逐级下降。

第一类是公开基准。附录给了一张全量表，覆盖学术知识、编码、指令遵循、长上下文、视觉、函数调用六类，对照模型包括 GPT-4o（2024-11-20 版）、GPT-4o mini、o1（high）、o3-mini（high）和 GPT-4.5。公开基准的定义、评分方式大多有脚注说明。例如 SWE-bench Verified 的脚注说，500 道题里有 23 道因基础设施跑不起来而被省略；如果把这 23 道保守地记为 0 分，54.6% 会变成 52.1%。MultiChallenge 的脚注说，默认评分器 GPT-4o 经常误判，换成 o3-mini 当评分器后分数会显著提高，帖子把两套结果都公布了。GPQA 的脚注说，他们用模型抽答案而不是正则表达式，对 GPT-4.1 的影响不到 1%，对 GPT-4o 则能把分数从约 46% 提到约 54%——也就是说，GPT-4o 的 GPQA 46.0% 是抽取方式更友好的口径下的数字。

第二类是 OpenAI 的内部评测。包括内部指令遵循评测（分格式遵循、否定指令、有序指令、内容要求、排序、过度自信六类，每类再分易、中、难三档）、needle-in-a-haystack（大海捞针）长上下文检索评测，以及两个新开源的长上下文评测 OpenAI-MRCR（多轮共指消解）和 Graphwalks（多跳长上下文推理）。内部评测没有公开实现细节，只有结果数字和一句话的方法描述。

第三类是合作伙伴的内部评测。六家 alpha 测试伙伴在自己的生产任务上测了 GPT-4.1：Windsurf 的内部编码基准、Qodo 的代码审查对比、Hex 的 SQL 评测集、Blue J 的税务场景基准、Thomson Reuters 的 CoCounsel 多文档审查、Carlyle 的金融文档抽取。这些结果是合作伙伴自述的，没有公开方法、样本量或统计细节，帖子只引用了它们的结论性数字。

### 两个新开源的长上下文评测

帖子顺带发布了两个新的长上下文评测数据集。OpenAI-MRCR（Multi-Round Coreference，多轮共指消解）考的是在多轮合成对话里，从 2 个、4 个或 8 个相同的请求中找出与指定实例对应的回答，例如“给我第三首关于食蚁兽的诗”。难点在于干扰项之间只有细微差别：一篇关于食蚁兽的短故事而不是诗，或者一首关于青蛙而不是食蚁兽的诗，都很容易误导模型。

Graphwalks 考的是多跳长上下文推理：把上下文填满一个由十六进制哈希组成的有向图，让模型从一个随机节点出发做广度优先搜索（BFS），返回某一深度的全部节点。帖子说，一个模型甚至一个人理论上可以一遍读完就解出 OpenAI-MRCR，但 Graphwalks 要求跨多个位置推理，不能顺序求解。

### 延迟与定价

帖子还报告了推理延迟。初步测试里，GPT-4.1 在 128K token 上下文下首 token 延迟约 15 秒，1M token 上下文下约 1 分钟。mini 和 nano 更快，nano 在 128K 输入下大多数时候不到 5 秒就返回首 token。帖子说推理栈的改进降低了首 token 时间，提示缓存（prompt caching）能进一步降延迟、省成本。

定价按每 1M token 计：GPT-4.1 输入 2.00 美元、缓存输入 0.50 美元、输出 8.00 美元，混合定价 1.84 美元；mini 是 0.40 / 0.10 / 1.60 美元，混合 0.42 美元；nano 是 0.10 / 0.025 / 0.40 美元，混合 0.12 美元。帖子说 GPT-4.1 对中位数查询比 GPT-4o 便宜 26%，提示缓存折扣从 50% 提高到 75%，长上下文请求不额外加价，Batch API 再打五折。

按 NeurIPS / Pineau 检查表，以下几项是“未报告”或“未提供”：训练数据、模型规模与架构、训练方法与算力、超参数、随机种子与运行次数、误差棒与统计显著性、公开基准的具体评估配置（除 SWE-bench Verified 的 cookbook 链接外）、内部评测的实现细节、合作伙伴评测的方法与样本量、前端编码对比的人类评分细节（评分人数、样本量、统计方法）、以及 system card。

## 三、主要发现

### 编码：SWE-bench Verified 上 54.6%，但有两处要打折

在 SWE-bench Verified 上，GPT-4.1 完成 54.6% 的任务，GPT-4o（2024-11-20）是 33.2%，o1 是 41.0%，o3-mini 是 49.3%，GPT-4.5 是 38.0%。正文说这是比 GPT-4o 高 21.4 个百分点、比 GPT-4.5 高 26.6 个百分点。第一个数字与附录表一致（54.6 − 33.2 = 21.4），第二个数字与附录表对不上：按附录表 GPT-4.5 的 38.0% 算，差距是 16.6 个百分点，不是 26.6 个百分点。这个出入见第六节与文末未核实清单，帖子没有解释。

另外，54.6% 这个数字本身建立在省略 23 道题的基础上。脚注说，500 道题里有 23 道因基础设施跑不起来而被省略；如果把这 23 道保守地记为 0 分，54.6% 会变成 52.1%。帖子把这一点写进了脚注，但正文只引用 54.6%。

在 Aider polyglot 编码基准上，GPT-4.1 的 diff 格式得分 52.9%，GPT-4o 是 18.2%，GPT-4.5 是 44.9%。正文说 GPT-4.1 的分数是 GPT-4o 的两倍多、比 GPT-4.5 高 8 个百分点，两个说法都与附录表一致。whole 格式下 GPT-4.1 是 51.6%，GPT-4o 是 30.7%。不过附录表也显示，在这个基准上 o1（diff 61.7%）和 o3-mini（diff 60.4%）都高于 GPT-4.1。

在 SWE-Lancer 上，GPT-4.1 赚到 176K 美元（完成率 35.1%），GPT-4o 是 163K 美元（32.6%），但 GPT-4.5 是 186K 美元（37.3%），高于 GPT-4.1。IC-Diamond 子集上 GPT-4.1 是 34K 美元（14.4%），GPT-4.5 是 41K 美元（17.4%），同样高于 GPT-4.1。也就是说，在“真实软件工程任务能赚多少钱”这个指标上，GPT-4.1 并没有赢过 GPT-4.5。

前端编码上，帖子说，在付费人类评分员的面对面比较里，GPT-4.1 生成的网站 80% 的时间优于 GPT-4o。评分人数、比较的样本量、统计方法都没有报告。

内部评测方面，代码无关改动（extraneous edits）的比例从 GPT-4o 的 9% 降到 GPT-4.1 的 2%。这个数字没有样本量和评估细节。

### 指令遵循：提升是真实的，但推理模型仍然更高

在 Scale 的 MultiChallenge 多轮指令遵循基准上，GPT-4.1 得 38.3%，GPT-4o 是 27.8%，高 10.5 个百分点，与正文一致。换 o3-mini 当评分器后，GPT-4.1 是 46.2%，GPT-4o 是 39.9%。但附录表也显示，o1 是 44.9%（o3-mini 评分器下 52.9%），o3-mini 是 39.9%（50.2%），GPT-4.5 是 43.8%（50.1%）——GPT-4.1 在这个基准上并没有超过推理模型和 GPT-4.5。

在 IFEval 上，GPT-4.1 是 87.4%，GPT-4o 是 81.0%。在内部指令遵循评测的 hard 档上，GPT-4.1 是 49.1%，GPT-4o 是 29.2%，o1 是 51.3%，o3-mini 是 50.0%，GPT-4.5 是 54.0%——同样，推理模型和 GPT-4.5 更高。在 COLLIE 上，GPT-4.1 是 65.8%，GPT-4o 是 50.2%，但 o1 是 95.3%，o3-mini 是 98.7%，差距非常大。

正文还提到一个使用上的提醒：早期测试者发现 GPT-4.1 会更字面地执行指令，所以建议在提示里写得明确、具体。

### 长上下文：1M 窗口是真的，但长到 1M 之后性能掉得厉害

三个模型都能处理 1M token 的上下文，是 GPT-4o 128K 的约 8 倍。帖子说 GPT-4.1 在所有位置、所有上下文长度上都能准确找回藏起来的“针”，一直到 1M token。但这句话没有配数字：needle-in-a-haystack 的准确率数值只在图里，正文没有给出，本文件按未核实处理，不印数字。

有数字的是两个新评测。OpenAI-MRCR 上，2 个针、128K 上下文时 GPT-4.1 是 57.2%，GPT-4o 是 31.9%；2 个针、1M 上下文时 GPT-4.1 是 46.3%，mini 是 33.3%，nano 是 12.0%。从 128K 到 1M，GPT-4.1 的分数掉了约 11 个百分点，nano 掉了约 25 个百分点。帖子说 GPT-4.1 在 128K 以内优于 GPT-4o、在 1M 时仍保持强劲表现，这与数字一致，但“强劲”要打折：46.3% 意味着超过一半的情况找不对。

Graphwalks 上，BFS、128K 以内时 GPT-4.1 是 61.7%，GPT-4o 是 41.7%，o1 是 62.0%，GPT-4.5 是 72.3%。正文说 GPT-4.1“与 o1 相当”，与数字基本一致（61.7% 对 62.0%），但 GPT-4.5 明显更高。BFS、超过 128K 时 GPT-4.1 跌到 19.0%，mini 是 15.0%，nano 是 2.9%。parents 任务上，128K 以内 GPT-4.1 是 58.0%，超过 128K 后是 25.0%。也就是说，窗口能开到 1M，但超过 128K 之后，多跳推理的准确率掉了一大半。

### 视觉：mini 的跃升是真的

在 Video-MME（long、无字幕）上，GPT-4.1 得 72.0%，GPT-4o 是 65.3%，高 6.7 个百分点，正文称之为新的 state-of-the-art，与附录表一致。MMMU 上 GPT-4.1 是 74.8%，GPT-4o 是 68.7%，mini 是 72.7%，nano 是 55.4%。MathVista 上 GPT-4.1 是 72.2%，GPT-4o 是 61.4%，mini 是 73.1%，反而略高于 GPT-4.1。CharXiv-R 上 GPT-4.1 是 56.7%，GPT-4o 是 52.7%；CharXiv-D 上 GPT-4.1 是 87.9%，GPT-4o 是 85.3%。帖子说 mini 在图像基准上经常打败 GPT-4o，附录表支持这个说法。

### 学术知识与函数调用：不是全面领先

学术知识类基准上，GPT-4.1 的 MMLU 是 90.2%，GPT-4o 是 85.7%，GPT-4.5 是 90.8%，o1 是 91.8%。GPQA Diamond 是 66.3%，GPT-4o 是 46.0%，但 o1 是 75.7%，o3-mini 是 77.2%。AIME '24 是 48.1%，GPT-4o 是 13.1%，但 o1 是 74.3%，o3-mini 是 87.3%。GPT-4.1 比 GPT-4o 强得多，但离推理模型还差得远。

函数调用上有一处 GPT-4.1 输给 GPT-4o 的地方：ComplexFuncBench 上 GPT-4.1 是 65.5%，GPT-4o 是 66.5%。tau-bench airline 上 GPT-4.1 是 49.4%，GPT-4o 是 42.8%；retail 上 GPT-4.1 是 68.0%（用 GPT-4.1 当用户模型时是 73.6%），GPT-4o 是 60.3%。

### 合作伙伴的证言：数字好看，方法没有

六家合作伙伴的说法都指向同一个方向：GPT-4.1 在各自的生产任务上比 GPT-4o 好用。Windsurf 说内部编码基准上 GPT-4.1 比 GPT-4o 高 60%，工具调用效率高 30%，重复不必要的编辑或过窄增量读代码的可能性低约 50%。Qodo 说在 200 个真实 pull request 上，GPT-4.1 的建议在 55% 的情况下更好。Blue J 说在最难的真实税务场景内部基准上准确率高 53%。Hex 说在最难的 SQL 评测集上有接近 2 倍的提升。Thomson Reuters 说多文档审查准确率提高 17%。Carlyle 说在超大文档检索上好 50%，并且是第一个克服针检索、中间丢失、多跳推理等已有模型局限的模型。

这些数字都没有公开方法、样本量或统计细节。它们是合作伙伴自述的证言，不是可复核的评估结果。本文件把它们记下来，但不把它们当作已确立的数字。

## 四、作者的结论与局限

### 作者的结论

帖子的结论是：GPT-4.1 是 AI 实际应用上的一大步。通过紧扣开发者的真实需求——编码、指令遵循、长上下文理解——这些模型为构建智能系统和复杂的 agent 应用打开了新的可能。帖子没有宣称 GPT-4.1 是最强的模型，也没有宣称它在所有基准上都领先；它的定位是“在每个价位点上都更强、更便宜、更快”的实用模型。

### 作者自述的局限

这篇帖子没有“局限”一节。作为产品发布帖，它没有像技术报告那样列出局限。但它在几处主动做了限定，值得原原本本记下来。

第一，SWE-bench Verified 的脚注主动说明省略了 23 道题，并给出了保守计分下的 52.1%。第二，MultiChallenge 的脚注主动说明默认评分器经常误判，并同时公布了换评分器后的结果。第三，GPQA 的脚注主动说明抽取方式会显著抬高 GPT-4o 的分数。第四，正文主动提醒 GPT-4.1 会更字面地执行指令，建议提示写得明确具体。第五，帖子说 GPT-4.1 只通过 API 提供，不进 ChatGPT，这是一个明确的可用性边界。

帖子没有说的局限更多：没有训练方法、没有模型规模、没有统计显著性、没有误差棒、没有评估的运行次数与种子（tau-bench 注明取了 5 次平均，是唯一的例外）、没有 system card、没有安全评估结果。

## 五、精读点评

这一节是分析者的判断，和上面对发布帖的呈现分开写。

### 这篇发布帖真正要回答的问题

这篇帖子真正要回答的问题是：开发者有没有理由从 GPT-4o 迁移到 GPT-4.1。它给出的答案是：有，至少在编码、指令遵循和长上下文这三项主打能力上，附录的大表支持这个答案的大方向。但它没有回答的问题是：GPT-4.1 到底是什么——没有训练方法、没有模型规模、没有安全评估。读者读完之后知道“它在基准上比 GPT-4o 强”，但不知道“它为什么强、强在哪里会失效”。这是一篇产品发布帖的正常形态，但按研究论文的标准衡量，它的信息量是很薄的。

### 科学问题还原：五问

**现象是什么？** GPT-4o 作为 API 主力，在三个地方让开发者不满意：写代码改不干净、指令遵循不可靠、上下文装不下整个代码库。反常不在于某一次实验失败，而在于“旗舰模型”与“日常开发任务”之间存在错位：模型在通用基准上很强，但在开发者每天要做的具体任务上总差一口气。

**为什么重要，不解决会怎样？** 对实践来说，编码和指令遵循的不可靠性直接决定了 agent 应用能不能落地：一个动不动多改无关代码、记不住前面要求的模型，没法独立完成软件工程任务。长上下文的短板则决定了模型能不能处理真实的代码库和文档堆。不解决这些，agent 应用就只能停留在演示阶段。对领域来说，GPT-4.1 的发布还回答了一个产品路线问题：GPT-4.5 这种大而贵的探索路线要不要继续——帖子的答案是不要，三个月后下线。

**为什么之前做不了？** 帖子没有回答这个问题。它没有说 GPT-4o 的短板是训练数据、模型规模还是对齐方法造成的，也没有说 GPT-4.1 是用什么办法解决的。按发布帖的定位，这不是它要回答的问题；但按精读的标准，这是它最缺的一块：读者无法从这篇帖子知道改进来自哪里，也就无法判断改进能不能推广到别的任务上。

**方法与问题是否匹配？** 帖子用的办法是“基准表加合作伙伴证言”。这个办法能回答“比 GPT-4o 强多少”，回答不了“为什么强”。附录大表覆盖六类基准、八个对照模型，是这篇帖子最扎实的部分；合作伙伴证言覆盖真实生产任务，是大表的补充。但两者都有同一个问题：评估配置不透明。SWE-bench Verified 的分数高度依赖提示和工具，帖子只给了一个 cookbook 链接；内部评测没有实现细节；合作伙伴评测没有方法。办法与“宣布一个产品”这个问题是匹配的，与“证明一个科学主张”这个问题是不匹配的。

**答案改变了什么？** 认知上，它没有改变任何关于模型能力的信念：没有新方法、没有新发现，只有一组“新模型在旧基准上分数更高”的数字。实践上，它改变的东西是具体的：开发者有了一个 1M 上下文、更便宜、编码更强的 API 模型可选，GPT-4.5 用户有了明确的迁移截止日期（2025 年 7 月 14 日），长上下文研究者多了两个开源评测（OpenAI-MRCR 和 Graphwalks）。这篇帖子的价值在实践层，不在认知层。

### 价值判断

认知价值是低的。它没有推翻或确认任何信念，没有提出新方法，也没有报告任何关于模型行为的新发现。反事实是：如果这篇帖子不存在，关于“怎么训出更好的编码模型”的知识不会少任何东西，少的只是一组基准数字和一个产品决策。

方法价值是中等偏低。它留下的可复用东西是两个开源的长上下文评测（OpenAI-MRCR 和 Graphwalks）和 SWE-bench Verified 的评估配置（cookbook 链接）。但评测本身没有经过同行检验，Graphwalks 的设计也没有消融或基线分析来证明它量的是“多跳推理”而不是“超长上下文里的搜索”。扣分项是：它没有留下任何关于训练或对齐的方法，别人没法从这篇帖子学到“怎么做”。

边界价值是中等偏高，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：GPT-4.1 在所有基准上都胜过 GPT-4o（ComplexFuncBench 上它输了 1 个百分点）；GPT-4.1 胜过 GPT-4.5（SWE-Lancer 上 GPT-4.5 赚得更多）；GPT-4.1 是编码最强的模型（o1 和 o3-mini 在 Aider diff 上都高于它）；1M 上下文等于 1M 上下文都能用好（超过 128K 后 Graphwalks 的分数掉了一大半）；以及合作伙伴证言里的百分比是可复核的评估结果（它们没有公开方法）。读者最容易误读的推论，是把开头的“全面胜过 GPT-4o”读成字面意思——附录表本身就反驳了这个读法。

启示价值在于，最便宜的决定性实验不是再跑一遍基准，而是做一次“独立复核”：按帖子给的 cookbook 配置，在第三方 harness 上重跑 SWE-bench Verified，看 54.6% 这个数字还剩多少，以及把省略的 23 道题算进来之后是多少。具体设计在下面“接下来看什么”里写。

### 最弱的一环

最弱的一环在“54.6%”与“GPT-4.1 是领先的编码模型”之间。整篇帖子最醒目的数字是 SWE-bench Verified 上的 54.6%，但它建立在三个脆弱的点上：第一，23 道题被省略，保守计分是 52.1%；第二，帖子自己承认这个分数高度依赖提示和工具；第三，正文说比 GPT-4.5 高 26.6 个百分点，但按附录表算只有 16.6 个百分点，帖子内部对不上。任何一个点单独看都不致命，三个点加在一起，54.6% 这个数字作为“领先”的证据就要打折。

第二弱的一环是“全面胜过”这个总括性宣称与附录表之间的张力。开篇说三个模型“在各方面都胜过 GPT-4o 和 GPT-4o mini”，但附录表里 GPT-4.1 在 ComplexFuncBench 上输给 GPT-4o，在 SWE-Lancer 上输给 GPT-4.5，在 Aider diff、MultiChallenge、COLLIE、GPQA、AIME 上都输给 o1 或 o3-mini。帖子没有在正文里提任何一处输的地方，输的数字只在附录表里。这不是造假，是选择性呈现；但读者如果只读正文，会得到一个比附录表更乐观的印象。

第三弱的一环是合作伙伴证言。六家伙伴的数字都很漂亮（60%、55%、53%、接近 2 倍、17%、50%），但没有一家公开方法、样本量或统计细节。它们是营销证言，不是评估证据。帖子把它们放在每一节的“真实案例”位置上，读者很容易把它们和公开基准放在同一个可信度层级上。

### 效度判断

下面是针对这篇发布帖作为证据的评分，满分 5 分，评的是证据，不是模型本身。

内部效度 2 分。附录大表覆盖六类基准、八个对照模型，SWE-bench Verified、MultiChallenge、GPQA 的脚注主动披露了评分口径上的关键细节，这是严谨的一面。扣分项是：没有运行次数与种子（tau-bench 除外）、没有误差棒、没有统计显著性、公开基准的具体评估配置大多没有披露、内部评测没有实现细节、合作伙伴评测没有方法。54.6% 这个数字的误差范围完全未知。

外部效度 2 分。结果能推广到“在这些基准的这个评估配置下，GPT-4.1 比 GPT-4o 强”这个范围，这是帖子有证据的部分。推广到“在开发者的生产任务上也强”，只有合作伙伴证言支持，方法没有公开；推广到“比 GPT-4.5 强”或“是最强的编码模型”，附录表本身就反驳了；推广到“1M 上下文都能用好”，Graphwalks 超过 128K 后的分数不支持。帖子没有训练细节，读者也无法判断改进能不能推广到别的任务上。

构念效度 2 分。基准分数确实量的是“在这些基准上的表现”，但帖子把它包装成“编码能力”“指令遵循能力”“长上下文理解能力”这些更宽的构念。SWE-bench Verified 的分数高度依赖提示和工具，帖子自己承认了这一点；MultiChallenge 的分数依赖评分器，换评分器分数就变；needle-in-a-haystack 的分数只在图里，没有数字。基准分与能力之间的换算关系，帖子没有论证。

统计结论效度 1 分。几乎没有统计信息：没有误差棒、没有置信区间、没有 p 值、没有多重比较校正、没有运行次数（tau-bench 注明取了 5 次平均，是唯一的例外）。很多对比只有 1 个百分点的差距（例如 ComplexFuncBench 上 GPT-4.1 比 GPT-4o 低 1 个百分点），在没有误差棒的情况下，这些差距有没有意义说不清。

可复现性 2 分。公开基准的部分可以复现：附录表给了完整的数字，SWE-bench Verified 给了 cookbook 链接，两个新评测开源了数据集。但内部评测没有实现细节，合作伙伴评测没有方法，评估的提示、工具、种子大多没有披露。一个能干的读者能重跑公开基准，但重跑出来的数字未必与帖子一致——帖子自己承认 SWE-bench Verified 的分数高度依赖提示和工具。

### 其他可能的解释

同一个结果，至少有三种别的解释也能说得通。

第一种是“评估配置解释”。SWE-bench Verified 的分数高度依赖提示和工具，帖子自己承认了这一点。有可能 GPT-4.1 的 54.6% 里有一部分不是模型能力，而是 OpenAI 为 GPT-4.1 调优过的提示和工具配置的功劳。预测：用同一套提示和工具重跑 GPT-4o，差距会缩小。区分证据：按 cookbook 配置，在第三方 harness 上重跑两个模型。

第二种是“评分器解释”。MultiChallenge 的脚注说默认评分器 GPT-4o 经常误判，换成 o3-mini 当评分器后分数显著提高。有可能 GPT-4.1 的 MultiChallenge 分数里有一部分是评分器偏好的产物。预测：换一个与 OpenAI 无关的评分器，GPT-4.1 与 GPT-4o 的差距会变化。区分证据：用独立评分器重评同一批回答。

第三种是“基准选择解释”。帖子正文突出的都是 GPT-4.1 赢的基准，输的地方只在附录表里。有可能 GPT-4.1 的真实画像比正文呈现的更参差：它在编码和指令遵循上确实强，但在函数调用和部分学术基准上并不突出。预测：在帖子没有列出的基准上，GPT-4.1 与 GPT-4o 的差距会更小，甚至反过来。区分证据：在独立的第三方基准套件上重测两个模型。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

“GPT-4.1 在编码上大幅超过 GPT-4o”：按帖子给的 cookbook 配置，在第三方 harness 上重跑 SWE-bench Verified。如果 GPT-4.1 与 GPT-4o 的差距大幅缩小，或者把省略的 23 道题算进来之后 54.6% 跌到 52.1% 以下，“大幅超过”的说法就要收回到更窄的范围。

“GPT-4.1 全面胜过 GPT-4o”：附录表本身已经提供了反例——ComplexFuncBench 上 GPT-4.1 是 65.5%，GPT-4o 是 66.5%。这个宣称在字面意义上已经被证伪，只能退回为“在多数基准上胜过”。

“GPT-4.1 胜过 GPT-4.5”：SWE-Lancer 上 GPT-4.5 赚 186K 美元，GPT-4.1 赚 176K 美元；IC-Diamond 子集上 GPT-4.5 是 41K 美元，GPT-4.1 是 34K 美元。如果这两个数字成立，“胜过 GPT-4.5”就只能限定在部分基准上。

“1M 上下文都能用好”：Graphwalks BFS 超过 128K 后 GPT-4.1 只有 19.0%，parents 任务只有 25.0%。如果这两个数字成立，1M 窗口的实际可用性就要打折，只能说“窗口能开到 1M，超过 128K 后多跳推理能力大幅下降”。

“合作伙伴证言证明生产任务上更好用”：请一家合作伙伴公开方法、样本量与统计细节，或者由第三方在同一任务上独立重测。如果公开后数字大幅缩水，证言就只能当作营销材料，不能当作评估证据。

### 替代解释

替代解释一：评估配置解释。SWE-bench Verified 的分数高度依赖提示和工具，帖子自己承认了这一点。有可能 GPT-4.1 的 54.6% 里有一部分是 OpenAI 为 GPT-4.1 调优过的提示和工具配置的功劳，而不是模型本身的能力。预测：用同一套提示和工具重跑 GPT-4o，差距会缩小。区分证据：按 cookbook 配置，在第三方 harness 上重跑两个模型。

替代解释二：评分器解释。MultiChallenge 的脚注说默认评分器 GPT-4o 经常误判，换成 o3-mini 当评分器后分数显著提高。有可能 GPT-4.1 的 MultiChallenge 分数里有一部分是评分器偏好的产物。预测：换一个与 OpenAI 无关的评分器，GPT-4.1 与 GPT-4o 的差距会变化。区分证据：用独立评分器重评同一批回答。

替代解释三：基准选择解释。帖子正文突出的都是 GPT-4.1 赢的基准，输的地方只在附录表里。有可能 GPT-4.1 的真实画像比正文呈现的更参差：它在编码和指令遵循上确实强，但在函数调用和部分学术基准上并不突出。预测：在帖子没有列出的基准上，GPT-4.1 与 GPT-4o 的差距会更小，甚至反过来。区分证据：在独立的第三方基准套件上重测两个模型。

### 作者自述局限与分析者发现的局限

作者自述的限定见第四节：SWE-bench Verified 省略 23 道题的脚注、MultiChallenge 评分器的脚注、GPQA 抽取方式的脚注、GPT-4.1 更字面地执行指令的提醒、只通过 API 提供的可用性边界。

分析者发现的、作者没说的局限有五点。第一，正文“比 GPT-4.5 高 26.6 个百分点”与附录表对不上，按附录表算只有 16.6 个百分点。第二，正文“全面胜过 GPT-4o”与附录表对不上，ComplexFuncBench 上 GPT-4.1 输给 GPT-4o。第三，正文说 nano 在 MMLU、GPQA、Aider 三项上“高于 GPT-4o mini”，但附录表显示 nano 的 MMLU（80.1%）低于 GPT-4o mini（82.0%）。第四，合作伙伴证言的六个百分比都没有公开方法、样本量或统计细节。第五，几乎没有统计信息：没有误差棒、没有置信区间、没有运行次数（tau-bench 除外）、没有种子，1 个百分点量级的差距有没有意义说不清。

### 接下来看什么

最值得先做的，是做一次“独立复核”：按帖子给的 cookbook 配置，在第三方 harness 上重跑 SWE-bench Verified，看 54.6% 这个数字还剩多少。这是启示价值里最便宜的决定性实验，也是全篇最缺的一块。

具体设计：取 GPT-4.1 与 GPT-4o（2024-11-20），用同一套提示、同一套工具、同一份 500 道题（含被省略的 23 道），在第三方 harness 上各跑一次。

判据很简单：如果两者差距仍在 20 个百分点上下，54.6% 作为“编码大幅超过”的证据就得到支持；如果差距大幅缩小，或者把 23 道题算进来之后 GPT-4.1 跌到 52% 附近，54.6% 这个数字就要收回到“在 OpenAI 自己的评估配置下”的范围。

其次是把“1M 上下文到底多能用”弄清楚。成本很低：只需要公开 needle-in-a-haystack 在各长度、各位置上的准确率数字（现在只有图），并在 OpenAI-MRCR 与 Graphwalks 上补上 GPT-4o 与 o1 在 1M 长度下的数字（现在是空白）。如果 1M 下的分数继续往下掉，1M 窗口的实际可用性就要重新评估。

再往后看两件事：GPT-4.1 的 system card 何时发布、里面怎么写安全评估与局限；以及 GPT-4.5 下线之后，原来用 GPT-4.5 的开发者迁移到 GPT-4.1 的实际体验如何——SWE-Lancer 上 GPT-4.5 仍然领先，这个差距在生产任务上会不会被感受到。

## I. 结论、结果与价值总览

### 一句话结论

GPT-4.1、mini 与 nano 三个 API 模型在编码、指令遵循和 1M 长上下文上确实比 GPT-4o 强了一大截，但这是一篇产品发布帖而不是研究论文：没有训练方法、没有统计、没有安全评估，而且正文“全面胜过”的说法被附录表自己的数字反驳了至少一处。

### 核心结论

1. **编码上大幅超过 GPT-4o（置信度：高）。** SWE-bench Verified 54.6% 对 33.2%，Aider diff 52.9% 对 18.2%。但 54.6% 省略了 23 道题，保守计分是 52.1%，且正文“比 GPT-4.5 高 26.6 个百分点”与附录表对不上。

2. **指令遵循上明显超过 GPT-4o，但没超过推理模型（置信度：高）。** MultiChallenge 38.3% 对 27.8%，IFEval 87.4% 对 81.0%，内部 hard 档 49.1% 对 29.2%。但 o1、o3-mini 与 GPT-4.5 在这几项上都高于 GPT-4.1。

3. **1M 上下文是真的，但超过 128K 后能力掉得厉害（置信度：高）。** OpenAI-MRCR 2 针从 128K 的 57.2% 掉到 1M 的 46.3%；Graphwalks BFS 超过 128K 后从 61.7% 跌到 19.0%。

4. **“全面胜过”在字面意义上不成立（置信度：高）。** ComplexFuncBench 上 GPT-4.1 是 65.5%，GPT-4o 是 66.5%；SWE-Lancer 上 GPT-4.5 赚得比 GPT-4.1 更多。

5. **mini 与 nano 的定位成立（置信度：中）。** mini 在许多基准上打平或超过 GPT-4o，成本降低 83%；nano 在 GPQA 与 Aider 上高于 GPT-4o mini，但 MMLU 上低于 GPT-4o mini，正文“高于 GPT-4o mini”的说法不覆盖 MMLU。

6. **这是一篇产品发布帖，不是研究论文（置信度：高）。** 没有训练方法、没有模型规模、没有统计显著性、没有 system card。它的价值在实践层，不在认知层。

### 科学价值总评

认知价值是低的。没有推翻或确认任何信念，没有提出新方法，也没有报告任何关于模型行为的新发现。它没有回答“改进来自哪里”，读者无法从这篇帖子学到“怎么做”。

方法价值是中等偏低。留下的可复用东西是两个开源的长上下文评测（OpenAI-MRCR 和 Graphwalks）和 SWE-bench Verified 的评估配置。扣分项是：评测没有经过同行检验，Graphwalks 没有消融或基线分析来证明它量的是“多跳推理”而不是“超长上下文里的搜索”，而且帖子没有留下任何关于训练或对齐的方法。

边界价值是中等偏高。它明确不证明：GPT-4.1 在所有基准上都胜过 GPT-4o；GPT-4.1 胜过 GPT-4.5；GPT-4.1 是编码最强的模型；1M 上下文等于 1M 上下文都能用好；以及合作伙伴证言里的百分比是可复核的评估结果。最容易误读的推论，是把开头的“全面胜过 GPT-4o”读成字面意思——附录表本身就反驳了这个读法。

启示价值在于，最便宜的决定性实验是做一次“独立复核”：按帖子给的 cookbook 配置，在第三方 harness 上重跑 SWE-bench Verified，看 54.6% 这个数字还剩多少。

总体 verdict 是：这篇工作值得被记住为一次有分量的产品发布——三个 API 模型、1M 上下文、两个开源长上下文评测、以及 GPT-4.5 的明确下线日期。不值得被记住为一项研究发现——它没有回答任何科学问题，也不该用它的数字去论证关于模型能力的一般性主张。

### 适用边界

不要用这篇帖子论证 GPT-4.1 在所有基准上都胜过 GPT-4o，不要用它论证 GPT-4.1 胜过 GPT-4.5，不要用 54.6% 论证 GPT-4.1 是编码最强的模型，不要用 1M 上下文论证模型在 1M 长度下都能用好，不要引用合作伙伴证言里的百分比为已确立的数字，不要引用图里的 needle-in-a-haystack 准确率为已确立的数字。
