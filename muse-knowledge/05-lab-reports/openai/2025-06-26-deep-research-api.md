## 一、背景与问题

### 发布之前是什么局面

深度研究（deep research）是 OpenAI 在 2025 年 2 月 2 日首先在 ChatGPT 里推出的功能：给它一个高层问题，它会自己拆分子问题、做几十次联网搜索、跑代码分析，最后交出一份带引用的结构化研究报告。但它一直只活在 ChatGPT 的界面里。开发者想在自己的工具或工作流里用同样的能力，只能自己搭一套编排：拆问题、调搜索、拼报告。

2025 年 6 月 26 日的这篇公告要补的，就是这一步：把 ChatGPT 里的深度研究模型直接放进 API，让开发者能用程序触发深度研究；同时补上两块配套能力——webhooks（Webhook，任务完成时主动通知，不用轮询）和 o 系列推理模型的联网搜索（web search）。

这篇公告没有提出一个科学问题，也没有要验证的假设。它要回答的问题是产品层面的：API 里多了什么、怎么用、多少钱。它不是一篇论文，不能按论文的标准去要求它；精读它的意义在于，把它宣称的东西原原本本记下来，并且分清哪些是可核查的事实、哪些只是没有数字支撑的说法。

## 二、方法与设计

### 第一项：深度研究进 API

开发者现在可以直接在 API 里使用 ChatGPT 中提供的同款深度研究模型：o3-deep-research 和 o4-mini-deep-research。用法是编程式触发：从自己的内部工具里，或者作为 AI 工作流的一部分，发起一次深度研究。

除了模型自身的内部知识，这两个模型还能通过联网搜索（web search）和 MCP 服务器（Model Context Protocol server，模型上下文协议服务器）支持拉取外部上下文。MCP 的意思是，开发者可以接自己的私有知识库或第三方服务，让研究智能体在公开网络之外再查内部资料。

公告给的定价是：o3-deep-research 每百万输入 token 10 美元、每百万输出 token 40 美元；o4-mini-deep-research 每百万输入 token 2 美元、每百万输出 token 8 美元。

官方 Cookbook 对用法补了几句具体说明。深度研究走 Responses API（responses 端点），模型名是带日期快照的 `o3-deep-research-2025-06-26` 与 `o4-mini-deep-research-2025-06-26`。调用时必须带 `web_search_preview` 工具，可选再加 `code_interpreter`（代码解释器）。因为一次深度研究任务可能要跑几分钟，Cookbook 建议把 `background` 参数设为 `True`，让请求异步跑。返回结果是一份结构化的最终答案，带行内引用、推理步骤摘要和来源元数据；中间步骤（推理步骤、联网搜索调用、代码执行）都暴露在 `response.output` 里，可以逐项检查。

Cookbook 还点出一个 ChatGPT 版与 API 版的重要差别：ChatGPT 里的深度研究在用户提交问题后常常会先追问澄清意图，API 版跳过了这一步。模型默认输入的问题就是完整成型的问题，不会主动追问、也不会补全缺失的信息，直接开始研究。开发者要自己负责把问题写清楚，或者在前面再加一个改写问题的步骤。

### 第二项：webhooks

开发者现在可以不用轮询（polling），改为监听事件（listen for events），在任务完成时收到通知。公告说，这对异步批量任务（async batch jobs）和长时间运行的任务特别有用，举的例子就是深度研究和 o3-pro。公告建议，把新的深度研究模型和后台模式（background mode）与 webhooks 一起用，以提高可靠性，避免超时或网络错误。

### 第三项：o 系列模型的联网搜索

API 里的联网搜索最初只支持 GPT-4o 和 GPT-4.1 系列。现在，o 系列模型也可以在推理过程中调用联网搜索：o3、o3-pro 和 o4-mini 都能一边推理一边搜索，把相关的上下文直接拉进思维链（chain-of-thought）里，得到更有帮助的回答。

公告同时简化了联网搜索的定价：GPT-4o 和 GPT-4.1 系列是每 1,000 次工具调用 25 美元，o 系列推理模型是每 1,000 次工具调用 10 美元。公告给了一个选型建议：如果想要更好的联网搜索效果，试试 o 系列模型；如果最在意延迟，GPT-4o 和 GPT-4.1 的联网搜索会是最快的选择。

### 模型页上的规格（公告发布后读取，非公告内容）

两个模型的官方模型页（2026-11-23 读取）给出了一组公告里没有的规格：两个模型都是 200,000 token 上下文窗口、最大输出 100,000 token，知识截止日期都是 2024 年 6 月 1 日，支持推理 token。缓存输入价分别是 o3-deep-research 每百万 token 2.50 美元、o4-mini-deep-research 每百万 token 0.50 美元。功能清单上，两个模型都不支持函数调用（function calling）与结构化输出（structured outputs）。

模型页还显示，这两个模型都已经关闭：2026 年 7 月 23 日停止服务（shut down），页面指向新的“更长联网研究”工作流。这是公告发布一年多之后的状态变化，不是 2025 年 6 月 26 日公告的一部分，这里只作后续注记。

## 三、主要发现

### 发布内容：三个东西，一次上线

公告一共宣布了三件事。第一，深度研究模型进 API：o3-deep-research 与 o4-mini-deep-research，可编程触发，支持联网搜索与 MCP 服务器，定价分别是每百万输入/输出 token 10/40 美元与 2/8 美元。第二，webhooks：任务完成时主动通知，替代轮询，适合异步批量任务与深度研究、o3-pro 这样的长任务，建议配合后台模式使用。第三，o 系列联网搜索：o3、o3-pro、o4-mini 现在能在推理中调用联网搜索；联网搜索的工具调用价在 GPT-4o/4.1 系列是每 1,000 次 25 美元，在 o 系列是每 1,000 次 10 美元。

### 公告没有给的东西

公告没有给出任何关于模型能力的数字：没有基准分数，没有与 ChatGPT 版深度研究的对比，没有任务成功率，没有延迟，没有一份完整研究报告的典型成本。也没有说明深度研究在 API 里的可用范围（向哪些用户或层级开放）、速率限制、以及一次研究最多能做多少次搜索、跑多长时间。这些在公告里都是空白。

公告也没有解释为什么深度研究花了将近五个月才进 API。ChatGPT 版 2 月就上线了，API 版 6 月底才来，中间隔了什么、改了什么，公告一个字没提。

## 四、作者的结论与局限

### 作者的结论

公告没有研究结论。它要传达的信息是三句：ChatGPT 里的深度研究模型现在可以在 API 里用了；长任务不用再轮询，webhooks 会在完成时通知你；o 系列模型现在能在推理中联网搜索，而且联网搜索在 o 系列上更便宜。

关于选型，公告给了一个明确的建议：要效果，用 o 系列的联网搜索；要延迟，用 GPT-4o 和 GPT-4.1 的联网搜索。关于可靠性，公告给了一个明确的建议：深度研究这类长任务，用后台模式加 webhooks，别用同步调用去赌超时。

### 作者自述的局限

公告没有列出任何局限。它没有说深度研究在 API 里有什么做不到、有什么限制，也没有说联网搜索在 o 系列上有什么边界。这一点不是疏忽，是这类三段话发布帖的常态：它只宣布“有了”，不讨论“有什么代价”。

### 配套文档补上的限制

官方 Cookbook 补上了一个公告没说的限制：API 版深度研究不会追问澄清意图。ChatGPT 版会在研究开始前问清楚你的偏好、目标和约束，API 版直接开工。这意味着同样的提问，在 API 里得到差报告的风险更高，责任转移到了开发者写提示词的能力上。

官方模型页补上了另一组限制：两个深度研究模型都不支持函数调用与结构化输出。也就是说，开发者不能要求它们按一个固定 JSON 结构返回报告，也不能让它们在研究过程中调用自定义函数。这两点在公告里都没有提。

## 五、精读点评

这一节是分析者的判断，和上面对公告的呈现分开写。

### 这篇文档真正要回答的问题

这篇文档真正要回答的问题不是科学问题，而是产品问题：ChatGPT 里的深度研究能力，能不能搬进开发者的工作流里。它给出的答案分两层。第一层是“能用了”：两个模型进了 API，webhooks 补上了异步通知，o 系列能边推理边搜索——这三件事都是具体的、可核查的。第二层是“它有多强、多少钱能办一件事”：公告只给了 token 单价，没给任何一件事的实际成本，也没给任何能力数字。第二层是这篇公告立不住的部分。

### 科学问题还原：五问

**现象是什么？** 深度研究只活在 ChatGPT 的界面里。开发者想在自己的工具或工作流里做同样的事，只能自己搭编排。反常不在于某一次实验失败，而在于“模型会做深度研究”和“开发者能用程序调用深度研究”之间没有现成的接口——前者 2 月就有了，后者拖到 6 月底。

**为什么重要，不解决会怎样？** 对实践来说，不解决它，任何想把深度研究嵌进内部工具、批量任务或自动化流程的团队，都只能停留在手工操作或自研编排上。对领域来说，不解决它，深度研究就只是一个聊天产品，不是一块可以组合进更大系统里的积木。这篇公告的重要性首先在于它宣布了一个可用的 API 形态，而不是提出了一个新发现。

**为什么之前做不了？** 公告没有回答这个问题。分析者能从公告与 Cookbook 里推断的 blocker 有三个：一是执行时间，一次深度研究要跑几分钟，同步 API 调用扛不住超时，这就是公告建议后台模式加 webhooks 的原因；二是成本与可靠性，一次研究烧掉的 token 量很大，失败一次就很贵；三是输入质量，ChatGPT 版靠追问澄清来保证输入质量，API 版没有这个环节，开发者得自己解决。但这三点是分析者的推断，公告本身没有把它们写成“之前卡住的点”。

**方法与问题是否匹配？** 这篇文档没有方法，也就没有方法与问题的匹配问题。它提供的不是一个实验设计，而是一组 API：两个模型、webhooks、联网搜索工具。这套东西回答的是“怎么把深度研究调起来”，而不是“深度研究做得有多好”。把公告里的定价读成一个成本结论，就是方法与问题不匹配的地方——公告根本没有给出一份报告的实际成本。

**答案改变了什么？** 认知上，什么都没改变——公告没有提供任何新证据来改变我们对深度研究能力的认识。实践上，它改变了一件事：从 2025 年 6 月 26 日起，开发者可以用程序触发深度研究，用 webhooks 等长任务完成，让 o 系列模型在推理中联网搜索。这是一次 API 发布，不是一次认知更新。

### 价值判断

认知价值是低的。公告没有推翻或确认任何信念，也没有给出任何可复核的数字。反事实是：如果这篇公告不存在，我们对深度研究模型的认识不会有任何不同——因为它本来就没有提供认识它的证据。

方法价值是低的。它留下的可复用东西只有两样：一是“后台模式加 webhooks”这个跑长任务的异步模式；二是 Cookbook 里“提示词改写器加澄清步骤”的做法——因为 API 版跳过了澄清，开发者要在调用之前自己把问题写完整。这两样都是工程做法，不是研究方法。Cookbook 里暴露中间步骤（推理、搜索调用、代码执行都在 `response.output` 里可查）的设计，对调试研究智能体有用，但它是一份文档，不是一项方法。

边界价值是中等偏高的，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：深度研究在 API 里做出来的报告质量如何；o 系列的联网搜索比 GPT-4o/4.1 好多少；一份研究报告实际要花多少钱；以及深度研究在 API 里的任务成功率。读者最容易误读的推论，是把“o 系列联网搜索效果更好”这句选型建议读成一个有数字支撑的评估结论——公告里没有任何对比数字，这句话只是一个没有证据的产品建议。

启示价值在于，最便宜的决定性下一步不是再读一遍这篇公告，而是去找深度研究模型的评估材料：它在发布时配套的基准表现、与 ChatGPT 版的对比、以及一份典型研究报告的实际 token 消耗与成本。拿到这些数字，才能判断 API 版深度研究到底值多少钱、适合哪些任务。

### 最弱的一环

最弱的一环在“更好”这个说法与任何数字之间。公告说 o 系列的联网搜索效果更好，却没有给出任何对比数字：没有准确率，没有引用质量，没有与 GPT-4o/4.1 的对照。选型建议建立在一句没有数字支撑的断言上。

第二弱的一环是定价的完整性。公告给了 token 单价与工具调用单价，但没有给出一份研究报告的实际成本。一次深度研究要烧多少输入 token、多少输出 token、多少次搜索调用，公告一个字没提。开发者按单价算不出账，定价信息是不完整的。

第三弱的一环是公告没有提的限制。API 版跳过澄清步骤、两个模型不支持结构化输出与函数调用，这两点都只在配套文档与模型页里，公告正文没有提。一个只读公告的开发者，会对 API 版的能力边界产生过高的预期。

### 其他可能的解释

同一个结果，至少有两种别的解释也能说得通。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

“o 系列的联网搜索效果更好”：在一组相同的、需要实时信息的问题上，让 o3 与 GPT-4.1 分别调用联网搜索回答，由人类评估者盲评答案的准确率与引用质量。如果 o3 没有显著优于 GPT-4.1，“更好”这个说法就只能退回为“没有测出差别”。

“后台模式加 webhooks 能提高长任务的可靠性”：统计一批深度研究任务在同步调用与后台模式加 webhooks 下的失败率（超时、网络错误、任务丢失）。如果两者的失败率没有差别，这个建议就只是工程习惯，不是实测结论。

“深度研究模型适合放进 AI 工作流”：统计真实开发者工作流里的任务完成率与单份报告成本。如果大量任务因输入不完整而产出差报告（API 版没有澄清步骤），“适合放进工作流”就要加上“只适合输入已经写完整的任务”这个限定。

### 替代解释

替代解释一：产品发布解释。公告没有评估数字，是因为它本来就不是评估报告，它的目的是宣布 API 可用、说明用法、给出定价。预测：2 月份 ChatGPT 版深度研究的发布材料里有能力的评估数字，API 版只是换了一个调用方式。区分证据：读 2025 年 2 月 2 日《Introducing deep research》的评估部分。

替代解释二：定价引导解释。o 系列联网搜索的工具调用价只有 GPT-4o/4.1 的一半以下，同时公告建议“要效果就用 o 系列”，这可能是在引导开发者把搜索流量迁到 o 系列。预测：按完整账单算，o 系列一次搜索的实际成本会高于工具调用价所暗示的水平，因为检索内容的计费方式没有在公告里说明。区分证据：拿一份真实账单，对照工具调用次数与检索内容的 token 计费。

替代解释三：延迟解释。公告说 GPT-4o/4.1 的联网搜索延迟最低，但没有给出任何延迟数字。这个说法可能只是从“推理模型要先想再搜”这个机制上推断出来的，而不是实测结果。预测：实测延迟差距会小于“推理加搜索”这个机制所暗示的程度，尤其是在搜索本身占主导的任务上。区分证据：实测两组模型的端到端延迟分布。

### 作者自述局限与分析者发现的局限

作者自述的局限：公告没有列出任何局限。

分析者发现的、作者没说的局限有三点。第一，正文没有任何可核查的能力数字，关于“效果更好”的说法没有对比数据。第二，定价信息不完整：只有 token 单价与工具调用单价，没有一份研究报告的实际成本，开发者按单价算不出账。第三，公告没有提的限制只在配套文档里：API 版跳过澄清步骤、两个模型不支持结构化输出与函数调用，一个只读公告的开发者会对 API 版的能力边界产生过高的预期。

### 接下来看什么

最值得先做的，是去找深度研究模型的评估材料：2 月份 ChatGPT 版发布时的基准表现、与 API 版的对比、以及一份典型研究报告的实际 token 消耗与成本。这是启示价值里最便宜的决定性实验，也是这篇公告最缺的一块。

具体设计：找到 2025 年 2 月 2 日《Introducing deep research》里的评估表，对照 6 月公告的定价，算出一份典型报告在 o3-deep-research 与 o4-mini-deep-research 下的实际成本。

判据很简单：如果 API 版的报告质量与 ChatGPT 版相当、成本在可接受范围，公告“放进工作流”的说法就得到支持；如果成本远高于预期、或因缺少澄清步骤导致报告质量明显下降，这个说法就要收回到“只适合输入已经写完整的任务”这个更窄的范围。

其次是看发布后的实际使用数据：真实开发者任务的完成率、失败原因分布（超时、输入不完整、成本超支各占多少）、以及 webhooks  adoption 之后轮询量下降了多少。这些数据能验证“后台模式加 webhooks 提高可靠性”这个建议到底有没有兑现。

再往后看一件事：两个模型已于 2026 年 7 月 23 日关闭，OpenAI 指向了新的“更长联网研究”工作流。后续值得看的是，替代模型是否保留了 API 版深度研究的接口与定价结构，还是换了一套新的计费方式——这决定了 2025 年 6 月这篇公告里的定价信息还有多少参考价值。

## I. 结论、结果与价值总览

### 一句话结论

这是一篇三段话的 API 发布帖，不是研究论文：它宣布深度研究模型进了 API、补上了 webhooks、给 o 系列加上了联网搜索，给了 token 单价与工具调用价，但关于模型能力，没有给出任何可核查的数字。

### 核心结论

1. **深度研究模型进了 API（置信度：高）。** o3-deep-research 与 o4-mini-deep-research 可在 API 里编程触发，支持联网搜索与 MCP 服务器，定价分别是每百万输入/输出 token 10/40 美元与 2/8 美元。

2. **webhooks 补上了长任务的异步通知（置信度：高）。** 任务完成时主动通知，替代轮询，适合异步批量任务与深度研究、o3-pro 这样的长任务，公告建议配合后台模式使用以提高可靠性。

3. **o 系列模型现在能在推理中联网搜索（置信度：高）。** o3、o3-pro、o4-mini 可以在推理过程中调用联网搜索，把上下文拉进思维链；联网搜索的工具调用价在 GPT-4o/4.1 系列是每 1,000 次 25 美元，在 o 系列是每 1,000 次 10 美元。

4. **“效果更好”没有数字支撑（置信度：高）。** 公告建议要效果就用 o 系列的联网搜索、要延迟就用 GPT-4o/4.1，但正文没有任何对比数字，这个选型建议无法核查。

5. **API 版跳过澄清步骤，两个模型不支持结构化输出（置信度：高）。** 这两点不在公告正文里，只在官方 Cookbook 与模型页里；它们是 API 版最重要的能力边界，一个只读公告的开发者会低估它们的影响。

6. **两个模型已经关闭（置信度：高）。** 官方模型页显示，o3-deep-research 与 o4-mini-deep-research 均于 2026 年 7 月 23 日停止服务。这是公告发布一年多之后的状态，引用公告里的定价时须注明它已经随模型下线而失效。

### 科学价值总评

认知价值是低的。公告没有提供任何新证据来改变我们对深度研究能力的认识；如果这篇公告不存在，我们对深度研究模型的认识不会有任何不同。

方法价值是低的。留下的可复用东西只有“后台模式加 webhooks”的长任务异步模式和 Cookbook 里“提示词改写器加澄清步骤”的做法，都是工程做法，不是研究方法。

边界价值是中等偏高的。它明确不证明：深度研究在 API 里做出来的报告质量如何；o 系列的联网搜索比 GPT-4o/4.1 好多少；一份研究报告实际要花多少钱；深度研究在 API 里的任务成功率。最容易误读的推论，是把“o 系列联网搜索效果更好”读成一个有数字支撑的评估结论——公告里没有任何对比数字。

启示价值在于，最便宜的决定性下一步是去找 2 月份 ChatGPT 版深度研究的评估材料，并算出一份典型报告在两个模型下的实际成本，看 API 版到底值多少钱、适合哪些任务。

总体 verdict 是：这篇工作值得被记住为一个 API 形态的发布——深度研究模型进了 API、webhooks 补上了异步通知、o 系列能边推理边搜索。不值得被记住为关于模型能力的证据——它没有提供那样的证据，也不该用它的选型建议去论证 o 系列的联网搜索有多强。它的定价信息也已经随两个模型在 2026 年 7 月 23 日的关闭而失效，引用时须注明这一点。

### 适用边界

不要用这篇公告论证 o 系列的联网搜索比 GPT-4o/4.1 好多少，不要用它的 token 单价论证一份研究报告的实际成本，不要用“后台模式加 webhooks 提高可靠性”论证长任务的失败率真的下降了，不要用公告里的定价论证现在的成本——两个模型已经关闭。
