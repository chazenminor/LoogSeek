## 一、背景与问题

### 发布之前是什么局面

2025 年上半年，OpenAI 先后推了两个各有短板的智能体产品：Operator 能在网页上滚动、点击、输入，但做不了深入的分析、写不了详细的报告；deep research（深度研究）擅长分析与综合信息，但没法与网站互动来细化结果，也打不开需要用户登录才能看的内容。两个工具各管一摊，用户在实际使用中常常发现：用 Operator 发起的查询，其实更适合交给 deep research。

这篇博客要推的，就是把两者合起来的一步：一个统一的智能体系统（unified agentic system），把 Operator 的网页操作能力、deep research 的信息综合能力、ChatGPT 的对话能力装进同一个模型，再配上一套工具——可视化浏览器（visual browser）、文本浏览器（text-based browser）、终端（terminal）、直接 API 访问，以及 ChatGPT 连接器（connectors）。用户用自然语言下一个指令，智能体自己在自己的虚拟计算机（virtual computer）上推理与行动交替进行，把复杂任务从头做到尾。

这篇博客没有提出一个科学问题，也没有要验证的假设。它要回答的问题是产品层面的：ChatGPT agent 是什么、怎么用、凭什么可信、多少钱、风险怎么管。它不是一篇论文，不能按论文的标准去要求它；精读它的意义在于，把它宣称的东西原原本本记下来，并且分清哪些是可核查的数字、哪些只是没有数字支撑的说法。

标题是 Introducing ChatGPT agent，中文可译为“ChatGPT agent 发布”。发表地是 OpenAI 官方博客，发布日期 2025 年 7 月 17 日。没有作者署名，没有 arXiv 版，没有同行评审。这是一篇产品发布公告，附带一张 SpreadsheetBench 的对照表作为附录，以及一篇系统卡（system card）的链接和一个漏洞赏金计划（bug bounty program）的链接。

## 二、方法与设计

### ChatGPT agent 是什么，怎么工作

ChatGPT agent 是一个统一的智能体系统。用户在 ChatGPT 消息框的工具下拉菜单里选择“agent mode”（智能体模式），用自然语言描述任务，智能体就在自己的虚拟计算机上工作：推理与行动交替进行，根据任务需要自己选择工具——用可视化浏览器在图形界面上操作网站，用文本浏览器做推理型的网页查询，在终端里运行代码，通过 API 直接取数据，还可以通过 ChatGPT 连接器接入 Gmail、GitHub 这类应用。

同一个任务里，上下文是保留的：模型可以用文本浏览器打开一个页面，从网上下载文件，在终端里用命令处理它，再回到可视化浏览器里查看输出。它也可以在网站上接管浏览器（takeover mode），由用户登录之后继续深入执行任务。

工作方式强调协作与可控。任务进行中，用户可以随时打断、澄清指令、改变任务，智能体会在新信息下从断点继续，而不丢失此前的进展；任务耗时过长或卡住时，可以暂停、要一份进度总结，或者直接停止并拿到部分结果。手机上有 ChatGPT 应用的话，任务完成时会收到通知。用户可以在任务开始前要求智能体在采取有后果的行动之前先征得许可，也可以随时接管浏览器或停止任务。

博客给的任务例子是：“看看我的日历，根据最近的新闻给我讲讲接下来的客户会议”“计划并购买做四人份日式早餐的食材”“分析三个竞争对手并做一份幻灯片”。

### 工具套件

博客列出的工具一共四类：通过图形界面与网络互动的可视化浏览器、用于简单推理型网页查询的文本浏览器、终端、直接 API 访问。再加上 ChatGPT 连接器（Gmail、GitHub 等应用）和浏览器接管模式（用户登录后智能体可以深入操作）。不同的信息获取路径让模型可以选最高效的一条：比如通过 API 拿日历、用文本浏览器高效推理大量文本、同时保留对以人类为主要用户设计的网站进行可视化操作的能力。

还可以把完成的任务设为自动定期重复，比如每周一早上生成一份周度指标报告。

### 安全设计：确认、监督、限数据

博客说，这是第一次用户可以让 ChatGPT 直接在网上采取行动，风险也随之变大。安全设计分了几层。

第一层是针对模型失误的缓解。做有现实后果的行动之前，模型要明确向用户请求许可；某些关键任务（比如发邮件）需要用户主动监督，即“Watch Mode”（注视模式）；模型会被训练主动拒绝高风险任务，比如银行转账。

第二层是针对提示注入（prompt injection）的防御。博客把提示注入列为智能体系统普遍存在的风险：网页上藏着的恶意指令（比如不可见元素或元数据里的指令）可能诱使智能体泄露连接器里的隐私数据，或者在用户已登录的网站上做有害操作。博客说，团队训练并测试了智能体识别和抵抗提示注入的能力，同时用监控快速发现和响应攻击；要求用户在有后果的行动前明确确认，也能进一步降低伤害。博客同时提醒用户自己权衡：决定给智能体提供什么信息，不用的时候可以关掉连接器。

第三层是限制模型能接触的数据。设置里一键可以删除全部浏览数据并立即登出所有活跃网站会话；否则 cookie 按各网站自己的策略保留。浏览器接管模式下，用户输入的内容是私密的——ChatGPT 不收集、不存储用户在接管会话中输入的密码之类数据，因为模型不需要这些数据，而且不看到更安全。

### 生物风险：按“高能力”对待

因为能力提升，OpenAI 决定把 ChatGPT agent 按照《准备度框架》（Preparedness Framework）里的“高生物与化学能力”（High Biological and Chemical capabilities）来对待，启动相应的保障措施。博客同时承认，没有确切证据表明该模型能实质性地帮助新手造成严重的生物伤害——也就是没有达到“高能力”的阈值——但出于谨慎，现在就实施保障措施。

相应的安全栈是博客所说的“迄今最全面的生物安全措施”：全面的威胁建模、双重用途拒绝训练（dual-use refusal training）、常开的分类器与推理监控、明确的执行管线。博客还提到与外部生物安全专家、安全机构和学术研究者合作，生物学训练过的评审者验证了评估数据，领域专家红队在真实场景里对保障措施做了压力测试；本月早些时候还召开了一个生物防御（biodefense）研讨会，参与者来自政府、学术界、国家实验室和非政府组织。

更详细的安全做法在同日发布的系统卡里，博客只在正文里给了一个链接。本文件不替系统卡的内容背书。

## 三、主要发现

### 评估数字：正文里给了五组数字

博客在“Broadening real-world utility”（拓宽现实世界的用途）一节里给出了评估结果，数字都在正文里，不是只在图里：

在 Humanity's Last Exam（HLE，人类最后的考试）上，驱动 ChatGPT agent 的模型取得了 pass@1（首次通过率）41.6 的新纪录（SOTA，最优成绩）。博客说，因为智能体动态规划、自己选工具，同一任务在不同运行里可能走不同的路径；用一个简单的并行展开策略——同时跑最多八次尝试，挑自我报告置信度最高的那一次——HLE 分数可以提高到 44.4。

在 FrontierMath（已知最难的数学基准，题目新颖、未发表，专家数学家常常要花几小时甚至几天才能解出）上，配合工具使用（比如用终端执行代码），ChatGPT agent 达到 27.4% 的准确率，大幅超过此前的模型。

在 BrowseComp（OpenAI 今年早些时候发布的、衡量浏览智能体定位网上难找信息能力的基准）上，模型以 68.9% 创下新纪录，比 deep research 高 17.4 个百分点。

在 SpreadsheetBench（衡量模型编辑真实场景电子表格能力的基准）上，ChatGPT agent 大幅超过现有模型；获得直接编辑电子表格的能力后，得分 45.5%，而 Copilot in Excel（Excel 中的 Copilot）是 20.0%。附录的对照表给出了更细的数字，见第六节。

在 WebArena（衡量网页浏览智能体完成真实网络任务能力的基准）上，模型比 o3 驱动的 CUA（Operator 背后的模型）有所提升，但没有给出具体数字。

### 没有数字的能力主张

三组评估只有定性说法，没有数字：

一是内部基准，衡量模型完成复杂、有经济价值的知识工作任务的能力。博客说，在一系列任务完成时间上，ChatGPT agent 的输出在大约一半的案例中与人类相当或更好，同时大幅超过 o3 和 o4-mini。任务由各领域专家打分，对照的是各领域顶尖从业者建立的高质量人类基线，任务例子包括准备按需紧急护理提供商的竞争分析、制作详细的摊销表、为新建绿色氢能工厂寻找可行的水井。任务数量、人类基线的具体规模、“大约一半”到底是多少，都没有给出。

二是 DSBench（衡量智能体完成真实数据科学任务的基准，覆盖数据分析与建模）。博客只说 ChatGPT agent“以显著优势超过人类表现”，没有给出数字。

三是内部基准，衡量模型承担一到三年级投行分析师建模任务的能力，比如为一家财富 500 强公司做带格式与引用的三表财务模型，或为一起私有化交易做杠杆收购模型。博客只说模型“大幅超过 deep research 和 o3”，每个任务按数百条与正确性和公式使用相关的标准打分，没有给出数字。

### 发布内容：向谁开放，多少钱

发布当天开始向 Pro、Plus 和 Team 用户推出：Pro 用户当天结束前获得访问权限，Plus 和 Team 用户在接下来几天内获得；Enterprise（企业版）和 Education（教育版）用户在未来几周内获得。欧洲经济区和瑞士的访问仍在推进中。

用量额度是：Pro 用户每月 400 条智能体消息，其他付费用户每月 40 条，超出部分可以通过灵活的按信用额度（credit-based）方式购买更多用量。

Operator 的研究预览网站还会继续运行几周，之后关闭。deep research 现在是 ChatGPT agent 能力的一部分；如果用户更喜欢原来的 deep research 功能（运行时间可能更长，但默认给出更详细、更深入的回答），仍然可以在消息框下拉菜单里选择“deep research”。

### 博客自己承认的局限

博客明确承认的局限有两点。第一，ChatGPT agent 还处在早期阶段，能承担一系列复杂任务，但仍然会犯错。第二，幻灯片生成功能目前还在测试版（beta）：输出在格式与打磨程度上时常显得粗糙，特别是在没有现成文档作为起点的时候；幻灯片查看器里的内容与导出的 PowerPoint 文件之间偶尔会有差异，团队正在努力缩小这种差异；目前可以上传现成电子表格让 ChatGPT 编辑或用作模板，但幻灯片还不支持这个功能。博客说，下一代幻灯片生成正在训练中，目标是更精致、更成熟的输出、更强的能力和更好的格式。

除此之外，博客没有列出别的局限。特别是，内部基准、DSBench、投行建模基准和 WebArena 都没有给出数字。这一点不是博客自己承认的局限，是分析者发现的缺口，见下一节。

## 四、作者的结论与局限

### 作者的结论

博客没有研究结论。它要传达的信息是三句：ChatGPT agent 已经可以用了，是一个把 Operator、deep research 与 ChatGPT 合并的统一智能体；它在几项基准上取得了正文里可核查的分数；它的风险比以前更高，因为它第一次可以直接在网上采取行动、直接接触用户的数据，所以配上了迄今最全面的安全栈，并按“高生物与化学能力”对待。

关于未来，博客的判断是：发布只是一个开始，接下来会定期持续加入重大的改进，让它对更多人更有能力、更有用；同时会继续调整所需的监督程度，让它在保持安全的前提下更有用。

### 作者自述的局限

博客明确承认的局限有两点：第一，智能体还处在早期阶段，仍然会犯错；第二，幻灯片生成功能还在测试版，格式与打磨程度时常粗糙，查看器与导出的 PowerPoint 之间偶尔有差异，幻灯片还不支持上传现成文件作模板。

除此之外，博客没有列出别的局限。特别是，它没有报告内部知识工作基准、DSBench、投行建模基准和 WebArena 的具体数字，也没有给出这些基准的任务数量与评分细节。这一点不是博客自己承认的局限，是分析者发现的缺口，见下一节。

## 五、精读点评

这一节是分析者的判断，和上面对博客的呈现分开写。

### 这篇文档真正要回答的问题

这篇文档真正要回答的问题不是科学问题，而是产品问题：一个能直接在网上替你干活的 ChatGPT，值不值得你现在就用、安不安全。它给出的答案分两层。第一层是产品形态本身：统一智能体、可视化浏览器加文本浏览器加终端加 API、浏览器接管模式、随时打断与接管、发邮件要主动监督、做购买要先征得许可——这套形态是具体的、可核查的。第二层是“它有多强”：博客给了五组正文数字（HLE 41.6、FrontierMath 27.4%、BrowseComp 68.9%、SpreadsheetBench 45.5% 对 20.0%、WebArena 定性提升），其中前四组是可核查的，WebArena 只有方向没有数字；另外三组评估（内部知识工作基准、DSBench、投行建模基准）只有“大幅超过”“与人类相当或更好”这类定性说法。第二层里，数字的部分立得住，没有数字的部分立不住。

### 科学问题还原：五问

**现象是什么？** Operator 和 deep research 各管一摊：前者能动手、不会深想，后者会深想、不能动手。用户在实际使用中发现，很多用 Operator 发起的查询其实更适合 deep research。反常不在于某一次实验失败，而在于“能动手”和“会深想”之间没有现成的统一产品形态——两者都有了，合起来还没有。

**为什么重要，不解决会怎样？** 对实践来说，不解决它，用户就只能在两个工具之间来回切换，复杂任务做不到“从头做到尾”；对领域来说，不解决它，智能体就只能停留在“要么动手、要么动脑”的分工里，统一的通用智能体这条路就走不通。这篇博客的重要性首先在于它宣布了一个可用的产品形态，而不是提出了一个新发现。

**为什么之前做不了？** 博客没有回答这个问题。分析者能从产品描述里推断的 blocker 有三个：一是工具选择，要让同一个模型在可视化浏览器、文本浏览器、终端、API 之间自己选最高效的路径；二是可控性，要让用户能随时打断、接管、停止，而不丢失进展；三是安全，要在智能体能直接接触用户数据、直接在网上采取行动的前提下，管住提示注入与高风险操作。但这三点是分析者的推断，博客本身没有把它们写成“之前卡住的点”。

**方法与问题是否匹配？** 这篇文档没有方法，也就没有方法与问题的匹配问题。它提供的不是一个实验设计，而是一个产品：统一智能体模型、工具套件、浏览器接管、Watch Mode、明确确认。这套产品设计回答的是“怎么把复杂任务从头做到尾”，而不是“模型的能力有多强”。把博客里的“大幅超过”读成一个评估结论，就是方法与问题不匹配的地方——博客在那几项评估上根本没有做评估报告该做的事（给数字、给任务数、给评分细节）。

**答案改变了什么？** 认知上，基本没改变——博客没有提供任何新证据来改变我们对模型能力的认识，HLE、FrontierMath、BrowseComp、SpreadsheetBench 的数字是新的测量结果，但它们测量的是一个新产品的表现，不是关于智能体本质的新发现。实践上，它改变了一件事：从 2025 年 7 月 17 日起，ChatGPT Pro、Plus、Team 用户可以直接用上一个能替你操作网站、跑代码、做幻灯片和电子表格的智能体，Pro 每月 400 条消息，其他付费用户每月 40 条。这是一次产品发布，不是一次认知更新。

### 价值判断

认知价值是低的。博客没有推翻或确认任何信念，也没有给出任何关于智能体机制的新证据。反事实是：如果这篇博客不存在，我们对统一智能体的认识不会有任何不同——因为它本来就没有提供认识它的证据。

方法价值是低的。它留下的可复用东西只有两样：一是“可视化浏览器加文本浏览器加终端加 API”这套工具组合与动态工具选择的思路；二是“明确确认加 Watch Mode 加一键清除浏览数据”这套针对可行动智能体的安全控制设计。这两样都是产品设计层面的做法，不是研究方法。附录的 SpreadsheetBench 对照表对后来人有用，但它是一张结果表，不是一项方法。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

“驱动 ChatGPT agent 的模型在 HLE 上取得 pass@1 41.6 的新纪录”：按 HLE 的公开定义与同一口径重跑单次运行。如果重跑的分数明显低于 41.6，这个说法就要修正；如果 44.4 被当作单次分数引用，那是口径错误——44.4 是八次并行、挑置信度最高者的策略分数。

“ChatGPT agent 在 BrowseComp 上以 68.9% 创下新纪录，比 deep research 高 17.4 个百分点”：按 BrowseComp 的公开定义重跑，并核实 deep research 的绝对分数是否为 51.5% 左右。如果 deep research 的分数不是 51.5% 左右，“高 17.4 个百分点”这个说法就要重新核对。

“ChatGPT agent 在 DSBench 上以显著优势超过人类表现”：找到 DSBench 的具体分数与人类基线。如果分数与人类相当或更低，“显著超过”即被反驳。

“ChatGPT agent 能抵抗提示注入”：博客正文没有给出任何数字，这个主张目前不可证伪——需要系统卡里的具体测量（比如抵抗率、误判率）才能写出证伪器。

## I. 结论、结果与价值总览

### 一句话结论

这是一篇产品发布博客，不是研究论文：它宣布了把 Operator、deep research 与 ChatGPT 合并的统一智能体 ChatGPT agent，给出了四组正文里可核查的公开基准数字，但关于“与人类相当或更好”“大幅超过”这类最重的能力主张，没有给出任何可核查的数字。

### 核心结论

1. **ChatGPT agent 是一个统一的智能体系统（置信度：高）。** 把 Operator 的网页操作能力、deep research 的信息综合能力、ChatGPT 的对话能力装进同一个模型，配上可视化浏览器、文本浏览器、终端、直接 API 访问与 ChatGPT 连接器，在自己的虚拟计算机上把复杂任务从头做到尾。

2. **四组公开基准的数字是正文里可核查的（置信度：高）。** HLE pass@1 41.6（单次），并行展开策略下 44.4；FrontierMath 27.4%；BrowseComp 68.9%，比 deep research 高 17.4 个百分点；SpreadsheetBench 直接编辑电子表格时 45.5%，Copilot in Excel 20.0%。

### 科学价值总评

认知价值是低的。博客没有提供任何新证据来改变我们对模型能力的认识；如果这篇博客不存在，我们对统一智能体的认识不会有任何不同。

方法价值是低的。留下的可复用东西只有“可视化浏览器加文本浏览器加终端加 API”这套工具组合与动态工具选择的思路，以及“明确确认加 Watch Mode 加一键清除浏览数据”这套针对可行动智能体的安全控制设计，都是产品设计层面的做法，不是研究方法。

边界价值是中等偏高的。它明确不证明：内部知识工作基准上“大约一半”到底是多少；DSBench 上“显著超过人类”到底是多少；投行建模基准上“大幅超过”到底是多少；WebArena 上比 o3 驱动的 CUA 强多少；以及 ChatGPT agent 在真实用户任务上的成功率。最容易误读的推论，是把博客里的“大幅超过”“显著超过”读成具体的分数差距——那些分数在正文里根本不存在。

启示价值在于，最便宜的决定性下一步是去读同日发布的系统卡，看它有没有给出内部基准、DSBench、投行建模基准和 WebArena 的完整数字，以及提示注入抵抗能力的具体测量。

总体 verdict 是：这篇工作值得被记住为一个产品形态的发布——统一智能体、虚拟计算机、浏览器接管模式、Watch Mode、按“高生物与化学能力”对待的安全栈。不值得被记住为关于模型能力的证据——它在公开基准上给了四组可核查的数字，但在最重的能力主张上没有提供那样的证据，也不该用它的措辞去论证 ChatGPT agent 在真实知识工作上与人类相当或更好。

### 适用边界

不要用这篇博客论证 ChatGPT agent 在内部知识工作基准、DSBench、投行建模基准或 WebArena 上取得了某个具体分数，不要用“大约一半与人类相当或更好”论证它在真实知识工作上与人类相当，不要用 HLE 的 44.4 论证单次运行的分数，不要用 SpreadsheetBench 的 45.5% 对 20.0% 论证同一环境下的优势（两者评估环境不同）。

可以引用的是产品形态本身（统一智能体、工具套件、虚拟计算机、浏览器接管、随时打断与接管）、四组公开基准的正文数字（带口径说明）、安全设计的四层结构（带可核查性有限的提醒）、开放范围与用量额度、以及博客自己承认的局限（早期阶段仍会犯错、幻灯片功能还在测试版）。引用“大幅超过”“显著超过”时，须同时说明正文里没有任何数字支撑。
