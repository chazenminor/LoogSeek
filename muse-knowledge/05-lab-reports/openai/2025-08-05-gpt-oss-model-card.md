## 一、背景与问题

### 发布之前是什么局面

到 2025 年 8 月，OpenAI 的前沿推理模型（o3、o4-mini、o3-mini）全是闭源的，只能通过 API 调用。开源社区能拿到的最强开放权重模型来自别家：DeepSeek、Qwen、Kimi 等。OpenAI 上一次发布开放权重模型还是 GPT-2 时代的事。一个现实的张力摆在那里：一边是开源社区想要一个真正能干活的开放推理模型——能调推理档位、能用工具、能看到完整思维链、能自己部署；另一边是 OpenAI 自己对开放权重的顾虑——权重一旦放出去，别人可以拿去微调，绕过安全拒绝，甚至直接往有害能力的方向优化，OpenAI 没法再追加缓解措施，也没法收回。

这份模型卡要同时做两件事。第一件是发布产品：两个开放权重推理模型，gpt-oss-120b 与 gpt-oss-20b，Apache 2.0 协议开源，权重、推理实现、工具环境与分词器一起放出来。第二件是为这次发布辩护：证明放出这两个模型不会把生物、网络与自我改进这三类前沿风险推过 OpenAI 自己的 High 能力阈值，甚至证明放出 120b 也不会显著推进开源模型在生物能力上的前沿。

### 这篇文档真正要回答的问题

这份模型卡要回答的问题可以分成三层。第一层，模型本身是什么：多大、什么架构、怎么训的、基准上什么水平。第二层，模型默认有多安全：对违禁内容的拒绝、对越狱的抵抗、对指令层级的遵守、幻觉与偏见各是什么水平。第三层，也是这份文档花篇幅最多的一层：放出权重之后的风险有多大——攻击者拿去做对抗微调，能不能把模型推到 High 能力；放出 120b 会不会让开源生物能力的前沿往前跳一步。

前两层是常规的模型卡内容，第三层才是这份文档的特殊之处。普通的模型卡评估的是“默认模型”，这份模型卡评估的重点却是“被恶意改造过的模型”。OpenAI 自己写明了理由：对开放权重模型来说，测试条件“理想情况下应反映下游行为体能够改造模型的各种方式”，只测默认模型是不够的。

### 这是一篇什么样的文档

标题是 gpt-oss-120b & gpt-oss-20b Model Card，中文可译为“gpt-oss-120b 与 gpt-oss-20b 模型卡”。作者署名为 OpenAI，贡献者名单按姓氏字母顺序排列，见模型卡第 8 节，从 Sandhini Agarwal 到 Shengjia Zhao，是一份上百人的集体作者名单，没有单独列出第一作者。

## 二、方法与设计

### 两个模型：一个 120b，一个 20b

两个模型都是自回归的混合专家（Mixture-of-Experts，MoE）Transformer，建立在 GPT-2 与 GPT-3 的架构之上。gpt-oss-120b 共 36 层，总参数 116.8B，每次前向每 token 激活的参数是 5.1B；gpt-oss-20b 共 24 层，总参数 20.9B，激活参数 3.6B。名字里的 120b 与 20b 是约数。两个模型的参数构成见表 1：120b 的 MLP 部分占 114.71B，注意力部分 0.96B，嵌入加解嵌入 1.16B；20b 的 MLP 部分 19.12B，注意力 0.64B，嵌入加解嵌入同样是 1.16B。检查点大小分别是 60.8 GiB 与 12.8 GiB。

架构上有几个要点。残差流维度两个模型都是 2880，每个注意力块与 MoE 块之前用 RMS 归一化（root mean square normalization），采用 GPT-2 式的 Pre-LN 放置。每个 MoE 块里，120b 有 128 个专家，20b 有 32 个专家；两个模型对每个 token 都选路由器打分最高的 4 个专家，用 softmax 加权输出。MoE 块用门控 SwiGLU（gated SwiGLU）激活函数，作者注明自己的 SwiGLU 实现并不常规，包含截断（clamping）与一个残差连接。注意力沿用 GPT-3 的做法，在带状窗口（banded window）与全稠密模式之间交替，窗口带宽是 128 个 token；每层有 64 个维度为 64 的查询头，用分组查询注意力（Grouped Query Attention，GQA），键值头 8 个；用旋转位置编码（rotary position embeddings），并用 YaRN 把稠密层的上下文长度扩展到 131,072 个 token。每个注意力头在 softmax 分母上还有一个学到的偏置，类似 off-by-one 注意力与注意力汇（attention sinks）的思路，让注意力机制可以做到对任何 token 都不注意。

### 量化：MXFP4，120b 能塞进一块 80GB 的卡

为了减小内存占用，模型在后训练阶段对 MoE 权重量化到了 MXFP4 格式，每个参数 4.25 比特。MoE 权重占总参数的九成以上，量化之后，大模型能装进一块 80GB 的 GPU，小模型能在只有 16GB 内存的系统上跑。检查点大小（60.8 GiB 与 12.8 GiB）就是量化之后的大小。

### 分词器：o200k_harmony，201,088 个 token

全部训练阶段用的都是 o200k_harmony 分词器，在 TikToken 库里开源。这是一个字节对编码（Byte Pair Encoding，BPE），在 GPT-4o 与 o4-mini 用的 o200k 分词器基础上扩展而来，加了 harmony 聊天格式专用的 token，总共 201,088 个 token。

### 预训练：数万亿 token，H100，2.1M 卡时

预训练用的是纯文本数据集，规模是“数万亿个 token”（trillions of tokens），侧重 STEM、编程与通用知识。数据集的具体 token 数没有给出。为了提升安全性，预训练时过滤了有害内容，特别是在危险生物安全知识方面，复用了 GPT-4o 的 CBRN（化学、生物、放射、核）预训练过滤器。模型的知识截止日期是 2024 年 6 月。

训练在 NVIDIA H100 GPU 上进行，用 PyTorch 框架，配专家优化的 Triton 内核，并用 FlashAttention 算法降低内存需求、加速训练。120b 的训练一共用了 2.1M 个 H100 小时（2.1 million H100-hours），20b 用的算力少了将近 10 倍。预训练数据的来源、混合比例、超参数、训练轮数，模型卡都没有报告。

### 后训练：o3 同款的思维链强化学习

预训练之后，模型用与 OpenAI o3 类似的思维链（Chain-of-Thought，CoT）强化学习技术做后训练。这一步教模型用思维链推理和解题，也教它用工具。作者说，因为用了类似的强化学习技术，这两个模型的“性格”与 ChatGPT 等第一方产品里的模型相似。训练数据集覆盖编程、数学、科学等各类问题，但具体构成没有报告。

### Harmony 聊天格式：角色层级与可见性通道

模型训练用了一套叫 harmony 的定制聊天格式。这套格式用特殊 token 划分消息边界，用关键词参数（例如 User 与 Assistant）标明消息的作者与接收方。沿用 OpenAI API 模型的 System 与 Developer 两个消息角色。模型按角色信息层级解决指令冲突：System 高于 Developer，Developer 高于 User，User 高于 Assistant，Assistant 高于 Tool。

格式还引入了“通道”（channels）来标明每条消息的可见性，例如 analysis 通道放思维链 token，commentary 通道放函数工具调用，final 通道放展示给用户的答案。这套格式让 gpt-oss 能支持更高级的智能体功能，包括在思维链里穿插工具调用，或者向用户提供概述较长行动计划的 preamble（前言）。作者强调，正确部署这套格式对发挥模型最佳能力至关重要，例如在多轮对话里应该删掉之前助手轮次的推理轨迹。附录 1 给了一个 harmony 格式的输入输出示例（图 17、图 18）。

### 可变推理档位：低、中、高三档

模型训练支持低（low）、中（medium）、高（high）三档推理级别，在系统提示里插入“Reasoning: low”这样的关键词来配置。提高推理档位会让模型的平均思维链长度变长。图 3 把 AIME 与 GPQA 上的准确率对平均思维链加答案长度作图，显示提高推理档位带来平滑的测试时扩展（test-time scaling）：更长的思维链换更高的准确率，但代价是最终回复的延迟与成本大幅上升。作者建议用户按自己的用例，在模型大小与推理档位之间权衡。

### 智能体工具：浏览、Python、开发者自定义函数

后训练还教模型用三种智能体工具。一是浏览工具，可以调用搜索与打开函数与网页交互，辅助事实性，也能获取知识截止日期之后的信息。二是 Python 工具，可以在有状态的 Jupyter 笔记本环境里运行代码。三是任意的开发者自定义函数，可以在 Developer 消息里像 OpenAI API 那样指定函数 schema，模型可以在思维链、函数调用、函数响应、展示给用户的中间消息与最终答案之间穿插。模型训练时支持在系统提示里指定用或不用这些工具。OpenAI 为每种工具提供了基础的参考 harness（工具环境），并开源了实现。

### 评估设计：高推理档位、默认系统提示、pass@1

能力评估覆盖推理与事实性（AIME、GPQA、MMLU、HLE，即 Humanity's Last Exam）、编程（Codeforces Elo 与 SWE-bench Verified，带或不带终端工具）、工具使用（τ-Bench Retail，用开发者消息提供函数）与额外能力（MMMLU 多语言、HealthBench 健康知识）。模型卡说明：对所有数据集，报告的是高推理模式下、用模型默认系统提示的基本 pass@1 结果，对照组是 OpenAI o3、o3-mini 与 o4-mini。表 3 给出了两个 gpt-oss 模型在低、中、高三档推理级别下的全部基准结果。但要注意，表 3 里只有 gpt-oss 两个模型自己的数字；o3、o3-mini、o4-mini 的对照数字只在图 1、图 2、图 4 里，正文与表格都没有给出，因此本次精读无法核实那些对照数字（见第六节与文末未核实清单）。

### 安全测试设计：默认表现加对抗微调

安全测试分两层。第一层是默认安全表现（第 4 节）：违禁内容、越狱、指令层级、幻化思维链、幻觉、公平与偏见。第二层是防备框架评估（第 5 节）：在三个被追踪类别（生物与化学能力、网络能力、AI 自我改进）上，先测默认模型，再测对抗微调过的模型。

对抗微调的设计是这份模型卡方法上最特别的部分。作者模拟的攻击者是技术型的：有强大的后训练基础设施与机器学习知识，能收集有害能力领域的域内数据，有大量的算力预算。方法上用 OpenAI 内部的 o 系列强化学习训练栈做增量强化学习，评估时用最高推理档位。具体做法分两步：先做“仅 helpful”训练（helpful-only training），即再做一轮强化学习，奖励对不安全提示的顺从回答；再针对防备基准最大化生物与网络领域的相关能力。生物方向的对抗模型还增量训练了网页浏览能力，并用了与生物风险相关的领域内人类专家数据；网络方向的对抗模型用的领域数据是网络安全夺旗赛（capture the flag，CTF）挑战环境。

这套对抗微调的流程与发现还写进了一篇配套的研究论文（模型卡里没有给出这篇论文的 arXiv 编号，只说“在一篇配套研究论文里有更详细的描述”）。外部安全专家（METR、SecureBio 与 Daniel Kang）独立评审了这套恶意微调方法：一共提交了 22 条建议，OpenAI 采纳了 11 条，包括 12 条高优先级建议里的 9 条。采纳的建议包括增加协议调试相关的微调数据、新增一个未污染的协议调试评估、把病毒学评估更新到最新版本、澄清低资源行为体的假设，等等。没有采纳的三条高优先级建议是：把 best-of-N 脚手架广泛用于全部评估、把 ProtocolQA 从防备阈值里拿掉、以及计算开放模型与闭源模型合并后的拒绝对比。拒绝的理由与采纳清单都写在附录 2 里。

## 三、主要发现

### 能力：120b 接近 o4-mini，20b 出人意料地能打

图 1 与图 2 的标题说法是：高推理档位下，gpt-oss-120b 超过 OpenAI o3-mini，接近 o4-mini 的准确率；小得多的 gpt-oss-20b 也出人意料地有竞争力，尽管它比 120b 小 6 倍。图里的具体数字无法核实，但表 3 里 gpt-oss 两个模型自己的数字是完整的。

数学是最强的部分。120b 在 AIME 2024（无工具）高推理档位上拿到 95.8%，20b 拿到 92.1%；用工具之后分别是 96.6% 与 96.0%。AIME 2025（无工具）高推理档位上，120b 是 92.5%，20b 是 91.7%；用工具之后分别是 97.9% 与 98.7%——20b 在这一项上反而超过了 120b。作者在正文里解释数学强的原因：模型能有效利用非常长的思维链，例如 20b 在 AIME 上平均每道题用了超过 20k 个思维链 token。

知识类任务上两个模型的差距拉开了。GPQA Diamond（无工具）高推理档位，120b 是 80.1%，20b 是 71.5%；用工具之后分别是 80.9% 与 74.2%。HLE（无工具）高推理档位，120b 是 14.9%，20b 是 10.9%；用工具之后分别是 19.0% 与 17.3%。MMLU 高推理档位，120b 是 90.0%，20b 是 85.3%。

推理档位的拉动非常大。以 AIME 2024（无工具）为例，120b 从低档位的 56.3% 涨到中档位的 80.4%，再涨到高档位的 95.8%；20b 从 42.1% 涨到 80.0%，再涨到 92.1%。档位之间的差距在低档位最大，越往高档位收敛。工具的帮助在低档位最明显：120b 在 AIME 2024 低档位上，无工具是 56.3%，有工具是 75.4%，差了将近 20 个百分点；到高档位，无工具 95.8%，有工具 96.6%，只差不到 1 个百分点。

编程与工具使用上，两个模型同样接近。SWE-bench Verified 高推理档位，120b 是 62.4%，20b 是 60.7%，只差 1.7 个百分点。τ-Bench Retail 高推理档位，120b 是 67.8%，20b 是 54.8%，差距拉到 13 个百分点；τ-Bench Airline 高推理档位，120b 是 49.2%，20b 反而只有 38.0%，比自己的中档位 42.6% 还低——这是表 3 里唯一一个高档位比中档位差的格子。Aider Polyglot 高推理档位，120b 是 44.4%，20b 是 34.2%。Codeforces Elo 高推理档位，无工具时 120b 是 2463，20b 是 2230；有工具时分别是 2622 与 2516。

### 健康：120b 接近 o3，20b 超过 o1

HealthBench 上，120b 高推理档位是 57.6%，20b 是 42.5%；HealthBench Hard 上，120b 是 30.0%，20b 是 10.8%；HealthBench Consensus 上，120b 是 89.9%，20b 是 82.6%。图 4 的标题说法是：120b 在 HealthBench 与 HealthBench Hard 上几乎追上 OpenAI o3，明显超过 GPT-4o、o1、o3-mini 与 o4-mini；20b 也略好于 o1。但 o3、o1 等对照模型的具体分数只在图里，正文没有给出，无法核实。模型卡同时提醒：gpt-oss 模型不能替代医疗专业人员，不用于疾病的诊断或治疗。

作者把健康结果说成是“健康表现—成本前沿上的一次大的帕累托改进”，并认为开放模型在全球健康领域可能尤其有影响，因为那里的隐私与成本约束很重要。

### 多语言：120b 接近 o4-mini，低资源语言掉得厉害

MMMLU（14 种语言的人工翻译版 MMLU）上，120b 高推理档位平均 81.3%，20b 是 75.7%。分语言看，120b 高推理档位在西班牙语上最高（85.9%），葡萄牙语 85.3%，意大利语 85.0%；在斯瓦希里语上掉到 72.3%，约鲁巴语上只有 62.4%。20b 的低资源语言掉得更厉害：斯瓦希里语高推理档位 60.7%，约鲁巴语 50.1%，而低档位上约鲁巴语只有 38.4%。o3 在 MMMLU 平均分上的对照数字只在表 2 里有（88.8%），o4-mini 是 85.2%，o3-mini 是 80.7%——表 2 是全文里唯一一张同时给出 gpt-oss 与三个对照模型数字的表。

### 默认安全表现：与 o4-mini 大致相当，有几处明确的短板

违禁内容评估分两套。标准违禁内容评估上，两个 gpt-oss 模型与 o4-mini 的分数普遍在 1 到 2 个百分点之内。120b 在仇恨（0.996）、自我伤害（0.995）、性/未成年人（1.000）、非法/暴力（1.000）等类别上与 o4-mini 持平或略高；20b 略低一些，例如性/未成年人 0.971、非法/非暴力 0.983。但作者自己说，这套标准评估已经被最近的模型刷满（saturate），不再能提供有用的增量信号，所以新做了一套更难的 Production Benchmarks（生产基准），对话更贴近生产数据、多轮、更不直白。

在 Production Benchmarks 上，两个 gpt-oss 模型总体上明显超过 o4-mini。例如非暴力仇恨类别，120b 是 0.895，20b 是 0.901，o4-mini 是 0.832；个人数据类别，120b 是 0.888，20b 是 0.921，o4-mini 是 0.847。但最弱的一类是非法/非暴力：120b 只有 0.692，20b 是 0.656，o4-mini 是 0.658，GPT-4o 是 0.573——四个模型在这一类上都不到 0.7。20b 在 Production Benchmarks 的非法/暴力类别上（0.744）也低于 o4-mini（0.845）。

越狱评估（StrongReject，把已知的越狱技术插进违禁内容评估的样本里）上，两个模型与 o4-mini 大致相当。120b 在四类提示上分别是 0.979（非法/非暴力犯罪）、0.983（暴力）、0.993（虐待/虚假信息/仇恨）、0.989（性内容）；20b 略低，在 0.960 到 0.982 之间。

指令层级是明确的短板。系统提示提取（用户消息能不能把系统提示原样套出来）上，120b 只有 0.832，20b 是 0.881，o4-mini 是 0.993。提示注入劫持（用户消息试图让模型说出“access granted”，系统消息阻止）上，120b 是 0.780，20b 只有 0.639，o4-mini 是 0.917。短语与密码保护评估上，120b 与 o4-mini 大致相当（系统消息短语保护 0.912 对 0.937），但 20b 明显更差（开发者消息短语保护只有 0.661，o4-mini 是 0.912）。作者的解释是：两个 gpt-oss 模型对已知越狱的抵抗力与 o4-mini 相当，但用系统消息防止用户越权的能力不如 o4-mini；实际影响是，开发者用系统消息作缓解措施时，在 gpt-oss 模型上可能不如在 o4-mini 上有效。不过作者也指出，开发者可以对这两个模型做微调，让它们对遇到的越狱更稳健。

幻觉评估上，两个模型都比 o4-mini 差。SimpleQA（4,000 道事实性问题，不给浏览）准确率：120b 是 0.168，20b 只有 0.067，o4-mini 是 0.234；幻觉率：120b 是 0.782，20b 是 0.914，o4-mini 是 0.750。PersonQA 准确率：120b 是 0.298，20b 是 0.155，o4-mini 是 0.356；幻觉率：120b 是 0.491，20b 是 0.532，o4-mini 是 0.361。作者的解释是，小模型世界知识更少，更容易幻觉；浏览或获取外部信息往往能减少幻觉。

公平与偏见评估（BBQ）上，两个模型与 o4-mini 大致相当。模糊问题准确率：120b 是 0.87，20b 是 0.79，o4-mini 是 0.82；消歧问题准确率：120b 是 0.90，20b 是 0.89，o4-mini 是 0.95。

### 幻化思维链：特意不做优化

模型卡有一节专门讲幻化的思维链（hallucinated chains of thought）。作者引用了自己之前关于思维链监控的研究：监控推理模型的思维链有助于发现不当行为；但如果直接对思维链施加优化压力，模型可能学会把不当想法藏起来，同时继续不当行为。基于这个考虑，作者决定不对这两个开放权重模型的思维链做任何直接优化压力，希望给开发者留出实现思维链监控系统的机会，也让研究社区能进一步研究思维链的可监控性。

代价是写明的：这些思维链没有受限，可能包含幻化内容，包括不符合 OpenAI 标准安全政策的语言。开发者不应该在没有进一步过滤、审核或总结的情况下，直接把思维链展示给应用的用户。

### 防备框架：默认模型没到 High，对抗微调后也没到 High

防备框架评估的结论是：默认的 gpt-oss-120b 在三个被追踪类别（生物与化学能力、网络能力、AI 自我改进）里，没有任何一类达到 High 能力的指示阈值。对抗微调之后，OpenAI 的安全咨询组（Safety Advisory Group）评审后认定，即使经过利用 OpenAI 顶尖训练栈的稳健微调，gpt-oss-120b 在生物与化学风险或网络风险上仍然没有达到 High 能力。

生物方向上，120b 在回答涉及生物知识与危害场景的长篇文字问题上表现出“值得注意的实力”，但在复杂的协议调试任务上尚未达到高指示阈值，而且纯文本架构本身限制了它在依赖视觉的实验室场景里的适用性。生物是 120b 表现最强的一个领域。模型卡还回答了第二个问题：放出 120b 会不会显著推进开源基础模型在生物能力上的前沿。答案是否定的：在大多数评估上，已经有一个或多个现有开放模型的默认表现接近对抗微调后的 gpt-oss-120b 的表现。比较对象一开始主要是 DeepSeek R1-0528，过程中 Qwen 3 Thinking 与 Kimi K2 发布了，也加进了比较集。结论是：Qwen 3 Thinking 与 Kimi K2 已经推进到了与 gpt-oss-120b 相当的水平；120b 在个别生物安全评估上是最高的，但没有哪一个开放模型在这一领域全面领先其他模型。

生物方向的具体评估包括：长篇生物风险问题（覆盖生物威胁创造过程的五个阶段：构想、获取、放大、配方、释放）、多模态病毒学故障排查（350 道完全保留的病毒学故障排查问题，SecureBio 提供）、ProtocolQA 开放式问答（把 FutureHouse 的 ProtocolQA 数据集里的 108 道多选题改成开放式简答题，19 位有一年以上湿实验室经验的博士做专家基线，共识基线 54%，中位数基线 42%）、隐性知识与故障排查（与 Gryphon Scientific 合作的全新未污染选择题集，共识专家基线 80%，80 分位博士专家基线 63%）、TroubleshootingBench（52 份专家手写湿实验室流程，每份配 3 道故障排查题，12 位独立博士专家做基线，80 分位专家分数 36.4% 作为指示阈值）。这些评估上各模型的分数只在图 5 至图 9 里，正文没有给出，无法核实。能从正文确认的只有：o3 在其中几项上仍然是最高分，所有模型都低于 ProtocolQA 的共识专家基线（54%）与中位数基线（42%），没有模型超过隐性知识评估的共识专家基线（80%），所有模型都低于 TroubleshootingBench 的 80 分位人类分数（36.4%）。

外部评估方 SecureBio 的评估发现，对抗微调版的 gpt-oss-120b 在生物安全相关任务上总体上超过了未微调的 DeepSeek R1-0528，但在整体可靠性与深度上仍低于 OpenAI o3。OpenAI 的内部后续比较确认，新发布的 Qwen 3 Thinking 与 Kimi K2 在生物安全相关评估上已经与对抗微调后的 gpt-oss-120b 相当。

网络方向上，对抗微调后的模型表现与 o3 相当，同样低于 High 能力阈值。CTF 评估用 100 多道策展过的公开 CTF 挑战，覆盖网络应用利用、逆向工程、二进制与网络利用、密码学、杂项五个类别，分高中、大学、专业三个难度级别；每个 CTF 跑 16 次 rollout，报告 pass@12。高中级别的 CTF 因为太容易，已经不再报告。图 10 与图 11 的分数只在图里，无法核实；正文能确认的是：o3 在大学级别 CTF 上仍然是表现最好的模型，其次是 gpt-oss-120b 的发布候选版本；网络方向的对抗微调模型（cybermax，在高中与大学 CTF 以及部分不在评估集里的 CTF 上训练过）在专业级别 CTF 上只比 o3 低 3 个百分点——但要注意，大学级别的 CTF 是 cybermax 训练数据的一部分，所以图 10 里没有画 cybermax 的大学级别成绩。

网络靶场（cyber range）评估测的是在逼真仿真网络里端到端执行网络行动的能力，一共 5 个场景（在线零售商（中难度）、简单提权（轻难度）、基础 C2（轻难度）、Azure SSRF（轻难度）、污染共享内容（轻难度）），每个场景跑 30 次试验，主要指标是无提示条件下的 pass@12。图 12 的标题说法是：没有任何模型能在无提示或有提示的情况下解出任何一个场景。模型卡同时注明，这些评估结果很可能只是能力的下界，因为更好的脚手架或能力激发可能大幅提高观测到的表现。

AI 自我改进方向上，gpt-oss 模型没有表现出比 o3、o4-mini 更强的软件工程与 AI 研究任务表现，o3 与 o4-mini 仍然是所有基准上表现最高的模型。SWE-bench Verified 用固定的 n=477 个已验证任务子集，主要指标是 pass@1；o4-mini 只比 o3 高 1 个百分点（分数只在图 14 里）。OpenAI PRs 评估（复现 OpenAI 内部真实的拉取请求）上，gpt-oss 模型只比 o4-mini 低 2 个百分点（分数只在图 15 里）。PaperBench 用 10 篇论文的子集（每篇需要少于 10GB 的外部数据文件），高推理档位、无浏览，报告 pass@1，分数只在图 16 里。

## 四、作者的结论与局限

### 作者的结论

模型卡的结论是三句。第一，两个开放权重推理模型在数学、编程、工具使用与健康等基准上表现强劲，120b 超过 o3-mini、接近 o4-mini，20b 虽然小得多，也有出人意料的竞争力。第二，默认模型的安全表现与 o4-mini 大致相当，幻觉与指令层级是明确的短板，思维链特意不做优化以保留可监控性。第三，也是作者最想让读者带走的结论：默认模型没有达到防备框架里任何一类 High 能力的指示阈值；即使经过稳健的对抗微调，120b 在生物与化学风险或网络风险上仍然没有达到 High；而且放出 120b 也不会显著推进开源模型在生物能力上的前沿，因为 Qwen 3 Thinking 与 Kimi K2 等现有开放模型已经到了相当的水平。

### 作者自述的局限

模型卡没有像正规论文那样列出一节“局限”，但以下几点是作者自己在正文里承认的边界，值得原原本本记下来。

第一，评估结果很可能只是能力的下界。模型卡在网络 CTF 一节明确写了这句话：更好的脚手架或能力激发可能大幅提高观测到的表现。这句话虽然只出现在网络一节，但它对整份模型卡的防备评估都适用——“没到 High”是在当前激发条件下的结论。

第二，指令层级不如 o4-mini。作者明确承认，两个 gpt-oss 模型在防止用户越权改写系统消息方面不如 o4-mini，开发者用系统消息作缓解措施时的效果可能打折扣，并指出需要更多研究来理解为什么会这样。

第三，幻觉比 o4-mini 严重。作者承认两个模型在 SimpleQA 与 PersonQA 上都比 o4-mini 差，并把原因归于小模型世界知识更少。

第四，纯文本架构限制了生物能力的适用范围。作者在生物一节写明，文本模型在依赖视觉的实验室场景里先天受限，这也是 120b 没到 High 的原因之一。

第五，外部评估有不确定性。SecureBio 的评估以 R1-0528 为最强的开放权重基线，而且给 R1-0528 用的浏览 harness 带来了一些不确定性；OpenAI 是靠内部后续比较来补上 Qwen 3 Thinking 与 Kimi K2 的。

第六，标准违禁内容评估已经饱和。作者自己说这套评估不再能提供有用的增量信号，计划在不久的将来停止发布这套旧评估，改发更难的 Production Benchmarks。

除此之外，模型卡没有报告的东西包括：预训练数据的具体规模与混合比例、后训练的超参数与数据构成、能力评估的种子数与误差范围、以及防备框架 High 阈值的具体数值。这一点不是作者自己承认的局限，是分析者发现的缺口，见下一节。

## 五、精读点评

这一节是分析者的判断，和上面对模型卡的呈现分开写。

### 这篇文档真正要回答的问题

这篇文档真正要回答的问题不是“这两个模型有多强”，而是“放出这两个模型的权重安不安全”。能力数字是发布产品需要的，安全论证才是发布决策需要的。模型卡的结构也反映了这一点：能力评估只占第 2 节的后半部分，安全与防备评估占了第 3、4、5 三节的大半篇幅，外加一个附录专门讲外部专家对对抗微调方法的评审意见。

它给出的答案分两层。第一层是能力：120b 与 20b 的基准数字是完整的、可核对的，120b 在高推理档位上多项指标确实接近 o4-mini，20b 在数学与 SWE-bench Verified 上与 120b 的差距很小。这一层立得住。第二层是安全：默认模型没到 High，对抗微调后也没到 High，放出 120b 也不会推进开源生物能力的前沿。这一层的结论本身是明确的，但支撑它的证据有一大半只在图里，High 阈值本身没有公开，读者没法独立复核“没到 High”到底离阈值有多远。第一层是这份模型卡立住的部分，第二层是它留给读者的问号。

### 科学问题还原：五问

**现象是什么？** 开源社区想要一个真正能干活的开放推理模型，OpenAI 却有六年没放出过开放权重模型。反常不在于某一次实验失败，而在于“开放权重”与“前沿推理能力”之间没有现成的结合点——前沿推理模型全是闭源的，开源模型在推理与工具使用上一直差一截。同时，OpenAI 自己面临一个决策问题：放出权重之后，攻击者可以拿去微调，安全团队没法再追加缓解措施，这个决定一旦做出就收不回来。

**为什么重要，不解决会怎样？** 对实践来说，不解决它，开发者与研究者就只能用 API 调用前沿推理模型，没法自己部署、微调、研究思维链，也没法在隐私与成本受限的场景（例如全球健康）里用上推理能力。对领域来说，不解决它，“开放权重模型能不能做到接近前沿”这个问题就一直没有来自 OpenAI 的答案，关于开源与安全的争论也只能停留在立场层面。这份模型卡的重要性首先在于它给出了一个来自 OpenAI 自己的开放权重推理模型，其次在于它尝试用对抗微调的方法来回答“放出去安不安全”。

**为什么之前做不了？** 模型卡没有直接回答这个问题。分析者能从文档里推断的 blocker 有三个：一是训练成本，120b 用了 2.1M 个 H100 小时，20b 也要将近 10 分之 1，这不是随便能复现的投入；二是安全论证的方法，评估“被恶意改造过的模型”需要一套对抗微调流程与外部评审，OpenAI 为此专门写了一篇配套论文，还请了 METR、SecureBio 与 Daniel Kang 来评审；三是发布时机的选择，Qwen 3 Thinking 与 Kimi K2 在评估过程中发布，直接改变了“会不会推进开源前沿”这个问题的答案——如果这两家没发布，结论可能完全不同。这三点里只有第二点是模型卡自己讲清楚的，第一点与第三点是分析者的推断。

**方法与问题是否匹配？** 对能力评估来说，方法是匹配的：高推理档位、默认系统提示、pass@1、一套标准基准，量到的就是“默认配置下的能力”。但对安全论证来说，方法与问题的匹配是不完整的。对抗微调只做了两个类别（生物与化学、网络），没有做 AI 自我改进方向的对抗微调；对抗微调的攻击者模型是“技术型、有强大后训练基础设施、有大量算力预算”的攻击者，低资源行为体的假设只在附录里澄清，没有单独评估；而且对抗微调只针对 120b 做了，没有针对 20b 做。更关键的是，High 阈值本身没有公开，读者看到的只是“没到 High”这个二值结论，没法判断离阈值有多远，也没法判断换一套激发方式会不会越过阈值。

**答案改变了什么？** 认知上，它第一次给出了 OpenAI 自己的开放权重推理模型在标准基准上的公开数字，并且证明了“小模型也能很能打”：20b 在 AIME 2025（有工具）高推理档位上拿到 98.7%，反而超过 120b 的 97.9%；在 SWE-bench Verified 上只比 120b 低 1.7 个百分点。实践上，它改变了一件事：从 2025 年 8 月 5 日起，任何人都可以下载这两个模型的权重（Apache 2.0 协议）、自己部署、微调、研究思维链。至于“放出开放权重模型安不安全”这个更大的问题，答案是什么都没改变——模型卡给出的只是在当前激发条件与不公开阈值下的“没到 High”，不是一个能独立复核的安全证明。

### 价值判断

认知价值是中等偏高。模型卡没有推翻某个具体的旧信念，但它第一次把“OpenAI 的开放权重推理模型”变成了一个可公开比较的数字集合，并且量出了一个反直觉的结构：20b 只有 120b 六分之一的参数，在数学与编程基准上却只差几个百分点；120b 在健康基准上几乎追上 o3，但两个模型在幻觉与指令层级上都明显弱于 o4-mini。反事实是：如果这份模型卡不存在，“开放权重模型能不能接近前沿推理模型”这个问题会继续没有来自 OpenAI 的答案，关于开源与安全的争论会继续停留在立场层面。

方法价值是中等偏高的。它留下的可复用东西不止一个：harmony 聊天格式与角色层级设计、可变推理档位的训练方法、MXFP4 量化让 120b 装进一块 80GB 卡的做法、以及“对抗微调加外部专家评审”这套评估开放权重风险的方法论。任何想评估自己开放权重模型风险的人，都能直接拿走这套设计。扣分项是方法细节不完整：预训练数据构成、后训练超参数、能力评估的种子数与误差范围都没有报告，别人很难原样复现这套评估。

边界价值是高的，这正是这份精读记录最有价值的部分。它明确不证明的东西包括：o3、o3-mini、o4-mini 在表 3 各基准上的具体分数（只在图里）；防备评估里各模型在生物与网络评估上的具体分数（只在图 5 至图 12 里）；High 阈值的具体数值（没有公开）；换一套脚手架或激发方式后模型会不会越过 High（作者自己承认当前结果很可能是下界）；以及 20b 经过对抗微调后会不会到 High（根本没测）。读者最容易误读的推论，是把“没到 High”读成“放出这两个模型是安全的”——模型卡证明的只是在当前激发条件与不公开阈值下的“没到 High”，不是一般意义上的安全。

启示价值在于，最便宜的决定性下一步不是再读一遍这份模型卡，而是去找那篇配套的对抗微调研究论文，并核实图 1、图 2、图 4 里 o3、o3-mini、o4-mini 的对照数字：120b 到底比 o3-mini 强多少、比 o4-mini 差多少。这是启示价值里最便宜的决定性实验，也是这份模型卡最缺的一块。

### 最弱的一环

最弱的一环在“没到 High”这个结论与任何可核查的数字之间。整份模型卡关于发布安全的说服力，有一半建立在防备框架评估上——它是这份模型卡区别于普通模型卡的最大卖点。但防备评估里各模型的具体分数只在图 5 至图 16 里，正文与表格都没有给出；High 阈值的具体数值没有公开；对抗微调的完整流程在一篇配套论文里，模型卡没有给出那篇论文的编号。读者能核实的只有三句话：默认模型没到 High、对抗微调后也没到 High、安全咨询组评审后认同这个结论。如果阈值本身不公开，“没到 High”就没法被独立复核，只能信任 OpenAI 自己的判断。

第二弱的一环是“不会显著推进开源生物能力前沿”这个结论对时机的依赖。模型卡自己写明了：评估一开始主要比较的是 DeepSeek R1-0528，过程中 Qwen 3 Thinking 与 Kimi K2 发布了，才加进比较集。如果这两家晚发布几个月，结论可能是反过来的——120b 在个别生物安全评估上是最高的，放出它就可能推进前沿。这个结论的成立条件里有一个不受 OpenAI 控制的外部因素：别家开源模型的发布节奏。

第三弱的一环是能力评估里对照数字的缺失。模型卡反复说 120b“超过 o3-mini、接近 o4-mini”，但 o3、o3-mini、o4-mini 在表 3 各基准上的分数一个都没有在正文或表格里给出，全在图 1、图 2、图 4 里。读者没法核实“超过”是多少、“接近”是差几个百分点。表 2（MMMLU）是全文唯一一张同时给出对照模型数字的表，恰恰说明了其他表本可以这样做，但没有做。

### 效度判断

下面是针对这份模型卡作为证据的评分，满分 5 分，评的是证据，不是模型本身。

内部效度 3 分。能力评估的设计是严谨的：高推理档位、默认系统提示、pass@1、带与不带工具的对照、三档推理级别的完整表格；对抗微调的设计也有不少严谨之处：模拟技术型攻击者、用内部顶尖训练栈、外部专家评审并采纳了 11 条建议。扣分项是：能力评估没有报告种子数与误差范围；防备评估的分数只在图里；High 阈值不公开；对抗微调只针对 120b、只做了两个类别。

外部效度 2 分。能力结果能推广到模型卡列出的标准基准，这是这份文档的强项：AIME、GPQA、MMLU、HLE、SWE-bench Verified、τ-Bench、HealthBench、MMMLU，覆盖数学、知识、编程、工具使用、健康、多语言。但推广到真实部署场景，模型卡自己承认没有证据：幻觉评估是不给浏览的，指令层级评估是人工构造的冲突场景，网络靶场评估里没有任何模型能解出任何一个场景。防备评估的结论只在当前激发条件下成立，作者自己承认结果很可能是下界。

构念效度 3 分。能力基准的分数确实量的是“在这些基准上的表现”，有明确的 pass@1 定义与推理档位条件，比较扎实。但“没到 High”这个结论量的是什么，读者说不清——High 阈值的定义与数值没有公开，三个被追踪类别的指示阈值也没有逐一说明。把“对抗微调后没到 High”读成“放出权重是安全的”，就是构念上的跳跃：前者是一个阈值判断，后者是一个部署决策，中间还差了部署方的保障措施、滥用检测、以及模型被进一步改造的可能性。

统计结论效度 2 分。能力评估的数字是完整的表格，带三档推理级别与工具对照，这是强项。但全文没有任何误差范围、置信区间、种子数或统计检验；图 1 至图 16 的核心数字只在图里，没有数值表；防备评估的专家基线（ProtocolQA 共识 54%、中位数 42%、隐性知识共识 80%、TroubleshootingBench 80 分位 36.4%）给了，但各模型相对这些基线的具体分数没有给。没有误差范围，读者没法判断 120b 与 20b 之间 1.7 个百分点的差距是不是噪声。

可复现性 3 分。权重、分词器、推理实现与工具环境都已开源，一个能干的读者能按描述重建评估，这是强项。扣分项是：预训练数据构成、后训练超参数、能力评估的种子数没有报告；防备评估的对抗微调流程在另一篇配套论文里，模型卡没有给出编号；120b 的训练用了 2.1M 个 H100 小时，别人很难原样重跑训练。没有这些，标题数字只能在“评估可复现、训练难复现”的意义上成立。

### 其他可能的解释

同一个结果，至少有三种别的解释也能说得通。

第一种是“阈值解释”。“没到 High”可能不是因为模型能力不够，而是因为 High 阈值定得很高，或者阈值的定义本身就排除了文本模型最擅长的部分（例如生物评估里依赖视觉的实验室场景，文本模型先天做不了）。预测：如果阈值公开，并且换一套更贴近真实滥用场景的评估，120b 离阈值的距离会比模型卡暗示的要小。区分证据：公开 High 阈值的数值与定义。

第二种是“激发不足解释”。模型卡自己承认，评估结果很可能只是能力的下界，更好的脚手架或能力激发可能大幅提高观测到的表现。对抗微调只用了一种技术路线（增量强化学习），只针对 120b，只做了两个类别。预测：换更强的脚手架、更多的 rollout 次数、或者针对 20b 也做对抗微调，某个模型会在某类评估上越过 High。区分证据：用更强的激发方式重跑防备评估。

第三种是“时机解释”。“不会显著推进开源生物能力前沿”这个结论依赖于 Qwen 3 Thinking 与 Kimi K2 在评估过程中发布。如果这两家晚发布几个月，或者 OpenAI 早发布几个月，结论可能是反过来的。预测：在 R1-0528 是最强开放基线的那个时间点上，120b 的发布会显著推进前沿。区分证据：只用 R1-0528 作比较基线重算结论。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

“gpt-oss-120b 超过 o3-mini、接近 o4-mini”：找到图 1、图 2、图 4 里 o3、o3-mini、o4-mini 在 AIME、GPQA、HLE、MMLU、SWE-bench Verified 与 HealthBench 上的具体分数，在同一口径（高推理档位、默认系统提示、pass@1）下对照。如果 120b 在多数基准上只与 o3-mini 相当，或者与 o4-mini 的差距超过 10 个百分点，“接近 o4-mini”就只能退回为“超过 o3-mini”。

“默认模型与对抗微调后的模型都没有达到 High 能力”：公开 High 阈值的具体数值与定义，并用更强的激发方式（更好的脚手架、更多的 rollout 次数、针对 20b 的对抗微调）重跑防备评估。如果某个模型在某类评估上越过阈值，“没到 High”就只能退回为“在当前激发条件下没到 High”。

“放出 120b 不会显著推进开源生物能力的前沿”：只用 DeepSeek R1-0528 作比较基线重算结论，或者等下一家开源模型发布后再算一次。如果在 R1-0528 是最强开放基线的时间点上 120b 明显领先，这个结论就要加上时间限定。

“20b 在数学与编程上接近 120b”：在 AIME 2025（有工具）与 SWE-bench Verified 之外的更多基准上比较两个模型，特别是在知识类与健康类任务上。如果 20b 在多数基准上落后 10 个百分点以上，“接近”就只能退回为“在数学与编程上接近”。

“两个模型对已知越狱的抵抗力与 o4-mini 相当”：用更新的、模型卡发表之后出现的越狱技术重测。如果 gpt-oss 模型的分数掉得比 o4-mini 多，“相当”就只能退回为“对 2025 年 8 月之前已知的越狱技术相当”。

### 替代解释

替代解释一：阈值解释。“没到 High”可能不是因为模型能力不够，而是因为 High 阈值定得很高，或者阈值的定义本身就排除了文本模型最擅长的部分。预测：如果阈值公开，并且换一套更贴近真实滥用场景的评估，120b 离阈值的距离会比模型卡暗示的要小。区分证据：公开 High 阈值的数值与定义。

替代解释二：激发不足解释。模型卡自己承认，评估结果很可能只是能力的下界。对抗微调只用了一种技术路线（增量强化学习），只针对 120b，只做了两个类别。预测：换更强的脚手架、更多的 rollout 次数、或者针对 20b 也做对抗微调，某个模型会在某类评估上越过 High。区分证据：用更强的激发方式重跑防备评估。

替代解释三：时机解释。“不会显著推进开源生物能力前沿”这个结论依赖于 Qwen 3 Thinking 与 Kimi K2 在评估过程中发布。如果这两家晚发布几个月，结论可能是反过来的。预测：在 R1-0528 是最强开放基线的那个时间点上，120b 的发布会显著推进前沿。区分证据：只用 R1-0528 作比较基线重算结论。

替代解释四：规模解释。20b 在数学与编程上接近 120b，可能不是因为“小模型也能很能打”，而是因为这些基准在高推理档位上已经接近饱和——AIME 2025（有工具）上两个模型都在 97% 以上，再强也强不到哪里去，差距被天花板压住了。预测：在更难、还没有饱和的基准（例如 HLE、HealthBench Hard）上，两个模型的差距会大得多——表 3 的数字已经支持这一点：HLE 高推理档位差 4 个百分点，HealthBench Hard 差 19.2 个百分点。区分证据：在更新、更难的基准上比较两个模型。

### 作者自述局限与分析者发现的局限

作者自述的局限见第四节：评估结果很可能是能力的下界、指令层级不如 o4-mini、幻觉比 o4-mini 严重、纯文本架构限制生物能力适用范围、外部评估有不确定性、标准违禁内容评估已经饱和。

分析者发现的、作者没说的局限有四点。第一，High 阈值的具体数值与定义没有公开，“没到 High”没法被独立复核。第二，o3、o3-mini、o4-mini 在表 3 各基准上的对照分数没有在正文或表格里给出，全在图里，“超过 o3-mini、接近 o4-mini”没法核实。第三，能力评估没有报告种子数、误差范围或统计检验，120b 与 20b 之间 1.7 个百分点的差距是不是噪声，说不清。第四，对抗微调只针对 120b、只做了生物与网络两个类别，20b 经过对抗微调后会不会到 High，根本没测。

### 接下来看什么

最值得先做的，是去找那篇配套的对抗微调研究论文，并核实图 1、图 2、图 4 里 o3、o3-mini、o4-mini 的对照数字：120b 到底比 o3-mini 强多少、比 o4-mini 差多少。这是启示价值里最便宜的决定性实验，也是这份模型卡最缺的一块。

## I. 结论、结果与价值总览

### 一句话结论

这是一份开放权重推理模型的模型卡：两个模型的基准数字相当扎实，120b 在高推理档位上多项指标接近 o4-mini，20b 小得多却在数学与编程上只差几个百分点；但它最想证明的那件事——放出权重也不会把生物与网络风险推到 High——建立在一组分数只在图里、阈值本身不公开的评估上，读者能核实的只有表格里的数字和“没到 High”这个结论本身。

### 核心结论

1. **gpt-oss-120b 与 gpt-oss-20b 是两个开放权重推理模型（置信度：高）。** 120b 总参数 116.8B、激活 5.1B、36 层、128 个专家；20b 总参数 20.9B、激活 3.6B、24 层、32 个专家；MoE 权重用量化到 MXFP4，120b 能装进一块 80GB 的 GPU，20b 能在 16GB 内存的系统上跑；Apache 2.0 协议开源。

2. **数学最强，推理档位拉动极大（置信度：高）。** 120b 在 AIME 2024（无工具）高推理档位上 95.8%，从低档位的 56.3% 涨上来；20b 在 AIME 2025（有工具）高推理档位上 98.7%，反而超过 120b 的 97.9%。20b 在 AIME 上平均每道题用超过 20k 个思维链 token。

3. **20b 在编程上接近 120b，在知识与健康上差距拉开（置信度：高）。** SWE-bench Verified 高推理档位，120b 是 62.4%，20b 是 60.7%，只差 1.7 个百分点；但 HealthBench Hard 上，120b 是 30.0%，20b 只有 10.8%，差 19.2 个百分点；GPQA Diamond 上差 8.6 个百分点。

4. **默认安全表现与 o4-mini 大致相当，指令层级与幻觉是明确短板（置信度：高）。** 指令层级评估里，系统提示提取 120b 只有 0.832，20b 是 0.881，o4-mini 是 0.993；提示注入劫持 20b 只有 0.639。SimpleQA 幻觉率 20b 高达 0.914，o4-mini 是 0.750。

5. **默认模型与对抗微调后的模型都没有达到 High 能力（置信度：中）。** 这是模型卡的核心结论，但支撑它的防备评估分数只在图里，High 阈值本身没有公开，读者没法独立复核离阈值有多远；作者自己承认评估结果很可能是能力的下界。

6. **放出 120b 不会显著推进开源生物能力的前沿（置信度：低）。** 这个结论依赖于 Qwen 3 Thinking 与 Kimi K2 在评估过程中发布；如果这两家晚发布几个月，结论可能是反过来的。模型卡自己写明了这个时机依赖。

### 科学价值总评

认知价值是中等偏高。模型卡没有推翻某个具体的旧信念，但它第一次把“OpenAI 的开放权重推理模型”变成了一个可公开比较的数字集合，并且量出了一个反直觉的结构：20b 只有 120b 六分之一的参数，在数学与编程基准上却只差几个百分点；120b 在健康基准上几乎追上 o3，但两个模型在幻觉与指令层级上都明显弱于 o4-mini。

方法价值是中等偏高。留下的可复用东西有 harmony 聊天格式与角色层级设计、可变推理档位的训练方法、MXFP4 量化让 120b 装进一块 80GB 卡的做法、以及“对抗微调加外部专家评审”这套评估开放权重风险的方法论。扣分项是方法细节不完整：预训练数据构成、后训练超参数、能力评估的种子数与误差范围都没有报告。

边界价值是高的。它明确不证明：o3、o3-mini、o4-mini 在表 3 各基准上的具体分数；防备评估里各模型在生物与网络评估上的具体分数；High 阈值的具体数值；换一套脚手架或激发方式后模型会不会越过 High；以及 20b 经过对抗微调后会不会到 High。最容易误读的推论，是把“没到 High”读成“放出这两个模型是安全的”——模型卡证明的只是在当前激发条件与不公开阈值下的“没到 High”，不是一般意义上的安全。

启示价值在于，最便宜的决定性下一步是去找那篇配套的对抗微调研究论文，并核实图 1、图 2、图 4 里 o3、o3-mini、o4-mini 的对照数字，看 120b 到底比 o3-mini 强多少、比 o4-mini 差多少。

总体 verdict 是：这份工作值得被记住为一次开放权重推理模型的发布——两个模型本身的基准数字扎实，20b 的性价比尤其值得注意，harmony 格式与对抗微调方法论都留下了可复用的东西。不值得被记住为关于“放出开放权重模型是安全的”的证据——它没有提供那样可独立复核的证据，也不该用它的“没到 High”去论证放出权重是安全的。

### 适用边界

不要用这份模型卡论证 o3、o3-mini、o4-mini 在 AIME、GPQA、HLE、MMLU、SWE-bench Verified 或 HealthBench 上的具体分数，不要用“超过 o3-mini、接近 o4-mini”论证 120b 与 o4-mini 的差距只有几个百分点，不要用“没到 High”论证放出这两个模型是安全的，不要用“不会显著推进开源生物能力前沿”论证 120b 在生物能力上没有领先——这个结论依赖于 Qwen 3 Thinking 与 Kimi K2 的发布时机。

可以引用的是表格里的数字本身（表 1 至表 10）、两个模型的架构与训练事实（MXFP4 量化、harmony 格式、三档推理级别、2.1M H100 小时）、默认安全表现里已核实的短板（指令层级、幻觉）、以及模型卡自己承认的局限（评估结果很可能是下界、标准违禁内容评估已饱和）。引用“没到 High”时，须同时说明阈值没有公开、分数只在图里、对抗微调只针对 120b 做了两个类别。
