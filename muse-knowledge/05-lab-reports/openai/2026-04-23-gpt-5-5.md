## 一、背景与问题

### 这是一次什么样的发布

GPT-5.5 是 GPT-5.4 的继任者。OpenAI 称它是“迄今最聪明、最直观易用的模型”（smartest and most intuitive to use model yet），定位是“一种在电脑上完成工作的新方式的下一步”（the next step toward a new way of getting work done on a computer）。

这个定位值得说清。博客的叙事不是“模型更会答题了”，而是“模型更会把活干完了”：给它一个杂乱的多步骤任务，它自己规划、用工具、检查自己的工作、在含糊处导航、一直干到完成。发布帖反复强调的四个见长领域是 agentic coding（智能体编程）、computer use（电脑操作）、knowledge work（知识工作）与 early scientific research（早期科学研究）——共同点是都要跨越上下文推理、随时间采取行动。

### 它声称解决了什么张力

博客点出的张力是速度与智能的 trade-off（权衡）：“更大、更强的模型往往更慢。”GPT-5.5 的核心卖点是这一步智能提升没有牺牲速度：在真实服务中，GPT-5.5 的每 token 延迟与 GPT-5.4 相当，同时智能水平高得多；而且在同样的 Codex 任务上用的 token 明显更少，既更强也更高效。

### 主要主张

按博客的说法，这次发布立了四条主张。

第一，GPT-5.5 是迄今最强的智能体编程模型，在 Terminal-Bench 2.0 上达到 82.7%，领先 GPT-5.4 的 75.1% 与 Claude Opus 4.7 的 69.4%。

第二，智能提升没有牺牲速度：每 token 延迟与 GPT-5.4 相当，token 效率更高，在 Codex 里以更少的 token、更少的重试达到更高质量的输出。

第三，这是 OpenAI 迄今防护最强的一次发布，生物/化学与网络安全能力按 Preparedness Framework（准备度框架）被定为 High（高），但未达到 Critical（关键）级别。

第四，模型不只会写代码：它在知识工作与科研流程上同样更强，从理解意图、找信息、用工具、检查输出，到把原材料变成有用的东西，构成完整的工作闭环。

## 二、方法与设计

### 文档结构

博客按这个顺序展开：开场定性 → 摘要评估表（9 行）→ 三个能力小节（智能体编程、知识工作、科学研究）→ 推理效率（Next-generation inference efficiency）→ 网络安全与防护 → 可用性与定价 → 完整评估表（8 组、37 行）。

这是一份发布帖，不是论文。全文没有训练方法：没有架构、没有训练数据、没有算力、没有训练配方。唯一的方法论内容在文末脚注里的一句话：评估以推理努力（reasoning effort）设为 xhigh 运行，在研究环境中进行，“在某些情况下可能与生产版 ChatGPT 的输出略有不同”。

### 评估是怎么做的——以及没说什么

评估表列了六列：GPT-5.5、GPT-5.4、GPT-5.5 Pro、GPT-5.4 Pro、Claude Opus 4.7、Gemini 3.1 Pro。大量单元格是“-”，即未报告。内部评估明确标注了 (Internal)：Expert-SWE（专家级长周期编程任务）、Investment Banking Modeling Tasks（投行建模任务）、Capture-the-Flags challenge tasks（夺旗挑战任务）。

按检查表，以下项目在发布帖里都没有：样本量、运行次数、随机种子、误差棒或置信区间、评估 harness（评估工具链）版本、提示模板、解码参数（除推理努力 xhigh 外）、以及任何消融或失败分析。评估的复现性因此很低：没有权重、没有 harness 细节，第三方无法重跑这些数字。

### 脚注里藏着的三点

有三条脚注值得单独记下，因为它们是博客自己承认的限定。

第一，SWE-Bench Pro 一行下标注：“各实验室已注意到该评估存在记忆（memorization）的证据。”也就是说，这项评估的分数可能部分来自模型见过测试内容。

第二，MCP Atlas 的结果来自 Scale AI 在 2026 年 4 月最近一次更新之后的数据。

第三，Tau2-bench Telecom 一行说明：GPT-5.5 与 GPT-5.4 的结果用的是原始提示、未做提示调整；其他实验室用提示调整后评估的结果被省略了。这意味着跨实验室的比较口径并不一致。

### 安全评估是怎么说的

博客说，模型发布前经过了完整的安全与治理流程：全套安全与准备度框架评估、内部与外部红队测试、针对高级网络安全与生物能力的新增专项测试，以及发布前近 200 家可信早期访问合作伙伴的真实用例反馈。更多细节被推到 system card（系统卡）里，发布帖正文链接了它，但抓取文本未暴露该链接的 URL，本次未核实（见文末未核实清单）。

## 三、主要发现

### 摘要表里的数字

博客开头的摘要表只列了 9 行，全部是 GPT-5.5 领先或打平的项：Terminal-Bench 2.0 82.7% 对 75.1%；Expert-SWE 73.1% 对 68.5%；GDPval 84.9% 对 83.0%；OSWorld-Verified 78.7% 对 75.0%；Toolathlon 55.6% 对 54.6%；BrowseComp 84.4% 对 82.7%，Pro 版 90.1% 对 89.3%；FrontierMath Tier 1–3 51.7% 对 47.6%，Tier 4 35.4% 对 27.1%；CyberGym 81.8% 对 79.0%。

这些数字与文末完整评估表里的对应行逐项一致，本次已核对。

### 完整评估表里被摘要表略去的输项

完整评估表一共 37 行，里面有 GPT-5.5 输给竞品的项，摘要表一行也没列。

SWE-Bench Pro（公开版）：GPT-5.5 58.6%，GPT-5.4 57.7%，Claude Opus 4.7 64.3%——GPT-5.5 只比上一代高 0.9 个百分点，落后 Claude 5.7 个百分点。而且这项评估还有上面提到的记忆证据脚注。

FinanceAgent v1.1：GPT-5.5 60.0%，GPT-5.4 56.0%，Claude Opus 4.7 64.4%——落后 Claude 4.4 个百分点。

MCP Atlas：GPT-5.5 75.3%，Claude Opus 4.7 79.1%，Gemini 3.1 Pro 78.2%——两家竞品都高于 GPT-5.5。

GPQA Diamond：GPT-5.5 93.6%，GPT-5.4 Pro 94.4%，Claude Opus 4.7 94.2%，Gemini 3.1 Pro 94.3%——GPT-5.5 低于三家对手。

Humanity's Last Exam（无工具）：GPT-5.5 41.4%，Claude Opus 4.7 46.9%——落后 5.5 个百分点；有工具版 GPT-5.5 52.2%，GPT-5.5 Pro 57.2%，GPT-5.4 Pro 58.7%——Pro 版反而不如上一代 Pro。

ARC-AGI-1（Verified）：GPT-5.5 95.0%，Gemini 3.1 Pro 98.0%——落后 3 个百分点。

Graphwalks（长上下文图遍历）：BFS 256k 73.7% 对 Claude 76.9%；parents 256k 90.1% 对 Claude 93.6%；parents 1M 58.5% 对 Claude 72.0%（注：Claude 一栏标的是 Opus 4.6）。

这些输项不是小事：它们集中在金融、工具协议（MCP）、学术问答、抽象推理与长上下文图遍历上，恰好是博客叙事里“全面领先”的反例。

### 提升最大的几项

另一头也有提升很大的项。Graphwalks BFS 1M：GPT-5.5 45.4%，GPT-5.4 只有 9.4%，提升 36 个百分点；OpenAI MRCR v2 512K–1M：74.0% 对 36.6%，提升 37.4 个百分点；ARC-AGI-2：85.0% 对 73.3%，提升 11.7 个百分点；FrontierMath Tier 4：35.4% 对 27.1%。这些是长上下文与高难度推理上的真实进步，幅度远超测量噪声的常见量级——但博客没有给误差棒，这个判断只能是定性的。

也有原地踏步甚至退步的项。MMMU Pro（无工具）GPT-5.5 与 GPT-5.4 都是 81.2%，打平；MRCR v2 16K–32K GPT-5.5 96.5% 低于 GPT-5.4 的 97.2%，64K–128K 83.1% 低于 GPT-5.4 的 86.0%。长上下文的表现随长度起伏，不是单调改进。

### 智能体编程：数字之外是轶事

博客用三段早期测试者的轶事来支撑“概念清晰度”的说法。Every 的创始人 Dan Shipper 说 GPT-5.5 是他用过的第一款“有真正的概念清晰度”的编程模型：他让模型复现一位工程师花数天调试后做的重写，GPT-5.4 做不到，GPT-5.5 做到了。MagicPath 的 CEO Pietro Schirano 说模型一次合并了一个有数百处前端与重构改动的分支，用了约 20 分钟。Cursor 的 CEO Michael Truell 说 GPT-5.5 明显更聪明、更持久，工具使用更可靠，在长任务上不停得更晚。

这些都是精选的个案，没有对照、没有分母、没有失败案例。它们说明早期测试者的主观感受，不构成证据。

### 知识工作：内部用例的数字

博客给了三组 OpenAI 内部使用数字：全公司超过 85% 的员工每周使用 Codex；财务团队用 Codex 审阅了 24,771 份 K-1 税表、共 71,637 页，比上一年提前两周完成；Go-to-Market 团队一名员工用自动化生成每周业务报告，每周节省 5–10 小时。

这些数字来自 OpenAI 自己，没有外部核对。K-1 税表的工作流明确写了排除了个人信息，这是三组数字里唯一提到数据处理方式的一处。

知识工作的评估数字：GDPval 84.9%（44 个职业的规范知识工作），OSWorld-Verified 78.7%，Tau2-bench Telecom 98.0%（无提示调优，用户模型为 GPT-4.1），FinanceAgent 60.0%，内部投行建模任务 88.5%，OfficeQA Pro 54.1%。

### 科学研究：两项评估与三个例子

科学研究方面，博客强调两项新评估。GeneBench 是聚焦遗传学与定量生物学多阶段科学数据分析的新评估，GPT-5.5 得 25.0%，GPT-5.4 得 19.0%，Pro 版 33.2%。BixBench 是围绕真实生物信息学与数据分析的基准，GPT-5.5 得 80.5%，GPT-5.4 得 74.0%，在已公布分数的模型中领先。两项评估的绝对分数都不高（GeneBench 只有 25%），博客的说法是这些任务往往对应科学专家数天的项目。

三个例子：内部版 GPT-5.5 加定制 harness（工具链）帮助发现了一个关于 Ramsey 数（拉姆齐数，组合数学的核心对象）的新证明，是关于非对角 Ramsey 数的一个长期渐近事实，后来在 Lean 中验证；Jackson Laboratory 的免疫学教授 Derya Unutmaz 用 GPT-5.5 Pro 分析了一个 62 个样本、近 28,000 个基因的基因表达数据集，产出的研究报告还提出了关键问题与洞见，他说这项工作他的团队要花数月；Adam Mickiewicz 大学的数学助理教授 Bartosz Naskręcki 用 GPT-5.5 在 Codex 里从一句话提示出发，11 分钟搭建了一个代数几何应用，可视化二次曲面的交线并转为 Weierstrass 模型。

Ramsey 数证明的说法只给了博客正文里一个指向 cdn.openai.com 的 PDF 链接，本次没有通读该 PDF，不能独立确认证明的内容与新颖性（见文末未核实清单）。

### 推理效率：模型帮自己提速

博客专设一节讲推理效率。GPT-5.5 与 NVIDIA GB200 与 GB300 NVL72 系统协同设计、协同训练、协同 serving（部署）。Codex 与 GPT-5.5 本身参与了性能目标的达成：Codex 帮助团队从想法更快走到可测基准的实现，GPT-5.5 帮助找到并实现了栈里的关键改进。用博客的话说，模型帮助改进了 serving 它自己的基础设施。

唯一给出的具体改进是负载均衡与分区启发式：以前把一个加速器上的请求切成固定数量的块来平衡各计算核的工作，但固定切块对所有流量形状都不是最优；Codex 分析了数周的生产流量模式，写了定制的启发式算法来最优地分区与平衡工作。博客称这项工作让 token 生成速度提升超过 20%。这个“超过 20%”没有基线、没有测量条件，无法复核。

### 安全与防护：High，但不是 Critical

博客说 GPT-5.5 的生物/化学与网络安全能力按 Preparedness Framework 被定为 High，但没有达到 Critical 的网络安全能力级别；评估与测试显示其网络安全能力比 GPT-5.4 上了一个台阶。2025 年 12 月随 GPT-5.2 部署了必要的网络安全防护；GPT-5.5 进一步部署了更严格的网络风险分类器，博客承认“一些用户起初可能会觉得烦”，因为分类器还在持续调优。

同时发布了两项配套举措：Trusted Access for Cyber（网络可信访问），从 Codex 开始向通过信任信号验证的用户开放网络防护模型的更强能力、更少限制；以及 GPT-5.5 Bio Bug Bounty（生物漏洞赏金）。博客还提到 GPT-5.4-Cyber 这类网络防护模型可供负责关键基础设施的组织申请使用。

### 可用性与定价

发布当日，GPT-5.5 向 ChatGPT Plus、Pro、Business 与 Enterprise 用户在 ChatGPT 与 Codex 中推出；GPT-5.5 Pro 向 Pro、Business 与 Enterprise 用户在 ChatGPT 中推出。API 当时写的是“很快会来”（very soon）；页面顶部的更新注写明，2026-04-24 GPT-5.5 与 GPT-5.5 Pro 已在 API 中可用。

Codex 中的上下文窗口为 400K token；另有 Fast 模式，token 生成速度快 1.5 倍，价格为 2.5 倍。API 定价：gpt-5.5 每百万输入 token 5 美元、每百万输出 token 30 美元，上下文窗口 1M；gpt-5.5-pro 每百万输入 token 30 美元、每百万输出 token 180 美元；Batch 与 Flex 定价为标准价的一半，Priority 处理为标准价的 2.5 倍。博客承认 GPT-5.5 定价高于 GPT-5.4，但称它更智能且 token 效率高得多，在 Codex 里对多数用户用更少的 token 交付更好的结果——“用更少的 token”这个说法没有给出数字。

## 四、作者的结论与局限

### 作者的结论

博客的结论就是它的开场白：GPT-5.5 是迄今最聪明、最直观易用的模型，是让 AI 在电脑上真正完成工作的新方式的下一步；智能提升没有牺牲速度；防护是迄今最强的一套；强大的 AI 应该交到用来防御系统、机构与公众的人手里。

### 作者自述的局限

发布帖没有设“局限”一节，但它自己承认了四处限定。

第一，评估在研究环境中以推理努力 xhigh 运行，生产版 ChatGPT 的输出在某些情况下可能略有不同。

第二，SWE-Bench Pro 存在记忆证据的脚注，直接削弱了这项评估作为“真实世界问题解决能力”证据的力度。

第三，更严格的网络风险分类器“一些用户起初可能会觉得烦”，还在持续调优中——即防护的误报率当时尚未收敛。

第四，API 在发布当日尚未可用，定价与可用性承诺是“很快”，不是当日事实（后由 2026-04-24 的更新注补上）。

除此之外，博客没有承认任何方法论局限：没有训练细节、没有消融、没有失败案例、没有不确定性。这是发布帖与研究论文的根本区别——它不是来接受检验的，是来宣布产品的。

## 五、精读点评

### 这篇东西真正要回答的问题

先把问题还原成它本来的样子。这不是一篇论文，没有科学反常要解释。它要回答的是一个产品问题：模型能不能把多步骤的电脑工作端到端地干完，同时不变得更慢、更贵？

为什么这个问题值得问？对实践来说，答案决定了 AI 是停留在“回答问题”还是进入“完成工作”——后者才是智能体产品的商业前提。对领域来说，GPT-5.5 的答案如果成立，意味着前沿模型的竞争维度从单题正确率转向了长程任务的可靠性与单位成本。

为什么之前做不到？博客的答案是推理效率：更大的模型通常更慢，GPT-5.5 的办法是与 NVIDIA GB200/GB300 系统协同设计、协同训练、协同 serving，并在 serving 栈里用模型自己写的启发式算法提速。这个说法把“为什么能做到”归因于系统级协同设计，而不是某一个算法突破。

方法与问题是否匹配？评估表是唯一的证据形式。37 行评估数字确实覆盖了编程、知识工作、电脑操作、工具使用、学术、网络安全、长上下文与抽象推理，广度够了；但证据的深度不够：没有误差棒、没有运行次数、没有 harness 版本、没有生产环境下的复测。方法回答的是“在我们的评估设置下分数是多少”，不是“在用户手里表现如何”。

答案改变了什么？认知上几乎没有改变——没有任何关于模型能力本质的新主张。实践上改变的是产品线：一个新的旗舰模型、新的定价、新的 Fast 模式、新的网络可信访问通道。把它当作产品发布来读，它是合格的；把它当作研究发现来读，它什么都没证明。

### 最弱的一环

全篇最承重、也最薄弱的一环，是评估数字的可信度。所有数字都来自 OpenAI 自己，没有第三方复测，没有不确定性，没有可复现的 harness。摘要表只挑了领先的 9 项，完整表里有 8 项 GPT-5.5 输给竞品或上一代 Pro，其中 SWE-Bench Pro 还自带记忆证据的脚注。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

- 第三方在生产设置下复测 Terminal-Bench 2.0，若 GPT-5.5 的分数显著低于 82.7%（例如落回 GPT-5.4 的 75% 附近），“最强智能体编程模型”的主张即被削弱。
- 独立测量 API 的每 token 延迟，若 GPT-5.5 显著慢于 GPT-5.4，“不牺牲速度”的主张即错。
- 统计 API 上线后的实际 token 用量与账单，若多数用户的单位任务成本高于 GPT-5.4，“更贵但更省 token”的说法即不成立。
- 在 SWE-Bench Pro 上做去污染复测，若分数大幅下跌，说明该项分数确实被记忆抬高了。

### 替代解释

替代解释一：评估提升来自评估设置，不是模型本身。评估以推理努力 xhigh、在研究环境中运行，生产版 ChatGPT 的输出可能不同。区分的办法是看生产环境下的第三方复测：如果分数回落，说明提升至少部分是设置带来的。

替代解释二：提升集中在 OpenAI 自家的评估上。37 行里提升最大的几项（Graphwalks、MRCR、ARC-AGI-2）与 OpenAI 自己的长上下文和推理工作高度相关，而在第三方色彩更浓的评估（SWE-Bench Pro、FinanceAgent、MCP Atlas、GPQA Diamond）上 GPT-5.5 反而落后。区分的办法是等独立基准（例如 Artificial Analysis 的榜单）更新：若独立榜单上 GPT-5.5 同样领先，替代解释被削弱；若不领先，说明提升有评估选择的问题。

替代解释三：摘要表的挑选制造了“全面领先”的印象。摘要表 9 行全是领先项，完整表 37 行里有 8 项输给竞品或上一代。区分的办法不需要新实验：把两张表并排看就够了，本篇已经这样做了。

### 作者自述局限与分析者发现的局限

作者自述的局限：评估在研究环境中运行、生产输出可能不同；SWE-Bench Pro 存在记忆证据；网络风险分类器起初可能让用户觉得烦；API 发布当日尚未可用。

分析者发现的局限，作者没有明说的有四点。第一，没有任何不确定性报告：37 行数字全是点估计，0.9 个百分点这类小差距无法判断是不是噪声。第二，摘要表经过挑选，只列领先项。第三，关键的效率主张（“用更少的 token”“token 生成速度提升超过 20%”）没有给出任何数字。第四，全部证据来自 OpenAI 自己与经过挑选的早期测试者，没有独立复测，没有失败案例。

### 接下来看什么

排第一的是独立复测与 system card。博客引用了 Artificial Analysis 的 Intelligence Index 与 Coding Index，但没有给出 GPT-5.5 在上面的具体分数；等独立榜单更新，看这些分数在生产设置下是否成立，是最便宜的决定性检验。其次是 system card：博客把安全评估的细节全部推给了它，读到它才能判断 High 定级与新增防护的具体内容。最后是 API 上线后的实际用量数据：定价高于 GPT-5.4，token 效率的说法有没有数字支撑，要看真实账单。

### 未解问题

- GPT-5.5 在生产环境下的表现与研究环境评估差多少？说不清，需要第三方复测。
- “用更少的 token”到底少了多少？说不清，博客没有给数字。

## I. 结论、结果与价值总览

### 一句话结论

GPT-5.5 是一次以智能体工作为卖点的旗舰模型发布：在 OpenAI 自家的评估设置下，它在编程、知识工作与科研上全面超过 GPT-5.4 且不牺牲速度——但这是一份厂商声明，不是一项研究发现。

### 核心结论

1. GPT-5.5 在 OpenAI 的评估设置下全面超过 GPT-5.4，尤其在长上下文与高难度推理上提升幅度大。置信度中。证据：数字台账 E1、E25、E35、E37；但没有误差棒，无法判断小差距是否显著。
2. GPT-5.5 不是全面最强的模型，在金融、工具协议、学术问答、抽象推理与长上下文图遍历上输给 Claude Opus 4.7 或 Gemini 3.1 Pro。置信度高。证据：数字台账 E2、E5、E12、E19、E20、E24、E26、E27、E36。
3. “不牺牲速度、更省 token”的主张没有给出可复核的数字。置信度低。证据：数字台账 E41（“超过 20%”无基线）；“用更少的 token”全文无数字。
4. 生物/化学与网络安全能力被定为 High，未达 Critical；发布伴随更严格的网络风险分类器与 Trusted Access for Cyber。置信度中。证据：博客安全一节的说法；细节在 system card 里，本次未读。
5. API 定价高于 GPT-5.4，GPT-5.5 为每百万输入 token 5 美元、输出 30 美元，Pro 版为 30 美元与 180 美元。置信度高。证据：数字台账 E38。

认知价值：低。没有提出或检验任何关于模型能力的新主张，值得被记住的是一个产品节点，不是一个发现。方法价值：低。没有留下可复用的方法、工具、度量或数据集，只有一个“模型帮自己改进 serving 栈”的思路，没有配方。边界价值：这是本篇最有价值的一维——它明确不证明 GPT-5.5 全面最强、不证明生产表现与研究环境一致、不证明更高的定价能被 token 效率抵消。启示价值：下一步最值得看的是独立复测、system card 与 API 上线后的真实用量数据，这三件事会决定这次发布的分数有多少站得住。
