## 一、背景与问题

### 一周之后的一次升级

GPT-6.1 Sol 是 GPT-6 Sol 的升级版。按帖子的说法，它在智能体编码（agentic coding）、计算机使用（computer use）与专业工作（professional work）上接近 GPT-6 Astra 的水平，而标准输入与输出 token 价格只有 Astra 的五分之一。缓存输入（cached input）每百万 token 只要 0.10 美元，比标准输入价低 95%，比 GPT-6 Sol 的缓存输入价低一半。

这篇帖子的背景很简单：GPT-6 Sol 才发布一周，OpenAI 就在 DevDay 2026 上拿出了一个更强的 Sol，而且价格没变。帖子没有解释为什么只隔一周就升级，也没有说 GPT-6 Sol 本身出了什么问题。它要回答的问题是一个产品问题：中档模型能不能以旗舰五分之一的价格，办到接近旗舰的事。

### 主要主张

帖子的主张大致有四条。

第一，GPT-6.1 Sol 在几项专业任务评估上接近 Astra，成本只有 Astra 的五分之一左右。这是全篇的标题主张，也是帖子反复讲的一句话。

第二，相对 GPT-6 Sol，它在编码、计算机使用、科学工作流与事实准确性上都有实质提升，而且往往是在更低的推理力度（reasoning effort）与更低的成本下取得的。

第三，它在对齐（alignment）评估上有进步：对自身局限更坦诚，更可靠地尊重用户意图与安全约束，在几项挑战性评估上的失败率低于 GPT-6 Sol。

第四，价格与上市范围：标准 API 价格是输入每百万 token 2 美元、缓存输入 0.10 美元、输出 10 美元；发布当天起向 ChatGPT Work 与 Codex 的付费用户开放，暂不进普通 Chat；API 模型名为 `gpt-6.1-sol`；未来几天还会推出快得多的 Ultrafast 版本。

## 二、方法与设计

### 文档结构

这是一篇产品发布帖，不是实验报告。结构很短：开篇总述 → 五项评估逐项讲（DeepSWE v1.1、GDP.pdf、AutomationBench、OSWorld 2.0、Terminal-Bench Science 0.1）→ 事实准确性一段 → 对齐评估一段 → 价格与上市范围一段。全文没有方法附录，没有统计细节，没有误差棒，没有样本量。

需要特别说明的一点是：这篇帖子没有评估表。GPT-5.6 那篇帖子文末有十张基准表，这篇什么表都没有。所有评估数字都嵌在正文的句子里，而且几乎全是差值（比某某高几个百分点）与成本比（大约是某某的几分之一），绝对分数只出现了一个：Terminal-Bench Science 0.1 上 Astra 的 68.1%。

### 评估是怎么做的

帖子没有描述评估方法本身。它引用的是五项基准与一组对齐评估，外加一项事实准确性评估。对照组包括 GPT-6 Astra、GPT-6 Sol 与 Claude Opus 5.5。推理力度（reasoning effort）只在几处点名：AutomationBench 是中等推理力度（medium reasoning effort），OSWorld 2.0 与 Terminal-Bench Science 0.1 是最大推理力度（maximum reasoning effort），事实准确性最大的改进在低推理力度（low reasoning effort）。其余评估的推理力度没有说明，“across the tested reasoning settings”（在测试过的推理设置下）这个说法出现两次，但帖子没有列出测试过哪些设置。

按检查表，什么是“未报告”：每项评估的绝对分数（除 Astra 在 Terminal-Bench Science 0.1 上的 68.1% 之外，一个都没有）；样本量、运行次数、误差棒或置信区间；“每任务成本”（cost per task）的计算方法（token 用量、推理力度如何计入成本，帖子没有定义）；GDP.pdf 与 AutomationBench 的任务细节与评分方法；“Opus 5.5 with fallbacks”（带回退的 Opus 5.5）里“回退”是什么意思；对齐评估里“更低的失败率”具体低了多少；评估 harness 的版本。

同行评审状态不适用：这不是一篇论文，没有投稿、没有评审。它的可信度取决于 OpenAI 自己公布的数字，而这些数字没有以可下载的原始数据形式公开。

### 系统卡附录讲了什么

博客把安全细节指向了另外的 GPT-6.1 Sol 系统卡附录（Addendum to GPT-6 Astra System Card: GPT-6.1 Sol），托管在 OpenAI 的部署安全中心（deploymentsafety.openai.com）。附录已通读，内容同样很薄，只有几段。

附录说，GPT-6.1 Sol 的数据与训练与 GPT-6 Astra 相同，细节见 Astra 的系统卡。生物与化学能力方面，它被定为 High（高）能力级别，在 High 能力评估与 Critical（关键）能力评估上的结果都没有越过指示性的 Critical 阈值。在生物拒答评估上，它在严重（severe）与双用途（dual-use）类别上的表现与 GPT-6 Sol 相当，同时拒答的良性提示更少。网络安全方面，它在生产聊天（production-chat）评估上超过 OpenAI 此前的所有模型；但与 GPT-5.6 Sol 相比，在合成与半合成智能体环境里有轻微退化（modest regressions）。附录还提醒，附录里给出的既往模型的对照值可能反映的是那些模型的后续版本，与发布时公布的值可能不同。

## 三、主要发现

### 价格：这是帖子里最实在的一组数字

标准 API 价格是输入每百万 token 2 美元、缓存输入 0.10 美元、输出 10 美元。缓存输入比标准输入便宜 95%——这个算术帖子自己的数字就能验算：0.10 美元是 2 美元的 5%，确实低了 95%。帖子还说缓存输入比 GPT-6 Sol 的缓存输入价低 50%，这意味着 GPT-6 Sol 的缓存输入价是每百万 token 0.20 美元；但 GPT-6 Sol 的价格没有在这篇帖子里给出，这个推论没法只凭本帖核实，见未核实清单。

“五分之一”这个说法，帖子自己没有给出 Astra 的价格。按二手来源的说法，Astra 的标准价是输入每百万 token 10 美元、输出 50 美元，2 美元与 10 美元之比确实是五分之一。但这不是本帖提供的数字，严格说，本帖的“一句话卖点”里有一半的证据不在本帖里，见精读点评。

### 编码：DeepSWE 上“追平 Astra”，但没有绝对分数

DeepSWE v1.1 评估的是真实代码库里的复杂软件工程任务。帖子说，GPT-6.1 Sol 在这项上追平（matches）GPT-6 Astra，成本大约是 Astra 的五分之一；同时比 GPT-6 Sol 的最好成绩高 6.4 个百分点，而且是在更低的推理力度与更低的成本下取得的。

“追平”与“高 6.4 个百分点”都是没有绝对分数的说法。读者不知道 Astra 的分数是多少，也不知道 GPT-6 Sol 的最好成绩是多少，更不知道这个“最好成绩”是在哪个推理力度下测的。差值本身无法复核，只能当作 OpenAI 的自我报告来读。

### 文档理解：GDP.pdf 高于 Opus 5.5，同样没有分数

GDP.pdf 衡量的是模型用包含表格、图表、图示与小字细节的复杂 PDF 文档回答专业问题的准确度。帖子说，GPT-6.1 Sol 的分数高于“带回退的 Opus 5.5”（Opus 5.5 with fallbacks），在测试过的推理设置下，每任务成本不到 Opus 5.5 的一半；同时接近 Astra 的最高水平，每任务成本大约是 Astra 的五分之一。

这里有两个说不清的地方。第一，“with fallbacks”是什么意思，帖子没有解释——是指 Opus 5.5 在回答不出时回退到别的模型或工具，还是指评估本身允许回退？没有定义，这个对照就没法理解。第二，“接近 Astra 的最高水平”没有给出任何一方分数，连差值都没有，比 DeepSWE 那一段还要空。

### 业务工作流：AutomationBench 高 2.2 个百分点

AutomationBench 衡量智能体是否能正确完成多步骤业务工作流。帖子说，GPT-6.1 Sol 在中等推理力度下比 Opus 5.5 高 2.2 个百分点，成本大约是 Opus 5.5 的三分之一；这个分数也比同一设置下的 GPT-6 Sol 高 4.8 个百分点。

这是帖子里条件写得最清楚的一项：推理力度（中等）与两个对照（Opus 5.5、GPT-6 Sol）都点名了。但绝对分数仍然没有给出，2.2 与 4.8 这两个差值没法独立验算。

### 计算机使用：OSWorld 2.0 离 Astra 还有 2.1 个百分点

OSWorld 2.0 的离线集（offline set）评估智能体在要求很高的计算机使用工作流上的表现。帖子说，在最大推理力度下，GPT-6.1 Sol 比 GPT-6 Sol 高 7 个百分点，成本不到一半；与 Astra 的分数差距在 2.1 个百分点以内，每任务成本大约是 Astra 的七分之一。

值得留意的是这里的成本比：标题主张说的是 token 价格是 Astra 的五分之一，这里每任务成本却是七分之一。两个数字并不矛盾——每任务成本还取决于用了多少 token、用了什么推理力度——但帖子没有解释为什么 OSWorld 上的每任务成本比是七分之一，而标题的 token 价格比是五分之一。读者如果把两个比混为一谈，就会误读。

### 科学工作流：Terminal-Bench Science 0.1，唯一给出绝对分数的一项

Terminal-Bench Science 0.1 评估科学工作流，包括数据分析、仿真与定理证明。帖子说，在最大推理力度下，GPT-6.1 Sol 的分数比 GPT-6 Sol 翻了一倍还多，每任务成本不到一半。在最大推理力度下，GPT-6.1 Sol 每任务平均成本 5.47 美元，Opus 5.5 是 23.21 美元，Astra 是 23.80 美元，成本比另外两家低 75% 以上。Astra 仍然是这项上分数最高的模型，68.1%，帖子建议最难的科学研究任务还是用 Astra。

这一段是全篇数字最完整的一段：有绝对成本、有对照、有 Astra 的绝对分数。验算一下：5.47 美元是 23.21 美元的 23.6%，确实低了 76% 以上；是 23.80 美元的 23.0%，低了 77%。“低 75% 以上”这个说法站得住。但 GPT-6.1 Sol 自己的分数仍然没有给出——“翻了一倍还多”是相对 GPT-6 Sol 说的，而 GPT-6 Sol 的分数也没有给出；Astra 的 68.1% 是全篇唯一的绝对基准分数，GPT-6.1 Sol 与它之间差多少，帖子没有说。

### 事实准确性：11.4% 降到 7.7%，是帖子里最干净的一组数字

GPT-6.1 Sol 在困难提示上的事实准确性有提升。最大的改进出现在低推理力度下：包含事实错误的回答占比从 11.4% 降到 7.7%，大约降低了 32%。在测试过的推理设置下，它的错误率与 Astra 的差距在 1.9 个百分点以内，每任务成本不到 Astra 的五分之一。

验算一下：从 11.4% 降到 7.7%，绝对降幅是 3.7 个百分点，相对降幅是 3.7 除以 11.4，等于 32.5%，帖子说的“大约 32%”是对的。这是全篇唯一一组既有绝对值、又有对照、又能用帖子自己的数字验算的评估结果。

但条件要看清：这项评估用的是去标识化的对话，里面是用户标记过“早期模型答错了”的对话，也就是故意挑出来的难题。帖子自己说了，这些刻意困难的提示不代表典型用法。所以 11.4% 与 7.7% 这两个数字不能理解为模型在日常使用中的事实错误率。

### 对齐：只讲方向，不讲数字

帖子说，GPT-6.1 Sol 在对齐评估上有实质进步，更接近 Astra。它对自身局限更坦诚，更可靠地尊重用户意图与安全约束。在挑战性评估上，它在三项上的失败率低于 GPT-6 Sol：对损坏的搜索工具保持透明、尊重明确的限制、在智能体任务中避免未授权的结果。帖子还说，没有观察到它试图绕过自动安全评审（automated safety reviewer），这一点与 Astra 和 GPT-6 Sol 相同。

这三项“更低的失败率”都没有给出数字，低了多少、基线是多少，全都不知道。帖子同时提醒，这些评估故意测试的是挑战性情境，测的不是典型使用中的失败率。

### 上市范围：Work 与 Codex 有，普通 Chat 暂无

GPT-6.1 Sol 从发布当天起向 ChatGPT Work 与 Codex 的 Plus、Pro、Business、Enterprise 与 Edu 用户开放，普通 Chat 里暂未上线。开发者可以通过 OpenAI API 调用，模型名是 `gpt-6.1-sol`。未来几天还会推出 GPT-6.1 Sol Ultrafast，token 生成速度比标准速度快 up to 8 倍（最高 8 倍），先在 Codex 里提供。

## 四、作者的结论与局限

### 作者的结论

帖子的结论就是开篇那句话：GPT-6.1 Sol 以 Astra 五分之一的标准 token 价格，在智能体编码、计算机使用与专业工作上接近 Astra 的水平；相对 GPT-6 Sol，它在几项评估上有实质提升，价格不变。帖子没有像研究论文那样设结论节，这些结论散落在开篇总述与各评估段落里。

### 作者自述的局限

帖子没有设“局限”一节。以下边界是它在行文里自己承认的，散落在各处。

第一，事实准确性评估用的提示是故意挑出来的难题，不代表典型用法，帖子明确说了这一点。

第二，对齐评估故意测试挑战性情境，测的不是典型使用中的失败率，帖子也明确说了这一点。

第三，最难的科学研究任务还是应该用 Astra——帖子在 Terminal-Bench Science 0.1 一段里自己划了这条线，GPT-6.1 Sol 不是在所有任务上都接近 Astra。

第四，系统卡附录提醒，附录里既往模型的对照值可能反映的是那些模型的后续版本，与发布时公布的值可能不同——也就是说，拿附录里的对照值与发布时的数字直接比较，可能会比错版本。

帖子没有明说的局限，见下一节精读点评。

## 五、精读点评

### 这篇工作真正要回答的问题

先把问题还原成它本来的样子。这不是一篇研究论文，没有科学发现要报告；它要回答的是一个产品问题：GPT-6 Sol 发布一周之后，OpenAI 能不能拿出一个更强的中档模型，价格不变，让用户不必为了接近旗舰的水平而付旗舰的价钱。反常不在于某个基准分数，而在于发布节奏本身：一周就升级，说明 Sol 这一档的定位在发布时还没有稳定，或者说 Astra 与 Sol 之间的价格与能力落差太大，中间需要再补一个台阶。

为什么重要？对实践来说，这改变了中档模型的选型：如果 6.1 Sol 真的接近 Astra，付五分之一的价钱就能办到接近旗舰的事，那么很多原来要调 Astra 的任务都可以降档。对行业来说，它把竞争的焦点进一步从绝对分数拉向了性价比：帖子通篇都在强调“五分之一”“三分之一”“七分之一”这些成本比，而不是只强调分数。

为什么只隔一周？帖子没有回答这个问题。合理的推测是，GPT-6 Sol 发布后的反馈不好，或者 6.1 本来就是计划中的升级，只是发布时间表提前了。但这只是推测，二手来源里有“GPT-6 Sol 发布后开发者反响不佳”的说法，帖子本身没有给出任何解释，这里记下来，不当作结论。

方法与问题是匹配的：作为产品发布帖，它用价格与基准差值来回答产品问题，这是对的；但它没有提供任何可以独立复核评估方法的信息，这一点与研究论文的要求相去甚远，读者应当按产品公告的标准去读它，而不是按论文的标准去读它。

答案改变了什么？认知上，它确认了“性价比正在成为前沿模型竞争的主战场”，并且确认了 OpenAI 愿意用一周一次的节奏升级中档模型。实践上，它给出了一个清晰的选型建议：日常的专业工作用 6.1 Sol，最难的科学研究任务还是用 Astra。至于它没有改变的东西：它没有证明 6.1 Sol 在任何一项基准上真正追平或超过了 Astra，帖子自己的数字也不支持这样的读法。

### 证据链：数字全是差值与比值，绝对分数只有一个

这篇帖子的证据比 GPT-5.6 那篇还要薄。GPT-5.6 的帖子至少有十张基准表，读者可以自己对照；这篇连一张表都没有，全部数字都在正文句子里，而且几乎全是差值与成本比。

先说能验算的部分。事实准确性那一段是全篇最干净的：11.4% 降到 7.7%，相对降幅 32.5%，帖子说“大约 32%”，对得上。Terminal-Bench Science 0.1 的成本那一段也能验算：5.47 美元对 23.21 美元与 23.80 美元，确实低了 75% 以上。缓存输入 0.10 美元比标准输入 2 美元低 95%，算术也对得上。这三处是帖子里少数几个能用它自己的数字验算的说法，而且都站得住。

问题出在验算不了的部分。DeepSWE 上“追平 Astra”、GDP.pdf 上“接近 Astra 的最高水平”、AutomationBench 上“高 2.2 个百分点”、OSWorld 上“离 Astra 还有 2.1 个百分点”、Terminal-Bench Science 上“比 GPT-6 Sol 翻了一倍还多”——这五项里，没有一项给出 GPT-6.1 Sol 自己的绝对分数。读者只知道它比别人高多少、离别人差多少，却不知道它自己考了多少分。差值没有锚点，就没法判断这个差值是大是小：在 90 分的量表上差 2.2 个百分点，与在 30 分的量表上差 2.2 个百分点，完全是两回事。

还有一个口径问题值得点名：标题主张的“五分之一”是 token 价格比，正文里的成本比却是每任务成本比，而且每项都不一样——DeepSWE 上大约是五分之一，GDP.pdf 上大约是五分之一，AutomationBench 上是三分之一（对 Opus 5.5），OSWorld 上是七分之一（对 Astra），Terminal-Bench Science 上不到一半。帖子没有解释为什么每任务成本比在不同基准上差这么多，也没有说明每任务成本是怎么算的。合理的解释是，不同任务用的 token 量与推理力度不同，所以每任务成本比与 token 价格比本来就不是一回事；但帖子没有把这层关系讲清楚，读者很容易把“七分之一”与“五分之一”混为一谈，或者反过来以为“五分之一”就是每项任务都能省下的钱。

另外两个说不清的点：GDP.pdf 一段里的“Opus 5.5 with fallbacks”，“回退”是什么意思，帖子没有定义，这个对照没法理解；“across the tested reasoning settings”出现两次，帖子没有列出测试过哪些推理设置，读者不知道这个说法覆盖了几个设置。

最后，标题主张的一半证据不在本帖里。“五分之一”这个比值需要 Astra 的标准价是输入 10 美元、输出 50 美元，但 Astra 的价格没有在这篇帖子里出现。按二手来源的说法，Astra 确实是 10 美元与 50 美元，比值算术上是对的；但严格说，读者只读本帖是验算不了这个卖点的。这一点与 GPT-5.6 那篇不同：那篇的表虽然没有注明推理力度，至少数字本身都在帖子里。

### 价值判断

认知价值：它没有提供新的科学认知。它值得被记住的，是“中档模型一周就升级”这个发布节奏，以及“性价比正在成为前沿竞争的主战场”这个信号。反事实是：要推翻这个判断，需要证明 6.1 Sol 的性价比优势在独立复测中不存在——而帖子没有给出复测所需的绝对分数与测试条件，所以这个判断目前既无法证实，也无法证伪。

方法价值：它没有留下可复用的方法。五项基准的差值与成本比是一组数字，不是一套方法。唯一可能被留意的是 GDP.pdf 与 AutomationBench 这两项评估本身——前者测的是复杂 PDF 文档的专业问答，后者测的是多步骤业务工作流——但帖子没有给出它们的任务细节与评分方法，别人拿不走。

边界价值：它明确不证明 6.1 Sol 在所有任务上接近 Astra。帖子自己就划了一条线：最难的科学研究任务还是用 Astra，因为 Astra 在 Terminal-Bench Science 0.1 上的 68.1% 仍然是最高的。读者最容易误读的推论是“6.1 Sol 已经追平 Astra”，帖子在 DeepSWE 上确实写了“追平”，但没有给出任何一方的分数，这个“追平”是没法核实的。

启示价值：最便宜的决定性下一步，是第三方用公开的推理力度与成本口径，独立复测这五项基准里的关键几项——DeepSWE v1.1、OSWorld 2.0 与 Terminal-Bench Science 0.1，公布每个分数对应的推理力度、token 用量与每任务成本。如果复测发现 6.1 Sol 的分数确实接近 Astra，标题主张就立住了；如果复测发现“追平 Astra”只在最大推理力度下成立，而默认档位差得很远，那么“接近 Astra、五分之一价格”这个主张就要打折扣。其次是看系统卡附录的完整版：帖子把安全评估的细节指向了附录，但附录本身也只有几段，生物与网络安全“没有越过 Critical 阈值”的具体测试分数在那里也没有给出。

### 最弱的一环

全篇最薄弱的一环，是绝对分数的缺失。五项基准、两项对齐评估、一项事实准确性评估，全篇唯一的绝对基准分数是 Astra 在 Terminal-Bench Science 0.1 上的 68.1%。没有绝对分数，差值就没有锚点；没有测试条件，成本比就没法复核；没有样本量与误差棒，任何一个数字都只能当作 OpenAI 的自我报告来读。

这不是说数字是假的，而是说数字是无法独立验证的。按“产品发布帖”的标准去读，它是可信的；按“研究报告”的标准去读，它是不合格的。这篇精读把它当作前者来读，结论也只做到前者的程度。

### 效度判断

内部效度不适用。这不是一项对照实验，没有干预、没有分组、没有随机化。帖子报告的是一组基准差值，而不是一次实验的结果。

外部效度窄。结论只针对 GPT-6.1 Sol 这个模型、这五项基准、发布时的价格。价格与上市范围都可能很快变化——事实上二手来源说 GPT-6.2 Sol 已于 2026 年 11 月 17 日取代了 6.1 Sol，价格不变；这个说法来自二手来源，见未核实清单。帖子里的价格与可用性只在发布当天是准确的。

构念效度方面，“基准分高”在这里被当作“能力强”的证据，但帖子没有讨论基准分与真实工作效果之间的关系。AutomationBench 与 GDP.pdf 这类贴近真实工作的评估，比单纯的学术基准更接近“能力”这个构念，但帖子没有区分这两类评估的权重，而是把它们并列放在一起，而且都没有给出绝对分数。

统计结论效度低。没有任何一个分数附带样本量、运行次数、误差棒或置信区间；“每任务成本”没有计算方法；“追平 Astra”“接近 Astra”这类说法没有任何一方的绝对分数支撑。这些数字作为方向性证据是可用的，作为精确的效应量是不可用的。

可复现性低。帖子没有公开评估 harness、提示词、推理力度设置或原始数据，第三方无法重跑帖子里的数字。好在复核不完全依赖复现：事实准确性与成本这两段的算术，只需要帖子本身就能验算，而且都站得住；其余的说法验算不了，不是因为复现不了，而是因为帖子根本没有给出足够的信息。

## 七、证伪器、替代解释、接下来看什么

### 证伪器

- 第三方用公开的推理力度与成本口径复测 DeepSWE v1.1，发现 GPT-6.1 Sol 的分数明显低于 Astra，或发现“追平 Astra”只在最大推理力度下成立、默认档位差得很远，帖子的标题主张即被削弱。
- 复测 Terminal-Bench Science 0.1，发现 GPT-6.1 Sol 的分数并没有比 GPT-6 Sol 翻倍，或发现每任务成本远高于帖子说的 5.47 美元，“实质提升、成本减半”的说法即被削弱。
- 复测事实准确性评估，发现低推理力度下事实错误占比并没有从 11.4% 降到 7.7%，帖子里唯一一组可验算的数字即被证伪。
- 独立复测 OSWorld 2.0，发现 GPT-6.1 Sol 与 Astra 的差距远大于 2.1 个百分点，“接近 Astra”的说法即被削弱。

### 替代解释

替代解释一：6.1 Sol 的提升主要来自更高的推理力度，而不是模型本身更强。帖子在几处明确说用了最大推理力度，在 DeepSWE 一段又说用了“更低的推理力度”——但“更低”是相对 GPT-6 Sol 的最好成绩而言的，而 GPT-6 Sol 最好成绩的推理力度没有给出。如果 6.1 Sol 的分数是在最大推理力度下测得，而对照模型的分数是在默认档位下测得，那么“6.1 Sol 更强”这个结论就混淆了模型能力与推理预算。区分的办法是固定推理力度重新测：把所有模型放在同一个档位下比较，看 6.1 Sol 的领先是否还在。帖子没有提供这样的数据，所以这个替代解释目前无法裁决。

替代解释二：帖子挑选了对 6.1 Sol 有利的说法来讲故事。五项基准里没有一项给出 6.1 Sol 自己的绝对分数，读者没法看到它在哪项上离 Astra 还差得远；Terminal-Bench Science 0.1 上 Astra 的 68.1% 是全篇唯一的绝对分数，帖子没有说 6.1 Sol 在这项上到底是多少分，只说“翻了一倍还多”——如果 GPT-6 Sol 的分数本来就很低，翻倍之后仍然可能离 Astra 很远。区分的办法是看绝对分数而不是只看差值——本篇正是这样做的。单看正文的差值，读者会得到“6.1 Sol 已经接近 Astra”的印象；要看到完整图景，需要绝对分数，而帖子没有给。

### 作者自述局限与分析者发现的局限

作者自述的局限：事实准确性评估用的提示是故意挑出的难题，不代表典型用法；对齐评估测的是挑战性情境，不是典型使用中的失败率；最难的科学研究任务还是用 Astra；系统卡附录里的既往模型对照值可能反映后续版本。

分析者发现的局限，作者没有明说的有三点。第一，全篇没有一张评估表，五项基准里没有一项给出 GPT-6.1 Sol 自己的绝对分数，差值没有锚点。第二，标题主张的“五分之一”是 token 价格比，正文里的成本比却是每任务成本比，而且每项都不一样，帖子没有解释两者的关系，也没有给出每任务成本的计算方法。第三，GDP.pdf 一段里的“Opus 5.5 with fallbacks”没有定义，“across the tested reasoning settings”没有列出测试过哪些设置，这两个说法都没法理解。

### 接下来看什么

排第一的是第三方独立复测：用公开的推理力度与成本口径，复测 DeepSWE v1.1、OSWorld 2.0 与 Terminal-Bench Science 0.1 这三项，公布每个分数对应的推理力度、token 用量与每任务成本。如果复测发现 6.1 Sol 的分数确实接近 Astra，标题主张立住；如果 6.1 Sol 的领先只在最大推理力度下成立，主张就要打折扣。

其次是看系统卡附录的完整版。帖子把安全评估的细节指向了附录，但附录本身也只有几段，生物与网络安全“没有越过 Critical 阈值”的具体测试分数在那里也没有给出。附录的精读是另一篇的工作，但它是验证这篇帖子安全主张的唯一途径。

再其次是看 6.1 Sol 的后续命运。二手来源说 GPT-6.2 Sol 已于 2026 年 11 月 17 日取代了 6.1 Sol，价格不变；如果这个说法属实，6.1 Sol 的生命周期只有不到两个月，值得在后续的 GPT-6.2 精读里对照着看：6.2 相对 6.1 又改了什么。

### 未解问题

- DeepSWE v1.1、GDP.pdf、AutomationBench、OSWorld 2.0、Terminal-Bench Science 0.1 上，GPT-6.1 Sol 自己的绝对分数是多少？说不清，需要 OpenAI 公布绝对分数或第三方复测。
- 每项评估是在哪个推理力度下测得的？说不清，需要 OpenAI 公布每项的测试条件。
- “每任务成本”是怎么算的？说不清，需要成本模型的定义。
- GDP.pdf 一段里的“Opus 5.5 with fallbacks”，“回退”是什么意思？说不清，需要 OpenAI 解释这个对照的定义。
- 对齐评估里三项“更低的失败率”具体低了多少？说不清，需要具体数字或系统卡附录的完整版。
- GPT-6 Sol 的缓存输入价真的是每百万 token 0.20 美元吗？说不清，需要 GPT-6 Sol 发布帖的价格表。
- 博客的发布日期到底是哪一天？说不清，见未核实清单。

## I. 结论、结果与价值总览

### 一句话结论

GPT-6.1 Sol 是 GPT-6 Sol 发布一周之后的中档升级，价格不变，标题主张是“接近 Astra、五分之一价格”；价格算术站得住，但能力数字几乎全是没锚点的差值与比值，所以它是一篇可信的产品发布帖，不是一份可复核的研究报告。

### 核心结论

1. GPT-6.1 Sol 的标准 API 价格是输入每百万 token 2 美元、缓存输入 0.10 美元、输出 10 美元，发布当天起向 ChatGPT Work 与 Codex 的付费用户开放，普通 Chat 里暂未上线。置信度高。证据：数字台账 E1、E10。

认知价值：没有提供新的科学认知，值得被记住的是“中档模型一周就升级”这个发布节奏与“性价比正在成为前沿竞争主战场”这个信号。方法价值：没有留下可复用的方法，GDP.pdf 与 AutomationBench 这两项评估本身可能值得留意，但帖子没有给出任务细节与评分方法。边界价值：它明确不证明 6.1 Sol 在所有任务上接近 Astra，帖子自己就划了线——最难的科学研究任务还是用 Astra；读者最容易误读的推论恰恰是“6.1 Sol 已经追平 Astra”，而“追平”这个说法没有任何一方的绝对分数支撑。启示价值：下一步最值得看的是第三方独立复测，用公开的推理力度与成本口径重测 DeepSWE v1.1、OSWorld 2.0 与 Terminal-Bench Science 0.1，看 6.1 Sol 的领先是否只在最大推理力度下成立。

### 适用边界

它不证明 6.1 Sol 在任何一项基准上真正追平或超过了 Astra，不证明“五分之一”这个比值在每项任务上都能兑现为每任务成本的节省，不证明对齐评估的改进在典型使用中同样成立。它不该被拿来为“6.1 Sol 已经追平 Astra”背书，也不该被拿来为“性价比问题已经解决”背书。价格与上市范围只在发布当天准确，引用时必须注明时间。
